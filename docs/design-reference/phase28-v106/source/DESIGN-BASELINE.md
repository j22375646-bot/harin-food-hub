# 하린식품 허브 Phase 28 시안 고정 기준

이 폴더는 `하린식품 허브 시안 제작 전용` 대화에서 계속 사용하는 인터랙티브 시안 원본이다.

## 현재 체크포인트

- 공통 셸: V72 보강 계약 고정. V42의 `Harin Daily Desk`와 `오늘의 운영선`을 시각 기반으로 유지
- 공통 상단 제목: V75 주문·CS의 상태점·한국어 운영 맥락·제목·설명 구조를 모든 후속 페이지에 고정
- 선택 표면: V76 카드·행·패널의 한쪽 강조선을 전면 금지하고 옅은 전체 배경과 균형 잡힌 1px 전체 테두리로 고정
- 공통 가독성: V77 주문·배송과 고객·CS를 기준으로 주요 행 14~15px, 본문·조작부 13px 이상, 보조문구 12px 이상, 조작 높이 44px 이상을 모든 페이지에 고정
- 기준 페이지: V78 `오늘(메인) · 주문·배송 · 고객·CS` 세 화면을 이후 모든 수정·신설 시안의 고정 비교 원본으로 사용
- 재고·상품 행: V79 고객·CS 인박스의 17px 주요문구·14px 보조문구·중립 선택 표면·전체 1px 테두리를 고정 적용하고 긴 가로 정보는 맥락별 세로 묶음으로 전환
- 경계 무결성: V84 둥근 목록·카드의 외곽선과 인접한 헤더·도구 행 구분선이 같은 위치에 중첩되거나 모서리 밖으로 연장되지 않도록 고정
- 메인: 결정 3건과 운영 확인 4건의 의미를 분리하고 공통 표본 스냅샷 적용
- 주문·배송: V56 공개 상호작용을 유지하며 모바일 출고 레일 안내·고정 액션 안전 여백 보강
- 고객·CS: V61 상담 인박스·30분 응대 레인을 유지하며 모바일 응대 레인 안내·고정 액션 안전 여백 보강
- 재고·상품: V66 두 경로 기능, V67 가독성·터치·수동 다크 모드, V72 명시적 라이트 색상·큰 한눈 요약판까지 고정 승인
- 정산·비용: V72 채널별 지급 레인·대조 작업공간·차이 근거 패널 고정
- 키워드: V74 네이버 직접 운영·쿠팡 WING 수동 작업의 채널 분리형 운영 페이지 고정
- 분석: V72 원인→행동 브리지와 성과·키워드·시장 근거 작업공간 고정
- 개발: V72 시장→경쟁→구매 전환→실험→검증 단계 레일과 승인·실행 검증 연결 고정
- 시스템: V72 제공자별 연결 상태 지도와 실패·재시도 작업공간 고정
- 시스템: V102 `시스템 데이터 흐름선 → 핵심 연결 → 받는 자료 → 작업·스케줄 → 오류·복구` 구조 고정. 필수 운영 연결 6개만 상시 표시하고 보조 공급자는 기능 활성화·자격증명·최근 실행 근거가 있을 때만 노출
- 실제 허브 보완: V103~V105 `알림 · 진단목록 · 변경기록 · 실행검증 · A/B 테스트 · AI 기준자료` 여섯 독립 경로를 고정. 기존 분석·개발·시스템에 억지로 합치지 않고 그룹형 보조 내비게이션과 모바일 더보기·명령 팔레트에서 모두 접근

## V103~V105 실제 허브 보완 경로 고정

- 왼쪽 메뉴의 기존 1차 항목 밀도는 유지하고 `진단목록`, `실행검증`, `A/B 테스트`, `변경기록`, `알림`, `AI 기준자료`를 작은 보조 경로로 연결한다. 현재 경로는 공통 옅은 배경과 전체 1px 테두리만 사용하며 왼쪽선·선택점·넓은 파란 면을 만들지 않는다.
- 모바일 주요 다섯 칸은 바꾸지 않는다. 여섯 경로는 `더보기` 목록에서 독립 진입할 수 있고, 알림은 상단 알림 버튼에서도 바로 연다. 명령 팔레트는 기존 11개와 신규 6개를 합친 17개 경로를 검색한다.
- V103 알림은 `발견 → 확인 → 처리 → 기록` 흐름과 고객·CS형 인박스를 대표 구조로 사용한다. `열림 · 1시간 숨김 · 확인 · 해결 · 전체`를 분리하고 허브 내부 상태 변경과 외부 이메일 발송을 같은 동작처럼 표현하지 않는다.
- V104 진단·변경·실행검증·A/B 테스트는 `진단 근거 → 변경 기록 → 7·14일 결과 → 다음 실험` 네 단계 결정 흐름을 공유하되 자료와 작업은 독립 경로에 보존한다. 진단을 열어도 자동 실행하지 않고, 변경은 전후값·멱등키·재조회·롤백을 표시하며, 검증은 기대→실행→7일→14일을 비교하고, 실험은 최소 표본·신뢰도를 통과하기 전 승자를 만들지 않는다.
- 실행검증의 `고객·재구매`는 실행 결과 탭과 분리한다. 최소 90일 이력과 반복 구매 간격이 부족하면 `판단 보류`를 유지하고 고객 식별정보를 시안에 표시하지 않는다.
- V105 AI 기준자료는 AI 채팅이 아니라 `원본 비공개 보관 → 개인정보 제외 검수 → 페이지 적용 범위 → 검색 준비` 신뢰 게이트와 버전 보관함으로 고정한다. 원본 교체 시 재검수가 필요하고 개인정보·원본·적용 범위가 준비되기 전에 자동 적용하지 않는다.

## V106 전체 경로 가독성·탐색 디테일 고정

- 17개 시안 페이지의 화면에 보이는 운영 텍스트는 `12px` 미만으로 줄이지 않는다. 요일·상태시각·SLA·표본 라벨·차트 축·SHA 식별자처럼 조밀한 정보도 축소하지 않고 공간을 재배치한다.
- 공통 채널 로고 글자는 모든 크기 변형에서 최소 `12px`로 유지한다. 고객 아바타 보조 로고는 `22×22px` 안에서 네이버 `N`, Cafe24 `24`, 쿠팡 `C`를 중앙 정렬한다.
- 긴 데스크톱 사이드바에서 직접 진입한 활성 메뉴가 화면 밖에 있으면 사이드바 자체만 필요한 만큼 이동한다. `scrollIntoView`로 문서 전체를 움직이지 않으며 페이지 전환 시 본문 스크롤 규칙과 섞지 않는다.
- 모바일 `진단목록 → 변경기록 → 실행검증 → A/B 테스트` 결정 순환은 내부 가로 스크롤과 스냅을 사용하고 `옆으로 넘겨 4단계 전체 보기` 안내를 표시한다. 모션 감소 환경에서는 안내 아이콘 움직임을 제거한다.
- 레거시 브라우저 테스트도 현재 17개 경로, V102 시스템 서비스 선택자, V95 상품분석 접힘 구조를 실제로 열어 검증한다. 닫힌 상세의 빈 `innerText`를 기능 누락으로 오판하지 않는다.
- 여섯 경로 모두 기존 `operations-main`, 공통 상단 제목, 44px 조작부, 고객·CS형 목록 가독성, `operations-layout` 오른쪽 작업석, 48×48px 접힘과 440ms 모션을 재사용한다. 1450px 이하에서는 작업석을 본문 아래에 쌓고 390px·430px에서 정보를 삭제하지 않는다.
- 모든 값은 시안 샘플이다. 실제 API, 파일 업로드, 이메일 발송, 광고·상품·채널 쓰기를 호출하지 않으며 `READY`, `SETUP_REQUIRED`, `확인 필요`, `판단 보류`, `표본 대기`를 성공이나 0으로 바꾸지 않는다.
- 시안은 시각·상호작용 명세이며 실제 운영 배포나 API 연결 완료를 의미하지 않는다.

## V102 시스템 운영 콘솔 고정

- 시스템 페이지는 외부 API, 읽기 검증, 수집 작업, Supabase 저장, 허브 반영의 다섯 단계를 한 흐름선으로 보여준다. 연결 성공과 최신 자료 반영을 같은 상태로 합치지 않는다.
- 기본 화면에는 Cafe24, 네이버 검색광고, 네이버 커머스, 쿠팡, ePost, Supabase의 핵심 연결만 상시 표시한다. 후보·선택형 API는 단순히 코드나 환경변수 이름이 존재한다는 이유로 설정 오류에 포함하지 않는다.
- 상태는 설정, 읽기 검증, 자료 최신성, 쓰기 잠금, 작업 상태의 다섯 축을 분리한다. 누락·오래됨·최근 실패를 숫자 0이나 정상으로 바꾸지 않고 `확인 필요`, `이전 성공 자료`, `판단 보류`로 표시한다.
- 공급자 상세는 선택할 때 한 건씩 불러오고 같은 공급자는 화면 캐시를 재사용한다. 초기 화면은 요약과 서비스 헤더만 표시하며 전체 실행 이력이나 로그를 한 번에 적재하지 않는다.
- 비밀번호·토큰·API 키 실제 값은 시안과 실제 화면 모두에서 표시하지 않는다. 보관 위치, 권한 종류, 마지막 읽기 검증, 사용 페이지와 안전한 다음 행동만 보여준다.

## V78 기준 페이지 3종 고정

- 이후 시안을 수정하거나 새로 만들기 전에 `오늘(메인)`, `주문·배송`, `고객·CS`를 같은 화면 폭과 테마에서 나란히 비교한다. 다른 페이지의 임의 값이나 오래된 버전을 새 기준으로 삼지 않는다.
- 오늘(메인)은 공통 셸, 캔버스 폭과 좌우 여백, 상단바, 큰 한국어 판단 제목, 설명 간격, 표면·모서리·반응형 기반을 소유한다.
- 주문·배송은 운영 목록의 정보 밀도, 주요·보조 글자 위계, 44px 이상 조작부, 작업공간과 오른쪽 레일의 균형을 소유한다.
- 고객·CS는 인박스형 행의 가독성, 고객·문의 맥락 위계, 오른쪽 보조 작업석의 탭·패널 구조와 자연스러운 접힘·펼침 경험을 소유한다.
- 세 화면의 공통 수치를 토큰처럼 재사용한다. 데스크톱 제목은 `clamp(34px, 3vw, 50px)`/900/1.08, 설명은 18px/1.55, 상태 맥락 행은 15px/800, 주요 행은 14~17px, 본문·조작부는 13px 이상, 조작 높이는 44px 이상을 유지한다.
- 오른쪽 작업석은 공통 열린 폭 `clamp(370px, 21vw, 410px)`, 열린 간격 28px, 접힌 간격 16px, 접힌 크기 `48×48px`, 440ms와 `cubic-bezier(.22,1,.36,1)`을 사용한다. 접힌 뒤 빈 세로 레일이나 패널 배경을 남기지 않는다.
- 새 페이지는 업무에 맞는 정보 구조를 가져야 하지만 공통 셸, 글자 크기, 요소 크기, 제목 체계, 오른쪽 탭·패널 모션을 페이지 전용 값으로 다시 만들지 않는다.
- 승인 전 1728px 데스크톱과 430px·390px 모바일, 라이트·다크, 모션 감소 환경에서 세 기준 페이지와 함께 비교하고 가로 넘침·콘솔 오류·접힘 상태를 확인한다.

## V79 재고·상품 목록 행 고정

- 재고의 판매 상품 행과 상품의 기준 상품 행은 고객·CS 인박스 행의 가독성 크기를 그대로 사용한다. 주요 상품명은 17px/1.42, SKU·옵션·판매 상태 같은 보조문구는 14px/1.45를 유지한다.
- 행은 최소 104px 높이와 48px 썸네일을 사용하며 글자만 키우지 않고 내부 여백, 상태 배지, 수치 간격을 함께 키운다.
- 재고의 `주문 가능·30일 판매`는 같은 맥락 열에서 세로로 묶고, 상품의 `원가 상태·판매 판단`도 같은 판단 열에서 세로로 묶어 정보가 화면 끝까지 길게 흩어지지 않게 한다.
- 선택 행은 파란색 면 채움을 사용하지 않는다. 고객·CS와 같은 중립 표면과 균형 잡힌 1px 전체 테두리로만 구분하며 왼쪽 선, 한쪽 색 띠, 강한 파란 배경을 다시 만들지 않는다.
- 데스크톱 목록은 작업공간 가장자리에서 18px 안쪽, 모바일은 10px 안쪽에 두어 행이 컨테이너 끝까지 과도하게 늘어나지 않게 한다.
- 모바일에서도 상품명 17px·보조문구 14px을 유지한다. 재고는 핵심 보유일, 상품은 원가·판매 판단 배지를 오른쪽에 세로 배치하고 공간을 만들기 위해 글자를 줄이지 않는다.
- 이 규칙은 재고·상품뿐 아니라 이후 만드는 모든 운영 목록에서 고객·CS형 인박스 행을 사용할 때의 고정 컴포넌트 기준이다.

## 공통 셸

- 접을 수 있는 왼쪽 내비게이션, 고정 상단바, 넓고 유동적인 본문, 스크롤을 따라오는 오른쪽 보조 작업석을 유지한다.
- 모든 경로의 `main`은 공통 셸이 폭을 소유하며 페이지 내부에서 다시 최대 폭이나 바깥 패딩을 만들지 않는다. 캔버스는 V42 Main 기준인 최대 `2300px`, 데스크톱 좌우 여백 `clamp(34px, 3vw, 72px)`를 사용한다.
- 메인·주문·CS·재고·상품·정산·키워드·분석·개발·시스템은 같은 화면 폭에서 같은 본문 시작점과 끝점을 사용한다. `980px` 이하에서는 좌우 `16px`, `620px` 이하에서는 좌우 `12px`로 함께 전환한다.
- 오른쪽 보조 작업석의 공통 본문 아래 전환점은 `1480px`이다. 페이지가 개별 CSS에서 더 늦게 2열을 유지해 1451~1480px 구간에 좁은 본문이나 빈 레일을 만들지 않는다.
- 오른쪽 보조 작업석을 접으면 세로 레일·빈 테두리·패널 배경을 남기지 않고 상단의 `48×48px` 정사각형 펼치기 버튼만 표시한다. 이 규칙은 메인과 모든 페이지에 공통 적용한다.
- 모바일에서는 오른쪽 보조 작업석을 하단 시트 또는 본문 아래 작업 영역으로 바꾼다.
- 공통 셸은 같게 유지하되 페이지 본문은 업무 성격에 맞는 고유한 정보 구조를 사용한다. 다른 페이지의 레일이나 카드 구성을 그대로 복제하지 않는다.
- 로고, 채널 브랜드 타일, 다크 모드 토큰, 키보드 포커스, 모션 감소 설정을 공통으로 유지한다.
- 왼쪽 메뉴의 현재 경로는 옅은 선택 배경과 아이콘 상태로만 구분한다. 왼쪽 파란 세로선과 오른쪽 파란점은 사용하지 않아 우측 알림 숫자를 가리지 않는다.
- 모바일 주요 메뉴는 `오늘·주문·CS·재고·상품(통합)·더보기`의 다섯 칸으로 고정한다. 상품 운영과 정산·비용·분석·개발·시스템은 더보기에서 열고, 알림은 상단 버튼에 둔다.
- 정산·비용, 키워드, 분석, 개발, 시스템은 데스크톱 왼쪽 메뉴와 모바일 더보기에서 실제 시안 경로로 이동한다.

- 모든 현재 페이지는 `HS-20260828-1042` 표본 스냅샷과 같은 기준시각을 사용한다. 시안임을 공통 상단바와 모바일 헤더에서 항상 확인할 수 있어야 한다.

## 제목과 글자

- 메인 이후 모든 업무 페이지의 상단은 `한국어 운영 맥락 상태 행 → 판단 제목 → 설명`의 한 구조로 고정한다. 주문·CS의 상태 행을 기준으로 8px 민트 상태점, 15px/800 문구, 9px 내부 간격을 사용한다.
- 재고·상품·정산·키워드·분석·개발·시스템도 페이지 제목 위에 장식용 대문자 영문 eyebrow를 사용하지 않는다. 채널 범위, 조회 전용, 자료 기준, 실행 제한처럼 실제 운영 의미를 한국어로 표시한다.
- 상태 행과 제목 간격은 데스크톱·모바일 모두 8px이다. 데스크톱 제목은 최대 50px, 설명은 18px/상단 14px이며, 760px 이하에서는 주문·CS와 동일하게 제목 34px, 설명 16px/상단 20px로 전환한다.
- 페이지 제목: `clamp(34px, 3vw, 50px)`, 굵기 900, 줄높이 1.08, 자간 약 `-.052em`.
- 제목에서 판단에 중요한 문구나 숫자 하나만 `<em class="page-title-accent">`로 강조한다.
- 강조에는 같은 파란색과 3px 왼쪽→오른쪽 `headlineDraw` 밑줄을 사용한다. 밑줄은 첫 화면에서 `scaleX(0)`으로 숨겨진 상태로 시작해 왼쪽에서 오른쪽으로 한 번만 그려지고 완성 상태로 남는다.
- 각 페이지 CSS에서 `.page-title-accent::after` 또는 제목 `em::after`의 위치·색·`transform`을 재정의하지 않는다. 모든 페이지는 공통 밑줄 규칙을 그대로 상속한다.
- 제목 설명: 18px, 줄높이 1.55, 제목과의 간격은 `--page-title-summary-gap: 14px`로 설명 문단이 소유한다.
- 주문·배송과 고객·CS의 목록 밀도와 크기를 공통 가독성 기준으로 사용한다. 주요 행 이름은 14~15px, 본문·표 값·텍스트 조작부는 13px 이상, 보조 설명·표 라벨·상태 보조문구는 12px 이상을 유지한다.
- 버튼·입력·선택·탭처럼 글자가 있는 조작부는 모바일과 데스크톱 모두 높이 44px 이상을 유지한다. 글자만 키우지 않고 행 높이, 카드 내부 여백, 썸네일과 상태 배지 크기도 함께 키운다.
- 재고·상품뿐 아니라 정산·키워드·분석·개발·시스템과 이후 만드는 모든 페이지에 같은 최저선을 적용한다. 모바일에서도 글자를 다시 7~11px로 축소하지 않고, 밀집 표는 글자를 줄이는 대신 안전한 가로 스크롤이나 열 재배치를 사용한다.
- 데스크톱, 390px, 430px에서 제목·설명 간격, 줄바꿈, 정렬을 다시 확인한다.

## 모션과 접근성

- 오른쪽 패널 공통 모션은 `phase28-panel-motion.css`를 사용한다.
- 기본 전환: 440ms, `cubic-bezier(.22,1,.36,1)`.
- 닫을 때 콘텐츠가 먼저 잦아들고, 열 때 폭이 확보된 뒤 콘텐츠가 나타나게 한다.
- 패널 자체 폭을 접힌 순간 `48px`로 직접 바꾸지 않는다. 공통 그리드 레일이 `열린 폭 → 48px`로 전환되고 패널은 레일의 `width:100%`를 따라가야 하며, 이 규칙은 오늘·주문·CS·재고·상품·정산·키워드·분석·개발·시스템과 이후 신설 경로에 그대로 적용한다.
- 콘텐츠를 즉시 `display:none`으로 없애 덜컥거리게 만들지 않는다.
- 토글은 `aria-expanded`를 갱신하고 `prefers-reduced-motion: reduce`에서는 모션을 제거한다.
- 계속 시선을 끄는 장식보다 선택, 전환, 상태 변화처럼 의미 있는 순간에 제한된 모션을 사용한다.

## 주문·배송 오른쪽 작업석 고정 규칙

- 데스크톱의 `선택 주문`, `출고 작업`, `수집 상태` 탭은 같은 그리드 셀과 같은 최대 콘텐츠 높이를 공유한다. 탭마다 패널 높이가 달라져 페이지 본문·스크롤바·오른쪽 요약 위치가 움직이면 안 된다.
- 비활성 탭은 `display:none`으로 레이아웃에서 제거하지 않고 같은 셀에서 `visibility`, `opacity`, `pointer-events`, `inert`, `aria-hidden` 상태를 함께 전환한다.
- `1480px` 이하에서 오른쪽 작업석이 본문 아래로 내려가면 기존 단일 패널 흐름으로 복귀하고, 모바일의 별도 고정 출고 액션을 유지한다.

## 재고·상품 V80 상단 판단 픽토그램 고정 규칙

- 재고는 품절 위험 패키지, 14일 달력·시계, 안정 재고 방패, 장기 보유 보관함으로 구분한다. 상품은 판매 준비 상품, 채널 연결, 원가 증빙, 기준 상품으로 구분한다.

- 픽토그램은 외부 이미지가 아닌 `currentColor` 선형 인라인 SVG를 사용하고 `aria-hidden="true"`로 숨긴다. 상태의 의미는 아이콘이나 색만으로 전달하지 않고 제목, 수치, 설명을 항상 함께 둔다.

- 라이트·다크 테마 모두 같은 픽토그램 체계와 크기를 유지하고, 모바일의 보조 판단은 다음 항목이 보이는 가로 레일, 상품 준비 4단계는 2열로 유지한다.

- `prefers-reduced-motion:reduce`에서는 흐름선과 선택 링 이동을 완전히 제거한다. 모바일 `390px`·`430px`에서는 주 판단을 위에 두고 흐름선을 가로 탐색으로 바꿔 다음 상태가 일부 보이게 한다.
- 영문 장식 라벨을 사용하지 않고 `우선 판단`, `재고 리듬`, `보유일 흐름`처럼 운영자가 바로 이해하는 한글 문구를 사용한다.

## 상품개발 V101 프로젝트·증거선 고정 규칙

- 사용자에게 보이는 페이지명은 `상품개발`로 통일하고 내부 시안 라우트 키 `development`만 직접 링크 호환을 위해 유지한다. 상품분석과는 실행대·저장 장부·긴 보고서·오른쪽 판단석의 구조만 공유하며 분석 지표를 복제하지 않는다.
- 시작 흐름은 `판매상품 선택 → 프로젝트·버전 확인 → 개발공간 열기` 세 단계다. 상품을 선택하는 것만으로 프로젝트를 자동 생성하지 않으며 마지막 버튼을 명시적으로 눌렀을 때만 기존 프로젝트를 열거나 새 프로젝트 경로를 준비한다.
- 대표 장치는 `자료 준비 → 시장 분석 → 경쟁·전환 설계 → A/B 실험 → 결과 학습`의 다섯 단계 `상품개발 증거선`이다. 실제 허브의 데이터·시장·경쟁·전환·실행 브리지·결과 학습 소유권을 상품과 프로젝트별로 격리한다.
- 저장 프로젝트 장부는 프로젝트 ID, 상품, 버전, 진행 단계, 저장 시각을 먼저 보여준다. 과거 버전은 당시 Evidence와 계산을 읽기 전용으로 열며 최신 API 값으로 다시 계산하거나 현재 버전을 덮지 않는다.
- 자료 준비에는 공식 원문, 라벨, OCR 대조, Evidence ID가 포함된다. 시장 분석은 네이버 검색 수요와 자사 주문을 합산하지 않고 같은 기간의 독립 근거로 비교한다. 누락값은 `확인 필요`, `판단 보류`, `SETUP_REQUIRED`로 유지한다.
- A/B 실험은 V83의 네이버·쿠팡·Cafe24 로고를 사용하고 채널별 데이터와 쓰기 경로를 섞지 않는다. 대표 승인, 409 중복 방지, 되돌리기 기준, 결과 스냅샷을 전제로 하며 시안과 AI는 상품·가격·플랫폼을 직접 변경하지 않는다.
- 결과 학습은 7일·14일 관찰, 표본 부족 판단 보류, 최종 보고서와 다음 버전 연결을 함께 보존한다. B2B 조달과 페이지 전용 AI처럼 보조적인 무거운 기능은 기본 보고서에서 접고 최초 펼침 한 건만 불러온 뒤 화면 캐시를 사용한다.
- 선택 상태는 전체 1px 테두리와 중립 배경만 사용한다. 한쪽 장식선이나 넓은 파란 면을 만들지 않고 오른쪽 `PRODUCT DEVELOPMENT DESK`는 공통 440ms 모션으로 접혀 최종 `48×48px` 버튼 하나만 남는다.
- V101 시안은 외부 API나 실제 플랫폼 쓰기를 호출하지 않는다. 1728px·390px 라이트/다크, 모션 감소, 콘솔 오류, 외부 요청 없음, 제목 34px 이상, 컨트롤 44px 이상, 가로 넘침 없음, 프로젝트 자동 생성 0회, 지연 상세 재열람 무요청을 검증 계약으로 고정한다.

## 운영 기능 보존

- 실제 허브 연결 시 검증된 기능, API, 계산, 네이버·쿠팡 데이터 및 쓰기 경계, 페이지별 AI 분리를 유지한다.
- 미수집·오류·오래된 데이터는 0으로 바꾸지 않고 `확인 필요`, `판단 보류`, `BLOCKED`, `SETUP_REQUIRED`처럼 드러낸다.
- 메인·사이드바·모바일 배지는 같은 스냅샷 ID와 기준시각을 사용하며 취소·완료·해결 항목을 제외한다.
- 주문·배송은 판매자배송 작업공간, ePost 등록, 송장 기반 단계 이동, 취소 격리, 상품 이미지, 일괄선택, 시간/수동 동기화, 최근 30일 완료 이력을 보존한다.
- 수동 작업과 소유자 작업은 실제 연결 시 확인, 실행, 결과 검증, 이력, 멱등성, 롤백, 오래된 데이터 잠금을 유지한다.

## 카운트다운

- 일반 운영 카운트다운은 시·분만 표시하고 분 단위로 갱신한다.
- 단순 시간 표시를 위해 API를 다시 호출하지 않는다.
- 초 단위가 실제 업무상 중요한 경우에만 초를 표시한다.
