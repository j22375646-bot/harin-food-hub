# Phase 28 운영 덮어쓰기 기반 수용 기준

## 범위와 주소 원칙

Phase 28 화면은 별도 서비스나 새 주소로 이전하지 않는다. 현재 운영 허브의 인증, API, 계산 로직, 채널별 데이터 경계를 보존하고 기존 주소에서 페이지 단위로 교체한다. 레지스트리에 등록된 주소만 전환 대상으로 인정하며, 등록되지 않은 주소를 추측해 추가하지 않는다.

이번 기반 단계는 새 화면을 운영에 노출하지 않는다. 페이지별 어댑터와 실제 운영 라우트가 모두 준비되기 전에는 기존 V8 화면이 계속 권위 있는 운영 화면이다.

## 기본 상태

```dotenv
HARIN_PHASE28_ENABLED=false
HARIN_PHASE28_PAGES=
```

- 마스터 플래그의 기본값은 비활성이다.
- 페이지 목록의 기본값은 빈 목록이다.
- 알 수 없는 페이지 ID가 설정되면 fail-closed 원칙으로 모든 Phase 28 페이지를 비활성화한다.
- 기능 플래그를 끄면 코드 재배포 없이 기존 화면으로 되돌릴 수 있어야 한다.

## 검증 명령

```powershell
pnpm verify:phase28-foundation
pnpm test
pnpm build
```

`verify:phase28-foundation`은 주소 레지스트리, 기능 플래그, 근거 상태 계약, 준비 상태 검사기를 검증한다. 기반 구조가 정상일 때 `foundation: READY`가 될 수 있지만, 모든 페이지 어댑터와 운영 라우트가 구현되기 전까지 `cutover: BLOCKED`가 정상이다.

운영 전환을 승인하려면 다음 조건을 모두 만족해야 한다.

1. 대상 페이지의 기존 기능·API·계산을 보존하는 어댑터가 존재한다.
2. 레지스트리 주소가 실제 운영 라우트와 일치한다.
3. 누락·오류·설정 필요 상태가 숫자 0으로 바뀌지 않는다.
4. 전체 테스트와 프로덕션 빌드가 통과한다.
5. 페이지 단위로 먼저 활성화해 운영 검증한 뒤 다음 페이지로 진행한다.

## 롤백

문제가 확인되면 `HARIN_PHASE28_ENABLED=false`로 마스터 전환을 즉시 끈다. 일부 페이지에만 문제가 있으면 해당 ID를 `HARIN_PHASE28_PAGES`에서 제거한다. 이 롤백은 기존 라우트, 인증, 데이터, 작업 기록을 삭제하거나 변경하지 않는다.
