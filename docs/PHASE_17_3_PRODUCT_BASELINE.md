# 17-3 상품·옵션·정책 기준선

## 목적

선택 상품마다 상품 역할, 고객, 구매 상황, 망설임, 판매 문구, 상세페이지 점검표와 채널 옵션을 분리 저장한다. 작수차는 첫 검증 상품일 뿐이며 모든 판매 중 마스터 상품이 같은 템플릿을 재사용한다.

## 기존 자료 이전 원칙

- `product_growth_profiles`, `product_detail_checklists`, `product_growth_offers` 원본은 수정하거나 삭제하지 않는다.
- 직접 겹치는 프로필과 점검표는 `market_product_baselines`에 읽기 호환 방식으로 복사한다.
- 행 수, 필드 일치 여부, 원본 보존 여부와 확인 시각을 `migration_report`에 기록한다.
- 원본이 0건이면 `가져올 기존 자료 없음`으로 표시하며 빈 내용을 이전 성공처럼 표현하지 않는다.
- 연결된 채널 상품과 옵션은 읽기 전용 스냅샷이며 판매 플랫폼으로 쓰지 않는다.

## 안전 기준

- 브라우저 역할에는 테이블 권한을 주지 않고 서버의 `service_role`만 사용한다.
- 프로젝트와 상품 ID가 일치하지 않으면 DB 트리거가 저장을 거절한다.
- 치료, 완치, 무조건 같은 표현은 중지하고 건강 관련 표현은 근거 확인 대상으로 둔다.
- 위험 표현이 남아 있으면 사장님이 확인해도 기준선을 자동으로 `VERIFIED` 처리하지 않는다.
- 변경할 때마다 상품 프로젝트 버전을 기록한다.

## 완료 기준

1. 기존 자료 행 수와 필드 일치 결과가 화면과 DB에 남는다.
2. 연결 옵션의 묶음 수량, 총수량, 판매가를 확인할 수 있다.
3. 상품 기준선을 다른 상품 프로젝트와 섞지 않고 저장한다.
4. 기존 성장센터 기능과 원본 테이블은 롤백 기간 동안 유지한다.
5. 페이지별 AI는 별도 접이식 영역을 유지하며 OpenAI 호출은 하지 않는다.
