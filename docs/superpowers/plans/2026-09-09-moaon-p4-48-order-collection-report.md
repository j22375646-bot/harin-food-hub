# P4-48 — 앱 신규 주문 수집

2026-09-09 / 모아온 0.33.0 / 이 PC 설치·검증 완료

## 이번 단계의 목적

웹 허브 화면을 앱에 넣지 않고, 기존 주문 수집 기능을 앱 전용 주문 작업실에서 사용한다. 기존 DB·API·수집 서버·IP를 재사용하고 신규 유료 서비스를 추가하지 않는다.

기존 `POST /api/orders/live-refresh`는 Cafe24·네이버·쿠팡을 함께 수집한다. 따라서 앱의 채널 필터와 무관하게 ‘전체 채널 수집’으로 안내한다. 임의의 채널별 API를 만들거나 채널 필터가 수집 범위를 제한한다고 표시하지 않는다.

## 동작 및 UI 원칙

- 저장 주문 목록을 다시 읽는 작업과 플랫폼에 신규 수집을 요청하는 작업을 구분한다.
- Cafe24의 즉시 처리와 네이버·쿠팡의 서버 대기 작업을 채널별로 표시한다.
- 요청 접수·진행 중·성공·부분 결과·확인 필요를 혼동하지 않는다. 확인 시각이 없으면 임의로 현재 시각을 성공 시각으로 채우지 않는다.
- 결과 확인은 최초 수집의 요청번호로 GET만 실행한다. 반복 확인을 새 수집 POST로 바꾸지 않는다.
- 응답을 받지 못한 작업은 자동 재전송하지 않는다. 개인정보가 포함된 원본 응답과 요청번호는 앱 화면에 넘기지 않는다.
- 목록 재조회는 서버 자료를 읽어 반영하며, 선택 작업을 몰래 지우거나 로컬에서 주문 단계를 추정하지 않는다.
- 기존 Pretendard·테마·부드러운 상세 패널 동작을 유지한다. 수집 결과를 한 구역에 모으고 좁은 창에서도 정렬·줄바꿈·스크롤을 검증한다.

## 검증 결과

- 단위 테스트 182/182 통과. 실제 연결 모듈의 외부 통신 경계에서 요청 URL·메서드·인증·ID 고정·중복 방지·기한·로그아웃을 시험 응답으로 검증했다.
- 인증 만료 뒤 이전 성공을 재노출하는 실패, Cafe24 부분 결과가 사라지는 실패를 먼저 재현한 후 수정했다.
- 개발 코드와 패키지 코드에서 수집 및 배송추적 UI 시험 통과. 수집 중 선택 유지, 대기 상태에서 완료 재조회 숨김, 중복 클릭 차단과 로그아웃 뒤 늦은 응답 제거를 검증했다.
- 1040×800 창에서 결과를 여러 개 펼치면 목록이 줄어드는 회귀를 발견해 수정했다. 결과 영역 비율을 25%로 제한하고 주문 목록 높이 150px 이상을 확보했다. 접힌 상세로 포커스 이동 시 전체 화면이 옆으로 밀리는 문제도 보완했다.
- 라이트·다크 화면을 모의 주문으로 캡처하고 확인했다. 실제 수집 성공을 증명하는 화면은 아니다.
- 별도 리뷰에서 최소 창 1040×720 + 주문 선택 + 상세 열기 조합의 목록 축소를 추가 발견했다. 우선순위가 높은 CSS 규칙으로 최소 높이를 보장하고 작업 영역 세로 스크롤을 유지했다. 결과 4개 확장 및 모든 작업 버튼의 위치·클릭 대상 검사까지 추가해 수정 후 재검토 승인받았다.
- 수정 후 패키지 코드로 수집·배송추적·자동 발급·등록·수동 등록 UI 시험을 모두 재통과했다.
- NSIS 빌드 성공, 설치 종료 코드 0. 실제 설치 앱 버전 0.33.0 확인.
- 설치 앱 두 번 재실행 로그인 유지, 업무 화면 진입 3.855초/2.402초. 해당 실행의 측정값이며 속도 보장은 아니다.
- 실제 서버 저장 주문의 발급 전·등록 후·배송중·완료 구간 및 페이지 이동 조회 통과. 열 정렬 오차 0px, 상세 패널 전환 22프레임·내용 유지·접힘 비활성·스크롤바 숨김 통과.

테스트 중 실제 플랫폼 신규 수집 POST·우체국 발급·송장 전송·인쇄는 실행하지 않았다. 새 수집 기능의 서버 쓰기 응답은 시험 자료로 검증했으며, 실제 운영 수집 완료와 구분한다.

수집 결과는 현재 앱 실행 중에 유지한다. 앱 종료·로그아웃 뒤 요청 이력 복원은 이번 범위가 아니다. 결과 불명 시 새 수집은 잠기고 가능한 기존 요청만 조회한다. 일부 채널 미확인 시 기존 목록 새로고침은 사용할 수 있으나, 수집 UI가 전체 완료로 표시하지 않는다.

## 다음 범위

**P4-49: 선택 주문 일괄 출력·내보내기.** 기존 웹 허브의 출력/내보내기 계약을 대조한 뒤 앱의 선택 주문과 연결한다. 발급된 송장과 주문 일치, 미발급·취소·중복 제외, 프린터 설정·미리보기·재출력 구분을 우선 검증한다. 물리 인쇄 없이 파일·미리보기 시험부터 진행한다.

주문 화면의 남은 일괄 출력/내보내기와 실제 출고용 PC 인수를 이어간다. 실제 고객 주문의 우체국 발급·플랫폼 송장등록·프린터 출력은 모의 테스트와 별도 인수 대상으로 유지한다. 주문 기능을 먼저 마무리한 뒤 다른 페이지 이식으로 이동한다.
