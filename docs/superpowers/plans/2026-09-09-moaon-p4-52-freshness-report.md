# P4-52 주문 변경 감지·안전한 새 목록

2026-09-09 / 기준6a64043 / 모아온0.37.0 구현·검증·이 PC 설치 완료

## 무엇을 바꾸나

주문 화면을 오래 열어두어 주문·사은품 기준이 달라진 것을 놓치는 문제를 줄인다. 자동으로 변경 여부만 확인하고, 목록은 새 목록 보기 버튼을 눌렀을 때 교체한다. 출고 담당자가 보고 있던 주문의 선택·상세가 갑자기 바뀌지 않는 쪽을 선택했다. 완전 무클릭 갱신은 아니며 변경을 반영할 때 한 번의 확인 동작이 필요하다.

## 기존 웹과 연결되는 근거

- `app/api/orders/page/route.js`: 저장 주문과 캘린더 이벤트를 함께 읽고 실패 채널을 partial로 구분한다.
- `lib/ui/phase28-adapters/orders.js`의 `buildOrderPage`: 단계·채널·두 필터·캘린더 eventRevision·주문 상태를 snapshot에 포함한다. 다른 snapshot 요청은409로 거부한다.
- 앱은 이 기존 조회를 사용한다. 별도 calendar legacy API 권한이나 서버·DB·사업장 경계를 추가하지 않는다.
- snapshot에 없는 상품/수량/배송정보 등의 변경은 현재 Main 메모리 내용과 비교해 감지하도록 검증한다.

## 운용 원칙

주문 화면이 보이는 로그인 상태에서만 주기 확인한다. 실제 조회는 최대1분1회이고 동시 요청을 중복 실행하지 않는다. 이것은 기존 저장 주문 API의 GET이며 각 쇼핑몰 새 주문 수집이나 배송추적 POST가 아니다. 새 유료 서비스/인프라를 만들지 않는다. 다만 화면을 계속 열어두면 기존 서버 조회 사용량이 늘어나는 기능이지 네트워크 사용량이0인 기능은 아니다.

실제 주문 발급·쇼핑몰 송장등록·문서 작업 중에는 갱신 조작을 잠근다. 숨겨진 화면/다른 페이지에서는 주기 조회를 쉬고, 실패나 권한 문제는 확인 필요로 표시한다. 기존 화면에 남은 자료를 새 자료로 확정하지 않는다.

## 사용 흐름

주문 작업실을 열어두면 목록 위의 작은 상태줄에서 변경 여부를 확인한다. 변경 알림이 떠도 선택한 주문과 상세 패널은 자동으로 바뀌지 않는다. 안내된 새 목록 보기 버튼을 누르면 선택을 해제하고 현재 채널·조건의 첫 페이지를 다시 조회한다. 서버 연결에 실패하면 최신으로 확정하지 않는다.

이 기능은 쇼핑몰에서 새 주문을 수집하는 기능과 다르다. 기존 수집 기능이 서버에 반영한 주문, 또는 웹 캘린더에서 바꾼 사은품 기준을 앱이 뒤늦게 놓치지 않도록 확인하는 기능이다. 우체국 접수나 쇼핑몰 송장 전송을 자동 재실행하지 않는다.

상태줄은 검색 도구 아래·목록 제목 위에 배치했다. 버튼의 기본 브라우저 테두리를 앱 색상·폰트·둥근 테두리로 맞추고, 작업중 잠금과 해제 상태를 함께 검증했다. 낮은 창에서는 기존 작업영역 안의 스크롤은 유지하되 스크롤바는 숨긴다. 모든 내용을 한 화면 높이에 강제로 축소하지 않는다.

## 남은 단계

P4-53은 주문 전체 검색과 현재페이지 검색 범위 차이를 정리하고 기존 서버 기능으로 가능한 이식 범위를 확정한다. 전체 XLSX/기간 조건 내보내기, 출고용 프린터·용지·바코드와 실제 우체국 발급→플랫폼 등록 종단간 인수는 아직 남아 있다. 주문 기능 전체 완료로 표시하지 않는다.

이번에 `app/api/orders/export/route.js`를 읽어 웹 XLSX의 플랫폼·단계·검색어·시작/종료일 조건을 확인했다. 현재 모아온 사업장별 orders 경로와는 별도 endpoint이고 로켓그로스도 포함할 수 있으므로, 다음 단계에서 단순히 접근 허용만 풀지 않는다. 앱의 사업장·판매자배송 범위와 실패 표시를 보존한 내보내기 계약을 먼저 맞춘다.
