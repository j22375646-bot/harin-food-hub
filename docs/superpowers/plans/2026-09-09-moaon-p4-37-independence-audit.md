# P4-37 독립화 방향 수정과 소스 조사 기록

> **이후 사용자 설명으로 이 문서의 서버·DB 분리 방향은 폐기됨.** 웹 허브의 DB/API/서버/IP는 그대로 공유하고 앱 전용 화면·기능 동선을 구현한다. 아래 내용은 당시 조사 기록이며 현재 개발 지침이 아니다. 현재 결과는 `2026-09-09-moaon-p4-37-local-label-report.md`를 따른다.

상태: 구조 조사/설계 선택 대기. 독립 앱 전환 완료가 아님. 현재 설치 버전 0.24.0은 여전히 기존 웹 허브 API에 의존한다. 이번 조사에서 앱 실행·운영 API·DB·서버 설정을 변경하지 않았다.

## 사용자 기준
웹 허브와 모아온은 별도 공간이다. 웹의 화면이나 운영 API에 종속시키지 않고 검증된 업무 코드/기능을 모아온 구조로 이식한다. 주문을 마친 뒤 다른 페이지를 진행한다. 기존 앱 전용 UI는 보존한다.

## 독립화 선택지
1. 모아온 전용 서버·DB·수집/발급 워커 + Windows 앱: 웹 허브의 로그인/API/DB/큐를 사용하지 않는다. 출고용 PC가 달라도 동일 모아온 업무를 볼 수 있다. 별도 자원 용량·비용·운영 조건 확인 필요.
2. PC 내부 실행·로컬 DB + 플랫폼 직접 통신: 웹 의존성은 없지만 PC가 꺼진 동안 수집 불가, PC별 데이터 동기화/백업, 고정 IP/플랫폼 자격 증명 운영 문제가 별도로 생긴다.
3. 별도 앱 서버지만 웹 DB/워커 공유: 화면/API만 분리되며 이번 사용자가 요구한 엄격한 독립성과 부하 격리를 충족하지 못하므로 목표안에서 제외한다.

출고용 다른 PC와 향후 다른 사업장의 사용 의도를 고려하면 1번을 권고한다. 서버 없는 EXE가 의도라면 2번으로 기준을 변경해야 하므로, 실제 서버/저장 구현 전에 선택이 필요하다. 기존 유료 자원 재활용 가능 여부는 미확인이고 추가 과금 0원을 약속하지 않는다.

## 구현/인수 조건
- 웹 허브 origin을 차단한 상태에서도 독립 로그인·주문·발급·플랫폼 등록·출력이 동작해야 한다. 접속 실패 시 웹 허브로 자동 우회하지 않는다.
- 순수 주문 상태/정규화/금액/암호화/라벨 코드는 계약 시험과 함께 이식한다. Next 라우트, 전역 DB client, 하린 계정/키, 웹 CSS는 그대로 복사하지 않는다.
- 앱 전용 서버의 인증·사업장별 데이터/비밀키 저장·작업 큐를 각각 분리한다. DB 관리자 키/플랫폼 공통 비밀키를 EXE에 포함하지 않는다.
- 별도 DB라고 같은 판매자 주문을 중복 발급해도 되는 것은 아니다. 원천 주문 식별자·기존 송장 확인, 단일 발급 주체로 전환, 대기 작업 정리, 결과 불명 작업의 재전송 금지를 설계한다.
- 웹 운영 데이터 자동 복사/삭제/수집 중단은 하지 않는다. 전환 대상과 과거 이력 확보 방법은 별도 확정한다.
- 독립 환경의 테스트 데이터를 이용해 먼저 시험하고, 실제 출고 인수 전에는 송장을 임의 생성하지 않는다.

## 이번 결과와 미완료
기존 웹 의존 연결을 더 확대하지 않는 것으로 우선순위를 수정했다. 소스 목록과 핵심 의존성을 조사했다. 새 실행 코드/설치 파일/서버/DB는 만들지 않았다. 전체 소스 독해, 독립 인증/DB/수집/우체국 발급 전환은 아직 미완료다.
