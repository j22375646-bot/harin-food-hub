# P5-09 후속 — 인증된 선택 주문 재확인 연결

[전체 개발계획](./2026-09-07-multi-business-desktop-master-plan.md)

## 구현 범위

기존 `createHubConnection`에 Main 전용 `reviewShipment(hubOrderId)`를 연결했다. 별도 인증 구현이나 renderer의 주문 객체를 신뢰하지 않고, 기존 로그인 세션의 `recheckPage()`로 현재 페이지를 다시 조회한다.

- canonical Cafe24/쿠팡 판매자배송 주문 ID만 받는다.
- 주문 목록 조회 전에는 실행하지 않으며 저장된 snapshot과 페이지를 사용한다.
- 새 응답에서 같은 ID가 정확히 한 건이어야 한다. 누락·중복이면 확인 대상으로 반환하지 않는다.
- 부분 수집·인증 실패·취소·기존 송장·정보 부족 등은 기존 사전 확인 결과를 재사용해 차단한다.
- 조회 중 연결 해제나 세대 변경이 발생하면 주문을 반환하지 않는다.
- 반환 데이터는 기존 개인정보 제외 projection이다. 성공 명칭도 REVIEW_ONLY이며 실행 승인이나 발급 권한이 아니다.

## 검증

추가 4개 테스트의 실패를 확인한 후 구현했다. 기존 세션/고정 GET 옵션, 변경 상품 재조회, 잘못된 ID, 목록 없는 호출, 취소/누락/중복/401, 연결 해제 후 늦은 응답을 시험했다. 외부 응답은 합성 자료이며 실제 계정 로그인/송장 발급은 실행하지 않았다.

데스크톱 전체 81개 및 기존 웹 회귀 2,548개 통과. 문법·diff 검사 통과, 전체계획서 링크 62개 유효. 별도 코드 검토에서 확정 결함 없음. PARTIAL·동시 조회·CP 성공의 이 함수 전용 테스트는 비차단 보완 항목으로 남긴다.

## 미완료와 다음 단계

처음 예정한 확인창·진행 UI까지 완료한 것은 아니다. 이번 범위는 확인창에 넘길 선택 주문을 기존 인증 연결부에서 다시 확인하는 단계다. IPC와 UI 노출은 추가하지 않았고 EXE도 다시 만들지 않았다.

다음은 네이티브 확인창, 확인 대기 중 주문/세션 변경 재검사, 작업 코어 및 고정 통신 연결, 진행 UI와 Electron 종단간 시험이다. 조회 결과를 클라이언트용 발급 허가증으로 저장하지 않는다. 실제 발급에는 서버/worker의 최종 재검증이 계속 필요하다.

기존 UI·로그인 방식·조회 네트워크 정책·운영 서버는 변경하지 않았다. 신규 비용 자원·실주문 변경 없음.
