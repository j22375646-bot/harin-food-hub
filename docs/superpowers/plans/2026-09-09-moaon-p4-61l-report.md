# P4-61L — 서버가 공유하는 API 키 저장 요청 제한

## 변경

키 저장 요청에 네트워크 제한 → 동일 쿠키의 읽기 전용 세션 확인 → 사용자 제한을 필수로 적용하는 서버 후보를 구현했다. 제한 어댑터 없이 저장을 시작하지 않는다. 고정 후보 정책은 300초당 전체120/IP30/사용자10이며, 사용자 제한은 사업장·플랫폼·세션 변경으로 나뉘지 않는다. 원본 IP와 사용자 식별자는 별도 HMAC으로 치환한다.

제한 SQL은 기존 최소권한 계정의 두 SECURITY INVOKER 함수와 필요한 테이블 SELECT/INSERT/UPDATE만 사용한다. 잠금 후 DB 시각으로 창을 계산하고 거부된 요청의 선차감은 유지한다. 삭제·인증정보 수정·암호문 조회 권한을 추가하지 않는다.

검토에서 처리기보다 긴 내부 제한 시간이 후속 RPC를 시작할 수 있는 문제를 발견했다. admit(request, credential, {signal, deadline})의 취소 신호와 절대 단조 시각을 내부 어댑터까지 전달하도록 수정했다. 타이머가 밀려도 다음 단계와 저장은 시작하지 않는다. 저장 시작 후 결과 불명 처리도 보존한다.

## 검증

- 집중 시험16/16 통과. timeout/abort/잘못된 응답/동일 쿠키/사용자 정규화/필수 어댑터/저장 결과 불명을 확인했다.
- 실제 격리 PostgreSQL 첫 실행4/4 통과, 최종 SQL 권한·Request→암호화 저장·관측된 행잠금 시각 추가 실행3/3 통과. 실제 제한 로그인과 복수 연결의 GLOBAL120/IP30/USER10 합산을 확인했다. 생성한 시험 DB/역할은 정리했다.
- 독립 검토 승인. 전체 회귀 최종 결과는 아래에 기록한다.
- 전체 병렬 실행 중 일반 거부 응답 시험의10ms 제한이 CPU 대기로 만료돼429 대신503을 반환한 사례1건을 발견했다. 일반 응답 분기 시험은10초, 의도적으로 멈춘 어댑터만10ms를 사용하도록 시험 조건을 분리했다. 운영 코드는 완화하지 않았다.

## 실제 앱 및 사용자 작업 환경

설치 앱0.51.2의 오늘/주문 화면에서 저장 주문 표시와 조회 화면 전환을 확인했다. 사용자가 마우스와 포커스를 점유하는 원격 조작을 불편해하여 즉시 중단했다. 이후 검증은 기존 Electron 자동화를 우선하며 사용자 입력과 포커스를 점유하지 않는다는 지침을 AGENTS.md에 반영했다.

새 로컬 백그라운드 시험 실행기에서 Electron 모듈을 잘못 불러와 setPath 오류 대화상자를 띄운 실수가 있었다. 해당 시험 프로세스를 종료하고 실행기를 수정했다. 설치 앱 코드는 이 오류의 원인이 아니며 사용자 세션/설정은 변경하지 않았다. 숨겨진 창의 스크린샷 시도는 시간 초과되어 이미지 증거로 사용하지 않는다.

수정한 백그라운드 검증은 설치된 app.asar를 기존 개발 Electron과 D의 격리 프로필에서 실행했다. moaon://app/index.html, 로그인 필요 화면, sandbox/contextIsolation 유지, 창 숨김 및 포커스 없음 검증 통과. 이는 로그인된 설치 EXE의 업무 전체 검증이 아니며, 이번 서버 후보 활성화 증거도 아니다.

바탕화면은 존재하지 않는 이전 C 경로에서 D:\OneDrive\바탕 화면으로 복구했다. 변경 전 레지스트리를 D에 백업하고 Explorer 재시작 후 경로 오류 해소와 모아온 바로가기 표시를 확인했다. 다른 개인 폴더는 이동하지 않았다.

## 남은 범위

운영 SQL·역할·HTTP route·앱 서버 저장 연결은 활성화하지 않았다. 앱0.51.2 유지, 새 설치본 배포 없음. 운영량에 맞는 제한 정책, 제한 행 보존/정리, HMAC 교체, 신뢰 IP/세션 주입 검증이 활성화 전 필요하다. 다음은 이 조건과 HTTP/앱 저장 결과 연결이다. 실제 플랫폼 인증 성공을 주장하지 않는다.
