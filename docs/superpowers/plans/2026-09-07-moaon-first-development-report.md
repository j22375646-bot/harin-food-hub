# 모아온 첫 개발 보고서

작성일: 2026-09-07. 제품명: **모아온 / MOAON**. 대상 버전: **1.40.0**.
상태: 구현·로컬 검증 완료, 최종 변경 검토 및 운영 배포 대기.

## 사장님께 설명드리면

모아온은 프로그램 이름이고, 하린식품은 그 안에서 관리하는 사업장 이름입니다. 앞으로 다른 사용자는 자신의 계정으로 로그인하고 자신의 사업장만 열게 됩니다. 이번에는 이 방향으로 이름과 권한 검증 기반을 먼저 마련했습니다.

이 단계는 아직 Windows 설치파일이나 다른 사업장 가입을 제공하는 단계가 아닙니다. 기존 하린식품 업무를 계속 사용할 수 있도록 로그인과 플랫폼 연결은 유지합니다.

## 이번 작업

| 항목 | 내용 | 검증 상태 |
|---|---|---|
| 제품 이름 | 로그인·공통 메뉴·브라우저 제목·설치 이름에 모아온 적용, 하린식품 사업장 표시는 별도 유지 | SSR·회귀 테스트, 로그인 브라우저 검증 통과 |
| 오프라인 안내 | 이전 안내 파일은 보존하고 새 버전의 모아온 안내 제공. 주문/로그인 개인정보를 오프라인 저장하지 않음 | worker·접근 제한 테스트 및 Chrome 실제 offline 전환 통과 |
| 사업장 권한 기반 | 허용된 사업장의 활성 회원인지 확인. 조회/업무 처리/연결 관리/회원 관리 권한 구분 | 집중 테스트 19개 통과 및 독립 검토 승인 |
| 전환 전 조사 | 화면 파일 38개, API 처리 파일 145개. 운영 DB public table 129개를 catalog로 대조 | 읽기 전용 확인 완료; 전체 기능/보안 통과라는 뜻은 아님 |

권한 코드는 쉽게 말해 **어느 사업장의 어떤 문을 열 수 있는지 확인하는 검사기**입니다. 검사기는 만들었지만, 모든 실제 업무 경로와 DB에 연결하는 작업은 다음 단계입니다. 그래서 이번 작업만으로 사업장별 데이터 분리가 완료됐다고 말하지 않습니다.

## 유지한 것

- 현재 비밀번호 로그인, 세션 이름, 만료 시간, 로그아웃 및 기존 접근 제한.
- Cafe24/네이버/쿠팡 API 연결과 수집·주문·송장·정산 계산.
- 상품명, 사업자명, 과거 거래와 고객 자료.
- 기존 UI 배치와 라이트/다크 테마 저장 방식.
- 기존 설치 식별자. 이번에는 설치 파일을 만들거나 새 사업장을 생성하지 않음.
- 기존 H 래스터 아이콘 및 favicon은 후속 모아온 앱 아이콘 제작 단계에서 교체 예정.

## 발견한 다음 핵심 작업

운영 DB의 public table 129개 모두 RLS 설정은 켜져 있지만, tenant_id 컬럼은 0개입니다. 지금 새 사업장 연결 화면만 열면 데이터 분리 보장이 되지 않습니다.

따라서 다음은 개인 계정/초대/사업장 회원정보를 검증 환경에 구현하고, 실제 DB·저장 파일·캐시·수집 대기열을 사업장 단위로 분리하는 단계입니다. 하린식품의 기존 건수와 금액을 전환 전후 비교하고, 두 사업장 사이의 조회·수정·출력 차단을 검증한 뒤 사업장 연결 UI를 개방합니다.

## 이후 개발 순서

1. 계정·초대·사업장 권한과 기존 자료 이전 검증.
2. 사업장별 API 연결, 비밀키 보관, 수집 작업/오류 재시도 분리.
3. 사업장 선택과 연결 상태를 포함한 앱 전용 UI 조정.
4. Windows 설치·업데이트·인쇄 기능 실증과 EXE 제작.
5. 실제 프린터와 업무 시나리오 검증 후 비공개 시험 사용.

사용자에게 요청할 실제 API 연결/인증이나 프린터 확인이 필요해지는 시점에는 구체적인 항목만 안내합니다. 아직 모르는 프린터 모델을 임의로 확정하지 않습니다.

## 최종 검증·배포 결과

- `pnpm test`: **1,973개 통과 / 실패 0 / skip 0**. 최초 실행에서 버전 변경 이력 누락 1건이 검출되어 CHANGELOG를 보완한 뒤 전체 재실행으로 통과했다.
- `pnpm build`: **성공**, Next 16.3 production build. 소스 컴파일 44초는 로컬 빌드 시간이며 화면 로딩 속도가 아니다.
- 로컬 production 서버 + 실제 headless Chrome: 로그인 HTTP 200, 모아온 제목·입력란·라이트/다크, 가로 넘침 없음, 미인증 `/orders` 307 로그인 이동, manifest identity 유지, offline v2 안내 확인. 브라우저 pageerror 0.
- 실제 비밀번호 입력/인증 성공 및 인증 후 주문·송장 실행은 이번 브라우저 검증에 포함하지 않았다. 기존 로그인 회귀 테스트는 통과했으며 외부 실업무 변경은 실행하지 않았다.
- 두 구현 단위의 독립 검토 모두 승인. 권한 검토에서 발견한 비동기 만료/객체 변경, 잘못된 action/clock 예외를 회귀 테스트와 함께 보완했다.
- 운영 배포: 최종 전체 변경 검토 후 결과 기록 예정.
