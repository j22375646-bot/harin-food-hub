# 모아온 P1-04-9 개발 보고서

## 이번 개발의 의미

앞 단계에서 만든 ‘복구 처리 이력 확인·정리 기능’에 요청 입구를 연결한다. 누군가 화면에서 운영자 번호를 바꿔 보내더라도 그 번호를 믿지 않고, 서버가 다시 확인한 로그인 세션의 사용자만 요청자로 사용한다.

이 기능은 비밀번호를 바꾸거나 계정 잠금을 강제로 푸는 기능이 아니다. 확실한 근거가 있는 복구 검토 이력을 정리하는 내부 운영 기능이다. 일반 사업장 관리자는 내부 복구 운영자 권한을 자동으로 얻지 않는다.

## 구현·검증 범위

- 요청 출처, 전송 방식, JSON 크기와 필드, 중복 로그인 쿠키를 확인한다.
- 로그인 서명·세션·활성 계정·인증 이메일을 기존 검증기로 다시 확인하고 기존 복구 검토 연결부를 호출한다.
- 시간 초과나 연결 종료 뒤 아직 보내지 않은 DB 작업은 시작하지 않는다. 자동 재시도하지 않는다.
- 응답에는 비밀키·쿠키·이메일·내부 오류를 포함하지 않고 저장 금지 헤더를 보낸다.
- 합성 자료로 서명된 세션부터 로컬 DB까지 연결해 검사한다. 외부 Auth 서비스 응답은 테스트 대역이며 실제 서비스 검증을 뜻하지 않는다.

구현·소스 검증·독립 검토를 완료했다. 아래 증거와 별도 배포 기록을 구분한다.

## 운영 적용 경계와 개발 중 판단

새 공개 주소·UI·로그인·메일·운영 SQL·환경 설정을 변경하지 않는다. 비활성 후보 코드를 배포하는 것과 실제 복구 기능을 사용하는 것은 별개다. 기존 로그인과 주문·정산 기능을 유지한다.

세션은 DB 요청 직전에 확인하지만, 이미 DB에 도착한 작업을 로그아웃이나 시간 초과가 취소한다고 보장하지 않는다. 그 작업은 나중에 끝날 수 있으므로 같은 처리 식별자로 결과를 확인해야 한다. 이 정책이 운영 요구와 맞지 않으면 로그아웃 뒤 접수된 작업이 완료될 수 있는 위험이 있다. 따라서 실제 활성화 전에 세션 폐기와 DB 처리의 연결 정책을 별도로 검증한다.

운영 자료 복사·새 유료 서버·클라우드 테스트 브랜치는 만들지 않는다. 기존 서비스의 전체 사용량이 무조건 무료라는 뜻은 아니다.
