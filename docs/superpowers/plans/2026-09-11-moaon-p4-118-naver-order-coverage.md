# P4-118 · 네이버 새 주문 반영과 집계 구분 (0.104.0)

## 확인한 원인

운영 DB 읽기 조회에서 PAYED 상품주문 6건이 주문번호 5개에 연결되어 있었다. 한 주문번호에 상품주문 2건이 포함되어 있으며 최근 수집 시각은 2026-09-11 14:01:21 KST다. 해당 6건의 수집 누락은 없었다. 네이버 수집 요청도 SUCCESS였다.

앱 0.103.0의 60초 변경 확인은 CHANGED 안내만 표시하고 목록을 갱신하지 않았다. 기존 설치 패키지와 동일한 네트워크 모의 응답으로 새 주문을 추가했을 때, 수동 갱신 전까지 기존 목록을 유지하는 현상을 재현했다. 사용자 창의 당시 3건 목록 자체를 직접 추출한 것은 아니므로 당시 검색·필터 조건은 확정하지 않는다. 조사 당시 실행 앱은 0.103.0이었다.

## 변경

- 주문 화면이 보이고 첫 페이지이며 선택·상세·송장 작업·입력·대화상자가 없으면 변경 확인 후 새 목록을 자동 반영한다.
- 주문 선택이나 상세 확인 중에는 자동 교체하지 않고 기존 변경 안내와 수동 반영을 유지한다. 백그라운드·최소화 상태의 조회 제한과 Main의 작업 잠금은 유지한다.
- 갱신 시 스크롤 위치와 현재 페이지 검색어를 보존한다.
- 현재 페이지에 네이버 주문 수와 상품주문 수를 함께 표시한다. 현재 저장 자료는 주문 5건 / 상품주문 6건이다. 판매 수량과 상품주문 건수를 혼동하지 않는다. 기존 8개 상품 표시 상한에 도달하면 최소 건수로 표시한다.
- 묶인 상품의 이름·옵션·수량을 목록에서 각각 확인할 수 있게 한다. 주문 식별자와 배송/재고 차감 기준을 임의 분리하지 않는다.
