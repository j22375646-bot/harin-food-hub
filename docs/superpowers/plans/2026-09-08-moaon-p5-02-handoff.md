# P5-02 — Windows 앱의 기존 하린식품 주문 조회 연결

## 이번 개발의 목적과 범위

0.1이 화면과 조작을 확인하는 EXE였다면, 0.2는 그 앱에 기존 하린식품 서버의 로그인과 저장 주문 조회를 연결한 버전이다. 인터넷 브라우저 탭이 아닌 별도 Windows 창으로 실행한다. 서버 자료를 읽기 때문에 인터넷은 필요하다.

다사업장 공개 서비스 완성 버전이 아니다. 기존 하린식품의 OWNER 인증만 그대로 사용하며 다른 사업장 가입, 임의 서버주소·API 키 입력은 열지 않았다. 운영 웹의 인증, API, 데이터베이스와 화면은 변경하지 않았다.

## 사용 방법

1. `Moaon-Preview-0.2.0-Setup.exe`를 실행해 현재 Windows 사용자용으로 설치한다. 또는 `win-unpacked` 폴더 전체를 보존하고 그 안의 `MoaonPreview.exe`를 실행한다.
2. 처음에는 명확히 표시된 샘플 화면으로 시작한다. `하린식품 연결`을 누른다.
3. 별도 공식 로그인 창에서 사용자가 직접 기존 비밀번호를 입력한다. 앱 설정이나 채팅에 비밀번호를 입력하지 않는다.
4. 서버가 인증을 확인하면 주문·배송에서 저장된 '송장 발급 전' 판매자배송 주문의 첫 최대 20건을 조회한다. 전체 건수와 뒤에 더 있는지, 조회 시각, 일부 채널 확인 실패를 별도로 표시한다.
5. `다시 조회`는 허브 서버에 저장된 목록을 다시 읽는다. 쿠팡·네이버·카페24에서 신규 수집을 실행하는 버튼은 아니다.
6. 연결을 해제하거나 앱을 종료하면 앱의 로그인 세션이 사라진다. 다시 실행할 때 재로그인이 필요하며 화면 테마 설정은 유지한다.

## 구현한 안전장치

- 로그인 창에는 로컬 파일·Node·앱 명령 권한이 없다. 로컬 화면에는 연결·조회·해제 세 명령만 열었다.
- 앱 요청은 기존 하린식품의 지정된 로그인과 주문 조회 주소로 제한했다. 송장 발급, 주문 변경, 답변 등록, 파일 다운로드는 열지 않았다.
- 암호·세션을 앱 파일에 넣지 않는다. 주문 화면으로 전달하는 항목은 주문 식별자, 채널, 상품, 상태, 수량, 금액, 주문 시각으로 제한했다. 수취인 이름·연락처·주소는 이 화면에 전달하지 않는다.
- 조회 실패는 0건 또는 샘플 주문으로 대체하지 않는다. 인증 만료·연결 해제 시 실제 목록과 상세를 비우고, 샘플 복귀는 사용자가 직접 선택한다.
- 요청이 늦게 끝나도 연결 해제한 주문을 되살리지 않도록 처리했다. 연결 정보 제거 실패 시 재시작 전에는 재사용을 막는다.

## 검증 상태

- 기존 허브 회귀 테스트: 2,541/2,541 통과, 실패·취소·스킵 없음. 웹 소스와 root 의존성 변경 없음.
- 데스크톱 단위·실행·설치 검증의 최종 결과와 파일 해시는 아래 최종 검증 절에 기록한다.
- 실제 서버의 비로그인 주문 요청은 401로 거절되고 공식 로그인 폼이 열리는 것을 EXE에서 확인했다. 원격 로그인 창에 Node와 앱 bridge가 없는 것도 확인했다.
- **실제 사용자 인증 후 운영 주문을 받아 원본과 대조하는 검증은 아직 남아 있다.** 합성 응답으로 실행한 성공·부분 실패·인증 만료 테스트는 실제 운영 로그인 성공의 증거가 아니다.

## 제한과 다음 개발

미서명 개인 시험용 빌드이므로 Windows 게시자/SmartScreen 경고가 나타날 수 있다. 보안 기능을 끄지 않는다. 기본 아이콘을 사용하며 공개 배포·자동 업데이트·자동 시작은 없다. 새 클라우드 자원이나 유료 인증서는 구매하지 않았다.

다음 P5-03은 사용자 로그인 후 원본 주문 대조부터 시작한다. 그 결과를 바탕으로 앱의 주문 조회 범위와 검색·상세를 넓히고, 인증 오류·통신 단절 시 재연결을 검증한다. 우체국 발급·인쇄는 조회와 분리해 중복 발급 방지 및 실제 프린터 검증 후 연다. 다사업장 가입/API 연결은 기존 사업장 데이터가 섞이지 않는 격리 검증을 통과한 뒤 활성화한다.

## 최종 검증

- 데스크톱 단위 테스트 20/20 통과. 고정 주소·IPC 호출자, 응답 제한, 부분 실패·인증 만료, 지연 응답·연결 해제 등을 검증했다.
- 개발 실행과 패키징 실행에서 메뉴·검색·상세·테마·최소 1040px 창, 원격 요청 차단을 확인했다. 실제 Electron 안에서 합성 응답을 사용해 주문 표시, 인증 만료 시 제거, 샘플 카드 숨김, 명시적 샘플 복귀까지 통과했다.
- 원격 로그인 성공 후 창 종료가 조회 진행을 막을 수 있는 문제와 `display:grid`가 숨김 상태를 덮어쓰는 문제를 실행 검사로 발견해 수정했다.
- 이 PC의 격리된 사용자 설치 경로에서 0.1 설치 → 0.2 업데이트 → 재실행 → 최종 수정본 재설치 → 제거를 확인했다. 설치 버전 레지스트리는 0.2.0이며 최종 설치된 app.asar의 SHA256은 빌드본과 같았다. 시험용 설치는 제거했고 설치 EXE 산출물은 보존했다. 사용자 테마 설정은 임의 삭제하지 않았다.
- 최종 설치본에서 기본 화면, 합성 주문 연결, 실제 비로그인 API·공식 로그인 창 검증을 모두 재실행해 통과했다.
- 최종 설치본 첫 샘플 화면 준비 634ms: 이 PC의 단일 측정이며 실제 로그인·주문 조회 속도나 평균 성능을 뜻하지 않는다.
- app.asar에는 Main·정책·연결 모듈·preload·UI·package.json만 포함했다. 운영 환경변수·DB·테스트 파일은 포함하지 않았다.
- 설치파일 크기 111,358,479 bytes. Windows 서명 상태 `NotSigned`.
- 설치파일 SHA256: `AF266337C55B976D8ED29CA25428CA870379F59A17E7CF90D8060D0B8CED03D0`.
- 최종 app.asar SHA256: `016C79C5372C56C0C773068D561E99273585E9B20DCF29E3A17CA15180D9E4AB`.
- 작업 단위 독립 검토: 승인, 미해결 Critical/Important 없음. 중단을 늦게 처리하는 통신 환경의 즉시 재연결과 로그인 취소/로드 실패 테스트 보강은 후속 개선으로 기록했다.
- 전체 변경 최종 독립 검토: 승인. 최종 app.asar와 런타임 소스 8개를 바이트 단위로 대조해 일치를 확인했다. 사용자 인증 실조회 미검증 조건은 그대로 유지한다.
