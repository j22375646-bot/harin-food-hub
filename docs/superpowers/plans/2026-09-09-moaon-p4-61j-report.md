# P4-61J — API 키 저장과 로그아웃 경합 보호

## 변경

- 서버 자격증명 저장에 필수 세션 보호 어댑터를 추가했다. 어댑터 없는 구성은 거부한다.
- 외부 신원 확인만으로 저장하지 않고 같은 DB 트랜잭션에서 계정·사용자·세션을 순서대로 잠근다.
- 세션 ID·사용자·실제 요청 토큰 해시가 DB와 일치해야 한다. 차단·비활성·폐기·만료·무한 만료는 거부한다.
- tenant/member/revision 잠금 대기 후 쓰기 직전과 최종 외부 신원 확인 뒤 DB 시각으로 재검사한다. 실패는 전체 rollback.
- 기존 OWNER 조건·사업장 격리·revision 충돌·암호화 응답 제한을 보존한다.
- 기존 외부 verifier는 `touch:false` 읽기 전용이어야 한다. 별도 연결에서 잠긴 세션을 갱신하는 verifier는 사용하지 않는다.

행 잠금은 트랜잭션 종료까지 유지되어 저장과 로그아웃·비밀번호 변경의 순서를 정한다. 마지막 시각 검사와 네트워크 COMMIT이 물리적으로 같은 순간이라는 의미는 아니다. [PostgreSQL 공식 잠금 문서](https://www.postgresql.org/docs/current/explicit-locking.html)

## 검증 상태

- revoked DB 세션에서도 저장되던 문제와 필수 어댑터 누락을 먼저 실패로 재현.
- 저장·세션 보호·암호화·요청 관련 21개 시험 통과.
- 독립 스펙/코드 검토 승인. reviewer가 실행한 기본 명령은 D 의존성 미구성으로 시작 전에 실패했으며 독립 시험 재현으로 계산하지 않는다.
- 최초 전체 시험: 2,696개 중 2,664 통과 / 29 실패 / 3 건너뜀. 실패 29개는 의존성 junction 연결 전 ESM 모듈 탐색 실패이며, 연결 후 해당 6개 파일의 39개 시험을 재실행해 전부 통과했다. 따라서 초기 실행 자체를 전체 GREEN으로 표기하지 않는다. 건너뛴 3개는 production build chunk 검사이며 이번 후보 서버 모듈 변경에서는 빌드를 수행하지 않았다.
- native PostgreSQL 경합 본문 7개 통과. 초기 연결 제한 2초 및 fixture SQL 15초 제한은 D 외장 HDD의 초기화 지연에 걸렸다. 서버 로그의 statement timeout이 fixture TRUNCATE/INSERT를 가리켜 핵심 잠금 로직 실패와 구분했다. setup 전용 300초 제한을 적용하고 연결을 반환하기 전에 15초로 복원했다. 복원 실패 시 해당 연결을 폐기한다. 경합 쿼리 15초 및 잠금 관측 5초 제한은 유지했으며 이 변경도 독립 코드 검토 승인됐다. 시험용 서버는 fsync/synchronous_commit 비활성인 임시 환경으로, 이 결과는 경합 순서 검증이며 장애 시 디스크 내구성 검증이 아니다.
