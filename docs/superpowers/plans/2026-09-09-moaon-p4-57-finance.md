# P4-57 오늘 재무 요약 연결

## 목적과 제약

기존 웹 메인의 계산을 재사용해 앱에 월 매출·계산 이익·향후 30일 예상 잔액을 표시한다. 예상 잔액은 실제 정산 입금액이 아니다. 누락·불완전 자료는 0원으로 변환하지 않는다. 웹 화면 임베드, 새 DB, 운영 주문 쓰기, 유료 인프라 추가는 하지 않는다.

## 작업

1. 사업장 권한을 전후로 검증하는 읽기 전용 재무 요약 API. 기존 main loader/model 재사용, 허용 필드만 반환.
2. 앱 메인 프로세스 고정 GET, 제한된 응답 검증, 오늘 화면 카드. 로딩·부분·확인 필요·오류를 구분하고 로그아웃 시 제거.
3. 단위·UI·빌드·독립 리뷰 후 배포와 설치 결과 확인. 확인되지 않은 운영 검증은 완료라고 표시하지 않는다.

## 사전 검토

| 작업 | 인터페이스/검토 |
|---|---|
| API | 기존 월 계산 모델 재사용. 재무 정산 실입금과 예상 잔액을 혼용하지 않음 |
| 앱 | API의 기간·상태·null 값을 보존. 임의 URL이나 사업장 요청을 허용하지 않음 |
| API↔앱 | ok, month, generatedAt, metrics의 sales/profit/balance 값과 상태를 계약으로 사용 |
| 검증 | 가상 응답 테스트와 실제 서버 조회를 구분 |

## 진행 기록

- 기준 커밋: 2f4f4ce. 기존 codex/moaon-print-preview 작업 공간을 유지한다.
- 서버 경로 6428e67 및 신뢰도 보완 a25c801 구현·독립 재검토 승인. 집중 회귀 45개 통과.
- 전체 웹 테스트에서 기존 고정 banned_until 날짜가 지나는 테스트 결함을 재현했다. 3d4e501은 운영 코드가 아닌 테스트 날짜만 상대 미래로 보완했고 웹 전체 2,628개 통과.
- 기존 main loader 재사용은 원격 조회 budget 37로 비교적 무겁다. 계산 일관성을 우선해 이번에는 로더를 복제하지 않고 앱 자동 재진입 조회에 5분 간격을 둔다. 경량화는 후속 성능 항목이다.

## 최종 반영: 0.41.1

- `307737e`: 개인정보 없는 Server-Timing으로 실제 지연이 **auth-before 15,020ms**임을 확인했다. 재무 계산에 도달하기 전이었다.
- `8a99061`: 재무 권한 확인의 5회 개별 DB 연결을 1회 읽기 전용 트랜잭션으로 묶었다. 기존 4회 DB 시각 검사·세션 검증·소속 검사는 유지한다. 전후 권한 확인은 별도 트랜잭션이며, 연결 정리/커밋 실패 시 결과를 반환하지 않는다. 외부 인증 최대 10초를 고려해 해당 트랜잭션만 idle 제한 12초를 적용했다.

- 최종 서버 배포 `dpl_5B4b2RCcZDK7bjmk3pHy7DrRFCc4` **READY**, 기존 운영 주소에 반영했다.

## 최종 검증과 남은 항목

| 항목 | 결과 |
|---|---|
| 서버 전체 시험 | 최종 지정 테스트 경로, 동시성 2로 **2,633/2,633 통과** |
| 앱 단위 시험 | **245/245 통과** |
| 최종 패키지 UI | 재무 0/음수/부분/누락/실패/로그아웃/주문 탐색 보존, 1040·1440 및 밝은·어두운 테마 통과 |
| 레이아웃 | 두 창 크기·두 테마 가로 넘침 없음, 메뉴 84px 유지 |
| 독립 코드 검토 | 권한 보존·연결 수명·로컬 idle 제한 검토 승인 |
| 설치본 실제 최종 조회 | **LOGIN_REQUIRED — 미완료**. 최신 제한 적용 후 200 응답은 아직 확인하지 못함 |

중간 전체 시험에서 기존 step-up 저장소 테스트 1건이 일시 실패했고 단독 26개 및 최종 전체 재실행이 통과했다. 테스트 탐색 범위를 지정하지 않은 진단 실행은 UI 스크립트까지 탐색해 중단했으며 결과에 포함하지 않았다. 성공 수치는 지정 경로로 다시 실행한 최종 결과다.

앱에 표시될 `계산 이익`은 비용 자료가 완전한지에 따라 부분 확인이 될 수 있다. `향후 30일 예상 잔액`은 실제 정산 입금액/은행 잔고가 아니며 기존 웹 계산 모델의 추정치다. 이번 작업에서 운영 주문 수집·송장 발급·플랫폼 등록을 실행하지 않았다. 새 서버·DB·유료 자원도 만들지 않았다.

## 다음 개발 순서

1. 앱 로그인 후 설치본 재무 GET 200, 세 지표 상태, 실제 처리시간 확인. 성능 부족이 남으면 인증/재무 전용 읽기 경량화부터 진행한다.
2. P4-58 운영(정산) 페이지: 기존 웹 정산 기능 대조표, 채널별 실제 정산/예정 정산/추정치 구분, 기간 조회와 근거 상세를 앱 UI로 이식한다.
3. 주문의 실제 플랫폼 신규 등록 인수는 기존 미완료 상태를 유지한다. 과거 성공 이력이나 가상 시험을 새 운영 전송 성공으로 바꾸어 적지 않는다.
