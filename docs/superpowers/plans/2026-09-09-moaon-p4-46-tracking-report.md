# P4-46 — 앱 배송추적 조회·갱신

2026-09-09 / 모아온 0.31.0 / 이 PC 설치·검증 완료

## 범위

기존 GET/POST /api/shipping/tracking을 재사용한다. 웹 화면을 넣지 않으며 DB·서버·고정 IP 설정은 바꾸지 않는다. 선택한 Cafe24/쿠팡 판매자배송 주문 중 플랫폼에 등록된 송장 한 건의 저장 추적 조회와 명시적 갱신 요청을 연결했다. 네이버·로켓그로스·미등록 송장은 이번 지원 대상이 아니다.

갱신은 우체국 배송조회 작업을 서버 큐에 요청하는 작업이다. 새 송장 접수나 쇼핑몰 송장 재전송이 아니다. 실제 서버 갱신 POST는 시험 목적으로 실행하지 않는다.

## 구현 내역

- 현재 선택 주문의 13자리 송장과 서버 추적 기록이 일치할 때만 상태 표시.
- 대기·실패·기록 없음·시각 없음은 배송완료로 추정하지 않음. 서버 작업 접수는 완료와 구분.
- 갱신 전에 로그인과 현재 주문/송장을 재확인하고 빈 주문 선택이 전체 갱신으로 바뀌지 않게 차단.
- 오른쪽 상세에 ‘저장 추적 조회’ / ‘배송상태 갱신 요청’ 버튼. 상세를 여는 것만으로 API 반복 조회하지 않음.
- 결과·이력을 한 스크롤 영역으로 묶고 높이를 제한하여 주문 목록이 사라지지 않도록 함. 스크롤 동작은 유지하고 바만 숨김.
- 채널/주문 ID 불일치, 원본 주문 ID 누락, 송장 변경, 로그인 만료, 결과 중복/불명, 시간 초과는 확인 필요로 처리한다. 정확한 Main 요청 외에는 새 추적 URL 접근을 허용하지 않는다.

## 검증 결과

- UI 미구현 및 미등록 송장에 추적 도구가 노출되는 실패를 먼저 재현하고 수정 후 통과했다.
- 앱 단위 시험 174/174 통과. 잘못된 채널/ID 자료는 실제 전송 함수 경계에서 POST 0회를 확인했다(시험 응답).
- 추적 UI 개발/패키지 app.asar 시험 통과. 조회 대기를 완료로 취급하지 않으며 주문 단계는 이력 표시만으로 바꾸지 않는다. 조회는 상세 열기만으로 호출하지 않는다.
- 기존 수동 등록·자동 출고 UI 시험 재통과. 다수 이력 펼침·1040×800 창에서 주문 목록 높이 150px 이상과 가로 넘침 없음 검증. 결과 영역은 화면 작업공간의 최대 35%로 제한했다.
- 별도 코드 검토에서 ID 경계 누락을 발견해 보완하고 재검토 통과했다.
- NSIS 빌드 성공, 설치 종료 코드 0. 설치 EXE 버전 0.31.0 확인.
- 실제 설치 EXE에서 서버 저장 추적 GET: READY / DELIVERED, 기록 확인 시각 2026-09-08T04:54:13.823Z. 이 결과는 기존 서버 기록이며 새 우체국 조회 수행을 뜻하지 않는다. 주문번호/송장/수취정보는 보고서에서 제외했다.
- 설치본 재실행 두 번 로그인 유지(3.787초/2.494초), 네 주문 구간과 페이지 이동 조회 통과. 측정값은 해당 실행 기준이며 속도 보장은 아니다.
- 설치본 정렬 오차 0px, 패널 전환 22프레임·내용 유지·접힘 비활성·스크롤바 숨김 통과.
- 실제 서버 갱신 POST, 우체국 접수, 플랫폼 송장 전송, 물리 인쇄는 실행하지 않았다. 갱신 POST 경로는 시험 응답으로 검증했다.

## 남은 경계

등록 직후 자동 배송추적 연쇄 실행은 이번 명시적 조회/갱신과 별도다. 현재 화면 주문의 단계/뱃지는 이력 표시만으로 변경하지 않는다. 갱신 후 저장 추적 조회로 결과를 확인하고 주문 목록 새로고침으로 서버가 판정한 단계를 읽는다. 일괄 갱신·신규 주문 수집·일괄 출력/내보내기·실제 출고 PC 인수는 아직 남아 있다.

다음 P4-47은 등록 완료 주문의 추적 작업 연결과 완료 확인 후 목록 재조회 흐름을 연결한다. 새 추적 요청/기존 기록/실제 배송완료를 혼동하지 않는 안내와 중복 갱신 방지를 유지한다. 주문 화면을 먼저 마무리하고 다른 페이지 이식으로 넘어간다.
