# P4-37 / 0.25.0 로컬 송장 미리보기와 주문 UI 세부 동작

## 확정된 구조
기존 웹 허브의 DB, API, 서버, 고정 IP를 그대로 사용한다. 모아온은 별도 앱 전용 UI를 갖는 설치형 클라이언트다. 별도 서버/DB 구축 또는 운영 자료 복제는 진행하지 않는다. 이전 독립화 조사 문서의 서버 분리 제안은 사용자 설명으로 폐기했다.

## 구현
- 기존 웹의 순수 Code 128 바코드 로직을 앱 내부 모듈로 이식했다. 웹 서버 의존성을 포함하지 않으며 기존 함수 결과와 대조한다.
- 송장 문서는 앱의 격리된 메모리 창에서 생성한다. `/api/shipping/print` 웹 페이지를 불러오지 않는다. 주소/연락처/상품/수량/메모/송장번호와 바코드를 표시한다.
- 라벨 창의 네트워크 요청과 페이지 스크립트를 차단하고, 로그인 쿠키를 공유하지 않는다. 앱 코드가 별도 HTML 파일을 디스크에 저장하지 않는다. 운영체제의 메모리/인쇄 스풀까지 디스크 기록이 없다고 보장하는 의미는 아니다.
- 기존 서버에서 주문 및 송장 상태를 다시 확인한 뒤 미리보기/인쇄를 허용한다. 따라서 전체 앱 또는 인쇄 절차가 오프라인 지원으로 전환된 것은 아니다.
- 주소·번호 불일치, 13자리가 아닌 번호, 필수 배송정보 누락을 차단한다. 문서가 100×150mm 영역을 넘으면 인쇄하지 않는다.
- 실제 인쇄는 확인 창과 프린터 선택 절차를 유지한다. 중복 클릭 차단, 취소/실패 안내와 실제 출력물 확인 안내를 보존했다.
- 주문 선택 보조 메뉴는 작업을 선택하거나 바깥을 클릭하면 닫힌다. Esc는 먼저 보조 메뉴를 닫고 포커스를 메뉴 제목으로 돌린다. 상세 패널을 불필요하게 함께 닫지 않는다.

## 남은 범위
실제 프린터 용지/여백/바코드 스캔/우체국 운용 양식 적합성 인수는 미완료다. 이번 작업은 새 송장 발급이나 플랫폼 전송 시험이 아니다. 우체국 실제 발급 → 플랫폼 반영 → 실제 라벨 출력 확인은 실제 출고 대상으로 별도 확인해야 한다.

다음 개발도 주문 페이지에 집중한다. 누락 배송정보 수집, 발급 결과/등록 실패의 작업 추적·복구, 출력 실증을 마친 뒤 다음 페이지를 진행한다. 기반 서버 공유 여부를 다시 설계하는 작업은 하지 않는다.
