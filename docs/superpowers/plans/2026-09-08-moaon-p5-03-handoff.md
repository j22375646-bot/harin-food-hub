# P5-03 — 모아온 0.3 주문 페이지 조회 확대

## 목적

0.2는 송장 발급 전 주문 첫 20건만 조회했다. 0.3에서는 같은 저장 주문 범위를 이전·다음 페이지로 나눠 살펴본다. 플랫폼에서 새 주문을 수집하거나 송장을 발급하는 기능은 아니다. 하린식품 OWNER 계정만 지원하며 다른 사업장 가입/키 입력은 아직 열지 않았다.

## 사용 방법

1. 모아온에서 하린식품 연결 후 공식 로그인 창에 직접 로그인한다.
2. 주문·배송에서 현재 조회 범위와 저장된 활성 주문 전체 건수를 확인한다.
3. 이전/다음으로 한 페이지씩 이동한다. 검색은 현재 화면에 불러온 페이지 안에서만 적용한다. 전체 주문 검색으로 표시하지 않는다.
4. 주문이 추가·변경되어 기존 목록 기준이 달라지면 화면을 비우고 다시 조회하도록 안내한다. 다시 조회는 첫 페이지부터 새 기준으로 시작한다.
5. 페이지를 바꿀 때 이전 주문 선택·상세·검색어를 초기화한다. 앱 종료/연결 해제 시에는 로그인과 페이지 기준이 남지 않는다.

## 안전 범위

서버가 제공한 페이지 번호와 목록 기준은 앱 내부에서만 관리한다. 화면에서 임의 주소나 토큰을 입력받지 않는다. 모든 페이지는 기존 서버 인증을 통과해야 하며, 비밀번호/고객 연락처/주소를 앱 패키지에 넣지 않는다. 부분 조회 실패와 인증 만료를 정상 0건으로 바꾸지 않는다.

개발 중 열린 사용자 앱의 세션을 보존하기 위해 별도 임시 프로필의 테스트 실행을 사용한다. 이 장치는 배포 파일에서 제외한다. 격리 검증은 동일 런타임 코드와 Electron을 실행하지만 설치된 최종 EXE 자체를 직접 실행한 증거와 구분한다.

## 실사용 검증 조건

사용자에게 기존 앱의 로그인 결과 확인을 요청했다. 인증 후 실제 주문과 원본을 대조하는 결과는 아직 확인되지 않았다. 코드 개발과 합성 응답 검증은 이를 대신하지 않는다. 실제 로그인 완료를 가정하거나 비밀번호를 대신 입력하지 않는다.

## 최종 결과

- 전체 변경 코드 검토와 수정 후 재검토 완료. 병합을 막는 지적 없음. preload 설명의 메서드 수 오류도 수정했다(`c8b389f`). 이 승인은 아래 실사용 검증 조건의 완료를 뜻하지 않는다.
- 구현: `d4aad9d` — 고정 페이지 URL, 응답 기준 검증, 이전/다음/첫 페이지 조회, 409 복구, 재연결 지연 요청 격리, 로그인 창 종료 안정화.
- 기존 허브 회귀 테스트 2,541/2,541 통과. 운영 Next.js 코드·DB·인증 변경 없음.
- 데스크톱 단위 테스트 29/29 통과(연결 25개와 기존 자원 보안 4개). 기준값이 문자열이 아닌 배열·객체·숫자로 오면 거부하고 페이지 기준을 폐기하도록 검토 중 보완했다(`0f29c45`).
- 격리된 실제 Electron 실행에서 합성 45건을 20·20·5로 조회, 이전 이동, 현재 페이지 검색, 이전 선택·상세 초기화, 409 후 첫 페이지 복구, 401 후 비움, 명시적 샘플 복귀를 검증했다.
- 최종 패키지의 app.asar로도 같은 검사를 통과했다. 메뉴·검색·상세·테마·최소 창 크기 검사를 함께 실행했다. app.asar의 런타임 소스 8개가 작업 소스와 바이트 단위로 일치한다.
- 격리된 패키지 코드 실행에서 실제 서버의 비로그인 요청 401과 공식 로그인 폼 표시를 확인했다. 비밀번호는 입력하지 않았다.
- 최종 샘플 첫 화면 준비 430ms는 이 PC의 격리 실행 1회 측정이다. 설치 EXE 직접 실행이나 실제 로그인·주문 응답 성능을 뜻하지 않는다.
- 사용자 0.2 창을 보존했다. **0.3 설치 EXE 직접 설치·재실행·제거와 실제 사용자 인증 주문 대조는 이번 턴에서 확인하지 않았다.** 이전 0.2 설치 검증 결과를 0.3 완료로 전용하지 않는다.
- 패키지에는 테스트 bootstrap/임시 프로필/운영 비밀키/DB를 포함하지 않았다. 미서명 개인용 빌드(`NotSigned`), 공개 배포·자동 업데이트·유료 자원 추가 없음.
- 설치 EXE 크기: 111,359,488 bytes.
- 설치 EXE SHA256: `115B4205292F540700F8C493572B2773572523A04F3C548FDA01DDDAA6C4ECFF`.
- app.asar SHA256: `91C9BC3AC10F9322949553C57495C37133FAF76D6149436CA74B1C1F799FB129`.

## 진행 중 판단

사용자 로그인이 아직 확인되지 않았지만, 기존 서버 계약을 직접 확인할 수 있는 읽기 전용 페이지 이동 개발과 합성 검증은 별도로 진행했다. 이 판단으로 코드 개발은 앞당겼으나 운영 인증 호환성이 입증된 것은 아니다. 실제 대조에서 차이가 발견되면 다음 업무 기능을 열기 전에 수정한다.

## 다음 순서

실제 인증 주문 대조를 마친 뒤 배송 상태 범위와 업무 상세를 확대한다. 우체국 발급·인쇄는 별도 단계에서 대상 재검증·중복 발급 방지·실제 프린터 확인 후 연다. 다사업장 연결도 별도의 권한/데이터 격리 검증을 생략하지 않는다.
