### Task 1: A4 포장명세서·출고 작업표

기존 app/api/shipping/print/route.js standardDocument와 lib/shipping/workbench.js의 기능을 대조하여 desktop에 이식한다. 웹 URL/웹 페이지를 임베드하지 않는다. 기존 selectedDocument(ids,kind)와 fresh generation/scope/channel/offset/fingerprint 검증을 재사용해 previewWorklist(ids,type)를 연결한다. type은 packing 또는 dispatch만, trusted IPC와 preload 검증. 세 채널 주문 지원, 문서는 작업용이며 송장등록·출고승인 기능이 아님을 명시한다.

새 local-worklist.cjs 순수 렌더러와 worklist-preview.cjs 메모리 전용 미리보기 서비스를 권장한다. 기존 label-preview의 안전한 네이티브 창 패턴을 사용하되 송장 검증 자체를 약화하지 않는다. 공통추출은 최소화한다. Main child lifecycle/logout에 추가, JS off/sandbox/contextIsolation/CSP/network deny/외부창 deny. A4 210×297mm portrait, 페이지 안전영역과 명시적 페이지 번호, 연속 순번·반복 머리글·확인 체크칸. 자동 프린트 없음, native silent:false, 확인 전/후 fresh 재검증, 대기시간제한·busy·재출력 경고·실제출력완료 주장 금지. 인쇄 전 모든 페이지 크기/행 identity/문서내용 검증; overflow는 잘라내거나 글자 극소화하지 말고 명확히 차단. 출력 문서는 외부 송장 대신 사용할 수 없음을 명시.

포장명세서는 주문번호/채널/상품별 옵션·수량/포장지시·사은품/확인칸을 제공하고, 출고 작업표는 주문번호/채널/상품·수량/주문단계·등록송장 상태/확인칸으로 목적을 구분한다. 수취인 연락처·주소는 이 A4 문서에 불필요하므로 포함하지 않는다. packingInstructions/gifts/items를 서버가 제공하면 모두 보존(합리적 상한 초과는 명시 거부), renderer의 slice(0,8) 투영으로 조용히 빠지지 않도록 Main-only 문서 projection 사용. 누락 데이터는 확인 필요로 명시, 상품명 fallback만 쓰면 상세 누락 표시. 포장지시·사은품 변경도 fingerprint 재검증에 포함. 네이버/쿠팡 데이터 합산·자동합배송 금지.
