# 모아온 P1-02 개발 보고서

개발번호: **P1-02 — 사업장 회원·초대 저장 기반**.
릴리스 버전: **1.41.0**. 작성일: 2026-09-07.
상태: 내부 저장 기반 구현·회귀 테스트·빌드·작업 단위 독립 검토 완료. 전체 P1/다사업장 실사용/EXE 완료가 아닙니다. 운영 DB에는 아직 연결하지 않았습니다.

## 이번 단계의 목적

하린식품과 다른 사업장이 같은 모아온 프로그램을 사용하더라도, 로그인한 사람에게 허용된 사업장만 열어주는 구조를 만드는 중입니다. 지난 1.40.0은 이름과 권한 검사 기반이었고, 이번 단계는 그 권한을 저장하고 초대로 참여시키는 서버 내부 기능입니다.

구현한 내부 저장소는 다음 네 가지를 분리합니다.

| 저장 항목 | 쉽게 설명하면 |
|---|---|
| 사업장 | 서로 자료를 섞지 않을 독립 업무 공간 |
| 회원·역할 | 누가 어느 사업장에 속하고 어떤 일을 할 수 있는지 |
| 초대 | 누구에게 어떤 권한으로 가입을 허용했는지 |
| 감사 기록 | 누가 초대·회수·권한 변경을 실행했는지 |

## 구현한 동작

1. **내 사업장 소속 확인**: 로그인 확인 결과와 현재 활성 회원정보를 대조합니다. 같은 사람이 두 사업장에 속해도 역할을 따로 읽습니다.
2. **초대 생성**: 해당 사업장의 현재 관리자만 실무자·조회자 초대를 만들 수 있습니다. 유효시간은 DB 시각 기준 24시간입니다. 링크의 비밀값은 생성 때만 반환하고 저장소에는 SHA256 해시만 남깁니다.
3. **초대 수락**: 인증된 이메일이 초대받은 이메일과 일치해야 합니다. 만료·회수·재사용된 링크는 거부합니다. 기존 회원을 초대로 승격시키거나 정지 상태에서 되살리지 않습니다.
4. **초대 회수**: 같은 사업장의 관리자가 아직 사용하지 않은 초대를 회수합니다. 다른 사업장의 초대 ID로 변경할 수 없습니다.
5. **권한 변경·중지**: 최신 권한과 버전을 다시 검사합니다. 오래된 화면에서 덮어쓰는 변경을 막고, 마지막 활성 관리자를 없앨 수 없게 합니다. 회원 행을 바로 삭제하지 않고 상태와 변경 이력을 남깁니다.
6. **실패 시 원상복구**: 회원 생성·초대 사용 처리·감사 기록을 한 트랜잭션으로 묶었습니다. 감사 기록 저장을 고의로 실패시킨 시험에서 회원 생성과 초대 사용 처리도 함께 취소됨을 확인했습니다.

이 동작들은 내부 코드와 로컬 SQL 환경에서 구현·시험한 결과입니다. 현재 웹 화면에서 초대 메뉴를 사용할 수 있다는 뜻은 아닙니다.

## 기존 기능 유지 범위

이번 실행은 기존 로그인/비밀번호/화면/주문 수집/송장 발급/정산 계산/플랫폼 키를 교체하지 않습니다. 실제 사용자에게 초대를 보내거나 두 번째 사업장을 개방하지 않습니다. Windows 설치파일 제작도 이번 번호에 포함하지 않습니다.

## 이번에 내린 범위 결정

1. 운영 DB에 바로 스키마를 넣지 않고, 로컬 SQL 검증 환경에서 후보 스키마를 시험합니다. 운영 자료 변경을 피하는 대신, 실제 PostgreSQL 연결 풀과 동시 요청 시험은 P1-03에서 별도로 통과해야 합니다.
2. 초대는 실무자(OPERATOR)·조회자(VIEWER)만 허용합니다. 소유자(OWNER) 승격/이전에는 새 소유자 수락과 재인증 흐름이 필요하므로 후속 단계로 분리합니다.

## 검증 결과

- 변경 전 기준: 전체 테스트 1,973개 통과, 실패 0, skip 0.
- 신규 SQL 동작 최초 15개, 독립 검토 보완 후 16개. 기존 tenancy와 합산 35개 통과.
- 최초 구현 후 전체 테스트: 1,988개 통과, 실패 0, skip 0; UI 디자인 규칙 검사 통과. 검토 수정 후 최종 재실행 결과는 아래 최종 기록으로 구분합니다.
- SQL 시험 엔진: PGlite 0.5.8의 PostgreSQL 18.3/WASM 단일 연결. 실제 운영 PostgreSQL 17.6의 다중 연결 시험과 다릅니다.
- `pnpm build`: 성공. 빌드 성공은 실제 계정으로 주문/정산 업무를 실행했다는 의미가 아닙니다.
- 로컬 production 서버 + Chrome: 로그인 200, 모아온 제목·비밀번호 입력란, 라이트/다크와 가로 넘침 없음, 비로그인 주문 페이지 307 이동, manifest 및 오프라인 안내 통과. pageerror 0.
- 실제 비밀번호 입력이나 주문/송장/정산 외부 쓰기는 실행하지 않았습니다.
- 독립 작업 검토에서 발견한 인증/권한 확인 순서 문제를 수정하고 재검토 승인. 미해결 지적 없음.
- **최종 수정본 전체 테스트: 1,989개 통과 / 실패 0 / skip 0**, UI guard 통과. 최종 수정본 `pnpm build` 성공.
- 소스 구현 `2a5de01`, 검토 수정 `b22ef8b`. 실제 운영 배포 식별자·상태는 배포 후 사용자 최종 보고로 별도 안내합니다. 빌드 성공을 배포 완료로 혼동하지 않습니다.
- 운영 catalog 재확인: public table 129개, tenant_id 컬럼 0개, moaon_control 스키마 없음. 구조 정보만 조회했으며 운영 데이터 수정은 하지 않았습니다.

### 독립 검토에서 보완한 오류

초대 회수에서 관리자 여부를 확인하기 전에 초대 상태부터 읽으면, 권한 없는 사람도 오류 응답의 차이로 초대의 존재를 짐작할 수 있었습니다. 또한 DB 잠금을 기다리는 중 로그인이 만료되었는데도 만료 오류보다 회원 버전 충돌이 먼저 나오는 경로가 있었습니다.

수정 후에는 DB 잠금 직후 현재 시각과 로그인 만료를 먼저 검사하고, 초대 조회보다 관리자 권한을 먼저 확인합니다. 만료/비권한 요청의 응답과 저장 결과가 같은지 재현 테스트를 추가했습니다. 운영 경로에 아직 연결하지 않은 내부 코드에서 발견·보완한 사항입니다.

## 이어서 할 다음 개발

### P1-03 — 실제 인증·DB 연결 검증

현재 로그인 세션과 이메일 인증 사실을 안전하게 연결하고, 별도 서버 DB에서 초대 동시 수락·회수·마지막 관리자 보호를 시험합니다. 이번 로컬 SQL 시험만으로 실제 서버 동시 접속이 검증되었다고 판단하지 않습니다.

### P2 — 업무 자료의 사업장별 분리

주문·제품·문의·정산뿐 아니라 파일·캐시·알림·AI 자료·수집 대기열까지 분리합니다. 하린식품 기존 건수와 금액이 이전 전후 일치하는지 확인합니다. 다른 사업장 접근 차단 검증 전에는 가입 UI를 열지 않습니다.

### P3 → P4/P5 — 직접 연결과 Windows 프로그램

사업장별 Cafe24·네이버·쿠팡·우체국 연결을 분리한 뒤, 사업장 선택/전환과 앱 전용 UI를 구현합니다. Windows EXE 설치·업데이트·인쇄를 이어서 검증합니다. 프린터 모델과 용지 규격은 실제 장비 확인 후 확정합니다.
