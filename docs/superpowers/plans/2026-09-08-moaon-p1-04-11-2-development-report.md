# 모아온 P1-04-11-2 개발 보고서

## 이번 단계

추가 인증을 통과한 결과를 현재 모아온 로그인에 연결하고, 안전하게 보관·조회·폐기하는 서버 기반을 만든다. 지난 단계가 인증번호의 진위를 확인하는 연결부였다면 이번 단계는 그 결과가 어느 로그인에 속하는지 기록하고 사용 가능 여부를 판단하는 부분이다.

코드 구현·집중/전체 검사·독립 검토·최종 빌드를 완료했다. 운영 배포 확인은 아래 기록을 따른다. **새 인증의 운영 활성화는 아니다.** 기존 로그인·비밀번호·UI·주문·정산 API·운영 SQL·환경 설정을 바꾸지 않는다.

## 주요 동작

- 먼저 인증 작업을 예약하고, 인증 성공 결과와 암호화된 공급자 자격 증명을 한 번에 저장한다.
- 토큰 평문·인증번호·암호화 키는 DB 요청이나 브라우저 응답에 넣지 않는다.
- 현재 사용자·허브 로그인·공급자 로그인·인증 수단과 만료 여부를 다시 확인한다.
- 새 인증 시도는 이전 증거를 무효화한다. 처리 중인 시도는 최대60초 동안 중복 시작을 막는다.
- 증거를 폐기하면 암호문을 지우고 작업 이력은 남겨 늦은 응답이나 같은 작업번호가 되살아나지 않도록 한다.

## 개발 중 정한 범위와 비용

1. 운영 Auth 테이블·권한·키 관리와 전체 로그인 경로를 확인하기 전에는 새 조합을 활성화하지 않는다. 기존 로그인을 보존하는 대신 실제 사용자 MFA 적용은 후속 검수를 기다려야 한다.
2. 새 인증 시작 시 이전 증거는 무효가 되고, 처리 중에는 최대60초 동안 재시작을 막는다. 중복 요청으로 토큰이 엇갈리는 것을 줄이지만 실패 시 잠시 기다렸다 다시 인증해야 할 수 있다.
3. 암호화된 자격 증명은 유효한5분 증거에만 연결한다. 장기 토큰 갱신이나 여러 암호화 키의 순환 관리는 포함하지 않아 해당 운영 절차는 별도 준비해야 한다.
4. 결과가 불명확한 외부/DB 요청은 자동 재시도나 보상 로그아웃을 하지 않는다. 이미 완료됐을 수 있으므로 확인 또는 예약 만료 대기가 필요하다.
5. 공급자 인증 테이블에는 조회 권한만 유지한다. 실제 DB 검사에서 행 잠금에도 수정 권한이 필요한 것이 확인되어, 권한을 넓히는 대신 매번 원본을 조회한다. 공급자 로그아웃·삭제와 완전히 동시에 일어난 요청까지 한 거래로 묶지는 못하며 다음 조회부터 거부한다. 이미 반환된 증거의 즉각 원격 취소는 보장하지 않는다.

## 운영 적용 전 남는 조건

실제 Auth catalog·최소권한·암호화 키 보관/교체/복구·기록 보존 정책, 실제 계정 MFA, 모든 로그인/로그아웃 경로와 HTTP 요청 제한을 검수해야 한다. 공급자 세션 존재 검사는 공급자의 모든 비활성 시간·단일 로그인 정책을 즉시 대신하지 않는다.

후속 단계는 계정 인증 조합의 통합 진입·폐기 경로 검증이다. 이후 사업장 자료 격리(P2) → 플랫폼 연결(P3) → 앱 UI(P4) → Windows 설치 프로그램·출력(P5) 순서를 유지한다. 이번 작업은 EXE 설치 파일이나 다사업장 실사용 완료를 뜻하지 않는다.
