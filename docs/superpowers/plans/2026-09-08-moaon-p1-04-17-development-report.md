# 모아온 P1-04-17 — 실제 로컬 인증 연결

## 개발계획에서의 위치

전체 기준은 [다중 사업장 Windows 전용 프로그램 개발계획](2026-09-07-multi-business-desktop-master-plan.md)이다. 현재 P1 계정·인증 기반을 검증 중이며, P2 사업장별 데이터 격리와 P5 설치형 EXE 완료를 의미하지 않는다.

이전에는 설치한 인증 서버 자체의 가입·로그인·MFA를 확인했다. 이번에는 허브에 이미 작성한 `createSupabaseStepUpProvider`가 실제 인증 서버 응답을 받아 재인증 증거를 만드는 경로를 검증한다. 쉽게 말해 인증 부품 단독 점검에서 허브 부품과의 실제 연결 점검으로 넘어간다.

## 변경 범위

- 로컬 전용 재실행 시험 도구 및 안전장치 테스트. 기존 운영 로그인/화면/주문/정산/API 키는 변경하지 않는다.
- 고정 localhost HTTPS gateway를 실행 중에만 열어 설치된 Supabase SDK와 실제 GoTrue를 연결한다.
- 실제 GoTrue v2.189.0 / PostgreSQL 17.11의 가상 계정만 사용한다. HTTP 응답이나 JWT를 성공하도록 다시 쓰지 않는다.
- 기존 로컬 서버를 보존하고 시험용 인증 프로세스만 추가한다. 동일한 가상 계정 DB를 사용하므로 두 서버의 데이터 격리 시험은 아니다.
- TLS 인증서는 테스트 요청에만 지정한다. OS 신뢰 저장소와 전역 TLS 설정을 변경하지 않는다.

## 확인 범위와 한계

이번 환경은 HS256 서명 방식이며 SDK가 인증 서버에 사용자 확인을 요청하는 경로다. 클라우드 비대칭 키/JWKS 실환경 검증을 대신하지 않는다. 해당 경로의 모의 응답 기반 회귀 시험과 실제 HS256 시험을 구분한다.

새 MFA 모듈은 아직 공개 로그인 화면에 연결하지 않았다. 이메일 발송/초대, 복구, 실제 Hub 세션·권한 폐기, 최소 권한 DB 연결, Vercel 실제 전달 헤더 검증은 별도 단계다. 인증 부품 검사만으로 P1 전체 완료 또는 두 사업장 보안 격리 완료라고 하지 않는다.

## 다음 개발

1. **P1 실제 저장 연결:** 이번 실제 인증 결과를 새 세션 저장 모듈에 연결하고, 인증 서버 세션 ID와 허브 세션 ID를 분리해 저장하는지 확인한다.
2. **권한 폐기:** 로그아웃·복구·강등 후 이전 세션이 민감 작업을 계속할 수 없는지 실제 DB와 함께 검증한다. 이미 발급된 access token과 갱신 토큰의 차이를 구분한다.
3. **제한된 로그인 화면 연결:** 위 조건과 최소 권한, 초대/메일 조건을 충족한 뒤 검증용 화면부터 연결한다. 기존 하린식품 로그인은 먼저 교체하지 않는다.
4. **P2 → P4/P5:** 주문·정산·파일·캐시가 사업장별로 나뉘는 것을 검증한 뒤 앱 전용 UI와 Windows 설치파일을 연결한다. 공개 회원가입/모바일 앱은 범위 밖이다.

## 비용과 판단

신규 클라우드 자원·유료 DB 브랜치·운영 자료 복사·실메일 발송 없음. 이 PC의 로컬 자원을 사용한다. 기존 서비스의 원래 사용료까지 없어졌다는 뜻은 아니다.

- 기존 시험 환경을 지우거나 토큰을 고쳐서 통과시키지 않고, 올바른 발급자 주소를 가진 별도 로컬 인증 프로세스를 사용했다. 추가 로컬 메모리를 사용하므로 검증 후 해당 프로세스를 정지한다.
- 앱 런타임을 바꾸지 않는 시험 도구/문서 작업이므로 버전은 1.58.0을 유지한다. 운영 기능 적용 증거는 아니다.

## 실행 결과

첫 실제 실행 exit 0. 가상 가입/로그인/요소 등록/첫 TOTP 검증 뒤 다음 번호 구간을 기다리고 다음을 확인했다.

| 시험 | 실제 확인 |
|---|---|
| 틀린 TOTP | 서버 422, 허브 `STEP_UP_REJECTED` |
| 변조 토큰 | 서버 사용자 확인 403, 허브 거절 |
| 다른 userId | 허브 거절 |
| 정상 재인증 | 사용자·요소·공급자 세션 일치, MFA 증거·만료·동결 확인 |
| 묵시적 갱신 | provider 실행 중 refresh 요청 0건 |
| 로그아웃 | 서버 204 이후 refresh 400, 새 세션 없음 |

총 23건의 실제 HTTP 요청. TLS 클라이언트→로컬 gateway→실제 GoTrue→가상 DB 경로로 실행했다. gateway는 API key 심사 장치가 아니므로 클라우드 API gateway 권한 검증으로 간주하지 않는다.
