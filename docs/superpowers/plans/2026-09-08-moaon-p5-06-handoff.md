# P5-06 — 모아온 0.6.0 주문 상세 정보 확장

## 이번 인도

기존 주문 목록 API 응답의 필요한 필드를 앱의 오른쪽 상세에 연결했다. 상세를 선택할 때 추가 API 호출은 발생하지 않는다. P5-05의 화면 구성, 검색, 이전/다음 상세, 상태별 20건 조회를 유지한다.

| 항목 | 표시와 주의 사항 |
| --- | --- |
| 플랫폼 주문번호 | 허브 내부 번호와 쇼핑몰 원본 번호를 구분 |
| 상품 구성 | 상품명·옵션·개별 수량. API가 제공하는 최대 8개이며 전체 구성 보장 아님 |
| 저장 송장 | 검증된 13자리 번호. 발급 완료와 플랫폼 등록 완료 구분 |
| 배송상태 | 예약·배송중·배송완료·확인 필요와 우체국/쇼핑몰 출처 표시. 실시간 재조회 아님 |
| 출고 전 확인 | 취소됨·취소 요청 있음·저장 자료에 요청 없음·확인 필요 구분. 출고 승인 아님 |
| 기준 시각 | 주문 시각과 목록 확인 시각 유지 |

수취인 이름·전화·주소, 이미지 URL, 임의 원본 설명/오류는 전달하지 않는다. Main 프로세스에서 허용 필드만 복사하고 문자열 500자, 구성 8개, 유효 수량, 송장/배송 열거값을 검증한다. 중첩 객체와 배열은 동결한다. 수량의 0/음수/소수/문자열은 확인 필요로 남긴다.

취소 정보의 null 보존은 API 응답 기준이다. 기존 서버 adapter는 원본 플래그 누락을 false로 정규화하므로 앱의 '저장 자료에 취소 요청 없음'을 최신 채널 확인이나 취소 불가능의 증거로 해석하지 않는다. 화면에도 최신 채널 확인 안내를 둔다.

## 검증 결과

- 단위 테스트 37/37 PASS. 제한된 필드 전달, 개인정보 제외, 누락/오류 값, 실제 서버 adapter 계약 포함.
- 기존 허브 전체 테스트 2,541/2,541 PASS.
- 실제 Electron 합성 응답으로 플랫폼 주문번호·옵션·송장 발급/등록 구분·배송 출처·취소 요청 표시 검증. 상품 문자열을 HTML로 실행하지 않음, 새로고침 후 이전 송장 제거도 PASS.
- 설치된 EXE 직접 details/workspace/status 검사 PASS. 기존 UI의 세 가지 창 크기와 두 테마 검증 유지.
- 로그인 제출은 비밀번호 없는 시험 폼을 네트워크 전송 전에 취소한다. 설치본 검사 중 1회 제출 요청 미관측(0 != 1)이 있었다. 자격증명을 수집하지 않는 상태 진단을 추가한 뒤 9회 연속 PASS. 간헐 실패의 원인은 확정하지 못했다. 성공적인 실제 비밀번호 인증 증거와 구분한다.
- 제품 코드 리뷰에서 Critical/Important/Minor 지적 없음. 실제 채널 주문 전체 대조나 송장 발급 검증은 수행하지 않았다.
- 최종 패키지 소스 8개 바이트 일치. 설치 종료 코드0, Windows 등록 버전0.6.0, 설치 app.asar 해시 일치.

## 변경하지 않은 것

운영 웹사이트·서버·API URL·인증·DB·IPC 권한은 변경하지 않았다. 새 유료 자원/클라우드 브랜치/공개 배포/자동 업데이트 없음. 이전 설치본을 정상 종료하고 개인용 미서명0.6.0으로 교체했다. 종료 시 로그인 세션이 지워지므로 다시 로그인해야 한다.
