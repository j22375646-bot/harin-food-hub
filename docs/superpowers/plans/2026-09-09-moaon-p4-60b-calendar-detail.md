# P4-60B 캘린더 본문·공휴일 — 0.48.0

## 완료한 변경

- 월간 일정 상세에 본문 연결. 최대 4,000자 문자열만 허용하고 객체·초과 본문은 정상 자료로 처리하지 않는다.
- 본문 줄바꿈 유지, HTML은 실행하지 않고 일반 글자로 표시.
- 기존 서버 공휴일 목록을 날짜판에 표시. 최대 100개, 유효 날짜·80자 이내 이름만 전달한다.
- 공휴일 자료가 없거나 형식이 잘못되면 확인 필요로 표시. 공휴일 누락을 공휴일 없음으로 단정하지 않는다.
- 서버의 전량 조회 한계가 해결되지 않았으므로 화면에 일정 전량 조회 여부 확인 필요 안내 추가.
- 오늘 일정 카드의 본문 비노출 정책은 그대로 유지한다. 월간 상세만 본문을 제공한다.

## 확인된 조회 한계 — 미해결

기존 GET은 hub_work_items를 최대 500개 읽고 그 뒤 표시 기간으로 필터링한다. 따라서 월간 응답이 500개 미만이어도 전량이라는 보장은 없다. 또한 오래 지속되는 일정은 조회 시작일보다 366일 이전 시작이면 제외될 수 있다.

이번에는 이 서버 구조를 변경하지 않았다. 전량 조회 보장을 구현 완료로 표시하지 않는다. 다음 P4-60C에서 페이지 조회와 명시적인 완전성 상태를 서버·앱에 함께 연결한다. 실제 운영 계정의 일정/본문/공휴일 대조와 일정 쓰기 기능도 미완료다.

## 검증

테스트 우선 개발로 본문/공휴일 변환과 UI 표시가 빠진 상태에서 실패를 확인한 후 수정했다. 앱 전체 270개 통과. 월간 화면에서 본문·공휴일 표시, HTML 미실행, 월 이동·추가 조회 억제·실패/로그아웃 비움·화면 폭 시험을 통과했다.

화면 시험은 임시 프로필과 시험 응답이며 실제 운영 데이터 조회 성공을 뜻하지 않는다.

## 설치

0.48.0 설치 파일 생성 후 패키지 app.asar 대상으로 캘린더·분석·공통 레이아웃 UI 시험 3종을 통과했다. 시험 실행기는 개발용 Electron이며 임시 프로필과 시험 응답을 사용한다. 1040/1440 화면 폭, 공통 화면 밝은/어두운 테마에서 가로 넘침이 없었다.

설치 프로그램 종료 코드 0. 설치된 resources/app.asar와 빌드 산출물의 SHA-256이 일치했다. 기존 로그인 프로필은 삭제하지 않았다. 서버 배포/DB 쓰기·공휴일 수집 실행·새 유료 자원 생성은 없다.
