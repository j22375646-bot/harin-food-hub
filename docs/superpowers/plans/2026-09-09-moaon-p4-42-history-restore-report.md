# P4-42 — 이전 출고 기록 불러오기

2026-09-09 / Windows 앱 0.28.0

## 구현과 UI

기존 앱의 shipments/automatic-actions 기록을 읽는 전용 함수를 추가했다. 기록을 새로 만들거나 변경·삭제하지 않는다. 주문별 준비/발급/플랫폼 등록 기록을 묶으며 UPLOAD_INVOICE SUCCESS 기록이 있는 주문은 복원 후보에서 제외한다. 나머지는 실제 완료 여부와 무관하게 CHECK_REQUIRED로만 반환한다.

주문 화면에 ‘이전 출고 기록 불러오기’를 추가했다. 누르면 현재 서버 주문을 재조회해 인증을 확인한 뒤 로컬 기록을 읽는다. 현재 목록 미조회·인증 실패·출고 처리 중에는 복원을 거부한다. 연결/페이지가 바뀐 뒤의 늦은 결과도 표시하지 않는다.

복원 UI는 기존 출고 확인 목록을 재사용하며 주문 ID와 이전 상태만 보관한다. 주소·송장번호·지문·요청 UUID는 반환하지 않는다. 과거 기록이라는 안내, 읽는 중/복원 건수/기록 없음/확인 필요를 구분한다. 자동 발급·플랫폼 재전송은 실행하지 않는다.

## 보호 장치

- Main의 고정 경로만 읽고 renderer는 경로/사업장/파일명을 전달할 수 없음.
- 최대 500개 디렉터리 항목, 파일당 최대 4096바이트 검사. 초과는 확인 필요.
- 파일명 해시와 기록 스키마/사업장/주문/작업 종류 검증.
- 잘못된 파일·손상·비정상 파일 형태는 빈 정상 목록으로 처리하지 않음.
- 원본 중복 발급 방지 기록은 변경하지 않음.

## 검증

- 미구현 readShippingHistory 호출 실패부터 재현 후 실제 임시 파일 기반 복원 시험 통과.
- 파일 다시 읽기, 성공 등록 제외, 폴더 없음과 손상 기록 구별 시험 통과.
- Main의 새 인증 확인/인증 실패 시 비공개, GET만 허용한 시험 통과.
- IPC 신뢰 renderer 및 인자 거부 시험 통과.
- 전체 단위 시험 164/164 통과.
- 격리 UI와 패키지 app.asar의 복원 버튼→항목 표시→로그아웃 제거 검사 통과. 패키지 검사는 개발 Electron 런타임에서 실행.
- NSIS 빌드 성공.
- 설치 종료 코드 0. 실제 0.28.0 EXE 두 번 재실행 로그인 유지, 네 주문 구간·페이지 이동 통과(진입 3.149초/2.514초, 해당 측정값).
- 설치 앱의 복원 버튼을 실제 클릭해 ‘복원할 미확정 기록이 없습니다.’ 응답 확인. 이 PC에는 복원 후보가 없었다. 비어 있지 않은 기록 복원은 임시 시험 파일/UI 응답으로 검증한 것이다.
- 설치 UI 정렬 오차 0px, 패널 모션 21프레임·내용 유지·스크롤바 숨김 확인.

## 범위와 다음 단계

자동 시작 복원이 아닌 사용자 버튼 방식이다. 같은 Windows 사용자/이 PC에 남은 automatic-actions 기록만 대상이다. 다른 PC의 기록, 별도 legacy 발급 registry, 서버 전체 이력, 페이지 밖 주문 자동 검색은 포함하지 않는다. 실제 우체국 발급·플랫폼 등록·물리 출력은 이번 시험에서 수행하지 않았다.

다음은 확인 목록 주문을 페이지 밖에서도 읽기 전용으로 찾는 경로를 검토·구현한다. 현재 등록 완료 여부와 로컬 과거 기록이 다를 수 있으므로 실시간 완료 판정으로 사용하지 않는다.
