# 모아온 0.3.1 — 로그인 제출 차단 수정

## 원인과 수정

공식 로그인 폼은 /api/dashboard/login으로 native POST navigation을 한다. 세션 요청 정책은 해당 POST를 허용했지만 login window의 will-navigate guard는 /login만 허용하여 폼 이동을 취소했다. 웹 폼은 pending 상태가 되어 사용자에게 계속 확인 중으로 보였다.

공식 원점의 정확한 /api/dashboard/login 주소만 navigation에 추가 허용했다. 세션 요청 정책은 변경하지 않아 POST/로그인 창 제한을 유지한다. 외부 주소, 추가 쿼리/해시/슬래시, 주문 페이지 이동은 허용하지 않는다. 기존 서버 인증·비밀번호·DB·운영 웹 코드는 변경하지 않았다.

## 검증

- 수정 전 실제 guard를 호출하는 회귀 테스트가 공식 제출 주소에서 실패함을 확인.
- 수정 후 데스크톱 단위 30/30, 기존 허브 회귀 2541/2541 PASS.
- 실제 Electron 폼 제출이 운영 네트워크 허용 판단까지 도달함을 확인. 비밀번호 없는 별도 테스트 폼이며 POST는 테스트 코드가 서버 전송 전에 취소한다. 사용자 자격 증명이나 실제 인증은 사용하지 않았다.
- 별도 로그인 partition은 BrowserContext route와 달라 초기 합성 응답 주입 테스트를 폐기하고, 실제 partition의 요청 등록을 감싸 원래 판단 결과를 확인하는 검사로 변경했다.
- 패키지 runtime 및 설치된 0.3.1 EXE에서 제출 검사 PASS. 설치된 EXE 메뉴·검색·상세·테마·보안 검사 PASS. 페이지 이동 합성 검사도 PASS.
- NSIS 업데이트 종료 코드 0, Windows 설치 등록 버전 0.3.1 확인.
- 설치 파일 SHA256: 1B9B7954B6FEF305D05FA245C00980F78E13F1C6C27F6C5D58995028BD9F0650.
- 설치 app.asar SHA256: 2F1217E58A634DEAE34A52131ED1DE1F0023FE84FC9A257C8BC15240EF853000.

## 남은 실사용 확인

사용자가 비밀번호를 입력한 이후 실제 인증 성공 및 주문 대조는 별도 확인해야 한다. 이 보고서는 제출 차단 수정과 설치 확인이지 실사용 인증 성공 증거가 아니다. 미서명 개인용 빌드이며 추가 유료 자원은 만들지 않았다.
