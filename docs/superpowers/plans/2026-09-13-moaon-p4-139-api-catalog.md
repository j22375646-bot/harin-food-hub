# P4-139 · API 관리 탭·수집 기록·활용 추천 · 0.126.0

## 적용 내용

- 설정 상단을 실제 탭(프로필/화면/업데이트/조회 연결/사업장/API/출고 기록)으로 바꿨다. 선택 탭의 내용만 표시하며 키보드 좌우/Home/End 이동을 지원한다.
- 메뉴와 본문의 중심을 같은 최대 1160px 폭으로 정렬했다. 버튼 높이와 간격을 통일하고 라이트/다크·1040/1440px에서 중앙 위치를 확인했다.
- API 탭의 쿠팡, 네이버 커머스·검색광고, 카페24, 우체국 카드에 수집 정보, 사용하는 화면, 수집 방식, 키 종류, 마지막 수집 결과·시각을 추가했다.
- 기존 키 보기/가림/수정/저장/만료일/인증 재확인 기능을 유지했다. API 탭을 떠나면 원문 입력값과 보류 중 입력을 지우고 지연 응답을 폐기한다. 빠르게 탭을 다시 열어도 다시 불러온다.
- 마지막 인증 성공과 수집 성공은 별도 표시한다. 작업별 기록이 없으면 기록 없음, 읽기 실패는 확인 불가로 남긴다. 오래된 성공 기록을 실시간 정상 상태로 바꾸지 않는다.
- 추가 서버 서비스: AWS CloudWatch, Vercel 운영 API, GitHub 릴리스, UptimeRobot, Telegram, Resend, OpenAI, GA4, Search Console, PageSpeed, CrUX. 현재 서버 설정의 존재/실행 허용 여부만 반환하며 실제 호출 성공으로 표시하지 않는다. 운영 기반 Supabase/Vercel/AWS/GitHub의 역할도 설명한다.
- 운영 서비스의 루트 키는 원문을 노출하거나 이 화면에서 수정하지 않는다. 기존 판매채널 4개 카드의 키 수정과 별도다. PG 지급명세는 카페24 주문 자료와 별도 연동이 필요하다고 명시했다.

## 추천 순서

| 우선순위 | 기능 | 기대 효과와 적용 조건 |
|---|---|---|
| 우선 | 쿠팡 옵션 재고·판매상태 대조 | 내부 소분재고/묶음 수량과 옵션 매핑 후 과판매 방지. 자동 수량 변경은 별도 구현/검증 |
| 우선 | 쿠팡 반품·교환 진행 추적 | 현재 클레임 수집에 회수·입고·처리기한 연결. 승인/입고 처리는 사용자 확인 후 |
| 다음 | 쿠팡 카테고리 필수정보 검사 | 상품 등록 전 고시/인증/속성 누락 검사 |
| 후순위 | 쿠팡 쿠폰·가격 변경 | 마진 하한·예산·전후 성과 비교를 먼저 준비 |
| 우선 | 네이버 광고 낭비·전환 검색어 | 기존 광고 성과/검색어를 활용한 지출 점검, 입찰 상한·변경 전후 비교 |
| 우선 | 네이버 주문·정산 대조 | 수수료·환불·광고비를 원천별로 대조 |

추천은 추가 개발 목록이다. 이번에 신규 판매조건 변경 API를 실행하거나 활성화한 것이 아니다.

공식 근거: [쿠팡 API 목록](https://developers.coupang.com/ko/api), [쿠팡 상품 API 흐름](https://developers.coupang.com/ko/workflows/product-api-workflow), [네이버 커머스 API](https://apicenter.commerce.naver.com/docs/commerce-api/current), [네이버 검색광고 API](https://naver.github.io/searchad-apidoc/). 공급사 API 존재와 현재 계정의 실행 가능 권한은 별도로 확인해야 한다.
