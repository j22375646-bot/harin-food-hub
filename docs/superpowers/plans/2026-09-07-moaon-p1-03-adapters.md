## Global Constraints

- Preserve existing Harin login, UI, operational APIs and calculations. No public onboarding or new business routes before P2 isolation.
- No live customer/account writes, password changes, invitation delivery, production migration, paid resources or service-role business adapter.
- New control-plane code is server-only, explicitly composed, not automatically wired to legacy routes. Tenant roles come from current membership, never global profile role or user_metadata.
- Candidate SQL stays outside migrations. Local native PostgreSQL uses disposable synthetic data and loopback only. No OS service/global install.
- Test-first implementation; report real versus mocked verification separately. Password-reset lifecycle integration remains an explicit activation gate until its actual hook and session invalidation are proven; do not infer password changes from Auth updated_at.

### Task 1: Trusted existing-login identity adapter

Read this task as its complete requirements. Work in the current isolated worktree. Create `lib/tenancy/dashboard-identity.js` and `test/tenant-dashboard-identity.test.js`; add a short integration contract doc under docs/superpowers/specs. Do not edit existing login/proxy/routes or package versions.

Implement an explicitly server-composed factory `createDashboardIdentityVerifier({db, authAdmin, ...testDependencies})` returning the `verifySession(opaqueCredential)` function consumed by `createTenantControlStore`. `db` and `authAdmin` are required server dependencies; no environment fallback or browser credential input. Use the actual existing dashboard-auth validateSession with the supplied db (not resolveRequestSession or trusted-header shortcut). A test override for session validation/clock is permitted at factory composition only; tests must also cover the actual signed-token validator with a controlled DB boundary.

For every invocation: reject missing/non-string/oversized credentials; verify the signed DB session, UUID session/user IDs, finite future expiry; read dashboard_users by the verified user ID, require active === true and matching ID; ask `authAdmin.getUserById(userId)` for authoritative Auth identity and require matching ID, non-anonymous, non-deleted/non-currently-banned account. Normalize emails trim/lowercase, require usable matching profile/Auth email, derive emailVerified only from valid non-future `email_confirmed_at`, never profile flags, confirmed_at (phone), metadata or caller claims. Unconfirmed email may yield emailVerified=false so the store's EMAIL_VERIFICATION_REQUIRED behavior remains. Deny malformed confirmation/banned timestamps. Revalidate the DB session after external reads and check same session/user identity and both expiries, taking the earlier expiry. Fail closed on errors and no cache across calls. Snapshot validated values against mutation across awaits. Return only frozen {id,userId,email,emailVerified,expiresAt}; no secrets, Auth metadata or global role.

Bound verifier work with an explicit finite timeout (default 10 seconds, test override at factory) and generic safe errors: unavailable dependency/timeout versus unauthenticated; never leak provider messages/keys/emails/tokens in error fields or logs. No retries, no account writes. Browser invocation must be rejected.

Tests: happy path normalized verified email; unverified email; malformed/expired/revoked/session mismatch; actual signed-token tamper rejection; revoked session after Auth read; disabled profile; wrong Auth user; anonymous/deleted/banned (including expired ban allowed); mismatched email; spoofed metadata ignored; dependency failures/timeouts; expiry during reads; mutable returned records cannot switch identity; next request sees revocation/profile changes. Exercise adapter -> control-store acceptInvitation at the SQL-test boundary if feasible, proving unverified email cannot produce a membership. No production network or credentials in tests.

Document exact composition and remaining activation gates: SMTP/reset lifecycle, restricted DB provisioning, P2 data isolation, no existing user password changes. Run focused RED/GREEN then full suite once; commit only task-owned files (not scratch report). Full report in supplied SDD path with commands/output and limitations.

### Task 2: Restricted native PostgreSQL adapter and race verification

Read this as complete Task 2 requirements. Create `lib/tenancy/postgres-control-database.js`, `lib/tenancy/sql/control-role.sql` (candidate only), focused unit tests under `test/`, native integration suite under `test/integration/` and a dedicated package command `test:tenancy:postgres`. Keep native tests outside default suite discovery or explicitly skipped when no test URL; dedicated command must fail (not silently pass/skip) if URL is absent or unsafe. Add operator documentation. `pg` 8.23.0 is installed by controller with --ignore-scripts; own package/lock changes from this task onward. No edits to Task 1 files or legacy login/UI/routes. No new API endpoints.

Factory `createPostgresControlDatabase` explicitly receives server-only connection configuration (no default PG/env/service-role fallback), owns a bounded pg.Pool and exposes `{query,transaction,close}` for createTenantControlStore. Test-only pool injection permitted for transport failures. Reject browser usage. Require TLS certificate verification for non-loopback connections; explicit local-test opt-in permits loopback non-TLS only. Never accept database role, SQL or connection config from an HTTP input.

Every checkout must validate current_user/session_user equals fixed `moaon_control_app`, role is non-superuser/non-bypassrls/non-createrole/non-createdb/non-replication, owns no control tables/schema, and cannot inherit/set a privileged role (reject any role membership). Fail closed before work if privileged/wrong role; destroy that connection. Bounded pool connection wait, lock/statement/idle-in-transaction timeouts. Use the SAME leased client for BEGIN, all transaction SQL, COMMIT/ROLLBACK. Reset residual session state before reuse; failed reset/rollback/commit/connection must destroy the lease. No automatic retry of ambiguous writes. Preserve domain errors from callback after successful rollback, sanitize driver errors (no SQL/URL/password/detail leakage). Transaction handles cannot be used after callback completion and cannot leak raw pg clients/pool/release methods. No callback state shared across requests. Pool close rejects future operations.

Candidate SQL: fixed role `moaon_control_app`, initially NOLOGIN and restricted attributes, no table/schema ownership or memberships; fail on an unsafe preexisting role rather than silently downgrading/using it. Explicit least grants required by control-store: tenants read + minimum locking privilege (no tenant creation/removal), memberships read/insert/update mutable fields, invitations read/insert/update mutable fields, audit insert only. No DELETE/TRUNCATE/audit update or public schema grants, no SECURITY DEFINER/BYPASSRLS. Enable matching fixed-role RLS policies with USING/WITH CHECK. PUBLIC, anon and authenticated remain denied. This is an internal membership control plane: server fixed queries authorize tenants; its role policies are NOT P2 business-row tenant isolation. Document this distinction and credential provisioning separately. Do not run candidate SQL against production.

Native test harness: use only an explicit test URL on 127.0.0.1/localhost with database name `moaon_test_*`, reject production-like hosts/names before connecting or creating anything. Parent test supervisor creates a fresh uniquely named disposable database on controller's isolated local cluster, provisions synthetic fixtures and role and applies candidate SQL; don't drop arbitrary input databases/schemas. Tests use actual distinct pg connections and barrier/latch coordination plus pg_backend_pid evidence, not Promise.all on one serialized client. Verify same invitation accepted twice -> exactly one membership/accept audit; two active owners simultaneously self-demote -> at least one active owner; accept versus revoke -> one consistent terminal state and no partial membership; audit trigger failure -> transaction fully rolled back; next borrowed connection clean after rollback and SET LOCAL reset; explicit privileges deny role escalation/public role access/audit changes/tenant destruction; production superuser connection adapter refused. Unit transport fault tests cover connect, BEGIN, COMMIT, rollback, reset failure and released handles. All pools and temporary native server resources owned by test harness close in finally; controller owns cluster process.

Run focused RED/GREEN, dedicated native suite with real server, then full suite once. Commit only task-owned files and write report with exact PostgreSQL version, commands/test totals, role metadata and remaining hosted/reset/P2 gates. No mock result may be called native verification.
