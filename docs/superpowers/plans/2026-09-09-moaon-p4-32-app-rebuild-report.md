# P4-32 — 웹 UI를 가져오지 않는 앱 전용 주문 작업실

## 이번 판단

사용자 비교 화면에서 지적한 차이는 색상이 아니라 구조였다. 기존 문장형 큰 제목, 중복된 주문 목록 카드 제목, 여러 줄 필터, 긴 상세 상자가 웹 화면의 정보 배치를 유지하고 있었다. 따라서 기존 주문 기능을 보존하면서 HTML 구조와 Studio 스타일시트를 다시 구성했다.

## 0.21.0에서 변경

| 이전 | 이번 적용 |
|---|---|
| 긴 문장형 제목·밑줄·중복 영문 제목 | 주문 작업실 + 짧은 설명 |
| 여러 줄로 항상 펼쳐진 필터 | 상태 탭 + 한 줄 도구, 추가 필터 펼침 |
| 큰 카드 안의 주문 카드 | 열 제목과 간결한 상품 행 |
| 상품/채널/금액/상태의 불균형 | 동일 열 정렬, 선택 행 연보라 전체 배경 |
| 상세의 중복 안내·여러 작업 버튼 | 상품·금액 요약, 추가 정보, 주 동작, 보조 도구 펼침 |
| 목록만 클릭해 동작 | 1건 선택 도구: 내용 확인·선택 해제 |
| 여러 내부 영역에 중첩된 상세 스크롤 | 상세 카드 한 영역에서만 스크롤 |

84px 메뉴, Pretendard 내장 폰트, 밝은 목록과 짙은 상세, 180ms 전환을 적용했다. 움직임 줄이기 시스템 설정도 존중한다. 창 제어 방식은 이전 0.20.0의 기본 제목줄 숨김 설정을 유지했다.

## 기존 기능 보존

- 실제 주문 이미지·옵션·채널·배송·사은품 뱃지와 실패 시 이미지 대체 표시.
- 검색·채널·정렬·사전 확인 필터·다음/이전 페이지·키보드 조작.
- 주문 확인, 발급 전 경고, 실제 최종 확인, 발급 상태 조회, 라벨 미리보기.
- 잘못된 값과 미확인 금액을 정상/0으로 바꾸지 않음.
- 사전 확인의 이유는 접어 두되 확인·발급 시작 시 다시 펼침. 실제 진행/실패 결과는 접힌 영역 안에 숨기지 않음.
- 수취 정보는 현재 앱 확인창에 제공되지 않으므로 웹 허브에서 확인하도록 정확하게 안내.

API·DB·사업장 격리·인증·발급/인쇄 전송 코드는 이번에 변경하지 않았다.

## 서브 에이전트 활용

1. 화면 구조와 이벤트 연결 구현.
2. 기존 기능 회귀 테스트 통합.
3. 시안 비교와 독립 코드 검토.

메인 담당은 앱 전용 스타일·스크린샷 비교·패키지·설치 통합을 수행했다. 독립 검토에서 잘못된 수취 정보 확인 위치 문구 1건을 발견해 수정했고 재검토 승인받았다.

## 검증과 적용

- 앱 단위 테스트 127/127.
- 신규 화면 구조 검사 RED → GREEN: 접힌 필터/상세, 실제 경고 접근, 미확인 금액, 1건 선택/해제.
- 신규 레이아웃 검사 RED → GREEN: 1040/1440px, 라이트/다크, 첫 상품 320px 이전 시작, 수평 넘침 없음.
- 기존 검색/이미지/필터/상세/출고/라벨 소스 격리 검사 통과.
- 패키지 신규 화면·레이아웃·출고 후 목록 이동·라벨 미리보기 검사 통과.
- 로그인 우선 진입·취소·만료 상태 및 창 셸 검사 통과.
- 0.21.0 패키지 생성 및 이 PC 설치 종료 코드 0.
- 실제 설치 EXE 두 번 재시작: 저장 로그인 업무 진입 3,036/2,551ms, 로컬 UI 511/386ms. 네 가지 주문 상태 모두 READY, 상태 조회 2,022~2,107ms. 완료 목록 다음/이전 이동·정렬·초기화·메인 카드 통과. 이 PC의 두 번 측정이며 다른 환경의 보장값은 아니다.

모의 출고 검사는 격리된 API/확인창으로 수행했다. 운영 주문 송장 발급·인쇄·결제는 실행하지 않았다.

## 남은 작업

주문 작업실을 중심으로 이번 구조를 적용했다. 오늘/앱 설정은 공통 톤만 적용했으며 콘텐츠 구조 재설계는 P4-33에서 진행한다. 웹 허브 전체 기능이 이미 데스크톱에 이전됐다는 뜻은 아니다.

시안의 가상 사용자/예시 통계/다중선택/작업 결과 도크를 그대로 꾸며 넣지 않았다. 현재 선택 도구는 1건에만 적용한다. 이후 단계에서 실제 작업 기록을 연결한 도크와 메인·설정 화면을 같은 앱 기준으로 구성한다. 125/150% Windows 배율과 다른 출고 PC·실물 프린터는 추가 검증이 남는다.
