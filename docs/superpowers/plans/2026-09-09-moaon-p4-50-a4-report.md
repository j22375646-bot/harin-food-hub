# P4-50 — A4 포장명세서·출고 작업표

2026-09-09 / 모아온 0.35.0 / 구현·패키지 검증·이 PC 설치 완료

## 이번 작업의 목적

웹 허브의 포장명세서와 출고목록 기능을 모아온의 현재 선택 주문에 연결한다. 웹 화면을 넣는 방식이 아니라 앱이 기존 서버에서 주문을 재확인한 뒤 A4 문서를 메모리 안에서 만든다. 새 DB·서버·유료 서비스는 추가하지 않는다.

## 문서 구분

- 포장명세서: 상품별 옵션·수량과 사은품, 상품 기준 포장 안내, 확인칸.
- 출고 작업표: 주문번호·채널·상품·수량, 주문 단계와 송장 상태, 확인칸.
- 최대20건 현재 선택 주문만 사용한다. 네이버·Cafe24·쿠팡 행을 따로 유지하며 자동 합배송/합산하지 않는다.
- 작업용 문서이며 우체국 송장·플랫폼 출고 승인 대신 사용할 수 없다. 주소·연락처는 포함하지 않는다.

## 웹 기능과의 차이

웹의 주문 페이지 API에는 사은품/상품은 있지만 `packagingInstructions`가 없다. 같은 웹의 순수 상품별 안내 규칙을 앱에서 재사용하고 고객이 직접 남긴 지시로 오인하지 않게 표시한다. 누락된 항목·수량은 확인 필요로 남긴다. 서버 자체에도 상품8종 제한이 있으므로, 이 한도에 도달한 주문은 전체 상품임을 보장하지 않는다. 문서에서 누락 위험을 명시하거나 차단하며 서버의 제한 확대는 이번 작업에 포함하지 않는다.

## UI·안전장치

기존 앱의 Pretendard·선택 도구막대에 통합한다. 작은 창에서도 추가 작업 메뉴 접근을 확인한다. 인쇄는 자동 실행하지 않으며, 미리보기와 인쇄 전후에 선택 주문의 변경 여부를 재확인한다. 인쇄 요청 전달과 실제 출력 성공은 구분한다.

## 검증 결과

- 최종 단위/연결/안전장치 시험 **205/205 통과**(기존193개 포함).
- 실제 Electron Main/preload/IPC/UI를 사용하는 시험으로 합성20건→A4 5페이지, 확인칸20개, 연속순번, 본문12px, 최소1040×720 메뉴 클릭·선택 유지·로그아웃 창 정리 확인.
- 패키지의 신규 A4, 기존 CSV/송장 묶음, 단일 송장, 수집, 배송추적, 자동/수동 등록 UI 회귀 시험 통과. 외부 API 및 인쇄는 모의 처리이며 실제 발급·등록·인쇄는 실행하지 않음.
- 독립 검토의 P2(이미 열린 A4가 다른 송장등록 진행 중에도 검증 통과)를 수정. 동일한 합성 등록 시나리오 재검증에서 차단 확인.
- 저장소에 남긴 `desktop/test/worklist-ui-smoke.cjs` 명령으로 개발·패키지 시험을 재현했다. 임시 시험 파일만으로 완료 처리하지 않았다.
- 최초 설치본 시험은0.34.0의 메서드 부재로 예상대로 실패. 0.35.0 결과는 아래에 기록한다.
- 0.35.0 설치 종료코드0. **실제 주문2건**으로 포장명세서·출고 작업표 모두 메모리 미리보기 열림 확인. A4 크기·행2개·확인칸2개·하단 겹침 없음·JS차단·sandbox·print 호출0 확인. 개인정보 출력/파일 저장 없이 검증했다.
- 설치본 UI 정렬 오차0px, 상세 패널 전환21프레임, 내용 유지 및 숨긴 스크롤 검증 통과.

## 실제 화면에서 수정한 디테일

첫 문서 시안의 과도한 행 여백을 줄이고, 본문12px를 유지한 채 페이지당4건으로 정리했다. 표 머리글·체크칸·페이지 번호를 반복하고 한국 시간으로 작성 시각을 표시한다. 앱의 추가 작업 메뉴는 A4 문서 그룹으로 묶고 스크롤바만 숨겨 모든 항목에 접근하게 했다. 문서가 페이지/하단 안내를 넘거나 실제 본문이 달라지면 출력하지 않는다.
