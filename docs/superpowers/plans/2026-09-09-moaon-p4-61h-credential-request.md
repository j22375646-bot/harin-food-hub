# P4-61H API 설정 저장 요청 처리기

## 구현

- 서버가 지정한 HTTPS origin과 요청 origin의 일치, POST, JSON, 단일 로그인 쿠키를 요구한다. 요청 URL을 그대로 신뢰해 origin을 정하지 않는다.
- 본문을 16KiB와 읽기 제한 시간으로 제한하고 플랫폼별 필수 필드·revision·SEED 바이트 길이를 검사한다.
- 저장 응답에는 사업장·플랫폼·revision·미검증 상태만 반환하며 비밀값·내부 예외를 응답하지 않는다. no-store를 적용한다.
- 저장 어댑터가 없으면 SETUP_REQUIRED. 진행 중인 쓰기를 단순 응답 타임아웃과 경쟁시켜 무작정 재시도를 유도하지 않는다.

## 시험

정식 npm test 전체 2,683/2,683 통과.

잘못된 출처·중복/누락 쿠키·본문 초과·잘못된 플랫폼 필드·미구성·내부 오류를 검사하는 새 시험 3개 실패 확인 후 구현. 기존 격리 PGlite 시험에 Request → 처리기 → 실제 암호화 저장 트랜잭션 경로를 추가했다. 외부 신원 검증은 시험 어댑터다.

## 아직 활성화하지 않은 경계

이번 결과는 프레임워크 독립 요청 처리기다. Next.js 운영 route 등록, 요청 속도 제한과 세션 fence, 운영 DB 역할/암호화 키 구성, 앱의 서버 저장 버튼은 연결하지 않았다. 기존 PC 임시 저장을 몰래 서버 저장으로 바꾸지 않는다.

실제 HTTP 서버·플랫폼 인증 성공이나 새 사업장 연결 완료를 의미하지 않는다. 하린식품 운영 키·DB와 앱 버전 0.51.2는 그대로다. 다음은 위 운영 경계를 완성한 후 route/앱 transport를 연결하는 작업이다.
