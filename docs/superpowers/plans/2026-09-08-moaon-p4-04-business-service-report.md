# P4-04 인증·회원 저장소·목록 응답 연결 검증

## 구현한 연결

`createBusinessListService`는 서버 소유의 identityDb/authAdmin과 제한 제어 DB adapter를 받아 기존 서명 세션 검증기, 회원 저장소, HTTP 요청 처리기를 연결한다. 요청자가 userId나 권한을 전달하는 경로는 추가하지 않았다. 불완전한 구성은 생성 시 거부하고 브라우저 실행도 거부한다.

이번 단계는 서버 composition 함수와 로컬 통합 시험이다. 함수가 직접 DB 연결을 열거나 운영 route를 활성화하지 않는다. 실제 운영 route는 여전히 SETUP_REQUIRED 상태이며, 운영에서 사용할 제한 DB 연결 및 사용자 프로필·인증 관리자 adapter의 주입이 남아 있다.

## 실제로 검증한 것

두 시험 사용자에 대해 실제 dashboardAuth 서명 토큰을 생성하고, 쿠키→서명 검증→사용자 프로필/인증 사용자 대조→제어 저장소 SQL→HTTP JSON 응답을 하나의 흐름으로 실행했다. 목록 조회를 가짜 완성 응답으로 대체하지 않았다.

- 동시에 요청한 사용자 A/B가 각각 본인 사업장만 받음.
- A 회원을 REMOVED로 변경하면 A 목록은 비고 B는 유지.
- 세션 폐기 뒤 요청은 401.
- 서명 첫 글자를 변조한 토큰은 401.
- 사용자 프로필 비활성화 뒤 요청은 401.
- 누락/불완전한 서버 설정으로 서비스를 만들 수 없음.

회원 저장소는 PGlite의 실제 SQL 엔진을 사용한다. 세션/프로필 조회와 외부 인증 관리자 응답은 메모리 시험 adapter다. 따라서 실제 클라우드 인증, 제한 PostgreSQL 역할, 다중 연결 격리 또는 운영 HTTP 네트워크 시험을 완료한 것이 아니다. 시험 비밀키는 테스트 프로세스 안에서만 사용하고 기존 환경값을 복원한다. 토큰을 로그에 출력하지 않는다.

신규 함수 부재 상태에서 시험 실패 후 구현했고, 신규 2개와 관련 회귀를 합쳐 88개 통과. 앱/route 소스 변경이 없어 새 Next 빌드나 EXE 패키징은 수행하지 않았다. 이전 빌드를 이번 빌드 성공으로 주장하지 않는다.

## 적용 범위·남은 일

운영 DB 변경, 실제 계정 생성, 추가 과금 자원, 주문 수집/발급 없음. 앱 0.15.1 유지. 사업장 선택 화면이 생긴 단계는 아니다.

다음은 운영 주입 전에 제한 DB 역할·사용자 프로필 매핑의 구성 준비 상태를 점검하고, 완성된 service를 그 구성으로 연결하는 것이다. 준비 상태가 확인되기 전에는 기존 하린식품 로그인이나 전역 OWNER를 대체하지 않는다. 이후 선택 UI와 P4-01 응답 보호를 통합한다.
