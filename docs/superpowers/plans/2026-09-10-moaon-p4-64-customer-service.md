# P4-64 — 웹허브 고객·CS 목록의 모아온 이식

사용자 지시에 따라 업데이트 기반 작업에서 웹허브 업무 기능 이식으로 전환했다. 기준 0fea2dd. 이번 범위는 고객·CS의 저장된 미처리 접수 목록, 채널/유형 필터, 접수 번호 검색, 원본 상태/접수 시각 상세다.

## 구현 및 자료 경계

웹허브 lib/customer-service/operation-summary.js의 채널별 완료 판정을 재사용한다. customer_service_items, coupang_inquiries, coupang_returns, coupang_exchanges에서 접수 식별자·유형·상태·시각만 읽는다. 고객 본문, 개인정보, raw_data, 암호화 봉투를 읽거나 내려주지 않는다. 네이버·쿠팡·Cafe24 원본 식별자와 채널은 구분한다.

각 원본은 최신201개로 제한하고 응답은 최대200개다. 조회 상한 도달 시 일부 자료임을 표시한다. 화면 건수는 조회된 미처리 목록에만 해당하며 전체 미처리 건수나 실시간 수집 성공을 뜻하지 않는다. 어느 한 조회라도 실패하면 성공한 빈 목록/0건으로 바꾸지 않는다.

고정 하린식품 사업장 OWNER 권한을 조회 전후 확인하고 멤버십 변경 시 결과를 버린다. 다른 사업장, 추가 쿼리, 비로그인, 쓰기 요청은 거부한다. 앱은 Main의 일시적인 고정 GET 허용과 제한된 응답 변환을 거치며 연결 해제·늦은 결과·중복 요청을 차단한다.

원래 모아온 UI의 글꼴·색상·선택 배경·42px 도구를 재사용했다. 좁은 창에서는 상세를 목록 아래로 배치한다. 새 답변 전송, 취소/반품/교환 승인, 환불, 플랫폼 재수집은 이번 범위에 없다.

## 서버 배포

운영 배포 dpl_9wguebJkvyAUvw23bfEywgmCkNVr가 READY이며 기존 harin-cafe24-sync.vercel.app 별칭 연결을 확인했다. 클라우드 프로덕션 빌드는37초에 완료됐고 새 /api/moaon/businesses/[tenantId]/cs 경로가 빌드 목록에 포함됐다. 운영 비로그인 요청은401 UNAUTHENTICATED 및 private/no-store를 반환했다. 실제 로그인한 고객 접수 조회 증거로 해석하지 않는다.

로컬 Webpack은 컴파일/타입검사/정적 페이지 생성까지 진행했으나 C junction 의존성 추적이 길어져 클라우드 빌드 성공 후 해당 로컬 빌드 프로세스를 중단했다. 로컬 전체 빌드 완료로 보고하지 않는다. 기존 C 의존성 폴더를 변경하거나 삭제하지 않았다.

0.53.0 확인용 Windows 폴더 빌드는 D의 격리 staging에 앱 파일과 준비된 updater 의존성을 넣고 검증된 Electron44.2.0 배포판으로 조립한다. 기존 설치본0.52.1의 파일과 로그인 프로필은 교체하지 않는다.

## 웹허브 → 모아온 이식 현황과 다음 업무 범위

| 웹허브 기능 | 모아온 현황 | 남은 범위 |
|---|---|---|
| 주문·배송 | 조회·검색·송장/작업표·배송 동선 구현 | 실제 장비/실출고 인수 |
| 운영·정산 | 기간·채널별 요약·상세·지급 일정 구현 | 운영 금액 대조·일부 정산 보강 |
| 분석·인사이트 | 주간 보고서·근거·키워드 후보 구현 | 전체 웹 분석 작업대 기능 |
| 캘린더 | 월간 조회·선택 상세 구현 | 웹 작업 편집 기능 범위 대조 |
| 고객·CS | 이번 미처리 목록·필터·검색·접수 상태 상세 | 문의 본문·답변 이력 및 승인 후 처리 |
| 재고·상품 | 독립 앱 메뉴 미이식 | 다음 업무 이식 대상: 재고/품절·상품 목록과 근거 상세 |
| 키워드·상품 개발 | 보고서 요약 일부만 제공 | 전용 작업대 이식 |

서버 설정 점검이나 업데이트 도구를 잘게 나누는 작업보다 이 업무 이식 목록을 우선한다. 기존 사업장 격리와 채널별 쓰기 보호를 유지한다.
