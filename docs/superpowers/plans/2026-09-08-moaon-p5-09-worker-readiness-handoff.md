# P5-09 서버 준비 상태 판정 보완

## 범위와 발견

앱의 실제 송장 발급 연결에 앞서 기존 서버 준비 상태 조회를 점검했다. 최근 heartbeat만 있으면 ERROR 또는 STOPPING 상태도 운영 연결 화면에서 READY가 되는 오류를 발견했다. 미래 시각 heartbeat를 0분 전 신호로 해석하는 오류도 있었다.

## 수정

- 운영 연결 화면은 공통 worker.ready 판정을 사용한다. 최근 ONLINE/BUSY만 정상이며 ERROR/STOPPING은 실패로 표시한다.
- 생존 신호와 고정 IP 작업 상태, 수집·출고 capability의 표시를 같은 판정으로 맞췄다.
- 누락·잘못된·미래 신호 시각은 준비 완료 근거로 사용하지 않는다.
- 오래된 신호, 시각 확인 필요, 오류·종료 상태의 안내를 구분한다.

UI 배치, 로그인, 주문·정산 계산, 채널 API 권한, 실제 발급 경로는 변경하지 않았다. READY는 heartbeat 기반 준비 상태이며 안전장치 버전 배포나 실제 발급 성공을 증명하지 않는다.

## 검증

- 수정 전 미래 heartbeat 및 ERROR 상태 오판정 실패를 재현한 후 수정했다.
- 관련 회귀 시험 25/25 통과. 독립 코드 리뷰에서도 같은 시험 통과, 병합 차단 사항 없음.
- 기본 전체 시험에서 기존 tenant-step-up-storage 암호화 시험이 STEP_UP_UNAVAILABLE로 한 번 실패했다. 해당 파일 단독 재실행은 26/26 통과했다. 인증 정책 또는 테스트를 완화하지 않았다.
- 전체 시험을 동시 실행 4개로 제한한 재검증은 2,548/2,548 통과했다(73.8초). 기본 실행의 간헐 실패 원인은 아직 확정하지 않았으며 이를 테스트 통과와 구분한다. UI 규칙 검사도 통과했다.

## 남은 작업

AWS worker의 실제 안전장치 버전 적용 확인, 명시적 발급 확인창 및 진행 상태 연결, 실제 장비 출력 검증은 별도다. 이번 작업은 EXE 변경이 아니므로 0.10.0 설치 파일을 다시 만들지 않는다. 실제 송장 발급·고객정보 변경·유료 리소스 생성은 하지 않았다.
