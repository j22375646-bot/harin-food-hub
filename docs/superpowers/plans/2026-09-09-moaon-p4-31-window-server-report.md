# P4-31 — 서버 연결 오류와 Windows 앱 창·슬림 메뉴 보완

## 이번에 바뀐 것

- 앱 0.20.0 설치 완료. 기존 상품 이미지·옵션·채널/배송/사은품 뱃지, 로그인 유지, 출고 확인 기능 유지.
- Windows 기본 흰 제목 표시줄을 숨기고 최소화·최대화·닫기 버튼을 앱 위에 배치. 상단 빈 공간으로 창을 이동하고 버튼은 별도로 클릭하도록 구분.
- Studio V3 기준 메뉴 폭을 84px로 고정. 긴 문구 때문에 메뉴가 늘어나거나 하단 가로 스크롤이 생기는 문제를 수정.
- 좁은 메뉴에서 연결 상태 상세가 잘리지 않도록 별도 팝업으로 표시.

## 서버 오류: 추측이 아니라 운영 로그에서 확인

실제 설치 앱에서 사업장 목록을 반복 조회하자 간헐적인 503이 재현됐다. 운영 로그의 안전한 진단 코드가 `stage: connect, code: 53300`으로 확인됐다. 이는 DB 연결 수 한도에 걸린 오류다. 비밀번호 오류와는 다르다.

현재 Session pooler 연결은 따뜻하게 유지되는 서버 인스턴스별로 대기 연결을 보유할 수 있었다. 이를 다음과 같이 수정했다.

1. Session pooler의 서버별 연결 상한을 2에서 1로 줄임.
2. 조회/트랜잭션 종료 및 세션 정리가 끝나면 연결을 닫아 유휴 연결을 계속 점유하지 않음.
3. 1차 배포 후에도 순간 연결 거절 1건이 재현되어, SQL 실행 전 연결 거절 코드 53300에만 250ms/500ms 간격의 최대 2회 재시도 추가.
4. 실제 SQL·주문 처리·COMMIT은 재실행하지 않음. 계속 실패하면 확인 필요 오류를 유지.

권한 검사, TLS 인증서 검증, 사업장 분리, 트랜잭션 정리, 취소/발급 안전장치는 완화하지 않았다. 요금제 변경·유료 자원 추가·운영 데이터 삭제는 없었다.

## 검증

- 서버 연결·권한·실패 처리 테스트: 56/56 통과.
- 앱 단위 테스트: 127/127 통과.
- 격리 소스/패키지: 메뉴 84px, 1040/1440px 창에서 가로 넘침 없음, 드래그/버튼 영역 분리, 연결 상세 표시 통과.
- 이미지/뱃지, 로그인 진입, 패키지 출고 후 목록 이동 및 라벨 미리보기 시험 통과. 실제 고객 주문의 송장 발급/프린터 출력은 실행하지 않음.
- 설치 파일 생성 및 이 PC 설치 종료 코드 0.
- 운영 서버 최종 수정: `39e761c`, 배포 `dpl_C3qjDbpsVS3RLwCdjVqtx6fQ3WF5` READY, 운영 도메인 연결 확인.
- 최종 운영 사업장 조회 12/12 성공. 4회마다 15초 대기 포함. 응답 635~1,992ms. 검사 구간 동일 오류 로그 없음.
- 설치 EXE 2회 재시작·저장 로그인 모두 성공. 로컬 UI 표시 666/579ms, 업무 화면 진입 3,055/2,806ms.
- 실제 저장 주문의 발급 전/등록 후/배송중/완료 상태 조회 모두 READY. 상태별 조회 2,044~2,165ms. 완료 목록 다음/이전 페이지, 검색·정렬 초기화, 메인 상태 카드 확인 통과. 런타임 pageerror 없음.

측정 정정: 이전 인수 스크립트의 sessionCheckMs에는 로그인뿐 아니라 이후 주문·화면 시험 전체가 포함됐다. 이번부터 entryReadyMs와 runTotalMs를 분리했다. 26초는 전체 시험 수행 시간이지 로그인 시간이 아니다. 업무 화면 진입 약 2.8~3.1초는 이 PC의 저장 로그인 2회 측정치이며 모든 PC/신규 로그인의 보장값은 아니다.

## 아직 남은 차이와 다음 단계

시안 전체와 완전히 일치한다고 표시하지 않는다. 이번 범위는 사용자가 지적한 창·메뉴와 서버 오류다.

다음 P4-32에서는 V3의 선택 도구막대와 작업 결과 영역을 기존 확인·출고·라벨 기능에 연결한다. 이미지·뱃지·상세 패널을 함께 비교하고 라이트/다크, 작은 창, 125/150% 배율을 검수한다. 실주문 자동 재발급이나 검증 안 된 숫자 표시를 추가하지 않는다.

장시간·다수 PC 동시 부하와 실제 프린터 출력은 별도 검증이 남는다. 이번 반복 시험만으로 앞으로 오류가 전혀 없다고 보장하지 않는다.
