# P4-53 전체 주문 검색과 기간별 엑셀

사용자 승인: 주문 페이지 기능 이식과 앱 전용 UI를 계속 개발한다. 웹 디자인을 임베드하지 않고 기존 서버/DB/API를 재사용한다.
기준 커밋: c2b0181 (0.37.0). 목표 버전: 0.38.0.

## Global Constraints

- 판매자배송 주문만 포함하고 현재 하린식품 OWNER 사업장 경계를 유지한다. 다른 사업장에 기존 주문을 노출하지 않는다.
- 실제 송장 발급/채널 등록/인쇄 및 운영 데이터 쓰기는 이번 검증에서 실행하지 않는다. 유료 인프라 추가 없음.
- 기존 선택, 송장 사전확인, 필터, 페이지 이동, 재확인, 자동 최신성 확인의 안전장치를 유지한다.
- 검색과 엑셀은 서버가 조회 가능한 주문 전체가 대상이며 채널 보존기간 밖의 주문까지 조회했다고 표현하지 않는다.
- UI는 기존 앱 Pretendard/라벤더 톤, 정렬, 슬림 메뉴, 숨긴 스크롤바, 패널 축소 동작을 보존한다.
- 원본 주소/전화번호/주문 내용과 인증정보를 로그 및 보고서에 쓰지 않는다.

### Task 1: 전체 검색·기간 조회·XLSX 앱 통합

작업 디렉터리는 `.worktrees/moaon-foundation`이다. 먼저 AGENTS.md와 Next route 문서를 읽고 TDD로 진행한다. 하위 에이전트 생성 금지.

요구 기능:
1. 기존 tenant-bound `/api/moaon/businesses/[tenantId]/orders`를 확장한다. query(최대 100자), start/end(실제 유효 YYYY-MM-DD, 한국 날짜 경계, 시작<=종료)를 지원한다. 빈 값은 기존 동작. 알 수 없는/중복 파라미터는 거부한다. query는 주문번호/상품/채널 검색이며 개인정보 검색을 확대하지 않는다.
2. 동일 경로의 `format=xlsx`를 지원한다. 별도 웹 `/api/orders/export` 허용으로 우회하지 않는다. 동일 seller/stage/channel/delay/gift/query/date 후보 생성 함수를 조회 및 내보내기가 공유한다. 검색 및 기간은 snapshot에 포함한다. 이전 무조건 조회 계약은 호환 유지한다.
3. XLSX는 기존 서버 ExcelJS 사용, 최대 5000건 초과 또는 채널 일부 실패면 명시적 오류로 중단한다. 0건은 파일 생성 없이 안내한다. 번호/상품/채널/상태/수량/금액/주문일/송장번호만 내보내고 주소·전화번호는 포함하지 않는다. 알 수 없는 금액을 0으로 만들지 않는다. 수식 주입 차단. cache private,no-store/nosniff, XLSX MIME. 기존 tenant 접근 전후 재검증을 통과해야 한다.
4. Electron Main 고정 URL 정책 및 bridge에 엄격한 검색 조건/다운로드 계약을 추가한다. 서버가 검색 지원함을 확인할 수 있는 버전 메타데이터를 반환하고, 지원하지 않는 구 서버에서는 전체 검색 성공으로 가장하지 않는다. XLSX는 Main에서 인증된 읽기, MIME/최대 10MB/파일 형식 검증, native 저장 대화상자, 기존 안전 저장 패턴 사용. renderer에 로컬 경로·바이너리·인증정보를 주지 않는다. 취소/덮어쓰기/중복 클릭/로그아웃/사업장·조건 변경 중 늦은 응답을 안전 처리한다.
5. 앱 주문 상단에 접이식 `전체 검색·기간` 도구 추가: 검색어, 시작일, 종료일, 검색 적용, 조건 초기화, 엑셀 저장. 적용된 범위를 짧게 보여주고 기존 현재 페이지 검색과 혼동하지 않게 한다. 입력은 서버 요청을 즉시 반복하지 않고 제출 시 한 번만 보낸다. 조회 중/수집 중/송장 작업 중 중복 조작 잠금. 조건 변경은 선택과 cursor를 초기화하고 재조회한다. scope/channel 변경, 다음/이전 페이지, 재확인, 자동 최신성 확인, 송장 최신성 확인에서 조건을 보존한다.
6. 접힌 도구의 focus/inert/aria-expanded, reduced motion, 작은 창에서 overflow, 버튼/입력/헤더 정렬을 실제 DOM UI smoke로 검증한다. 기존 선택 CSV/작업표 기능은 유지한다.

범위 파일: app/api/orders/page/route.js, 해당 tenant wrapper/guards, lib/ui/phase28-adapters/orders.js 및 필요한 작은 공용 모듈, desktop 연결/bridge/UI와 관련 테스트. package 버전/배포/전체 계획서는 컨트롤러 담당. 빌드 포함 files 목록은 새 runtime 파일이 있을 때 수정 가능.

검증: 새 기능 실패 테스트를 먼저 확인하고 API guard/후보 필터/XLSX 내용/tenant 거부/공유 snapshot/Main 저장 취소 및 race/페이지 조건 보존을 테스트한다. desktop 전체 테스트와 관련 server 테스트를 실행한다. 실제 외부 쓰기 없이 fixture로 검증한다. 구현·테스트만 커밋하고 정확한 변경 파일과 테스트 명령/결과, 미검증 사항을 report에 기록한다.

### Task 2: 독립 검토·릴리스 검증

컨트롤러는 Task 1 diff를 독립 검토시킨다. 중요 문제 수정 후 server build/기존 desktop 회귀/UI smoke를 실행하고 실제 읽기 전용 연동을 검증한다. 백엔드 변경은 배포 READY와 인증 없는 접근 거부를 확인한다. 앱 0.38.0 installer를 빌드하고 설치 검증은 기존 실행 창을 확인하여 작업 손실 없이 진행한다. 운영 API 결과와 fixture 성공을 구분한다. 전체 계획서, P4-53 결과서, 다음 개발 항목을 갱신하고 명시 파일만 커밋/푸시한다. 서버 배포·실데이터 검증이 불가능하면 완료로 표시하지 않는다.
