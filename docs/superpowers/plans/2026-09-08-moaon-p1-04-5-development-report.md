# 모아온 P1-04-5 개발 보고서

> **현재 상태:** `1.47.0`은 UNRELEASED 후보입니다. 요청 제한과 복구 검토 이력의 로컬 구현·검증을 마쳤으며, 독립 검토·최종 빌드·운영 배포를 진행 중입니다. 새 인증 기능의 운영 활성화와는 구분합니다.

## 무엇을 바꾸는가

이번 단계는 로그인과 비밀번호 복구의 요청 제한을 DB에 안전하게 저장하고, 복구 도중 문제가 생기면 확인할 이력을 남기는 서버 기반을 구현한다. 운영 화면을 바꾸거나 새 가입 기능을 개방하는 단계는 아니다.

### 요청 횟수 제한

기존 로그인 실패 기록은 DB를 읽고 횟수를 계산한 뒤 다시 쓰므로 동시 요청에서 누락될 수 있는 구조다. 새 요청 제한은 DB 잠금 안에서 한 번에 판단한다. 서버 프로그램을 새로 띄워도 같은 DB에 저장된 횟수를 계속 사용한다. 기존 비밀번호 실패 차단 정책은 없애지 않는다.

| 대상별 요청 종류 | 새 고정 창 한도 |
|---|---|
| 로그인 | 15분 10회 |
| 복구 메일 | 1시간 3회 |
| 비밀번호 복구 완료 요청 | 15분 5회 |
| 이메일 확인 | 15분 5회 |

이 값은 아직 운영에 켜지 않은 새 경로의 정책이다. 성공·실패와 관계없이 외부 인증 호출 전 소비한다. 계정/이메일/토큰 원문은 제한 테이블에 넣지 않고 서버 비밀키로 계산한 식별값을 쓴다. 저장소가 고장 났다고 제한을 건너뛰지는 않는다.

### 복구 검토 이력

비밀번호 변경 전에 PENDING 이력을 먼저 기록한다. 처리 중 서버가 중단돼도 시작 흔적이 남고, 결과가 불명확하면 REVIEW_REQUIRED로 남긴다. 기록 자체가 계정 잠금을 풀거나 비밀번호 변경을 다시 실행하지 않으며, 작업 완료는 실제 DB 복구 완료 근거가 있을 때만 기록한다.

검토 목록은 서버 전용이다. 다른 사업장 관리자에게 전체 계정 정보를 노출하는 화면/API는 만들지 않는다. UUID·고정 단계·상태·DB 시각만 저장하고 비밀번호·토큰·메일·공급자 오류 원문은 기록하지 않는다.

| 기록 상태 | 뜻 |
|---|---|
| PENDING | 작업 시작 흔적은 있지만 최종 결과를 아직 기록하지 못함 |
| REVIEW_REQUIRED | 처리 중 오류·지연이 생겨 별도 확인이 필요함 |
| COMPLETED | 실제 DB의 복구 완료 기록을 확인함 |
| REJECTED | 변경 작업이 시작되지 않았음을 확인하고 거절함 |

이미 거절된 작업이 뒤늦게 시작되거나 다른 계정이 같은 작업번호를 쓰는 것도 후보 DB 규칙에서 차단한다. 기존 방식처럼 검토 행 없이 시작하는 경로는 유지되며, 이 호환성도 별도 검사했다.

## 검증과 운영 반영 범위

- 시작 기준71ee7c0, 전체2,167/2,167 통과, 실패·취소·건너뜀0.
- 기존 PC의 PostgreSQL17.11을127.0.0.1:55437에서 재사용한다. 운영 DB 복사나 외부 유료 테스트 자원 생성 없이 가상 계정만 쓴다.
- 요청 제한: 먼저 실패 재현41개 중 예상 실패8개를 확인한 뒤 구현했다. 집중49/49, 실제 PostgreSQL 다중 연결2/2, 전체2,182/2,182를 통과했다. 담당 구현과 별도로 PostgreSQL 검사를 다시 실행해2/2 통과를 확인했다.
- 동시 요청은20건을 보내 한도가10건인 경우 정확히10건만 허용되는지 검사했다. 별도 DB 연결의 실제 잠금 대기, 롤백 후 처리, 저장소를 닫고 다시 열어도 제한이 유지되는지 확인했다.
- 최초 동시성 검사에서는 테스트 연결을 너무 많이 열어1건이 실패했다. 테스트 연결 풀을4개로 제한하되20건의 요청은 유지한 후 통과했다. 운영 DB에 발생한 오류가 아니다.
- 복구 검토: 초기22개 중 예상 실패7개를 확인한 뒤 구현했다. 최종 집중37/37, 실제 PostgreSQL3/3, 전체2,204/2,204 통과. 계정 교차 작업번호, 잘못된 응답·NULL 단계, 같은 밀리초 기록의 정렬까지 실패 재현 후 보완했다.
- 기존 세션 차단의 실제 PostgreSQL 검사도2/2 통과했다. 변경 중 늦은 로그인 거절과 기존 세션 폐기를 확인했다.
- 전체 검사에는 기존 모듈 형식 경고와 오류 상황을 시험하기 위한 인증 진단 로그가 남아 있다. 새 검사 실패는 없지만 경고가 전혀 없는 출력이라고 보고하지 않는다.
- 최종 검토·빌드·배포 결과는 이후 기록한다. 코드 배포와 새 SQL/인증 조합의 운영 활성화는 별개다.
- 현재 운영 로그인·비밀번호·UI·업무 API는 유지한다. 새 SQL은 미적용 후보 파일이며 새 서버 의존성을 운영에 연결하지 않는다.

### 작업 중 내린 판단

1. **개발 중 버전을 출시 완료로 표시하지 않기:** 구현 중의1.47.0 표기는 출시 후보로 명시하고, 요청 제한과 복구 이력의 완료 상태를 나눠 기록했다. 버전 번호 준비와 실제 배포는 별개다. 이 판단이 잘못되면 문서 수정이 필요하지만 운영 설정에는 영향이 없다.
2. **거절된 복구의 뒤늦은 시작도 DB에서 막기:** 거절 함수만 잠그는 것으로는 거절이 끝난 다음 시작하는 요청을 막지 못해, 후보 SQL에 작업 시작 전 검사를 추가했다. 계정→검토 기록 순서로 잠그며 기존 검토 행 없는 경로는 유지한다. 잘못 구현하면 정상 복구 차단이나 DB 교착이 생길 수 있어, 양쪽 실행 순서와 기존 경로를 실제 PostgreSQL에서 검증했다. 운영 DB에는 아직 적용하지 않았다.

## 남아 있는 조건

대상별 제한은 IP/전체 서비스 요청량 제한과 다르다. 아이디·이메일 별칭 통합, 만료 제한 기록 정리/보관 정책, 지원 관리자 검토 화면 및 안전한 수동 해결 절차, 실제 Auth/SMTP/HTTP 전환 시험은 개방 전에 추가해야 한다. 이번 구현만으로 분산 공격 방어 또는 실제 다사업장 가입이 완료됐다는 뜻이 아니다.

이후 사업장별 업무 데이터 격리(P2), 플랫폼 연결(P3), 앱 UI(P4), Windows EXE/프린터(P5)를 이어간다.
