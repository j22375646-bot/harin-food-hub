# P4-55 / 0.39.0 오늘 페이지 — 운영 요약 자동 진입

## 순서 변경

주문 실등록 인수는 발급 대상 부재로 대기하며 완료로 처리하지 않는다. 오늘 페이지를 먼저 진행하자는 제안 후 사용자의 개발 진행 요청에 따라 오늘 이식을 시작했다. 과거 문서의 주문 인수 후에만 다음 페이지를 시작한다는 순서는 이 결정으로 대체한다.

## 구현

- 실제 로그인/연결 확인 후 오늘 화면의 네 가지 주문 요약을 자동 조회한다.
- 오늘 화면으로 다시 돌아올 때 마지막 시도 이후1분이 지났으면 새로 읽는다. 1분 이내 반복 이동은 재조회하지 않는다. 상시 폴링은 하지 않는다.
- 사용자가 전체 상태 조회를 누르면 즉시 재조회할 수 있다.
- 모든 구간이 정상 확인된 때만 발급전 건수에 따른 업무 안내를 표시한다. 부분 확인·누락·실패를0건이나 업무 없음으로 취급하지 않는다.
- 제목을 오늘의 운영 현황으로 정리하고 기존 앱 폰트·카드·색상·주문 바로가기를 유지한다. 서버 계산을 앱에서 다시 계산하지 않는다.

## 범위 구분

이번은 기존 주문 요약을 오늘 진입 흐름에 통합한 첫 단계다. 웹 메인의 매출·목표·이익·현금흐름·일정 전체 이전이 아니다. 주문 건수는 오늘 신규 주문 수나 오늘 매출이 아니다. readOverview의 기존 인증된 조회 경로만 사용하며 서버/DB 변경·실제 발급·등록 쓰기는 없다.

## 검증

수동 조회 없이 등록후0건이 나타나야 하는 검사에서 수정 전 실패를 확인했고 수정 후 통과했다. 부분/실패 표시, 반복 화면 이동 시 요청 억제, 주문 바로가기, 로그아웃 비움, 밝음/어두움 검사를 수행했다. 앱 단위231개 및 최종 패키지 오늘·자동 발급·레이아웃3종 통과. 오늘 화면 캡처를 확인했다.

## 다음 개발 묶음

0.39.0 이 PC 설치 종료0 및 패키지/설치 app.asar 해시 일치. 설치 앱 재실행 후 추가 클릭 없이 실제 네 구간이 READY로 표시됐다: 발급전0, 등록후0, 배송중2, 완료·취소89. 이는 해당 조회 시점 저장 상태이며 신규 송장 발급/등록 실행 결과가 아니다.

1. 웹의 오늘 일정 읽기 계약을 사업장 검사와 함께 연결한다. 오늘 화면에 해당 날짜 일정과 완료 상태를 표시하되 캘린더 전체 편집은 분리한다.
2. 웹 메인 재무 모델을 공통 서버 서비스로 연결한다. 매출·목표·이익의 기간·출처·미확인 상태를 그대로 유지한다.
3. 통합 오늘 화면의 실제 데이터·레이아웃을 검증한다. 주문 실등록 인수는 적합한 시험 대상 확보 시 별도로 수행한다.
