# P4-116 · 배포 설치파일과 동의형 업데이트 (0.102.0)

## 현재 상태

Windows x64 설치파일을 생성했다. 업데이트 안내·사용자 동의·다운로드 진행·적용 재시작 UI를 구현하고 검증했다. **실제 자동 업데이트 배포는 서명 계정과 HTTPS 배포 주소가 없어 아직 미연결**이다. 사용자가 서명 인증서/계정이 없다고 확인했으며, 임의 계정 생성·유료 결제·서명 검증 해제를 하지 않았다.

## 바뀐 업데이트 동작

앱 시작10초 뒤와6시간마다 확인한다. 사용자 동의 없이 다운로드하지 않는다. 새 버전 발견 시 앱 확인창에 다운로드/나중에를 표시한다. 나중에를 누른 버전은 이번 실행 중 자동 재안내하지 않으며 상단 새 버전 버튼으로 다시 열 수 있다. 로그인 진입 화면과 다른 대화상자가 열린 동안은 자동 안내를 미룬다.

다운로드 진행률, 작업 계속하기, 완료 후 저장 완료·재시작을 제공한다. 재시작은 별도 선택이며 처리 중 IPC/자식 창이 있으면 기존 작업 잠금으로 차단한다. 일반 종료 때 자동 설치하지 않는다. 데이터 보존 설정과 기존 앱 ID·사용자 데이터 경로를 유지한다.

## 배포 준비 도구

`desktop/scripts/build-distribution.ps1`은 별도 D 드라이브 스테이지에서 NSIS 설치파일을 만들고 해시·서명 상태를 기록한다. 기본값은 수동 배포본이며 자동 업로드하지 않는다. `-ChannelConfig`에 실제 설정 파일을 넣으면 HTTPS feed와 배포자명을 검증하고 mandatory signing 및 업데이트 메타데이터를 구성한다. 빌드 실패/유효하지 않은 서명에서는 서명 배포를 완료로 취급하지 않는다.

`desktop/release-channel.example.json`은 **예시**다. 실제 저장소 주소·검증된 배포자·서명 계정/프로필로 채워 별도 파일로 사용한다. 비밀키/로그인 정보는 JSON에 넣지 않는다. Azure 자격증명은 빌드 실행 환경에서만 제공한다. Windows 인증서 저장소를 쓰는 경우 azureSignOptions를 빼고 검증된 배포자명을 사용한다. 현재 설치된 electron-builder 스키마에 대해 두 서명 경로와 수동 경로를 검사했다. 실제 인증서를 이용한 서명 성공은 미검증이다.

## 사용자님이 준비할 것

1. **사업자 명의 Azure 구독과 Artifact Signing**: Microsoft 공식 문서(2026-09-11 확인)는 한국 조직을 Public Trust 지원 국가에 포함하며, 개인 개발자 신청은 미국/캐나다로 제한한다. 조직/DBA 심사는 실제 사업 형태로 신청한다. 법적 사업자명·주소·사업 식별번호, 사업체 사이트와 소유 도메인 이메일 등 본인확인 자료를 준비한다. Azure 청구 계정의 명의/종류와 신청 명의가 맞아야 한다.
2. Artifact Signing 계정을 만들고 **Public 신원 검증 → Public Trust 인증서 프로필**을 준비한다. 결제·명의 인증은 사용자님이 직접 진행한다. 계정명·프로필명·endpoint·검증된 publisherName을 확인하면 빌드 연결을 진행할 수 있다. 암호나 비밀키를 채팅에 보낼 필요는 없다.
3. **배포 전용 HTTPS 저장소**: 설치파일과 blockmap, latest.yml을 제공할 주소가 필요하다. 앱 소스/업무 DB와 분리한다. 접근 방식·비용·주소를 정한 뒤 연결한다. 비공개 업무 저장소의 접근 토큰을 설치앱에 넣지 않는다.
4. 서명된 첫 설치본을 별도 PC에 설치하고 로그인·조회·프린터를 확인한다. 다음 시험 버전을 게시해 다운로드 검증·재시작·버전 변경·자료 보존을 실제로 확인한 뒤 정식 배포한다. 설치파일/블록맵을 먼저 올리고 latest.yml을 마지막에 갱신한다. 소스 커밋/로컬 바로가기 갱신 자체는 고객 배포가 아니다.
