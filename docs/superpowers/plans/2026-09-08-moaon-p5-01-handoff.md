# P5-01 — 모아온 Windows EXE 첫 시제품

## 이번에 사용 가능한 결과

`desktop/dist/Moaon-Preview-0.1.0-Setup.exe`는 Windows x64 개인용 설치파일이다. 설치 없이 실행할 때는 `desktop/dist/win-unpacked/MoaonPreview.exe`를 사용하되 폴더 전체를 보존한다. Node.js나 웹 개발 서버를 따로 실행할 필요가 없다.

오늘, 주문·배송, 앱 설정 화면과 샘플 주문 3건의 검색·상세 열기/닫기, 라이트/다크 전환이 동작한다. 제목과 상단에 시험용 상태를 표시한다. 실제 운영 주문·고객·API 키는 포함하지 않는다.

## 검증

- 보안 URL/자원 경로 단위 검사: 4/4 통과.
- 실제 Electron 개발 실행과 패키징 EXE 실행: 메뉴, 검색, 검색 결과 없음, 상세 열기/닫기, 테마 전환, 최소 창 크기에서 가로 넘침 없음 확인.
- 실행 중 Node 접근 비활성, sandbox/contextIsolation/webSecurity 활성 확인. 팝업과 외부 fetch 차단 확인.
- 패키징 EXE 첫 화면 준비: 최종 파일에서 이 PC 단일 측정 489ms. 샘플 화면의 수치이며 실제 로그인/API 로딩 속도나 평균·상위 지연을 뜻하지 않는다.
- NSIS 설치파일 빌드 성공. 크기 111,351,706 bytes, 미서명(NotSigned).
- SHA256: `EC3375B4E248DC2E2904C41574B429575A7B37B4D1368B99787B119E3F536903`.
- app.asar에는 main.cjs, security.cjs, package.json, UI 세 파일만 포함됨. 운영 환경변수·DB·테스트 자료 파일은 없음.
- npm audit 전체 의존성: 알려진 취약점 0건(검사 시점). 설치 도구의 일부 간접 의존성에는 deprecated 경고가 있어 향후 도구 업데이트 시 재검토한다.
- 기존 허브 전체 회귀 검사: 2,541/2,541 통과, 실패·취소·스킵 0. 웹 소스와 root 의존성 변경 없음.

## 아직 완료하지 않은 것

이 버전에는 실제 로그인, 사업장 연결, 주문 수집, 송장 발급·인쇄, 자동 업데이트가 없다. Windows 서명 인증서가 없어 게시자/보안 경고가 나올 수 있다. 보안 기능을 끄는 방식으로 해결하지 않는다. 다른 PC의 설치·제거·업데이트와 프린터는 아직 검증하지 않았다. 운영 웹 배포는 변경하지 않았다.

## 다음 개발: P5-02 실사용 연결 기반

1. 사용자 단위 설치·재실행·제거와 앱 설정 보존/초기화 검증.
2. 기존 하린식품 로그인과 주문 조회를 앱에 연결하는 인증 경계 구현. 앱 안에 공용 관리자 키를 넣지 않고 서버가 현재 사용자·사업장 권한을 확인한다.
3. 연결 실패·세션 만료·재연결 표시와 조회 결과 갱신 검증. 첫 실제 업무 대상은 주문 조회이며 발급/수정은 별도 검증 후 연다.
4. 이후 우체국 인쇄·다사업장 가입/API 연결을 순차 연결. 인쇄는 100×150mm/A4를 기본 시험하되 실제 프린터 확정 전 완료로 처리하지 않는다.

## 진행 순서 조정

원래 종합 계획에도 P4/P5 샘플 병행이 허용돼 있었다. 인증 세부 검증을 계속 먼저 수행하던 순서를 바꿔 이번에 EXE를 인도한다. 실제 사업장 분리·권한 검증은 생략하지 않는다. 기본 Windows 창·기본 아이콘·미서명 시제품을 우선 선택해 추가 인증서 비용을 발생시키지 않았다. 이 선택 때문에 설치 경고와 최종 브랜딩 작업은 남아 있다.
