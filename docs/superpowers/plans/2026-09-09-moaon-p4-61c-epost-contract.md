# P4-61C 우체국 API 계약 설정 보완

## 발견과 수정

`lib/epost/config.js`의 기존 런타임은 인증키와 고객번호 외에 SEED 보안키, 계약 승인번호, 접수국 일련번호를 사용한다. 이전 앱 입력은 두 필드뿐이어서 실제 발급 구성에 부족했다.

- 계약 승인번호·접수국 일련번호·SEED 보안키·선택 배송추적 키 입력 추가.
- SEED 보안키를 화면과 메인 프로세스 양쪽에서 UTF-8 16바이트로 검증. 키는 password 입력이고 저장 후 비운다.
- 배송추적 인증키는 발급용 키와 구분하며 미입력 상태를 허용한다. 추적 기능까지 준비됐다고 표시하지 않는다.
- 기존 두 필드 암호화 자료는 삭제나 덮어쓰기 없이 읽는다. `CONFIGURATION_REQUIRED`로 표시하고, 새 저장은 완전한 계약 필드를 요구한다.
- 플랫폼별 안내를 분리하여 우체국에 Cafe24 OAuth 안내가 나오지 않도록 수정. 기존 앱의 2열 입력칸과 공통 스타일 유지.

## 검증

- 새 테스트 3개 실패 확인 후 구현. 앱 전체 285/285 통과.
- 누락 계약 필드, 잘못된 SEED 바이트 길이, 정상 다국어 16바이트, 선택 추적 키, 이전 암호화 파일 호환·갱신·삭제 검증.
- 격리 Windows 앱에서 우체국 입력·잘못된 키 차단·실제 암호화 저장·비밀값 비움 확인. 실제 API 키 대신 시험 문자열 사용.
- 패키지 app.asar로 동일 설정 시험 및 공통 UI 시험 통과. 0.51.1 설치 exit 0, 설치된 app.asar와 시험 패키지 SHA-256 일치.

## 미완료와 다음 단계

실제 우체국 인증 API를 호출하거나 송장을 발급하지 않았다. 서버 자격증명 저장, 플랫폼 인증 검증, Cafe24 OAuth 및 새 사업장 런타임 연결은 아직 미완료다. 다음은 기존 고정 IP 서버의 사업장별 자격증명 저장·검증 경로 구현이며, 로컬 입력을 실제 연결 성공으로 취급하지 않는다.

하린식품 운영 키와 서버·DB는 변경하지 않았다.
