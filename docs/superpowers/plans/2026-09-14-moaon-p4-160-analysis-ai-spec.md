## 1. 목표와 제품 결정

모아온의 분석 자료를 읽고 변화·근거·원인 후보·다음 확인 행동을 설명하는 분석 도우미를 만든다. 1차 고객은 하린식품 운영자이며, 다른 사업장으로 확장 가능한 권한 경계를 갖춘다.

- 1차 핵심: 분석 페이지의 ‘이번 주 살펴볼 점’, ‘이 자료에 질문하기’, ‘분석 기록’.
- AI는 서버가 확정한 지표를 설명한다. 주문·매출·원가·ROAS 계산은 기존 계산기가 담당한다.
- 내부 경영 자료: CLOVA Studio. 공개 시장 자료: Gemini 무료 등급. GPT/Claude 신규 호출 없음.
- 페이지 진입은 무료 저장 결과 조회만 한다. 첫 버전은 사용자가 분석/질문을 눌렀을 때만 생성한다.
- 현재의 보고서·광고 관리·키워드·주문·정산 UI와 동작을 보존한다. 별도 전역 챗봇을 만들지 않는다.
- 결과는 초안이며, 임의의 가격·광고·재고·주문 변경이나 고객 메시지 발송 권한을 갖지 않는다.

## 3. 단계별 범위

| 단계 | 전달할 기능 | 제외/후속 조건 | 완료 기준 |
|---|---|---|---|
| 160-A | CLOVA로 네이버 보고서 설명, 근거 카드, 범위 내 질문, 저장 결과 조회, 비용 통제 | 다채널 주문·자유 웹검색·업무 등록은 후속 | 아래 정확도/권한/비용/설치 기준 통과 |
| 160-B | Gemini 공개 트렌드 해석, 시장 관심도 카드 | 내부 자료·자유 입력 질문을 Gemini에 보내지 않음 | 공개 출처만 외부 전송, 실제 무료 등급/쿼터 확인 |
| 160-C | 채널별 주문 매출·상품별 이익 분석 | 수집/취소환불/상품 매핑/원가 준비도 검증 후 | 채널별 원장 대조, 누락 비용은 판단 보류 |
| 160-D | 이벤트·재고·CS 분석, 업무·이벤트 초안 연결 | 각 자료 범위와 기존 저장 흐름 검증 후 | 원장 변화 없음, 사용자 검토 후 초안 저장 |
| 160-E | 주간 자동 요약, 분석 결과의 실행 후 추적 | 비용·정확도 검증 및 스케줄 사용 결정 후 | 자료가 바뀐 경우만 생성, 중복 실행 차단 |

처음부터 모든 하위 페이지를 개발하지 않는다. A는 단독 배포 가능한 기능이며 B 이후의 상세 작업은 A의 실제 사용 결과에 맞춰 구체화한다.

## 4. 화면과 동작

### 분석 홈

기존 상단 지표와 필터를 유지하고 아래 순서로 배치한다.

1. 범위 띠: ‘네이버 광고 · 선택한 보고서 기간 · 저장 보고서 작성 시각’. 원천 수집 시각을 별도 표기하며 미확인이면 그대로 표시.
2. ‘이번 주 살펴볼 점’: 최대 3개 핵심 카드, 더 보기로 최대 5개. 기존 비교 카드와 중복하지 않게 동일 지표의 AI 설명을 펼친다.
3. 카드: 제목 / 관찰된 사실 / 원인 후보 / 확인할 행동 / 근거 보기.
4. ‘이 자료에 질문하기’: 우측 패널. 보고서 상세 패널과 동시에 겹쳐 열지 않는다.
5. 분석 기록: 기준 기간·자료 변경 여부·생성 시각·사용 엔진·자료 충분성·사용량 표시.

예시(설계용 문구, 실제 분석 결과 아님):
‘광고 전환매출이 감소했어요’ → 서버가 계산한 전후 수치 → ‘클릭 수와 전환율 중 어느 지표가 달라졌는지 확인해야 해요’ → ‘캠페인 근거 보기’.

### 질문 UX

- 1차 추천 질문: ‘어떤 지표가 가장 달라졌어?’, ‘어떤 키워드부터 확인할까?’, ‘이익을 판단할 자료가 충분해?’, ‘이 보고서에서 다음에 할 일은?’.
- CLOVA 사용자 질문은 500자, 대화 최대 6턴. 같은 snapshot 안에서만 이어간다.
- 비교 보고서는 서로 겹치지 않는 같은 길이의 기간이어야 한다. 7일/30일 임의 선택을 현재 주간 보고서 위에 억지로 적용하지 않는다.
- 사용자가 보고서·채널을 바꾸면 새 대화로 시작. 이전 답변은 기록에서 볼 수 있으며 현재 자료의 답변처럼 노출하지 않는다.
- Gemini 1차는 공개 키워드/카테고리와 정해진 질문 버튼만 허용. 비공개 수치가 들어갈 수 있는 자유 질문·내부 대화 재사용 금지.
- 범위 밖 질문에는 ‘현재 자료로는 확인할 수 없어요’와 필요한 자료를 표시. 다른 채널 값을 가져와 메우지 않는다.
- 분석 중 취소, 오류 후 재시도, 사용 한도, 미설정, 자료 없음 상태를 모두 디자인한다.

### 시각 규칙

현재 보라·라벤더를 기본으로 유지. 민트=개선, 앰버=확인, 로즈=악화, 중립=변화 미미/판단 보류. 광고비 감소를 무조건 개선으로 칠하지 않는다. 방향과 운영 의미를 별도 판단한다.

카드 전체에 균형 잡힌 1px 테두리, 최소 44px 조작 영역. 기존 가독성 크기 이하로 줄이지 않는다. 넓은 화면 3열, 중간 2열, 좁은 화면 1열. 질문 패널은 좁은 화면에서 본문 흐름에 배치하고 버튼·하단 선이 잘리지 않게 한다. 160~220ms의 펼침/전환 효과만 적용하고 reduced-motion을 따른다. 답변은 서버 검증을 마친 뒤 한 번에 표시하며, 검증 전 토큰을 타이핑 효과로 노출하지 않는다.

## 5. 분석의 근거와 계산 규칙

- 1차 scope=NAVER_AD_REPORT. WEEKLY 최신 20개 보고서 중 선택한 최대 2개만 분석한다. REPORT snapshot과 현재 광고 workbench snapshot을 섞지 않는다.
- 1차 metric: 광고 전환매출, 광고비, 클릭/전환수, CVR, ROAS, 기존 계산기의 재무 신뢰도가 READY인 공헌이익. 실제 필드가 없으면 null과 이유를 전달한다.
- 핵심 값이 없으면 해당 카드만 ‘확인 필요’. 가능한 다른 지표는 설명한다. 분석 전체를 READY로 과장하지 않는다.
- 증감률=(현재-이전)/이전×100, 이전 0이면 비율 대신 절대 차이. CVR 차이는 %p. 합산 CVR은 전환수/클릭수로 재계산하며 일별 비율의 단순 평균 금지.
- KST, 닫힌 기간만 비교. 기간 길이·통화·과세기준·광고 범위·집계 정의가 다르면 비교 차단. 운영 중 캠페인만 집계된 자료는 그 범위를 명시.
- 저장 보고서 작성시각은 원천 수집 시각과 다르다. 과거 보고서는 역사적 설명 가능하지만 현재 상황의 추천으로 표현하지 않는다. 현재 행동 추천에는 원천 freshness 증거가 필요하다.
- 충분성은 서버가 COMPLETE/PARTIAL/STALE/BLOCKED로 판정한다. AI 스스로 ‘신뢰도 98%’를 만들지 않는다.
- 원인은 측정된 분해만 확정적으로 설명하고, 나머지는 ‘가설’과 ‘추가 확인 자료’로 분리한다. 프로모션 전후 변화만으로 인과·기여도를 확정하지 않는다.
- 모든 수치 표시는 서버 metricId를 참조한다. 근거 없는 금액/비율/기간을 자유 텍스트에 생성한 결과는 노출하지 않는다. 문자로 풀어쓴 허위 주장까지 완벽 검출한다고 보장하지 않고 평가셋과 실사용 검토로 보완한다.
- 근거 링크는 서버 allowlist/reportId로만 생성. 모델이 URL·SQL·실행 명령을 만들지 않는다.

## 6. 모델·비용 결정

### 제공자

CLOVA Studio: 내부 집계 분석 전용. 모델은 HCX-007 Structured Outputs를 첫 적합성 시험 후보로 삼되, 계정 가용 모델·현재 단가·입출력 한도·처리/보관/학습 조건 확인 후 서버 allowlist에 고정한다. 무료 크레딧이라고 무조건 내부자료 전송이 승인된 것으로 보지 않는다. 연결되지 않았으면 계산 카드와 가상자료 시연만 작동한다.

Gemini: 별도 무료 프로젝트/모델 가용성 확인. 서버가 이미 조회한 공개 NAVER API HUB 자료 및 공개 상품 소개만 전달한다. 최초에는 자체 Google Search grounding 도구를 사용하지 않는다. AI가 최신 자료를 알고 있다고 가정하지 않는다. 공개 검색 결과도 본문 복제 대신 허용된 짧은 내용·URL·관측일을 사용한다.

OpenAI/Claude: 신규 기능 라우팅 대상 아님. OPENAI_ANALYSIS_ENABLED 유지, 무료 제한이나 CLOVA 오류 때 GPT로 자동 전환하지 않는다.

### 초기 운영 한도(개발 설정안)

- 앱 AI 스위치 기본 OFF. 준비된 계정/자료 정책을 확인한 뒤 사용 설정에서 켠다. 페이지 조회/새로고침은 모델 호출 0건.
- CLOVA 파일럿 누적 상한 30,000원(추정 공급자 비용 기준), 일 50회, 동시 1회/사업장. 모든 재시도·질문·비교 시험도 포함.
- Gemini 일 20회, 동시 1회/프로젝트. 공식 무료 쿼터가 더 작으면 그 값을 적용. 무료 한도 초과/등급 불명은 중단.
- 입력 snapshot+질문+정책 합계 최대 UTF-8 24KiB, 출력 상한 1,500토큰(추론 포함 모델이면 합계 상한으로 검증). 최대 요청 예상 비용을 선점한 뒤 호출한다.
- 동일 사업장·scope·질문·snapshot·모델·프롬프트 버전은 결과 재사용. 연속 클릭은 하나의 외부 요청만 만든다.
- 80% 경고, 100%에서 앱 호출 차단. 시간초과로 사용량 미확인이면 예약 비용을 즉시 환급하지 않고 UNKNOWN 상태로 남긴다. 공급자 청구 확인 후 정산한다.
- 화면의 50만 원은 2026-09-14 사용자가 제공한 이미지의 잔액이며 현재 잔액 보장이 아니다. 이미지의 2026-11-30 만료일보다 하루 앞선 2026-11-30 00:00 KST를 잠정 신규 요청 중단 시각으로 둔다. 콘솔 조건 확인 후 조정한다.
- 단가/크레딧 적용 범위/잔액의 확인 시각과 계정 담당자가 입력한 한도를 기록. 계정 잔액 API 제공 여부는 구현 전 확인하며, 없으면 잔액을 실시간이라고 표시하지 않는다.
- 앱 예산은 이 앱의 API 호출만 제한한다. 같은 Ncloud 계정의 다른 서비스가 크레딧을 소모할 수 있으므로 외부 청구 0원을 기술적으로 보장하지 않는다. 계정 사용량 확인 전에는 ‘추가 비용 0원’ 배지를 표시하지 않는다.

## 7. 요청 구조·저장·권한

흐름: Electron renderer → main의 허용 IPC → 사업장 권한 검증 API → 서버 snapshot 계산 → 자료 등급 검사/예산 선점 → CLOVA 또는 Gemini → JSON 검증·근거 참조 검사 → 저장 → 화면.

클라이언트는 reportId·질문·requestId만 전달한다. 모델/URL/금액/snapshot/tenant 권한을 클라이언트 값으로 신뢰하지 않는다. 선택한 tenant는 세션·회원·소유 범위를 매 요청 재확인한다. 응답 완료 시에도 범위·권한을 재확인하고 앱 로그아웃/사업장 전환 뒤 늦은 결과를 폐기한다.

- DATA_CLASS: PUBLIC_MARKET / INTERNAL_AGGREGATE. 고객 이름·연락처·주소·주문번호·메모·개별 주문원문은 snapshot에 포함하지 않는다.
- 집계 원가/매출은 개인정보가 없어도 기밀자료다. INTERNAL_AGGREGATE는 Gemini 무료로 전송 불가.
- 비밀키는 서버 환경/기존 비밀키 저장 구조에만 저장. 앱 JS/ASAR/브라우저에는 포함하지 않는다. 기존 credential 권한 격리를 완화하지 않는다.
- ai_insight_runs: tenant, requester, scope, reportIds, snapshotHash, metric snapshot, promptVersion, provider/model, 상태, 검증 결과, sourceAsOf, generatedAt, usage. 모델의 원문 오류 응답·전체 프롬프트를 일반 로그에 저장하지 않는다.
- ai_usage_reservations: unique requestId, tenant/provider, RESERVED/SUCCEEDED/FAILED/UNKNOWN, 최대비용/실제비용, 토큰, 시각. 공급자 계정 총한도와 사업장 한도를 같은 트랜잭션에서 예약하고 중복을 차단한다. in-memory 카운터만으로 예산을 지키지 않는다.
- 분석 기록과 익명화된 질문은 90일 보관 후 정리, 대화는 같은 snapshot 최대 6턴. 사용자는 기록 삭제 가능. 비용 원장은 본문 없이 180일 보관. 이는 제품 초안 정책이며 법정 보관기간을 뜻하지 않는다.
- 요청 중 권한 만료, 보고서 변경, 버전 변경은 실패/구버전 표시. 이미 공급자에 전달된 요청은 화면 취소만으로 비용이 없어지지 않는다.

## 8. 질문/결과 계약

요청 필드: requestId(UUID), reportIds(1~2), question(500자 이하, 기본 요약이면 빈 문자열), kind(SUMMARY/QUESTION). scope는 1차 NAVER_AD_REPORT로 서버 고정.

서버 snapshot: tenantId, scope, platform, sourceIds, period/currentComparison, metricDefinitions, metrics, findings, dataState, sourceAsOf, exclusions, hash, formulaVersion. 공개 시장용 snapshot은 별도 빌더/계약을 사용한다.

결과: status, runId, snapshotHash, generatedAt, provider, model, cards(최대 5), answer, nextChecks, exclusions, usage.
각 card: findingId, observation, hypothesis, metricRefs, evidenceRefs, nextCheck. 임의 action/tool/function 필드는 거부.

미설정=SETUP_REQUIRED / 실행 OFF=DISABLED / 자료부족=BLOCKED / 일부자료=PARTIAL / 오래된자료=STALE / 정상=READY / 한도=BUDGET_BLOCKED / 무료쿼터=QUOTA_BLOCKED / 시간초과=TIMEOUT / 내용검증실패=INVALID_OUTPUT / 실행중=PENDING. 자료 상태와 실행 상태는 내부 필드로 분리한다.

## 9. 평가·출시 기준

가상/허용 집계 자료 50건: 정상 비교 10, 누락 8, 전기 0/표본 문제 6, 기간/채널 혼합 6, 오래된 보고서 5, 악성 지시·개인정보 5, 범위 밖 질문 5, 비용·실패 5.

필수 통과:
- 수치·단위·기간·채널의 근거 일치 100%, 미확인 값을 0으로 대체 0건.
- 근거 없는 확정 인과 주장·미승인 자동 실행 0건. 중요 오류 1건이면 배포 보류.
- 다른 tenant/로그아웃 뒤 늦은 응답 노출 0건, 무료 Gemini로 내부자료 전송 0건.
- OFF/초과/만료/중복/새로고침/캐시 hit 시 예상 밖 유료 호출 0건. 동시 부하에서도 한도 초과 없음.
- 실제 공급자 허용 시험에서 구조화 응답 유효율 98% 이상. 실패 응답은 노출하지 않는다.
- ‘수정 없이 참고 가능’ 80% 이상을 사용자 검토 목표로 삼고, 1차 결과로 달성 여부를 기록한다. 품질을 이미 달성했다고 주장하지 않는다.
- 응답 목표 중앙값 8초 이하, 95백분위 20초 이하. 인증·snapshot·예약·외부 호출·저장을 합친 총 상한 25초(각 단계는 남은 시간만 사용), 실패 시 기존 지표와 저장 결과 이용 가능. 실제 측정 후 모델/출력 길이 조정.
- Electron 오른쪽 보조 모니터 가시 격리 시험, 밝음/다크, 700/1040/1440 너비, 선택·패널 스크롤·키보드·축소 동작 검증.
- 설치 ASAR 검증·운영 API 응답·공개 업데이트 서명/CURRENT 반복 확인. 실주문 발급/입찰/메일 발송 시험 없음.

## 10. 일정 추정과 시작 조건

담당 개발자 1명, 계정/모델 접근 가능, 원천 보고서 정상이라는 가정의 작업량 추정:
A: 데이터/규칙 1~2일 + 제공자/비용/저장 2~3일 + UI/질문 2일 + 평가/설치/배포 1~2일 = 약 6~9 개발일.
B: 공개자료 Gemini 연결/평가 약 2~3일. C~E는 원장 품질과 사용 결과 확인 후 별도 산정. 달력상 납기 약속이 아니다.

실데이터 모델 호출 전 확인할 조건: CLOVA 이용 조건·크레딧 적용·현재 단가, 사용 모델, 비밀키 저장 위치, 무료 Gemini 프로젝트/모델·쿼터, 자료 출처/갱신 상태. 이 정보 없이도 가상자료로 snapshot·예산·UI를 개발할 수 있다. 내부자료 전송 조건이 충족되지 않으면 그 부분은 OFF로 출시한다.
