# P5-09 후속 — 송장 발급 고정 통신 연결부

[전체 개발계획 및 단계별 현황](./2026-09-07-multi-business-desktop-master-plan.md)

## 이번 구현

`desktop/shipment-transport.cjs`에 Main 프로세스용 통신 adapter를 구현했다. 지난 작업 상태/재시작 복구 코어와 실제 함수 호출로 조합해 접수→조회→완료를 시험했다. 외부 HTTP는 합성 Response를 사용했으며 실제 발급 요청은 보내지 않았다.

- 주소는 기존 하린식품 서버의 `/api/epost/issue`로 고정한다. renderer에서 URL·사업장·세션을 지정하는 인터페이스가 아니다.
- 호스트가 선택한 canonical Cafe24/쿠팡 판매자배송 주문 한 건에만 POST한다. 다른 주문·중복 배열·확인 없는 요청을 거부하고 불필요한 필드를 전송하지 않는다.
- GET은 UUID 요청 번호로만 구성한다. 응답의 주문/작업 일치와 송장 검증은 기존 작업 코어가 담당한다.
- 호스트가 전달한 인증 세션 fetch를 사용하며 cookies include, no-store, redirect error를 고정한다. 자체 로그인·권한 부여 기능은 아니다.
- 응답 64KB, 총 15초, JSON 형식 제한. 401 등 비처리 상태의 원문을 버리고 자동 재시도하지 않는다.
- 호출자 취소와 자체 기한에 응답한다. fetch가 abort를 무시하거나 본문이 끝나지 않아도 호출 대기를 종료한다. 서버 접수 취소를 뜻하지 않는다.

## 검증

통신 모듈 부재로 실패하는 것을 먼저 확인한 뒤 구현했다. 전용 9개와 데스크톱 전체 77개 테스트 통과. 고정 주소·주문 제한·요청 ID·401·잘못된 JSON·정확히 64KB 허용/누적 초과 차단·취소·가상 시계 15초 기한 및 기존 코어 통합을 시험했다.

기존 웹 회귀 테스트 2,548개 통과. 별도 코드 검토에서 확정 결함 없음. 비차단 제안 중 응답 크기 경계 검증을 보강했다. 본문 수신 중 자체 기한 및 취소 후 늦은 응답 정리의 전용 테스트는 추가 보완 대상으로 남긴다. 문법·diff 검사와 전체계획서 링크 검사도 수행했다.

## 적용 범위와 남은 일

**새 EXE 또는 실제 앱 발급 기능 완성이 아니다.** 기존 `connection-policy.cjs`의 조회 전용 네트워크 정책은 변경하지 않았다. `main.cjs`, 로그인 세션, IPC, 확인창, UI 및 패키지 포함 목록 연결이 남아 있다. 이 adapter만 생성한다고 발급 권한이 생기지 않는다.

다음은 호스트가 최신 주문과 인증을 확인하고 명시적 네이티브 확인을 받은 경우에만 이 통신 경로를 허용하도록 연결한다. 로그아웃 시 suspend 및 기존 작업 종료를 기다리는 절차, 진행 화면, 실제 Electron 통합 시험 뒤 새 EXE를 생성한다. 한 작업의 이력 보존과 다음 주문 전환도 함께 검증한다.

신규 유료 자원·실주문 발급·API 키 변경·운영 자료 복사 없음. 사업장 범용 개방은 P1/P2/P3 게이트 이후이며 현재 고정 Harin 연결을 타 사업자용으로 재사용하지 않는다.
