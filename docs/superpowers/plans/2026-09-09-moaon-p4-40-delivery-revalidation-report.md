# P4-40 — 배송정보 조회 이후 발급 조건 재확인

2026-09-09 / 앱 0.26.1

## 운영 확인과 판단

실제 설치 앱의 저장된 인증을 사용해 쿠팡 발급 전 목록을 조회했다. 응답은 READY, total 0이었다. 따라서 출고할 쿠팡 주문을 임의 생성하거나 이미 완료된 주문을 발급 대상으로 바꾸지 않았다.

서버 코드를 대조한 결과, unified-orders의 successfulCoupangReceiverIndex가 성공한 ORDER_DETAIL 큐의 수취인 정보를 통합 주문에 반영한다. 이것은 코드 경로 확인이며 이번 실행에서 운영 쿠팡 상세조회 성공을 증명한 것은 아니다.

## UI·기능 수정

- 주소 추가 조회 후 발급 조건이 아직 충족되지 않은 HUB 경로 주문에 ‘발급 조건 다시 확인’ 버튼을 제공.
- ‘배송정보 조회 완료’와 ‘발급 가능’을 구분하는 안내 표시.
- 버튼은 기존 recheckPage를 이용해 서버 주문을 새로 조회하고 선택 주문을 다시 연다. 발급 요청이나 플랫폼 등록을 보내지 않는다.
- 조회해 표시한 주소로 클라이언트의 발급 자격을 임의 변경하지 않는다.
- 클릭 즉시 비활성화하며, 출고 처리 중에는 실행하지 않는다.
- 다른 주문 선택/연결 변경 뒤의 이전 버튼 실행을 차단한다.

## 검증

- 버튼 부재를 먼저 재현한 뒤 구현 및 UI 검증 통과.
- 시험 UI에서 배송정보 조회만으로 발급이 활성화되지 않고 서버 재확인 후 활성화됨을 확인.
- Main 명령 시험에서 서버 수취인 정보 반영 후 발급 조건 갱신, 다시 정보 누락 시 비활성화 확인. GET만 허용한 시험이다.
- 전체 단위 시험 161/161 통과.
- 배송정보 UI 격리 및 패키지 app.asar 검사, 자동 출고 결과 UI 회귀 통과.
- 패키지 검사는 개발 Electron에서 실행한 시험이다.
- NSIS 0.26.1 빌드 성공.
- 설치 종료 코드 0. 실제 설치 EXE 두 번 재실행에서 로그인 유지 통과(진입 3.160초/2.611초, 측정 시점 값).
- 실제 주문 네 구간과 완료 목록 다음/이전 페이지 조회 통과. 실제 발급·등록 요청은 하지 않았다.
- 설치 앱 표 정렬 오차 0px, 패널 접힘/확장 22프레임, 내용 유지·inert·스크롤바 숨김 검사 통과.

## 미완료 및 다음 단계

운영 쿠팡 상세조회 → 서버 주문 반영 → 발급 전 재검증의 종단간 인수는 대상 주문 부재로 완료하지 않았다. 우체국 실제 발급, 플랫폼 실제 송장 등록, 물리 출력도 이번에 수행하지 않았다.

다음은 발급 대기/결과 불명 작업을 페이지 이동 후 다시 찾는 동선 보완이다. 운영 대상 주문이 생기면 배송정보 조회 경로를 검증하며, 주문 페이지 인수 전에는 다음 페이지로 넘어가지 않는다.
