# P4-36 배송정보·선택 작업 정리 및 우체국 API 점검

## 목적
주문 페이지를 먼저 마무리한다. 웹 UI를 복제하지 않고 기존 주문/배송 API 기능을 앱 전용 UI에 연결한다.

## 이번 수정
- 선택 막대의 주 작업은 `자동 발급·등록` 하나로 강조. 내용 확인/기존 송장 등록은 `추가 작업`으로 접었다. 주문 상세만 열었을 때 불필요한 선택 막대를 표시하지 않는다.
- 배송정보: 받는 분, 연락처, 우편번호, 주소/상세주소, 배송 메모를 상세 패널에 표시한다. 원래 웹의 `DeliveryInfo`와 데이터 필드를 대조했다.
- 기존 서버 주문 DTO의 배송정보를 필요한 6개 문자열만 앱에 전달한다. 추가 원본 필드/토큰은 전달하지 않고 텍스트로 렌더링한다. 로그아웃 시 화면에서 제거한다. 인증정보 저장 방식은 변경하지 않았다.
- Cafe24 배송정보가 없는 경우 웹과 동일한 `GET /api/cafe24/orders/delivery-detail`을 선택 주문에 한해 자동 호출한다. 임의 URL/주문/사업장 인수를 허용하지 않으며 로그아웃·목록 변경 뒤 늦은 응답을 폐기한다.
- 쿠팡은 수집된 배송정보를 표시한다. 정보가 없는 주문의 새 상세 수집 작업은 이번에 추가하지 않았다. 누락을 빈 정상 값으로 위장하지 않는다.

## API 확인 결과
앱 → 기존 `/api/epost/issue` → 고정 IP 워커 `EPOST_LIVE_ISSUE` → `lib/epost/client.js`의 우체국 계약소포 API `api.InsertOrder.jparcel`/`api.GetResInfo.jparcel` 경로를 확인했다. 플랫폼 등록은 기존 `/api/shipping/actions`를 사용한다. 별도 가짜 송장 발급기를 만든 것이 아니다.

- 우체국 관련 서버 자동시험 35/35 통과: 암호화, 발급 API 인증/큐, 현재 주문 재확인, 중복/발급번호, 추적 등. 외부 응답은 시험 대역이며 실제 접수가 아니다.
- 설치 앱의 인증 세션으로 운영 `GET /api/epost/status`: HTTP 200. 최초 기록은 2026-08-13의 오래된 값이라 현재 정상 근거로 사용하지 않았다.
- 송장을 생성하지 않는 `POST /api/epost/status` 설정 점검을 1건 요청하고 그 작업 ID의 GET 결과를 확인했다.
- 새 점검 시각: 2026-09-09 03:42:09 KST. SUCCESS, fixedIp/apiKey/securityKey/contract/encryption/testWrite/liveWrite/tracking 모두 true, readyForLive true.
- 이 점검은 설정·IP·워커 작동 확인이며 우체국 접수 API의 실제 왕복 시험은 아니다.
- 현재 실제 발급 설정이 켜져 있다. 기존 `issueTestShipment`는 실제 발급 설정과 테스트 설정이 함께 켜져 있으면 `EPOST_LIVE_WRITE_CONFLICT`로 중단한다. 이를 우회하거나 운영 설정을 바꿔 테스트하지 않았다.

## 미완료와 다음 작업
자동 발급 흐름의 구현을 실제 출고 인수 완료로 부르지 않는다. 실제 출고 대상으로 우체국 번호 발급 → 해당 플랫폼 등록 → 라벨 출력 확인이 남았다. 주문이 적격하지 않거나 서버 배송정보가 누락되면 계속 차단한다. 화면의 추가 배송정보 조회만으로 출고 권한을 만들지 않는다.

다음은 주문 페이지의 누락 배송정보 수집, 발급 작업 추적/복구, 출력 경로 검증이다. 주문 페이지를 마치기 전 다른 페이지로 넘어가지 않는다. 추가 유료 서비스/DB 복사/운영 비밀키 노출 없음.
