# P4-102 — 선택·건수·상세 가독성 및 캘린더 이벤트

## 적용 범위

- 주문 체크박스에 동일한52px 칸/18px 체크박스를 적용했다. 목록 테두리1px까지 맞춰 헤더와 행의 체크박스가 같은 x좌표에 위치하도록 검증했다.
- ‘현재 페이지 전체선택’ 버튼, 선택/표시 건수, 선택 범위 안내를 노출했다. 부분 선택의 indeterminate 상태와 전체 해제를 유지한다. 전체 서버 주문을 무조건 선택하는 기능이 아니다.
- 단계별 상단에 전체 채널 저장 주문 건수 뱃지를 추가했다. 미조회/실패는 확인 필요, 부분자료는 일부로 표시한다. 조회 시각은 설명에 보존한다. 주문 진입과 등록 완료 후 요약을 갱신한다.
- 주문 상세 폭340/370px, 상품명19px, 본문15px, 구역 제목16/17px로 조정했다. 채널/등록 상태 뱃지와 별도 배송정보 박스를 추가하고, 긴 주소/상품명이 칸을 밀지 않도록 했다.
- 캘린더에서 선택 날짜의 ‘이 날짜에 등록’으로 편집창을 연다. 날짜가 미리 채워지고 일정/메모/이벤트, 여러 날 기간을 입력할 수 있다. 성공 후 창을 닫고 선택 날짜의 일정을 갱신한다.
- 일요일/토요일 색을 분리하고 서버 공휴일의 이름과 색을 표시한다. 공휴일 자료 미확인은 기존 안내를 유지하며 휴일을 임의 추정하지 않는다.
- 이벤트 기간,색상,금액대별 사은품(이상/선택적 이하/이름/수량,최대10구간)을 기존 `/api/calendar/entries`에 연결했다. 단순 일정 생성 시 기간을 강제로 하루로 덮던 문제를 수정했다.
- 이벤트 조회 투영에서 버리던 giftTiers/eventState/eventColor를 보존했다. 달력 날짜에 이벤트 제목을 표시하고 상세에서 적용 상태·사은품 조건을 읽을 수 있다.
- 저장 성공은 응답의 기간/이벤트 종류/색상/사은품 조건 일치를 확인한 뒤 표시한다. 불확실한 결과는 자동 재전송하지 않는다. 저장 후 주문 페이지를 다시 조회해 서버 사은품 계산을 반영한다. 주문 재조회 실패는 저장 성공과 구분한다.

## 웹허브 대조

실제 인증된 `/calendar` 화면에서 월간 일정, 토·일 표시, 추석 공휴일, 일정·메모·이벤트 입력,기간,색상,사은품 이상/이하 구간 UI를 확인했다. 저장 버튼은 누르지 않았다.

`app/_phase28/pages/calendar-page.js`, `app/api/calendar/entries/route.js`, `lib/calendar/calendar-center.js`, `lib/calendar/order-events.js`를 기준으로 기존 서버 이벤트 규칙과 연결했다. 사은품 판정은 적용 날짜/실결제금액에 대해 충족하는 가장 높은 기준 한 개를 선택한다. 클라이언트에서 주문 금액이나 채널별 사은품 결과를 새로 합산하지 않는다.
