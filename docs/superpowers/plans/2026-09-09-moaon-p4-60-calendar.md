# P4-60 캘린더 월간 조회 — 0.47.0

## 이번 구현

기존 웹 캘린더 GET을 앱 네이티브 화면에 연결했다. 서버·DB를 새로 만들지 않았고 웹 화면을 삽입하지 않았다.

- 월간 날짜판, 이전/다음 달, 이번 달 복귀, 새로 조회.
- 한국 날짜 기준 초기 선택. 윤년 2월과 월말 처리.
- 날짜별 일정 건수와 선택 날짜 목록. 월을 가로지르는 일정도 겹치는 날짜에 표시.
- 일정 제목·유형·기간·시간·완료 상태 상세. 날짜 선택과 상세 열기는 추가 요청 없음.
- 현재 앱 폰트·테마·슬림 메뉴 재사용. 큰 날짜 선택 영역, 선택 전체 테두리, 스크롤바 숨김/스크롤 유지.
- 서버 조회 실패·로그아웃 시 이전 일정과 상세 비움.

## 조회와 안전 범위

기존 주문 권한 조회를 먼저 수행한 뒤 월간 캘린더를 GET한다. 월은 2000-01~2099-12 형식만 받으며 해당 월 첫날~마지막 날의 고정 경로만 허용한다. 렌더러 직접 네트워크 요청과 쓰기 동작은 허용하지 않는다.

같은 월 진행 중 요청은 공유하고 다른 월 동시 요청은 실패로 반환한다. UI에서는 조회 중 월 이동을 잠근다. 로그아웃 때 진행 중 요청을 취소하고 늦은 응답을 표시하지 않는다.

응답 일정 500개 이상은 불완전할 수 있어 정상 빈 목록으로 표시하지 않고 조회 실패로 남긴다. 기존 서버가 원천 목록을 제한한 뒤 기간 필터링하는 경우의 전량 조회 보장은 별도 개선 범위다.

## 미완료 범위

일정 본문·공휴일·우선순위·작성/수정/삭제/완료 변경은 아직 미이식이다. 이번 상세는 제목·시간·유형·기간·상태다. 인증된 실제 운영 계정의 월간 일정 대조는 미완료이며 시험용 데이터 화면 검증을 실조회 성공으로 표시하지 않는다.

다음 P4-60B: 일정 본문과 공휴일·자료 누락 상태 연결, 조회 한도 보완. 이후 일정 쓰기는 기존 웹의 검증·권한·오류 처리를 대조한 뒤 별도 시험한다.

## 검증·설치

앱 자동 테스트 269개 통과. 윤년·잘못된 월·월간 기간 겹침·한도·네트워크 허용 범위·IPC 인자/발신자·동일 월 중복 억제·로그아웃 취소를 포함한다.

격리 Electron 화면에서 월 이동·날짜 선택·상세·추가 조회 없음·오류/로그아웃 비움·1040/1440 화면 폭을 확인했다.

- 최종 패키지 캘린더·분석·정산·주문 레이아웃 4종 통과. 개발 Electron에서 실제 app.asar와 임시 프로필/시험 응답을 사용한다.
- Windows 0.47.0 설치 프로그램 종료 0, 설치된 app.asar와 검증 패키지 SHA256 일치.
- 기존 로그인 프로필·쿠키 삭제 없음. 서버 코드/DB 변경 및 새 서버 배포 없음.
