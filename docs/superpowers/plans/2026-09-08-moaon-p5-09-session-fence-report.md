# P5-09 후속 — 전체계획 현황 복구 및 발급 연결 해제 차단

기준 문서: [모아온 전체 개발·검증 계획](./2026-09-07-multi-business-desktop-master-plan.md).

## 전체계획서 갱신

기존 계획서는 삭제되지 않았지만 실행 리스트에 P5 개발 기록이 빠져 있었다. 같은 문서 상단에 P0~P7/B1~B4 현황, 현재 집중 단계, 다음 순서와 최신 보고서 링크를 추가했다. P1-04-17 및 P5-01~P5-09의 앱 버전·작업판·서버 배포·작업 복구 기록을 연결했다.

개별 단계의 구현/시험과 설치/운영 적용을 구분했다. 전체 기능 인수가 끝나지 않은 체크박스를 일괄 완료로 바꾸지 않았다. 이후 매 개발 보고 때 전체계획서도 함께 갱신하는 원칙을 본문에 명시했다.

## 이번 코드 변경

지난 작업 상태 코어에 `suspend()`를 추가했다. 호스트가 연결 해제 전에 호출하는 계약이다.

- 발급 의도를 파일에 저장하는 도중 연결이 해제되면, 저장 완료 후 POST를 시작하지 않는다.
- 통신 중 해제하면 AbortSignal을 전달하고 대기 Promise를 중단한다. 외부 전송기가 abort를 무시해도 늦은 응답을 새 상태로 적용하지 않는다.
- 해제된 컨트롤러의 snapshot/submit/poll은 주문·요청 ID가 없는 DISCONNECTED 상태를 반환한다.
- 기존 기록은 삭제하지 않는다. 재인증 후 새 컨트롤러가 알려진 요청은 GET으로 확인하고 결과 불명 작업은 재발급하지 않는다.

**중요:** 네트워크 중단은 서버에 이미 접수된 송장 발급의 취소가 아니다. 호스트는 기존 작업 종료를 기다린 후 새 컨트롤러를 만들어야 한다. 이 호스트 연결·로그아웃 IPC 통합은 아직 남아 있다.

## 검증 및 적용 범위

추가 3개 테스트의 실패를 먼저 확인한 뒤 구현했고, 데스크톱 전체 68개가 통과했다. 저장 중 해제, 응답 없는 POST 중 해제, 알려진 작업의 재연결 조회를 합성 응답으로 시험했다. 실제 고객 주문/개인정보/외부 발급은 사용하지 않았다.

기존 웹 회귀 테스트도 이번 실행에서 2,548개 모두 통과했다 (`node --test --test-concurrency=4 'test/**/*.test.js'`). 전체계획서의 로컬 문서 링크 60개가 모두 존재함을 확인했다. 문법 검사와 diff 공백 검사도 통과했다.

변경은 내부 코어와 문서이며 EXE 버전은 0.10.0을 유지한다. 새 설치파일을 만들거나 운영 UI/API를 배포한 것은 아니다. 이번 시험 수는 앱 전체 기능 완성률이 아니다.

## 바로 다음에 남은 일

1. Main 호스트의 인증된 사업장·단일 작업·연결 해제 수명주기와 코어 연결.
2. 고정 API 통신·최신 주문 확인·명시적 발급 확인창 및 진행 UI 연결.
3. 실제 Electron에서 로그아웃/재시작/통신 장애/중복 클릭 통합 검증.
4. 새 EXE 생성·패키지 실행 검증. 실제 주문 발급과 프린터는 별도 확인 후 검증.

P5-09 전체 완료 또는 타 사업장 실사용 개방으로 표시하지 않는다. 신규 유료 리소스·운영 데이터 복사·API 키 변경 없음.
