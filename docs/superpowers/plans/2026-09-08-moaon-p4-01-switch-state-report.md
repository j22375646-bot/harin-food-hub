# P4-01 사업장 전환 응답 보호 기반

## 이번 범위

전체 계획 P4에 명시된 `mayApplyResult` 계약과 전환 상태 관리 모듈을 구현했다. 하린식품→다른 사업장→하린식품으로 돌아오더라도 첫 방문 때 요청한 응답은 반영하지 않는다. 선택 세대를 증가시키고 이전 요청에는 AbortSignal 취소를 전달한다. 취소를 무시하고 완료되는 작업도 응답 반영 검사에서 거부한다.

로그아웃에 해당하는 clear는 현재 사업장을 제거하고 이전 요청을 무효화한다. 사업장 없는 요청 생성과 잘못된 ID는 거부한다. 같은 사업장을 재선택해도 이전 방문 응답을 무효화한다. 취소 이벤트가 동기 실행될 때도 이전 상태가 유효하게 보이지 않도록 새 상태를 먼저 반영한다.

## 적용 범위와 한계

신규 파일은 `lib/tenancy/switch-state.js`, `test/tenancy-switch.test.js`다. 이번 모듈은 아직 운영 화면의 consumer에 연결하지 않았다. 따라서 기존 앱 UI가 달라지거나 실제 다사업장 전환이 가능해진 것은 아니다. 이 모듈은 화면 응답의 최신성 검사이며 서버 인증·멤버십·DB 격리를 대체하지 않는다. 화면 선택값을 권한으로 사용하면 안 된다.

P4 전체 완료, G4 인수 완료로 표시하지 않는다. 새 EXE 생성·운영 DB 변경·외부 API 쓰기·유료 자원 생성은 수행하지 않았다. 현재 설치본은 이전 단계의 0.15.1을 유지한다.

## 검증

모듈이 없는 상태에서 신규 시험 실패를 확인한 후 구현했다. 신규 7개 시험 통과: 다른 사업장, A→B→A, 누락/잘못된 상태, 로그아웃, 같은 사업장 재선택, 실제 비동기 늦은 완료, 동기 취소 이벤트 경합. 시험은 로컬 합성 사업장 식별자로 실행하며 운영 주문을 읽거나 복사하지 않는다.

## 다음 기능 단위

서버가 검증한 사업장 목록을 사용하는 선택 화면과 이 모듈을 연결하고, 전환 시 선택 주문·상세·검색·진행 작업 표시를 정리하는 통합 흐름을 구현한다. 연결되지 않은 사업장은 연결 필요로 표시하며 하린식품 자료를 기본값으로 복사하지 않는다. 신규 실사업장 개방은 P1/P2/P3 인수 조건을 충족한 후 진행한다.
