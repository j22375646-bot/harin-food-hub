# P5-09 1차 — 출고 확인 작업판 / 모아온 0.9.0

## 이번에 적용한 것

PC 앱의 주문·배송 오른쪽 상세 하단에 **저장 주문 다시 확인** 버튼을 추가했다. 현재 페이지를 다시 읽고 같은 주문이 있으면 상세를 복원한다. 확인 시각도 표시한다. 첫 페이지로 돌아가서 주문을 다시 찾을 필요 없이 현재 페이지에서 확인할 수 있다.

재확인 중에는 이전 주문과 확인 결과를 비운다. 서버에서 목록 변경, 인증 실패, 조회 실패를 알리면 이전 결과를 계속 보여주지 않는다. 확인이 성공하더라도 발급 승인이 아니라 **서버 저장 자료를 다시 읽은 결과**이다. 외부 채널을 즉시 동기화하거나 송장을 발급하는 기능은 아니다.

## UI 변경

- 주문 페이지 제목을 PC 작업용 크기로 정리하고 상세 영역을 넓혔다.
- 상세 본문과 재확인 작업판을 분리했다. 상품 정보를 스크롤해도 버튼과 확인 시각은 하단에 남는다.
- 취소·기존 송장 등 제외 사유는 경고색, 별도 플랫폼 처리 경로는 파란색, 정보 부족은 주의색으로 구분했다.
- 선택 주문은 전체 배경과 테두리로 구분한다.
- 라이트·다크 모드와 작은 PC 창에서도 버튼이 화면 밖으로 밀리지 않는지 확인했다.
- 설정 화면에 로그인 세션 유지가 반영되도록 안내 문구를 바로잡았다.

기획/디자인 스킬은 기존 앱의 색상·타이포그래피를 유지하면서 고정 작업판과 정보 우선순위를 정리하는 데 사용했다. 실제 주문 자료, 인증 경로, 채널 분리 원칙은 바꾸지 않았다.

## 검증

- 데스크톱 단위 테스트 45/45 통과.
- 기존 허브 종합 테스트 최종 2,541/2,541 통과.
- 첫 종합 실행에서는 변경하지 않은 tenant-step-up-storage 테스트가 실패했다. 해당 파일 단독 실행 26/26 및 전체 재실행 2,541/2,541 통과. 최초 실패 원인이 이번 변경이라고도, 단순 부하라고도 단정하지 않는다.
- 격리 Electron에서 실제 IPC·UI를 통해 서버 저장 자료 재조회, 동일 주문 복원, 409 목록 변경 시 기존 결과 폐기 확인.
- 설치 EXE에서 같은 재확인 시험과 상태별 조회, 공식 로그인창의 빈 제출 경로 확인. 빈 제출은 전송 전에 취소하여 실제 비밀번호/주문 쓰기를 사용하지 않았다.
- 재확인 작업판을 1040×720 / 1920×1080 / 1440×960 및 라이트·다크로 검사. 가로 넘침 없음, 상세 본문 스크롤 공간 유지, 버튼 화면 내 배치 확인.
- 기존 상세·로그인 세션 유지 시험 통과.
- 코드 리뷰: 중요/치명 이슈 없음. 401/403 상황의 재확인 UI 전용 테스트 추가는 비차단 보완 항목이다. 기존 오류 처리와 Main 테스트는 유지한다.
- 실행 소스 8개와 app.asar 바이트 일치. 설치본과 빌드본 app.asar 해시 일치.

모든 주문 시험 자료는 합성 자료이다. 실제 주문에 대한 발급 성공 또는 채널 실시간 검증으로 해석하지 않는다.

## 다음 개발 — P5-09 2차

P5-09 전체 출고 연결은 아직 완료되지 않았다. 다음에는 실제 출고 직전의 서버 재검증과 명시적 실행 확인을 연결한다. 최신 취소/송장 이력, 채널별 담당 경로, 중복 요청, 부분 실패, 재시도 기록을 검증한 뒤 발급 실행을 열어야 한다. 이번 재확인 결과를 실행 권한이나 승인 토큰으로 재사용하지 않는다. 앱 UI에는 실행 대상과 제외 이유, 처리 중/완료/실패를 명확히 나누는 작업 흐름을 이어 붙인다.
