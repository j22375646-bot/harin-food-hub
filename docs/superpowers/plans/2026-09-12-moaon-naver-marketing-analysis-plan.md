# 모아온 네이버 광고 분석 고도화 구성안

상태: 사용자 구현 승인 후 P4-123 / 0.109.0에서 1차 적용했다. 기간별 광고 계산·차트·캠페인/키워드 조회·규칙 진단·서버 예약을 구현했고, 2026-08-31~09-06 보고서 1건을 실제 DB에 생성했다. 아래 항목 전체의 완료를 뜻하지 않는다. 새 예약의 첫 운영 실행, AI 제공자 연결·평가, 검색어/상품/원가/재고 통합 진단과 행동 추적은 후속 범위다. 구체적 증거는 [P4-123 기록](./2026-09-12-moaon-p4-123-marketing-analysis.md)을 따른다.

## 최우선 원칙 · 자동화와 무료 우선

사용자 명시 요구: 모든 업무는 자동화를 목표로 설계한다. 수집 버튼·분석 버튼·보고서 버튼을 매번 누르게 하는 것을 기본 흐름으로 삼지 않는다. Gemini와 Hermes 등 다른 AI도 검토하며 가능하면 무료로 운영한다.

- 서버 예약 → 광고/업무 자료 수집 → 완전성 검사 → 계산/차트 자료 갱신 → 규칙 진단 → 선택한 AI 설명 → 주간 보고서 저장 → 모아온에서 결과/예외 확인을 하나의 파이프라인으로 구성한다.
- AI를 호출할 때마다 원천 수집을 다시 하지 않는다. 같은 자료·계산식·프롬프트 버전이면 저장 결과를 재사용한다. 두 PC에서 앱을 열어도 한 번만 실행한다.
- 수집 실패는 지수형 재시도·중복 실행 방지·실행 제한시간으로 처리한다. 일부 실패와 전체 실패, 아직 실행 전을 구분하고 마지막 정상 결과의 날짜를 유지한다.
- 기본 수치 보고서는 AI 없이도 자동 완성한다. AI 한도 초과/장애는 설명만 지연시키며 규칙 진단을 AI 결과라고 표시하지 않는다. 사용자는 문제 해결이나 실제 업무 판단이 필요한 경우만 개입한다.
- 주간 생성·후속 전환 재수집·수정 보고서·실행 과제 재평가도 예약 작업으로 묶는다. 광고 설정 자동 변경은 별도의 범위·조건 설정이 필요한 확장 단계다.
- 신규 외부 AI는 무료 한도 내에서 우선 검증하고 유료 모델로 자동 전환하지 않는다. 모델·제공자 허용 목록, 요청/토큰 상한, 제한적 재시도, 비용0 정책을 서버에서 검사한다. 무료 할당량이 부족하면 대기/규칙 보고서를 제공한다. 기존 서버·DB 비용까지0이라고 보장하지 않는다.

| 후보 | 활용 방향 | 제약과 도입 기준 |

2026-09-12 공식 문서를 조회했다. 모델 자체(Qwen, Llama, Gemma, Hermes, gpt-oss 등), 모델을 API로 제공하는 서비스(Groq, Cerebras 등), 도구 실행 에이전트(Hermes Agent)를 구분한다. 오픈 모델 라이선스가 무료 추론 서버를 제공한다는 뜻은 아니다. 아래 적합도는 도입 우선순위 판단이며 실제 한국어 성능 시험 결과가 아니다.

권장 검증 순서: Groq와 Cloudflare에 동일한 가상 사례20개를 넣어 한국어 설명·근거 일치·JSON 형식·대기시간을 비교한다. 구매0, 자료누락, 저표본, 전환기간 불일치, 고ROAS/저마진, 고ROAS/재고부족, 프로모션 동반 변화 등을 포함한다. 선택은 모델 명성이나 다수결이 아니라 수치 왜곡/근거 없는 주장/판단 보류 준수 결과로 한다. 이후 Cerebras·Gemini·OpenRouter의 허용 모델을 필요한 역할에만 추가한다.

자동 실행은 검증된 주력1개와 정책을 충족하는 예비1개로 시작한다. 모든 보고서를 여러 AI에 중복 전송하지 않는다. 원천 계산과 보고서 저장은 서버에서 진행하고, AI는 신규 자료에 대한 설명만 작성한다. 무료 할당량 소진 시 유료 전환 없이 제한적 재시도·대기·규칙 보고서를 사용한다. AI가 잠시 없어도 자동 보고서가 멈추지 않는 것을 완료 기준으로 둔다.

## 목적과 1차 범위

매주 광고비를 어디에 쓰고 있는지, 성과 변화의 근거가 무엇인지, 다음 주 무엇을 바꿔볼지 판단하는 마케터의 작업 공간을 만든다. 우선 검색광고·쇼핑검색광고를 가정한다. GFA 포함 여부는 사용자 답변에 따라 별도 연결 범위로 확정한다. 네이버 전환매출과 주문 전체 매출을 혼합하지 않는다.

## 현재 코드에서 확인한 기반

- `lib/dashboard/workspace-insights-loader.js`: 최신 네이버 주간 보고서 최대20개 조회.
- `lib/tenancy/workspace-insights-summary.js` / `desktop/insights-transport.cjs`: 앱에는 축약한 매출·이익·변화·원인·행동·보고서 상세만 전달. 신선도는 별도 확인이 필요하다.
- `lib/reports/weekly.js`, `naver-owner-insight.js`: 서버 계산, 캠페인/키워드 진단, 비교 조건, 표본 신뢰도, 보고서 버전 저장 기반.
- `lib/automation/report-scheduler.js`, `app/api/cron/weekly-report/route.js`, `vercel.json`: 월요일 KST07:30 주간 생성 코드가 있다. 모든 채널 생성 및 기존 알림 경로를 포함하므로 네이버 기능 작업 중 전체 채널 예약을 무심코 바꾸지 않는다.
- `lib/ai/foundation.js`, `openai-client.js`, `schema.js`: 구조화 설명·중복 호출 방지·서버 실행 설정 기반. 현재 운영 키/활성 상태/최근 성공은 아직 확인하지 않았다.

## 화면 구성

상단은 기존 Daybook 공통 상단·로고·뒤로가기를 유지한다. 분석 페이지 내부는 네이버 광고를 기본으로 하고 `성과 분석 / 주간 보고서 / 실행 기록` 3개 탭으로 정리한다. 설정은 별도 작은 버튼에서 연다.

### 성과 분석

1. 기간·직전 동일 기간·광고 유형·캠페인 필터, 마지막 수집 시각과 기간 수집률.
2. 핵심6개: 광고비, 구매 전환매출, 구매 전환수, ROAS, 구매 CPA, CVR. 클릭·노출·CTR·CPC는 펼쳐 확인한다.
3. 일별 광고비/전환매출 그래프와 ROAS 추이. 축·원/퍼센트·기간을 명시하고 누락일은 선을 끊는다. 서로 다른 단위는 독립 축이나 별도 그래프로 표현한다.
4. 변화 원인: 노출→클릭→구매→객단가 단계에서 어떤 지표가 변했는지 보여준다. 지표의 동반 변화는 관찰 사실로, 상세페이지/경쟁/계절성 등 입증되지 않은 이유는 가설로 표시한다.
5. 캠페인/광고그룹/키워드 상세: 비용, 전환, 매출, ROAS, CPC, CTR, CVR, 신뢰도, 전주 대비. 확대 검토/유지/개선 검토/관찰로 분류한다. 키워드 없는 쇼핑 유형에는 해당 차원 없음으로 표시한다.
6. 검색어 개선 후보: 무전환 고비용, 전환 우수, 등록 검토. 실제 수집 가능 차원부터 사용하며 검색어 자료 미수집을 빈 성과로 처리하지 않는다.

- 사장님용 간단 요약과 실무자용 근거 펼치기를 제공한다. 인쇄/PDF와 기존 주차 보관함을 연결한다.
- 기본 희망안은 월요일09:00 생성이나 기존07:30 예약이 있으므로 답변 확인 후 통합한다. 앱이 꺼져 있어도 서버가 생성하고 두 PC에서 같은 저장 보고서를 읽는다. 외부 메일/메신저 전송은 별도 사용자 요청 범위다.
- 계정+기간+보고서 유형+자료 버전 기준으로 중복 생성을 방지한다. 실패는 마지막 정상 보고서를 보존하고 원인을 표시한다. 지연 전환 재수집으로 내용이 바뀌면 수정본으로 남긴다.

### 실행 기록

권고별 대상·근거·담당·실행일·변경 전 값·성공 기준·재평가일을 저장한다. 사용자가 실행한 변경 이후 동일 요일 기간으로 추적하되 프로모션/품절/예산 변경을 함께 표시한다. 관찰된 개선을 광고 변경의 인과 효과로 단정하지 않는다. 초기 버전은 광고 예산·입찰·중지 자동 변경을 포함하지 않는다.

## 자동 계산 계약

| 지표 | 계산 | 조건 |
|---|---|---|
| CTR | 클릭 / 노출 ×100 | 노출0이면 계산 불가 |
| CPC | 광고비 / 클릭 | 클릭0이면 계산 불가 |
| 구매 CVR | 구매 전환 / 클릭 ×100 | 전체 전환과 구매 전환을 분리 |
| 구매 CPA | 광고비 / 구매 전환 | 구매0이면 계산 불가; 무전환 지출은 별도 경고 |
| Paid ROAS | 광고 귀속 구매매출 / 광고비 ×100 | 광고비0이면 계산 불가 |
| 광고 전환 객단가 | 광고 귀속 구매매출 / 구매 전환 | 주문 전체 객단가와 구분 |
| 전주 증감 | (이번 주-전주) / 전주 ×100 | 전주0이면 신규/비교불가; 퍼센트 지표 차이는 %p도 표시 |
| 손익분기 ROAS | 100 / 광고 전 공헌이익률(소수) | 원가·수수료·포장·부담배송·할인 근거와 세금 기준이 맞을 때만 |
| 목표 CPA | 구매1건당 광고 전 공헌이익-목표 잔여이익 | 구매 구성이 연결되고 원가가 유효할 때만 |

기간별 비율은 일별 비율의 평균이 아니라 원천 분자·분모 합계로 계산한다. 한국 날짜, VAT 포함 여부, 취소/환불 반영 여부, 전환 집계 기준과 기간을 명시한다. API 필드명 대신 검증된 의미로 매핑한다. 상품별 수익률 없이 기존 고정 ROAS 기준을 모든 상품의 손익분기점처럼 사용하지 않는다.

## AI 분석 계약

- 금액·비율·순위 계산은 서버 함수가 담당하고 AI에는 계산 완료 자료와 근거 ID를 전달한다.
- 결과는 관찰 사실 / 가능한 원인 / 제안 / 검증 방법 / 표본·자료 제약으로 구조화한다.
- 제안마다 대상과 실제 수치 근거를 연결한다. 자료에 없는 경쟁사 변화·소재 문제·검색량 감소를 사실처럼 작성하지 않는다.
- 주문자 개인정보는 전달하지 않는다. 캠페인명·검색어 등 원천 문자열은 분석 자료로만 취급한다.
- API 키는 서버 보관. 생성 중/미설정/한도/실패와 규칙 기반 진단을 구분한다. 같은 자료 재조회는 저장된 AI 결과를 재사용하고 주간 호출·토큰 비용 상한을 설정한다.
- AI 실패 시 수치 보고서와 계산 결과는 계속 사용할 수 있어야 한다.

## 구현 순서와 완료 조건

1. **데이터 검증·계산 계약**: 실제 연결 상태, 최근14일 수집 범위, 원천 전환 정의, 비용 세금 기준, 네이버 화면과 표본 대조. 분모0·자료누락·가중집계·KST경계·구매/전체전환 시험.
2. **성과 분석 페이지**: 검증된 지표·차트·캠페인 상세·기간 비교·자료상태를 서버와 Electron에 연결. 기존 읽기 계약은 호환 유지. 4개 창 너비와 테마·빈 자료·긴 상품명 점검.
3. **주간 자동 보고서**: 기존 예약/버전 저장 통합, 중복 방지·실패 재시도·잠정본/수정본·보관함·인쇄. 테스트 시 기존 외부 알림 발송을 호출하지 않는다. 운영 실행 이력까지 확인해야 자동화 완료다.
4. **AI와 실행 추적**: 기존 구조화 AI 연결, 근거 검증·비용 제한·저장/재사용·수동 재분석, 실행과 재평가. 실제 AI 호출 성공과 앱 표시까지 확인해야 AI 적용 완료다.

단계별 서버 검증·앱 패키지 시험·배포 결과를 분리해 기록한다. 현재 문서는 구성안이며 새 분석 기능이나 예약을 배포한 상태가 아니다.

### 차트별 질문과 동작

1. **일별 성과 추이**: 광고비와 전환매출(원)을 함께 비교하고 ROAS(%)는 별도 정렬 그래프로 보여준다. 기간 선택·전주 겹쳐보기·날짜 클릭→해당 캠페인 필터·툴팁/키보드 상세·원본 표를 제공한다.
2. **전환 단계 비교**: 노출→클릭→전환의 각 수치와 전주 변화를 나란히 표시한다. 구매 전환이 확인된 경우에만 구매라고 쓴다. 고유 방문자 퍼널이나 동일 사용자 여정으로 오해시키지 않는다.
3. **비용×효율 산점도**: 가로 광고비, 세로 ROAS, 점 크기 전환수. 캠페인별 목표선과 표본 상태를 표시한다. 점 클릭→상세 근거와 최근 변화. 낮은 표본을 바로 중지 대상으로 분류하지 않는다.
4. **광고비 집중도 막대**: 캠페인별 지출/귀속매출 상위N과 기타를 표시한다. 일부 조회분이면 전체 비중으로 표시하지 않는다. 수익성과 재고까지 확인해야 확대 추천이 가능하다.
5. **요일×시간대 히트맵**: 지원 자료 수집 후 비용·전환·CVR을 바꿔 볼 수 있다. 자료 없음과 실적0을 다른 패턴으로 표시한다. 확인 전 빈 모양만 채운 차트를 노출하지 않는다.
6. **상품별 이익 구조**: 원가 연결이 유효한 상품에 한해 매출→할인·수수료·배송·포장·광고비→추정 공헌이익을 폭포형 차트로 표시한다. 자료가 부족하면 확인할 비용 목록을 대신 보여준다.
7. **재고와 광고 효율**: 남은 판매 가능 구성 수량/최근 판매 속도/광고 효율을 함께 보고 품절 위험·생산 검토 대상을 정한다. 여러 채널이 공유하는 재고라는 근거를 표시한다.
8. **예산 집행 추이**: 누적 지출, 사용자 목표선, 현재 속도 유지 시 월말 예상치를 실제 구간과 점선 추정 구간으로 분리한다.

주요 추이·변화·실행3개를 첫 화면에 배치하고 세부 차트는 각 분석 탭에서 연다. 동일 필터를 유지하며 차트 클릭과 목록·상세를 연결한다. 모든 차트에 단위·기간·근거·수집 상태를 제공하고 색만으로 상태를 전달하지 않는다. 좁은 화면에서는 글자를 줄이지 않고 그래프와 표를 재배치한다.

### 검증 과정에서 발견한 선행 수정 항목

- `lib/naver/sync.js`의 `syncStats`에는 누락값을 `num(...)||0`으로 저장하는 부분이 있다. 미수집/잘못된 값과 실제0을 구분하는 정규화 및 수집 상태부터 정리해야 한다.
- 네이버 공식 통계 FAQ에서 `ccnt`는 일반 전환수, `convAmt`는 전환매출, `salesAmt`는 총비용이다. 구매만 집계된 근거가 없는 자료를 구매수/구매 CPA로 표시하지 않는다.
- 검색어 수집·입찰 분석 등의 기존 POST는 조회처럼 보여도 API 호출과 DB 기록을 수행한다. 화면 렌더링 시 모두 호출하지 않고 서버의 읽기 집계 경로를 구성한다. 수집은 별도 작업으로 중복 방지·주기·부분 실패를 관리한다.
- API의 상세 분해 데이터는 광고 유형마다 지원 범위와 보관 기간이 다르므로, 장기 분석을 위해 지원되는 일별 스냅샷을 축적해야 한다. 모든 차원을 한 번의 API 요청으로 얻는다는 전제는 두지 않는다.
- 검색 추이는 상대지수다. 광고 실적과 함께 볼 수 있지만 광고 API가 제공하는 절대 검색수나 실제 구매수처럼 표시하지 않는다.
