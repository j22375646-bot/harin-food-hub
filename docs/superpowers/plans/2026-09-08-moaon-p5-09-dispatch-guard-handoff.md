# P5-09 2차 선행 작업 — 실제 발급 직전 재검증

## 범위와 현재 상태

Windows 앱에 발급 실행을 연결하기 전, 기존 고정 IP 작업 서버의 발급 직전 안전 검사를 보완했다. 코드와 테스트 변경이며 **운영 worker 배포는 아직 확인하지 못했다**. PC 앱은 0.9.0 그대로다. 실행 확인 UI와 실제 발급 연결은 아직 완료하지 않았다.

## 발견한 문제와 수정

기존에는 발급을 요청할 때 주문을 확인하지만, 큐에서 대기한 후 worker가 실행할 때 최신 저장 주문의 취소·송장 상태를 다시 검사하지 않았다. 이제 HUB_ORDER 발급 직전에 다음을 확인한다.

- 요청 주문과 현재 주문의 플랫폼·주문번호·배송묶음이 일치하는가.
- 취소·반품 요청이나 배송 진행 상태가 아닌가.
- 기존 발급/등록 송장이 없는가.
- 판매자배송이며 서버 출고 자격과 송장 이력이 확인됐는가.
- 해당 채널과 필요한 보조 자료 조회가 성공했는가.

자료가 없거나 조회에 실패하면 허용하지 않는다. 오류 메시지는 고정 문구를 사용하며 개인정보나 원문 응답을 노출하지 않는다.

코드 리뷰에서 Cafe24 주문 item, Coupang 반품·주문 상세 조회 실패가 빈 자료로 처리되는 누락을 발견했다. 발급 전용 strict loader를 추가해 정규화 전에 이를 차단했다. 일반 목록의 부분 표시 동작은 변경하지 않았다. HUB_ORDER 외 기존 입고 등의 발급 흐름도 이번 변경에서 유지했다.

## 검증

최종 전체 테스트 2,546개 모두 통과(실패·건너뜀 0). `git diff --check` 통과.

관련 28개 테스트 통과. 실제 worker 함수의 발급 호출 앞에 검증이 실행되고 취소 시 운송사 호출이 0회임을 합성 의존성으로 확인했다. 실제 loader에 DB 오류를 넣어 Cafe24 item·Coupang 반품·ORDER_DETAIL 조회 실패가 차단됨을 확인했다. 최초 구현에서 이 실패 경로를 재현한 뒤 수정했다. 독립 코드 리뷰 재검토에서 추가 중대 발견 없음.

실제 채널을 새로 수집하거나 송장을 발급하지 않았다. 검증은 **서버 저장 상태 재검증**이다. 외부 채널에서 취소된 직후 아직 수집되지 않은 상태까지 해결하는 실시간 검증은 아니다.

## 배포 조건과 다음 단계

확인된 service 설정은 `harin-coupang-worker`, 작업 경로 `/opt/harin-food-hub/current`이다. 현재 환경에서 AWS CLI와 구성된 SSH 대상/배포 연결을 찾지 못했다. Git 변경만으로 worker 적용을 주장하지 않는다. AWS EC2 연결 후 실행 중 작업을 확인하고, 작업 도중 강제 종료하지 않는 절차로 배포한 뒤 실행 리비전·서비스 상태·heartbeat를 확인해야 한다.

그 다음에 앱의 명시적 실행 확인, 요청 접수/진행/완료/결과 불명 상태 표시를 연결한다. 응답 유실이나 결과 불명은 자동 재발급하지 않고 기존 작업번호와 운송사 이력을 대조해야 한다. 이 조건을 확인하기 전에는 앱 발급 버튼을 활성화하지 않는다.
