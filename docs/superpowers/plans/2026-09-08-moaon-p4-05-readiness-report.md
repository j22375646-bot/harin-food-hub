# P4-05 운영 연결 준비 상태 점검

## 확인 결과

이번 단계는 운영 연결의 선행 조건 점검이며 새 기능 구현 완료가 아니다.

- 로컬 환경 파일에서 SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, 기존 DASHBOARD_PASSWORD 설정 이름을 확인했다. 값은 출력하지 않았다.
- 로컬 파일/현재 프로세스 환경에서는 다사업장용 제한 PostgreSQL 연결 설정을 찾지 못했다. 배포 서버 환경까지 조사한 결과는 아니다.
- 기존 설정의 Supabase REST에 HEAD 요청으로 public.dashboard_users의 전체/활성 프로필 수를 확인했다. 둘 다 HTTP 200, 1개다. 세션 테이블 역시 HTTP 200으로 접근 가능했다.
- 최초 프로필 점검은 잘못된 id 컬럼을 지정해 400이었다. 기존 스키마의 user_id로 수정하여 성공했다. 400을 권한 장애로 판단하지 않았다.
- Supabase 관리 도구의 프로젝트 목록 조회는 Internal error로 실패했다. 이 결과만으로 서비스 장애나 토큰 만료를 단정하지 않는다.
- 현재 control-role.sql은 후보 SQL이며 자동 운영 적용 금지, NOLOGIN 시작이 명시되어 있다. 운영에 해당 역할이 존재하거나 로그인 가능한지는 확인하지 못했다.

## 이번에 하지 않은 일

운영 DB 권한 변경/역할 생성, 비밀번호 설정, 기존 사용자 소유자 매핑 변경, 회원/세션 삭제, API 활성화, EXE 교체 없음. 기존 관리자 service-role을 다사업장 DB 연결 대신 사용하지 않았다. 비밀키나 사용자 이메일·토큰을 출력하지 않았다.

프로필 1개 존재는 다사업장 가입 준비 완료나 auth.users/멤버십 전체 매핑 검증을 의미하지 않는다. private 제어 스키마는 REST 노출 여부로 존재를 추정하지 않았다.

## 실제 연결 전에 필요한 작업

### 후속 확인: 웹 관리 콘솔 접근 성공

관리 도구 재시도는 Connection failed였지만 MCP 서버 주소의 무인증 응답은 HTTP 401이었다. 주소 응답 가능과 인증된 관리 도구의 정상 연결은 다르다. 웹 콘솔은 로딩 후 정상 접근했고 프로젝트 Healthy 상태를 확인했다. 초기 Checking/Unknown/0건 표시는 로딩 중 값이었으며 실측 결과로 사용하지 않았다.

운영 프로젝트 Database → Roles의 전체 목록에서 `moaon_control_app`을 찾지 못했다. 표시된 Other database roles는 postgres와 supabase_privileged_role이었다. 조회 필터는 비어 있었다. 이는 웹 목록 확인이며 SQL 카탈로그 직접 검증은 아직 미실시다. private 제어 스키마 존재도 아직 확정하지 않았다.

따라서 웹 콘솔 재로그인은 현재 필요하지 않다. 다음은 읽기 전용 카탈로그 점검 후 필요한 제한 역할/제어 스키마 구성이다. 운영 접근 권한을 추가하는 작업은 대상·범위를 확인받고 진행한다. 역할 생성·GRANT·자격 증명 변경은 이번에 실행하지 않았다.

관리 화면: https://supabase.com/dashboard/project/llnlphdmcmwgjnpndaam/database/roles

1. Supabase 관리 연결을 복구하거나 관리 콘솔에 접근해 private 제어 스키마와 제한 역할의 현재 상태를 읽기 전용으로 확인한다.
2. 운영 적용용 권한/자격 증명 제공 경로를 확정한다. 후보 SQL을 그대로 자동 적용하지 않는다. 필요한 운영 역할 변경은 정확한 대상과 권한 범위를 제시한 뒤 진행한다.
3. 검증된 제한 연결 정보를 서버 비밀 설정으로 제공하고 사용자 프로필·Auth 계정·사업장 멤버십을 대조한다. 비밀값은 채팅에 보내지 않는다.
4. 구성 검증 후 P4-04 서비스를 route에 주입하고 사업장 선택 UI를 연결한다.

현재 route는 SETUP_REQUIRED 유지, 앱은 0.15.1 유지다. 추가 유료 자원을 생성하지 않았다.
