# 모아온 UI 방향 · 페이지별 실행 계획

## 공통 기준
- 목적: 운영자가 상태를 파악하고 필요한 업무로 바로 이동한다. 숫자 장식/가짜 추세/샘플을 운영 성공으로 보여주지 않는다.
- 기존 Pretendard를 유지한다. 제목28px/섹션20px/본문14~15px/핵심 금액26px 이상. 주요 버튼44px. 숫자는 고정폭 숫자, 설명은 충분한 행간.
- 색: 바탕#f5f4fa,면#ffffff,본문#292835,보조#767286,강조#7761b9,정상#267664. 기존 라이트/다크 토큰으로 동일 구조를 유지한다.
- 구조: 제목+기준 시각 → 우선 확인할 업무 → 주요 시각화 → 목록/상세. 고정된 필터 위치, 행동 버튼 위치, 전체 테두리 선택 표시.
- 동작: 페이지240ms/컨트롤160ms. reduced-motion은 끈다. 로딩은 자료 없음/실패와 구분하며 가짜 진행률/가짜0을 넣지 않는다.
- 그래프는 무엇을 비교하는지/기간/부분자료 여부를 함께 표시하고 관련 목록으로 연결한다. 값이 불명확하면 비율/추세를 만들지 않는다.

## 로딩/성능
- 현재 오늘 금융·일정·업무는 독립 호출되고 주문4상태는 Promise.all로 병렬 조회된다. 불필요하게 다시 병렬화하지 않는다.
- 기존 재방문 조회 억제와 중복 요청 차단을 유지한다. 첫 적용은 로딩 틀과 페이지별 스크롤 복원이다.
- 서버 응답시간 단축은 아직 입증하지 않았다. 이후 시작/응답/렌더 시각을 분리 측정하고 실제 병목에만 캐시/응답 축소를 적용한다. 권한/금융 데이터 캐시를 임의로 공유하지 않는다.

## 첫 적용의 한계
- 이번 변경은 오늘 및 공통 전환이다. 나머지 페이지를 모두 리디자인했다고 표시하지 않는다.
- 새로운 서버 통계나 외부 그래프 라이브러리를 추가하지 않는다. 기존 저장 주문 건수로 SVG 막대를 만든다. 부분/실패/0건을 구분한다.

- P4-91: 재고/CS의 재방문 render 중복 호출 제거. 가상 자료20회 목록 교체20→0회, 상세 DOM 유지. 서버 응답 단축과 구분한다.

- P4-92: 분석/정산 재방문 DOM 재사용,비용 펼침/상세 유지,5분 재조회와 중복 요청 잠금 검증.
