# 모아온 UI 방향 · 페이지별 실행 계획

## 2026-09-11 공통 디자인 개편 (P4-98)
- 사용자는 청록색 방향을 거절했다. 최종 강조색은 블루이며 청록색을 브랜드 색으로 사용하지 않는다. 정상/완료 의미의 상태색은 유지한다.
- 넓은 창에서는 196px 메뉴에 이름과 24px 선형 아이콘을 함께 표시한다. 1280px 미만은 84px 메뉴다.
- 전체 8개 페이지에 workspace-heading을 적용한다. 제목32px/750, 본문14~15px, 주요 조회 버튼44px, 카드18px, 공통 여백24px. 주문 수집은 제목 옆 행동 영역이다.
- 진입300ms/제목380ms/그래프480ms, 버튼160ms. 동작 줄이기에서는 전환과 그래프 진입 효과를 끈다.

## 2026-09-11 실데이터 밀도 보완 (P4-100)
- 오늘 주문 상태 막대는 사용자 요청으로 제거했다. 숫자4카드(900px 미만2열), 동일 기준선과 하단 링크 정렬이 현재 기준이다.
- 좁은 주문 작업 영역은 상품명/채널·금액/상태를 재배치하며 텍스트가 다른 칸을 침범하지 않게 한다.
- 조회 상태는15px 문구와 원형 회전 표시를 함께 사용한다. 실제 busy 상태에만 연결하고 동작 줄이기를 지원한다.
- 설정은 독립 높이 두 열로 배치해 큰 카드 옆 아래에 빈 공간이 생기지 않도록 한다.
- 캘린더는 일정/메모 등록 폼과 기존 서버 저장 경로를 연결한다. 쿠팡 출고는 서버 제한 사유를 표시하고 조건 재확인을 연결한다.

## 공통 기준
- 목적: 운영자가 상태를 파악하고 필요한 업무로 바로 이동한다. 숫자 장식/가짜 추세/샘플을 운영 성공으로 보여주지 않는다.
- 기존 Pretendard를 유지한다. 제목32px/섹션20px/본문14~15px/핵심 금액26px 이상. 주요 버튼44px. 숫자는 고정폭 숫자, 설명은 충분한 행간.
- 색: 바탕#f2f4f8,면#ffffff,본문#222938,보조#687386,강조#4c5ee8,정상#207658. 기존 라이트/다크 토큰으로 동일 구조를 유지한다.
- 구조: 제목+기준 시각 → 우선 확인할 업무 → 주요 시각화 → 목록/상세. 고정된 필터 위치, 행동 버튼 위치, 전체 테두리 선택 표시.
- 동작: 페이지300ms/컨트롤160ms. reduced-motion은 끈다. 로딩은 자료 없음/실패와 구분하며 가짜 진행률/가짜0을 넣지 않는다.
- 그래프는 무엇을 비교하는지/기간/부분자료 여부를 함께 표시하고 관련 목록으로 연결한다. 값이 불명확하면 비율/추세를 만들지 않는다.

## 로딩/성능
- 현재 오늘 금융·일정·업무는 독립 호출되고 주문4상태는 Promise.all로 병렬 조회된다. 불필요하게 다시 병렬화하지 않는다.
- 기존 재방문 조회 억제와 중복 요청 차단을 유지한다. 첫 적용은 로딩 틀과 페이지별 스크롤 복원이다.
- 서버 응답시간 단축은 아직 입증하지 않았다. 이후 시작/응답/렌더 시각을 분리 측정하고 실제 병목에만 캐시/응답 축소를 적용한다. 권한/금융 데이터 캐시를 임의로 공유하지 않는다.

## 첫 적용의 한계
- 이번 변경은 오늘 및 공통 전환이다. 나머지 페이지를 모두 리디자인했다고 표시하지 않는다.
- 새로운 서버 통계나 외부 그래프 라이브러리를 추가하지 않는다. 기존 저장 주문 건수로 SVG 막대를 만든다. 부분/실패/0건을 구분한다.
