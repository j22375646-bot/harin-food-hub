## 목표

웹 허브 화면을 앱 안에 넣는 것이 아니라 기존 주문 API 기능을 모아온 전용 UI에 연결한다. 이번 범위는 서버 기준 배송지연·사은품 필터와 웹/앱 기능 차이 확인이다. 주문 페이지 전체 이전 완료와 실제 출고 인수 완료는 별도로 판단한다.

## 검색과 조건 조회를 구분하는 이유

배송지연·사은품 조건은 서버가 해당 단계/채널의 목록 전체에 적용해야 한다. 반면 앱의 자유 검색·금액 정렬·사전 확인 분류는 현재 불러온 페이지 안에서 동작한다. 현재 페이지에서 없다고 전체 주문에 없다는 뜻은 아니다. 이번 변경으로 전체 자유 검색이 생긴다고 표시하지 않는다.

## 검증 기록

- 시작 기준 단위시험205/205 통과.
- 최종 단위시험209/209 통과. 기존 웹 권한·주문 어댑터·배송정보 관련23/23도 통과. 웹 서버 코드는 변경하지 않았다.
- 최초0.35 설치본은 새 filter 메서드가 없어 예상대로 실패. 신규 메서드·UI가 필요한 실패를 확인한 뒤 구현했다.
- 독립 검토에서 작업중 초기화의 결과 유실, 필터 건수의 전체 요약 오염, 일부 시험 범위 부족을 발견했다. 수정 후 동일 reviewer의 스펙·품질 재검토 승인.
- 실제 next/previous/recheck/channel/logout와 필터 유지, 문서 fresh 조회, 등록 후 비필터 복구를 시험했다. renderer 시험은 기존 전체100건 뒤 필터3건이어도 전체 요약100건을 유지하고 작업중 초기화가 generation/선택/요청을 바꾸지 않음을 확인했다.
- 0.36.0 빌드 종료0, 설치 종료0. 패키지 app.asar를 개발 Electron 바이너리로 실행하는 격리 시험에서 필터/수동등록/목록도구/A4 UI 통과. 이전 회귀로 자동등록·배송추적·수집·CSV/묶음송장도 확인했다. 실제 설치 EXE 검증은 아래와 별도로 수행했다.
- 설치 EXE에서 실제 완료 주문87건 조회, 지연만/지연+사은품/사은품만 조합은 각각0건 READY. 이 실행은 실제 조건 해당 주문이 있는 양성 사례까지 증명하지 않으며 양성·페이지 이동·오래된 응답은 합성 시험으로 검증했다. 쿠팡+사은품에서 초기화는 채널ALL·두 조건false로 정확히1회 조회했다.
- 설치본 UI 정렬 오차0px/0px, 상세 패널 전환22프레임, 내용 유지·접힌 패널 inert·스크롤바 숨김 통과.
- 설치본 재실행2회 저장 로그인 유지, 업무 화면 진입 약2.59초/2.48초. 네 주문 단계 READY 및 완료 목록 다음/이전 페이지 이동 통과. 이 측정은 해당 실행 환경의 관측값이며 속도 보장이 아니다.
- 설치 시험 최초 reset 클릭은 열린 필터 팝오버에 가려 시간초과였다. 팝오버를 닫고 외부 초기화 버튼을 누르는 실제 동선으로 시험을 보정한 뒤 통과했다.
- 실제 송장 발급·쇼핑몰 등록·인쇄, 유료 인프라 생성은 실행하지 않는다.

## 앱 사용법·UI

주문 작업실 → 추가 필터 → 전체 조회 조건에서 배송 지연만/사은품 동봉만을 켠다. 두 조건은 함께 적용 가능하다. 필터 메뉴를 닫고 초기화를 누르면 채널·서버조건·현재페이지 검색·정렬이 함께 풀린다. 조회 조건을 바꿀 때 이전 주문 선택과 상세 패널을 정리하며, 작업중에는 조건 변경을 잠근다. 기존 Pretendard·라벤더 선택색·슬림 도구줄을 유지하고 최소1040×720 필터 팝오버 접근과 라이트/다크 목록도구를 검증했다.

## 다음 개발

P4-52는 주문의 오래된 화면 감지·안전한 새로고침 정책을 우선한다. 웹과 앱을 동시에 켰을 때 수집·배송추적 POST가 중복 실행되지 않도록 하고, 캘린더 이벤트 변경이 사은품 표시와 선택 주문에 어떻게 반영될지 검증한다. 전체 자유 검색/XLSX와 출고용 PC 프린터·바코드·실주문 종단간 인수는 남은 항목으로 유지한다. 주문 단계 인수 전에 다른 페이지 완료로 넘어가지 않는다.
