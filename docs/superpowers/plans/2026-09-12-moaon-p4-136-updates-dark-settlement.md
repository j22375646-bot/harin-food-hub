# P4-136 · 업데이트 알림, 공통 체크박스·다크모드, 정산 · 0.123.0

## 사용자 동작 변경

- 최신 버전과 같은 버전이면 알림을 띄우지 않는다. 이 PC는 직전 단계에서 0.122.0을 직접 설치했으므로 같은 버전 알림이 없는 것이 정상이다.
- 기존 로그인 전 알림 억제를 제거했다. 업데이트 대화상자가 열리면 보안 로그인 WebContentsView만 잠시 가리고, 닫으면 같은 로그인 세션을 복원한다. 비밀번호가 앱 renderer/IPC로 전달되지 않는다.
- 시작 확인은 3초 후, 정상 주기는 6시간, 조회 실패 재시도는 1분이다. 다운로드·재시작은 여전히 사용자의 동의를 요구하며 진행 중 작업 잠금을 유지한다. 구버전은 이번 버전을 설치하기 전까지 기존 로그인 후 알림 정책을 사용하므로 필요하면 설정의 업데이트 확인을 이용한다.
- 모든 앱 네이티브 체크박스에 공통 모양·부분 선택·키보드 포커스·비활성 스타일을 적용했다. 업무 완료는 원형 구분을 유지한다. 고대비 모드에는 네이티브 표시를 사용한다.
- 다크 토큰을 차콜·연보라·민트로 통일했다. 기존 styles.css의 :root[data-theme] 우선순위가 후기 디자인 토큰을 가리던 원인을 수정했다. 공통 폼·카드·사이드바·상세창도 함께 적용했다.
- 정산 요약과 채널 카드, 상세 비용 행을 재정렬했다. 쿠팡 판매자배송과 로켓그로스는 별도 카드/원장으로 유지한다. 상세에서 API 연결 설정으로 이동할 수 있다.

## 네이버 금액 확인

2026-08-14~09-12 기준 저장 캠페인 비용 합계는 298,005원이다. 비즈머니 원본 기간 응답의 28행과 사용내역의 82행은 각각 560,050.221192원으로 동일하다. 화면의 560,050.221원은 부동소수점 표시와 출처 설명 부족이 문제였으며, 이 증거만으로 캠페인 비용과 일치하는 확정 광고비라고 볼 수 없다.

공유 집계는 비즈머니가 없는 날을 캠페인 비용으로 보완할 수 있다. 화면에는 소진 출처, 캠페인 성과 비용, 충전액을 분리하고 원 단위 반올림을 적용했다. 광고 계정 전체 범위이며 특정 쇼핑몰 정산 차감액과 같지 않음을 안내한다. 원장 원금과 기존 정산 계산을 임의로 수정하지 않았다.

## 연결 진단과 남은 조건

- 쿠팡: 최근 ORDERS_REALTIME/CUSTOMER_SERVICE 서버 수집 기록에서 HTTP 401 `Hmac key is expired.` 확인. 서명은 요청 직전 UTC로 생성되고 있으며 인증 만료를 코드에서 우회하지 않았다. Wing 키 상태 확인/갱신 및 서버 연결 설정 반영이 필요하다. 비밀키를 출력하거나 변경하지 않았다.
- 별도 원장 문제: coupang_settlements 23 LEGACY + 28 COUPANG_REVENUE_API 행과 지급 요약 9 LEGACY + 7 COUPANG_PAYOUT_API 행이 모두 delivery_family UNKNOWN. 인증 복구와 별개로 원본 배송유형 대조가 필요하며 임의로 판매자배송에 넣지 않았다.
- 카페24: 주문·고객서비스 조회는 SUCCESS, 최신 FETCH_ALL 매출통계는 HTTP 403 `Invalid API`. 사용하는 /financials/dailysales 경로는 공식 문서에 존재하지만 특정 클라이언트용 제한 API이고 mall.read_salesreport 권한을 요구한다. 재로그인만으로 해소된다고 판단하지 않았다. 실제 PG 지급 정산과 주문 결제액은 구분해야 한다.
- API 재연결은 완료되지 않았다. 사용자에게 Wing 확인을 요청했으며 PG사 지급 연동은 PG사/계약과 지원 API 확인이 남는다.

근거: [Cafe24 매출통계 공식 문서](https://developers.cafe24.com/docs/ko/api/admin/#financials-dailysales), [쿠팡 API 목록](https://developers.coupang.com/ko/api), [네이버 Search Ads API](https://naver.github.io/searchad-apidoc/).
