# P4-153 · 고객 응대, 반복 업무, 행사 재고

사용자 승인: 고객·CS, 업무 캘린더, 재고 추천 기능 적용.

- CS: 플랫폼별 팀 목표 응답시간(기본 24시간), 임박/초과 정렬·필터, 공용 답변 템플릿 편집/저장과 접수별 문구 복사. 플랫폼 직접 전송은 기존 연결이 없어 판매자센터에서 확인·발송한다.
- 업무: 매일/매주/매월 2~52회 일괄 등록. 월말은 해당 월 마지막 날로 조정. 담당자·체크리스트 복제, 회차별 완료, 이번만/이후 미완료 회차 수정·삭제. 서버 트랜잭션·중복 요청 및 동시 수정 방어.
- 재고: 같은 상품·단위의 유통기한별 출고 순서와 행사별 확보 기록. 기한 경과/누락은 출고 추천 제외, 행사 확보는 실수량 차감과 구분. 초과 확보 차단, 재고 감소 후 부족 상태 표시, 행사 종료·삭제 시 해제된 가용 수량 계산.
- 기존 공통 토큰·카드·읽기 크기 사용. 가시 격리 Electron으로 밝음/다크 및 폭별 확인. 운영 고객에게 메시지를 전송하거나 실제 출고하지 않는다.

## 저장과 호환

- CS 팀 목표는 1~168시간, 공휴일을 포함한 경과시간 기준이며 플랫폼 공식 답변 기한이 아니다. 접수 시각 누락/미래 시각은 확인 필요로 남긴다. 최대 30개 템플릿을 사업장 공용 설정으로 저장하고 수정 충돌을 검사한다. 개별 문의의 편집 중 초안은 메모리에만 남기며 로그아웃 시 제거한다.
- 반복 업무는 기존 업무 원장에 회차별로 저장한다. 월말 반복은 최초 날짜를 기준으로 1월 31일→2월 말일→3월 31일로 계산한다. 이후 회차 수정/삭제는 선택 회차 이후 미완료 업무에만 적용하며 완료 이력은 보존한다. 기존 체크·완료·재개 요청과 반복 묶음 수정의 버전 충돌을 검사한다.
- 행사 확보는 같은 사업장·재고 lot·행사를 연결하며 행사 종료일까지 기한이 유효한 재고만 허용한다. 종료/삭제된 행사의 기록은 보존하되 가용 수량 계산에서 제외한다. 실제 재고 수량이 이후 감소해 부족해지면 음수 가용량과 부족 안내를 표시한다. 상품과 단위를 나눠 추천하며 로켓그로스 원장을 섞지 않는다.
- 기존 로그인·소유자·활성 사업장 검증을 유지한다. 신규 테이블은 서버 전용, RLS 활성화와 anon/authenticated 접근 차단을 적용한다. 앱은 기존 인증 API를 사용하며 브라우저에 service_role 또는 비밀키를 전달하지 않는다.

## 검증 기록

- 서버 전체 2,851/2,851 PASS, 데스크톱 전체 404/404 PASS. 이후 실제 재고 복합키와 service_role 실행 권한을 맞춘 최종 도메인/격리 PostgreSQL 4/4 PASS. 최종 UI 시험은 반복 저장 회수 응답 검증까지 포함한다.
- 실제 재고 migration을 읽은 PGlite에서 월말·연말 반복, 중복 생성 방지, 이번만/이후 수정과 삭제, 완료 이력 및 체크 보존, CS 설정 저장 충돌, 초과 확보 거절, 해제, 취소된 세션 접근 거절을 검증했다.
- 소스 및 설치 위치 ASAR의 가시 Electron 시험 PASS: renderer→IPC→transport→격리 PostgreSQL 왕복 17개 명령. CS 필터/목표/템플릿 저장·재조회/문구 복사, 반복 등록·이후 수정·삭제, 기한 경과/누락 재고 제외, 확보 7→8 수정→해제, 연결 초기화.
- 밝음/다크 700·1040·1440px에서 카드·편집 창 가로 넘침 없음. 업무 폼 하단 버튼을 고정하고 반복 입력을 2열로 정리했다. 시험 창은 오른쪽 보조 모니터에 포커스 없이 표시했다. 실제 사용자 로그인 세션이나 운영 고객 발송·실재고 수정은 시험하지 않았다.
- Next 16.3 webpack production build PASS. 최종 설치 ASAR 0.139.0과 소스 99개 파일 대조 PASS.
- 신규 권한 실제 SQL 조회: 4개 테이블 모두 RLS=true, anon/authenticated SELECT=false, service_role SELECT=true. 신규 테이블의 정책 없음 알림은 서버 전용 구성에 대한 INFO이며 해당 테이블 관련 ERROR 없음.
