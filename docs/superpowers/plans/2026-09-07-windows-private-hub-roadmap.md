# Windows Private Harin Hub — 통합 개발계획

> 후속 다사업장/UI 확장 요청은 [새 통합 개발계획](2026-09-07-multi-business-desktop-master-plan.md)을 우선한다. 본문의 18~30일은 이전 단일 사업장 범위 추정이다. W1~W7의 설치·출력·검증 상세는 새 계획에 포함하며 중복 실행하지 않는다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task after explicit development start. 아래는 사용자 검토용 계획이며 지금 실행하라는 지시가 아니다. 기술 검증에서 선택이 달라지면 해당 작업 명세를 먼저 갱신한다.

**Goal:** 기존 허브의 UI·인증·업무 안전을 유지한 Windows 개인 업무용 설치 프로그램을 만들고, 기존 성능·정산·측정·실행 학습 계획을 단계적으로 연결한다.

**Architecture:** 기존 Next 서버와 DB·채널 수집 작업자를 유지하고 격리된 Windows 클라이언트를 추가한다. Electron을 우선 후보로 삼되 W1 기술 검증을 통과한 뒤 확정한다. 프로그램은 서버 비밀키나 주문 원장을 로컬로 가져오지 않는다.

**Tech Stack:** 기존 Next16.3/Node24/React와 기존 테스트. 데스크톱 후보 Electron+electron-builder/NSIS, node:test 및 패키징된 앱 E2E. 실제 버전은 W1에서 당시 지원·보안 상태를 확인하여 정확한 버전과 lockfile로 고정한다. 다른 패키지 버전까지 일괄 업그레이드하지 않는다.

**Spec:** `docs/superpowers/specs/2026-09-07-windows-private-hub-design.md` — 기획·구조·보안·운영 정책의 검토용 명세.

## Global Constraints

- Windows 개인 업무용 .exe, 모바일 앱·모바일 푸시·앱스토어·설치파일 공개 배포 제외.
- 기존 UI·로그인·세션 만료·CSRF·금액 산식·네이버/쿠팡·쿠팡 판매자배송/RG 구분 유지. 미수집은0이 아니다.
- PC에서 플랫폼 API를 새로 직접 호출하지 않는다. PC 종료와 서버 수집 중단은 별개다.
- 비밀번호·세션 비밀·서비스 역할 키·플랫폼 비밀키·고객 원문을 코드/설치파일/로그에 넣지 않는다.
- 설치파일은 새 desktop 하위 프로젝트의 명시적 파일만 포함. 기존 저장소 전체를 패키징하지 않는다.
- 로컬 파일·프로세스·외부 URL·IPC는 기본 거부, 목적별 허용. 원격 renderer에는 Node 권한을 주지 않는다.
- 송장 발급·환불·입찰·메시지·실제 인쇄는 승인된 검증 사례 외에는 실행하지 않는다.
- 문서/자동시험/모의시험/실기기/운영 결과를 구분한다. 자동 재시도는 읽기 작업과 쓰기 작업을 구분한다.
- 기존 자료·다른 작업 공간을 보존하고, 앱 제거는 해당 앱 소유 파일만 대상으로 한다.
- 기획 승인 후에도 실제 프린터 미확인·외부 권한 미설정·장기 관찰 미완료를 완료로 표시하지 않는다.

## A. 개발 방식과 중간 인도물

세 개의 독립 작업 묶음으로 나눈다. 모든 AI 기능을 끝낼 때까지 설치 프로그램을 기다리지 않는다.

1. **Windows 조회용 베타:** W0~W3. 설치·로그인·기존 페이지·파일·오류 복구. 실제 출고용으로 검증됐다는 표현 금지.
2. **Windows 업무용1.0:** W4~W7. 실프린터·출고 안전·수동 업데이트·장시간 사용 검증 포함.
3. **기존 허브 고도화:** B1~B4. 데이터 연결·실행 학습·선택 Hermes·소재/예산/사은품 후속. W6 서버 성능 작업은 두 묶음 모두에 적용.

각 작업은 요구사항 ID→실패 재현→최소 구현→집중 시험→전체 회귀→코드 검토→패키징/실행 증거→보고 순서다. 운영 결함 중 금액·중복 출고·인증 문제가 발견되면 새 편의 기능보다 먼저 해결한다. 개발 중 구현 변경만으로 매 단계 사용자 승인 질문을 반복하지 않되, 새 유료 자원·인증서 구매·실제 출고/환불은 별도 권한을 확인한다.

## W0. 업무 요구·기준선 고정

**결과물:** `docs/desktop/requirements.md`, `environment-baseline.md`, `acceptance-matrix.md`, `risk-register.md`.

- [ ] 현재 HEAD·운영 버전·기존 테스트 결과의 시점을 기록한다. 이전 오류 기록은 재현/수정완료/외부대기/미검증으로 다시 분류한다.
- [ ] 현재 화면 레지스트리의18개 주요 경로와 하위 작업을 목록화한다. 메인·캘린더·주문·CS·재고·상품·정산·키워드·상품분석·인사이트·상품개발·자료/시스템·진단·변경기록·실험·실행검증·알림을 빠짐없이 연결한다.
- [ ] 실제 업무 PC OS/CPU/RAM/모니터/배율/프린터 드라이버/용지를 조사한다. 현재PC의 가상 프린터만으로 출고 프린터가 없다고 단정하지 않는다.
- [ ] 로그인→주문조회→사은품확인→선택→기존 발급/인쇄→이력, 정산조회→원장대조, CS확인 등 업무 시나리오를 고정한다.

- [ ] 권한/자료/프린터가 없는 시험은 대체 fixture와 실제시험 미완료 표기를 함께 정의한다.

**통과 기준:** 기능별 보존/추가/제외, 검증 자료, 담당 작업과 완료 증거가 하나씩 연결되어 있음. 사장님이 용지 모델명을 외워야 다음 단계로 갈 수 있게 만들지 않음.

## W1. 기술 검증과 방식 확정

**파일:** 신규 desktop 실험용 최소 프로젝트, docs/desktop/architecture-decision.md. 별도 작업 공간에서 수행하며 폐기 가능한 시험과 본 구현을 구분한다.

- [ ] Electron·패키징 도구 지원 버전, 라이선스, 알려진 보안 경고, Windows 지원 범위를 공식 문서로 확인하고 고정한다.
- [ ] 원격 허브 renderer는 Node 비활성/컨텍스트 격리/샌드박스, 로컬 UI는 별도 origin으로 시험한다.
- [ ] 기존 로그인·12시간 만료의 단축 fixture·로그아웃·동일 origin POST가 정상인지 확인한다. origin 검사를 끄는 해결책은 탈락.
- [ ] 기존 인쇄 HTML·PDF 저장·blob/attachment 다운로드·파일 업로드·한글 입력·다크모드·팝업을 시험한다.
- [ ] OAuth를 기본 브라우저에서 진행하고 앱이 서버 연결 상태를 재조회하는 경로를 검증한다. 실계정 재연결은 사장님 입력/동의가 필요하다.
- [ ] 베이스 Chromium 창과 허브 탑재 후 메모리·CPU·시작 시간을 측정한다. Electron이 조건을 충족하지 못하면 같은 fixture로 Tauri를 비교한다.
- [ ] NSIS 형식 .exe 후보를 만들어 개발환경 밖에서 실행 가능한지 확인한다. 코드를 확정하지 않은 상태에서 출고용 배포로 명명하지 않는다.

**통과 기준:** 보안 완화 없이 로그인·기본 출력·파일 작업 가능, 사용자 PC 환경에서 실행 가능, 자원 예산 합의. 치명적 미충족 시 방식 재설계. 'Electron이 익숙해서'만으로 확정하지 않는다.

## W2. 설치·창·세션·보안 경계

**Files:** desktop/src/main.cjs, windows.cjs, settings.cjs, hub-view.cjs, navigation-policy.cjs, session-policy.cjs, local/*; desktop/test/navigation-policy.test.cjs, settings.test.cjs, session-policy.test.cjs.

**Interfaces — 신규 계약 제안:**
- `classifyNavigation(rawUrl, { hubOrigin, purpose }) -> 'HUB' | 'PRINT' | 'EXTERNAL_CONFIRM' | 'DENY'`. 임의 scheme/사용자정보/비허용 port·origin은 DENY. PRINT는 고정된 인쇄 경로와 별도 조회 파라미터 검증을 통과해야 함.
- `restoreWindowBounds(saved, displays) -> {x,y,width,height}`. 현재 모니터 범위로 보정. 원격 문서가 위치/파일 경로를 지정하지 못함.
- 설정에 저장할 항목: schemaVersion,windowBounds,maximized,autoStart=false,closeToTray=false,printerProfile. 앱 프로필·세션 쿠키를 JSON export에 포함하지 않음.

실패 재현용 예시(구현 전에 제안 API와 함께 작성):

```js
const test = require('node:test');
const assert = require('node:assert/strict');
const { classifyNavigation } = require('../src/navigation-policy.cjs');
const context = { hubOrigin: 'https://harin-cafe24-sync.vercel.app', purpose: 'main' };
test('비슷한 도메인과 로컬 실행 URL을 거부한다', () => {
  for (const value of [
    'https://harin-cafe24-sync.vercel.app.evil.invalid/orders',
    'https://harin-cafe24-sync.vercel.app@evil.invalid/',
    'file:///C:/Windows/System32/cmd.exe',
    'javascript:alert(1)', 'http://harin-cafe24-sync.vercel.app/'
  ]) assert.equal(classifyNavigation(value, context), 'DENY');
  assert.equal(classifyNavigation(context.hubOrigin + '/orders', context), 'HUB');
});
```

## W3. 전 페이지·파일·장애 복구 — 조회용 베타

**Files:** desktop/src/downloads.cjs, diagnostics.cjs, compatibility.cjs; desktop/e2e/auth.spec.cjs, pages.spec.cjs, files.spec.cjs, recovery.spec.cjs; 필요성이 입증된 기존 페이지 호환 수정만 별도 커밋.

- [ ] 기존18개 주요 경로와 실제 하위 탭을 app/browser에서 같은 기준 시각·자료로 비교한다. 표시 개수뿐 아니라 같은 주문/배송묶음 ID·금액·선택 대상도 비교.
- [ ] CSV/XLSX/PDF/HTML 등 실제 내려받는 형식, 업로드, 취소, 잘못된 MIME, 덮어쓰기, 한글 파일명, 긴 경로, 디스크 부족 시험.
- [ ] 화이트리스트 인쇄 창과 외부 링크가 로그인/위조 origin으로 리디렉션되면 권한을 유지하지 않는지 검사.
- [ ] 시작 시 오프라인, 실행 중 끊김, 서버401/403/500, 렌더러 충돌, 절전 복귀를 모의 재현. 오류를 정상0건/0원으로 표시하지 않음.
- [ ] 다시 열기/새로고침 전에 미확정 변경 결과를 조회하고, POST 자동 재전송이0건인지 네트워크 추적으로 확인.
- [ ] 진단파일에서 인증정보·고객정보를 제거하고 사용자 확인 후 저장. 자동 외부 업로드 없음.

## E. 일정·우선순위·변경관리

1명 개발자의 실작업일을 기준으로 한 초기 추정이며 확정 납기가 아니다. 자동화 도구 사용 시간, 외부권한 대기, 실제장비 확인, 사장님 실사용과 수정회차에 따라 달라진다.

개발 중 새 요청은 '업무안전 필수/이번앱 필수/편의/후속'으로 분류한다. 모바일·전체UI재디자인·별도원장복제·무조건서버이전·공개업데이트플랫폼은 이번 범위를 늘리지 않는다.

## F. 비용·남은 확인·승인 경계

기존 서버 비용은 유지된다. 전용 앱 자체를 위해 새 VPS를 필수로 구매하지 않는다. 코드 서명·빌드/서명 서비스·Hermes/LLM은 필요성과 당시 가격을 검증한 뒤 별도로 결정한다. 기존 PC에서 시험 가능한 부분과 실프린터·깨끗한 Windows 환경이 필요한 부분을 분리한다. 서명 비용·메모리·설치 크기를 시험 전에 단정하지 않는다.

사장님께 필요한 정보는 개발 초기 실제 출고 PC·프린터 접근, 테스트 가능한 시간, 허용할 실주문 사례다. 용지 규격을 지금 모르더라도 계획은 진행 가능하며, 연결된 프린터 설정과 실물 시험으로 확정한다.

이번 요청의 결과는 기획·개발·검증 계획 문서다. 개발 코드·패키지 설치·앱 설치·서버 배포·인쇄는 수행하지 않는다. 명세검토와 개발시작 요청 이후 W0부터 순서대로 실행하며, 각 인도 시 완료/부분완료/외부대기/미실행과 다음 작업을 보고한다.
