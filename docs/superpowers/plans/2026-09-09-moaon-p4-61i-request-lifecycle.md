# P4-61I 저장 요청 수명주기

## 수정

- 저장 처리기 인스턴스별 동시 요청 기본 8개 제한. 초과 시 CREDENTIAL_BUSY/429. 성공·실패·본문 취소 모두 슬롯을 반환한다.
- 연결 취소가 본문 read 대기에도 전달되도록 수정. 크기 초과 본문의 cancel 완료를 무한히 기다리지 않는다.
- 쓰기 시작 후 분류되지 않은 오류는 CREDENTIAL_RESULT_UNKNOWN/503으로 반환한다. 저장 여부를 모르는 상태를 재시도 가능한 단순 실패로 오인하지 않도록 한다.

## 검증

정식 npm test 전체 2,686/2,686 통과.

추가 시험 3개에서 제한 없는 동시 요청, 중단된 본문 대기, 불확실 쓰기 결과 오분류를 먼저 재현하고 수정 후 요청 시험6개 통과. 실제 HTTP Request/ReadableStream을 사용하며 DB 저장 대기·오류만 시험 어댑터로 제어한다.

## 남은 범위

동시성 제한은 처리기 인스턴스 내부 보호이며 분산 rate limit이 아니다. 재생성된 처리기·다른 서버를 공유하는 제한 저장소, 운영 세션 fence, HTTP route, 앱 전송·결과 확인 동선은 여전히 필요하다. 활성 쓰기를 임의로 취소하거나 성공을 단정하지 않는다.

운영 배포·실제 API 인증은 진행하지 않았다. 앱0.51.2 및 UI는 유지한다.
