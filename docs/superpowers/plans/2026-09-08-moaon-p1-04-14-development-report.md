# 모아온 P1-04-14 개발 보고서

## 목적

계정별 로그아웃 처리기를 HTTP 요청에 연결하는 내부 후보 어댑터다. 허용된 허브 주소에서 온 요청만 받고 세션 폐기를 확인한 뒤 성공과 쿠키 삭제를 함께 응답한다. 기존 공개 로그인·로그아웃·비밀번호·UI·업무 API는 유지한다. Windows EXE나 다사업장 공개의 완성 단계는 아니다.

## 동작

1. 등록된 HTTPS 주소에서 보낸 POST인지 확인한다. 전달 헤더로 허용 주소를 늘리지 않는다.
2. 세션 쿠키 하나만 기존 내부 처리기로 전달한다. 중복·잘못된 형식·본문·다른 인증 수단은 실행 전에 거절한다.
3. 폐기 성공이 확인된 경우에만 성공 응답과 해당 쿠키 삭제를 보낸다.
4. 실패·시간 초과·중단은 성공으로 꾸미지 않는다. 서버가 뒤늦게 작업을 마칠 수 있어 실패가 취소·복구를 뜻하지 않는다.

## 범위 판단과 한계

- 공개 경로는 아직 연결하지 않는다. 기존 인증 보호를 위한 선택이며 실제 적용까지 별도 연결 검수가 필요하다.
- HTTPS Origin을 요구하며 전달 헤더·Referer 대체는 허용하지 않는다. 실제 프록시나 앱 요청 방식에 맞춘 조정이 필요할 수 있다.
- 실패 시 쿠키를 지우지 않고 원격 작업을 되돌리지 않는다. 서버 세션이 이미 폐기되면 쓸 수 없는 쿠키가 남아 재확인이 필요할 수 있다.
- 기준 검사에서 기존 로그아웃 테스트가 짧은 실시간 대기 조건 때문에 두 번 실패했다. 테스트 안정화는 production 제한을 바꾸지 않는 범위에서 검증한다.

## 검증 기록

초기 구현51263ea의 집중 회귀97/97와 빌드가 통과했다. 전체 검사에서 기존 MFA 테스트의 조기 생성된 합성 증거가 freshness 조건에 걸려 배포를 보류했다. 수정20ec805 이후 전체2,508/2,508(60.08초, 실패·취소·건너뜀0)과 최종 빌드가 통과했다. 로컬 PGlite의 실제 로그인 저장과 MFA 증거 폐기를 사용하되 비밀번호/MFA 공급자는 합성 자료다. 실제 운영 인증과 native DB 동시 연결 시험을 대신하지 않는다.

기존 벽시계 역행 테스트는5ac0c76에서 실제5ms/30ms 대기 대신 제어된 경과시간으로 안정화했다. 메모리에서 잘못된 Date.now 계산을 넣자 예상30ms 대신60030ms가 되어 테스트가 실패했다. production 계산은 변경하지 않았다.

MFA 테스트는8867acf에서 검증 호출 시 증거를 생성하도록 수정했다. 증거00:43:47.000Z와 DB 시작00:43:49.920Z 차이로 실패를 재현한 뒤 대상1/1이 통과했다. 실제 인증 신선도와 기대값 검증은 그대로이며 독립 검토에서 확인했다.

독립 검토에서 쿠키 크기 제한을 전체 헤더에 적용한 오류와 완전히 빠진 Origin 테스트 누락을 발견했다. 20ec805에서 Cookie만 16,384바이트로 제한하고 초과는401·실행0회, 정확한 한도는 정상 처리, 큰 다른 헤더는 쿠키 한도에서 제외되도록 수정했다. 실패 재현 후 관련59/59 통과, 독립 재검토에서 해결을 확인했다. 계약 문구도 Cookie 기준으로 명확히 맞췄다.

최종 전체 검토에서 새 HTTP 어댑터의 시계 역행 테스트가 잘못된 Date.now 구현을 검출하지 못하는 공백을 발견했다. e5e6fdd에서 경과시간을 정확히 만료 시점까지 진행한 뒤 늦은 성공이503·쿠키 미삭제·호출1회로 처리되는지 검사했다. 정상59/59, 메모리 변이는200과503 차이로 실패했다. 최종 검토자가 정상1/1과 변이 실패를 독립 재현했으며 병합 가능, 미해결·보류 항목0으로 판정했다. production 코드는 이 보강에서 바꾸지 않았다.

## 다음 개발

신뢰된 프록시/IP와 요청 제한의 실제 진입 경로를 검증하고 지정된 인증 환경에서 키·DB 권한·MFA를 연결 시험한다. 기존 로그인 회귀와 실패 안내를 통과해야 공개 인증으로 전환할 수 있다. P2의 사업장별 주문·정산·파일·캐시 격리 검증 전에는 다른 실사업장을 개방하지 않는다. 앱 전용 UI와 Windows EXE는 P4/P5다.

유료 자원·hosted DB 브랜치·운영 자료 복사·실계정 비밀번호 입력·메일·송장 발급은 수행하지 않는다. 기존 서비스 사용량 과금까지 0원으로 보증하는 것은 아니다.
