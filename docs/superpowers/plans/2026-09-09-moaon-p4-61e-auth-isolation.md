# P4-61E 네이버 인증 캐시 분리

다사업장 인증 경로 검토 중 기존 네이버 커머스 클라이언트의 캐시 키가 tokenType/accountId만 사용하여 Client ID·Secret 변경에도 이전 토큰을 반환함을 재현했다.

## 수정

- Client ID, Secret, 토큰 유형, 판매자 계정 전체를 SHA-256으로 식별한다. 캐시 키에 Secret 원문을 보관하지 않는다.
- 캐시는 기존처럼 한 항목만 유지한다. 다른 인증정보는 새 토큰을 요청하므로 다른 사업장 토큰을 반환하지 않는다.
- 초기화 세대를 추가하여 초기화 이전에 시작한 응답이 늦게 도착해 캐시를 복원하지 않도록 한다. 이미 진행 중인 호출 자체를 취소하는 기능은 아니다.
- 강제 갱신 시 이전 캐시를 먼저 비운다. 갱신 실패 후 만료·거절된 토큰을 다시 재사용하지 않는다.
- 인증 요청 설정은 호출 시 복사하고, 응답을 읽은 뒤에도 취소 상태를 확인한다.

## 검증과 범위

- 신규 재현 테스트 3개가 기존 코드에서 실패하고 수정 후 통과. 네이버 클라이언트 테스트 총 7개 통과.
- 외부 네이버 응답만 시험 응답으로 대체했으며 서명과 토큰 캐시 코드는 실제 구현을 실행했다. 실제 API 인증 성공을 검증한 것은 아니다.
- 최초 범위 없는 node --test는 수동 앱 시험까지 실행해 환경 오류가 발생했으므로 중단. 정식 npm test로 재검증하여 2,675/2,675 통과했다.
- 이번 변경은 서버 라이브러리이며 앱 UI와 설치 버전 0.51.2는 그대로다. 운영 워커 배포·새 사업장 인증 API 연결은 별도 검증 전이다.

다음 단계는 사업장별 서버 자격증명 저장 및 고정 IP 인증 검증 경로 연결이다. 이 캐시 수정만으로 다사업장 연결 완료라고 표시하지 않는다.
