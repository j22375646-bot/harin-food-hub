# P4-60C / 0.49.0 — 공통 UI 1차·캘린더 조회 보완

## 앱 UI 적용

- 오늘·주문·운영정산·분석·캘린더·설정의 제목 크기, 줄높이, 굵기, 여백을 하나의 규칙으로 통일.
- 운영정산·분석·캘린더의 겹친 바깥 여백과 영문 보조 제목을 정리. 새로 조회 버튼 높이·모서리·글자 크기 통일.
- 카드·상세 패널의 여백과 모서리 기준을 공통 CSS로 관리. 기존 프리텐다드, 밝은/어두운 테마, 보라색 선택 상태 유지.
- 기존 주문 표의 열 배열과 동작은 변경하지 않는다. 모든 화면의 모든 컨트롤을 정리한 것은 아니며, 다음에는 입력창·필터·빈 화면·로딩 상태를 통일한다.

## 캘린더 개발 — 운영 배포 전

기존 서버의 500건 선제 제한 대신 500건 단위 페이지 조회 코드를 연결했다. 조회 시작보다 366일 이전인 일정도 제외하지 않아 장기 일정이 조회 후보에 포함된다. due_at/id 정렬을 사용한다.

서버 부담을 제한하기 위해 최대 5,000건 검사, 표시 일정 최대 499건으로 제한한다. 한도·중복·총건수 불일치는 complete=false로 반환하며, 앱은 일부 조회라고 안내한다. 오늘 요약은 명시적인 불완전 응답을 정상 요약으로 표시하지 않는다. 구 서버 응답은 전량 여부 확인 필요를 유지한다.

페이지 조회는 단일 DB 스냅샷이 아니다. 조회 중 동시 수정까지 포함하는 완전한 일관성 보장은 하지 않는다. 운영 DB 읽기와 운영 배포는 이번 기록 시점에 미실행이며, 서버 기능의 운영 완료로 보고하지 않는다. 다음 단계에서 실제 응답 계약과 부하를 확인한 뒤 배포·대조한다.

## 검증

- 테스트 우선: 제목 불일치와 페이지 누락 실패 확인 후 수정.
- 앱 271개, 서버 2,672개 테스트 통과. Next.js 프로덕션 빌드 통과.
- 패키지 화면 시험: 6개 제목/버튼 일치, 캘린더, 분석, 공통 주문 레이아웃 4종 통과.
- 임시 프로필과 시험 응답을 사용했으며 운영 데이터 성공 증거가 아니다.
- 실제 캘린더 화면 캡처로 여백·날짜판·공휴일 표시 확인.

페이지 범위는 [Supabase range 공식 문서](https://supabase.com/docs/reference/javascript/using-modifiers-range)의 양끝 포함 규칙을 적용했다.

## 설치

0.49.0 설치 종료 코드 0. 설치된 app.asar와 빌드 app.asar의 SHA-256 일치 확인. 로그인 프로필은 삭제하지 않았다. DB 쓰기·송장 발급·플랫폼 변경·추가 유료 자원 생성은 없다.
