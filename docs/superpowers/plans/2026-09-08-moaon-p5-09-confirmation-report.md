# P5-09 — 출고 내용 확인창 / 0.11.0

[전체 개발계획](./2026-09-07-multi-business-desktop-master-plan.md)

## 이번 변경

검토 후보 주문 상세에 `출고 내용 확인 (발급 안 함)` 버튼을 추가했다. 기존 앱 스타일과 작업판을 유지하고 Windows 네이티브 확인창을 연결했다. 디자인 스킬은 행동과 제한을 명확하게 표현하는 데 적용했다.

버튼→검증된 IPC→인증 GET 재조회→Windows 확인창→확인 후 GET 재조회→상태 표시 흐름이다. 기본 선택과 닫기는 취소다. 주문 ID·상품·수량과 발급하지 않는다는 안내를 표시하며 수취인 주소·전화번호는 창에 넘기지 않는다.

확인 중 주문 변경이나 연결 세대 변경은 무효화한다. Main의 동시 확인은 BUSY로 제한한다. 결과는 발급 허가증이 아니며 저장하지 않는다.

## 검증

- 확인 함수/버튼 부재 실패 확인 후 구현. 데스크톱 단위 83개, 기존 웹 회귀 2,548개 통과.
- 격리 Electron의 실제 버튼/IPC/Main/화면 결과 연결 통과. 주문 HTTP와 네이티브 창 응답은 모의 처리했다. 실제 OS 창을 사람이 클릭한 시험이나 실계정 로그인 검증과 구분한다.
- 0.11.0 빌드 완료. 패키지 app.asar를 개발 Electron/격리 프로필로 실행한 동일 시험도 통과했다. 설치 프로그램 실행·기존 설치본 업데이트 검증은 아니다.
- 기존 주문 재확인 Electron 시험 통과. 기존 화면의 라이트/다크·창 크기 검사는 새 버튼의 모든 크기 검수를 대체하지 않는다.
- 별도 코드 검토에서 차단 결함 없음. 검토자는 시험을 재실행하지 않았고 위 결과는 주 작업자가 실행했다.

서명 상태 NotSigned. 기존 설치본 자동 교체 없음. 보안 경고 우회는 안내하지 않는다.

0.11.0은 조회·내용 확인용이다. 실제 발급 POST·진행 조회·인쇄·다사업장 전환은 개방하지 않았다. 기존 외부 쓰기 제한 유지. 실제 고객 주문 발급 및 사용자 설치본 강제 종료 없음.

다음은 명시적 실제 발급 확인, 작업 기록·고정 통신·로그아웃 중단을 Main에 연결하는 단계다. 완료 후 다음 주문 전환, 결과 불명 대조, 진행 UI를 통합 검증한다. 실제 발급/프린터 시험은 별도 확인 후 수행한다.
