# P4-61K — 제한 서버 계정의 API 키 저장 권한

## 변경

- `moaon_control_app` 서버 역할용 별도 SQL 후보를 추가했다. 초기 NOLOGIN 역할의 안전 속성·소유권·테이블/RLS·공개 권한·정책 충돌을 확인하고 변경 전체를 원자적으로 적용한다.
- 인증 테이블은 세션 확인에 필요한 열 읽기와 행 잠금만 허용한다. 계정 상태 변경·세션 발급/폐기·같은 ID로 덮어쓰기까지 거부한다.
- 키 저장은 필요한 열의 INSERT/UPDATE 및 revision 조회만 허용한다. 암호문 직접 조회·RETURNING 우회·DELETE/TRUNCATE·사업장/플랫폼 키 변경은 거부한다.
- 기존 ON CONFLICT의 excluded 값 참조를 동일한 바인드 값으로 바꿔 암호문 SELECT 권한 없이 갱신하도록 했다.
- 기존 열별 과권한도 초기화한다. 다른 역할에 속한 정책은 덮어쓰지 않고 거부한다. 기존 초대·멤버십·감사 기록 권한은 유지한다.
- 연결 transport의 역할 검사를 인증 스키마/테이블 소유권까지 넓혔다. 소유자 권한에 의한 RLS 우회 및 검사 결과 누락은 연결 전에 거부한다.

이 역할은 신뢰된 서버용 broker다. DB 로그인 정보 자체가 특정 사용자나 사업장을 증명하지 않으며, OWNER·사업장·세션 검사는 저장 모듈이 계속 강제한다. 열 권한은 테이블 권한과 합쳐지므로 테이블 REVOKE만으로 기존 열별 권한이 없어지지 않는다. [PostgreSQL GRANT 공식 문서](https://www.postgresql.org/docs/current/sql-grant.html)

## 검증

- 최소 권한 후보 부재 및 인증 소유권 검사 누락을 먼저 실패로 확인했다.
- 관련 SQL·transport·저장·세션 보호 72개 시험 통과.
- 실제 제한 역할 로그인/transport 최종 5개 시험 통과(159.1초). 저장·revision 갱신·암호문 조회 거부·접근 거부·기존 초대/감사 동작·세션 폐기 잠금 경합을 검증했고 임시 DB/역할 정리도 성공했다.
- 전체 회귀: test/**/*.test.js의 401개 파일 집합과 실행 목록이 정확히 일치함을 확인했다. 2개 파일24/24 통과(581.8초), 나머지399개 파일은2,684개 중2,681 통과·3건너뜀·실패0(107.5초). 합계2,708개 중 **2,705 통과·실패0·건너뜀3**. 건너뜀은 기존 production build chunk 검사이며 이번 서버 SQL/모듈 변경에서는 빌드를 실행하지 않았다.
- 독립 명세/코드 검토 승인. 차단 결함 없음. 연결 및 후보 SQL 변경 외의 runtime 활성화는 하지 않았다.

## 적용 범위

검증용 후보 SQL이며 운영 마이그레이션이나 계정 권한 변경을 실행하지 않았다. 시험용 LOGIN과 합성 비밀번호는 D의 폐기 가능한 loopback PostgreSQL에만 적용했다. 종료 시 시험용 DB/역할을 제거하고 서버를 중지했으며55437 listener가 없음을 확인했다. 시험 서버의 fsync/synchronous_commit 비활성 상태는 경합 순서 검증용이며 장애 시 디스크 내구성 증명이 아니다.

앱 UI·설치본은0.51.2 유지. 신규 사업장 키의 실제 플랫폼 인증/수집 완료가 아니다. 다음은 여러 서버가 공유하는 저장 요청 제한, HTTP route와 앱의 명시적 서버 저장·revision 결과 확인 연결이다. 저장 결과 불명은 자동 재시도하지 않는다.

개발 소스·신규 로그·시험 데이터는 D:\GPT 하위다. 기존 C 의존성 junction과 Codex 자체 저장 위치는 이전 단계와 같으며 C 전체 이전/용량 확보를 이번 결과로 주장하지 않는다.
