# 모아온 P1-04-1 개발 보고

## 이번 단계가 하는 일

여러 사업장이 개인 계정으로 이용할 때 필요한 비밀번호 복구의 내부 안전장치를 만들었다. 비밀번호를 바꾼 뒤에도 예전 로그인이나 변경 직전에 시작한 로그인이 살아남는 일을 막기 위한 기반이다.

운영 화면에 비밀번호 찾기가 추가된 것은 아니다. P1-04 전체의 첫 세부 단계이며, 아직 실제 메일과 인증 공급자 변경·운영 로그인에는 연결하지 않았다. 기존 하린식품 비밀번호, UI, 주문·정산·출고 기능은 그대로다.

## 구현한 내용

1. 로그인 인증 전에 받는 접수표는 5분 안에 한 번만 사용한다. 계정과 발급 세대를 DB에 묶는다.
2. 비밀번호 변경 시작 시 새 로그인 발급 잠금·세대 변경·기존 허브 세션 폐기를 함께 저장한다. 일부 저장이 실패하면 전체를 취소한다.
3. 변경 전에 받은 접수표는 변경 완료 뒤에도 사용할 수 없다. 다른 계정의 세션은 건드리지 않는다.
4. 같은 진행 중 작업 재요청은 중복 처리하지 않는다. 다른 작업이나 오래된 완료 요청은 현재 잠금을 풀 수 없다.
5. 인증 서버의 비밀번호 변경과 공급자 세션 폐기가 확인된 뒤에만 서버가 잠금을 해제해야 한다. 연결 장애·시간 초과 시 이 연결부는 임의로 재시도하거나 해제하지 않는다.
6. 공개·일반 로그인 사용자에게 DB 함수 실행 권한을 주지 않는다. RPC 연결부는 명시적으로 주입한 서버 클라이언트만 사용하며 비밀키를 새로 저장하지 않는다.

이 접수표 자체는 비밀번호 인증 증거가 아니다. 후속 서버 조합부는 실제 인증 응답의 사용자 ID를 대조해야 한다. 이 파일의 메서드를 클라이언트가 보낸 사용자 ID로 곧바로 호출하는 HTTP API를 만들면 안 된다.

## 실제 검증 기록

- 실패하는 테스트를 먼저 실행한 뒤 후보 SQL·RPC 연결부를 구현했다.
- 합성 계정만 사용한 데이터 없는 Supabase 브랜치에서 기존 허브 세션 1건 폐기, 변경 후 새 세션 1건 발급, 이전 접수표 거부를 확인했다.
- 테스트 Supabase의 함수 4개 모두 SECURITY INVOKER이며 anon/authenticated 실행 권한 없음, service_role 실행 가능을 확인했다. anon/authenticated 역할로 실제 호출도 거부됐다. private 테이블 3개 모두 RLS 활성화·일반 사용자 SELECT 권한 없음.
- 호스팅 도구로 두 요청을 보냈을 때 PID 7350/7351은 달랐지만 두 번째 DB 실행은 잠금 대기 0.002초 수준이었다. 따라서 그 시험을 실제 겹치는 경쟁 검증으로 계산하지 않았다.
- 추가로 별도 로컬 PostgreSQL 17.11에서 연결 PID 29244/4260의 실제 `Lock` 대기를 조회했다. 변경이 먼저 시작하면 뒤늦은 발급 거부, 발급이 먼저 시작하면 변경이 기다렸다가 새 세션까지 폐기하는 양방향 시험 2개를 통과했다. 인증 공급자의 실제 비밀번호 API를 호출한 시험은 아니다.
- 전체 회귀 시험·빌드·최종 릴리스 상태는 아래 최종 검증 절에 기록한다.

## 남은 조건과 다음 개발

다음은 **P1-04-2: 실제 이메일·비밀번호 복구 연결**이다.

1. 발송 설정과 허용할 수신 주소를 확인한 후 이메일 확인·재설정 링크를 실제로 시험한다. 임의의 고객 주소로 메일을 보내지 않는다.
2. 만료·재사용·변조 링크, 중지된 계정, 발송/인증 서버 오류를 시험한다.
3. 모든 로그인 세션 생성 경로를 이번 접수표 방식으로 조합한다. 기존 직접 INSERT 경로가 남은 상태에서 복구 기능만 먼저 개방하지 않는다.
4. 인증 공급자 비밀번호 변경·공급자 세션 폐기 확인 후 잠금 해제, 불명확한 결과의 운영자 복구 절차를 구현한다. 로그인 요청 제한과 만료 접수표 보관 정리도 개방 조건이다.
5. 운영 인증서/제한 계정·실제 HTTP 흐름·기존 하린식품 로그인을 검증하고 전환한다. 이번 service_role SQL 시험은 이전 단계의 제한 연결 풀/TLS 검증을 대체하지 않는다.

이후 **P2 사업장 자료 격리 → P3 각 사업장 API 연결 → P4/P5 PC 전용 UI·EXE·인쇄** 순서를 유지한다. 현재 다른 사업장의 실데이터 가입·연결을 열지 않는다.
