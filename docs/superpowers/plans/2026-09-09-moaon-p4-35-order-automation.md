# P4-35 주문 자동 발급·등록

사용자 우선순위: 다른 페이지보다 주문을 먼저 완성. 웹 화면을 복사하지 않고 기존 출고 처리 기능을 앱 UI에 연결한다.

## 실행 범위
1. 현재 선택 주문의 출고 적격성·채널·최신정보 재확인.
2. 한 번의 명시 확인 후 필요한 준비 처리 → 우체국 발급 → 발급 완료 확인 → 플랫폼 등록.
3. 주문별 완료/대기/실패/결과불명 표시. 대기/불명 결과를 성공처럼 표시하지 않음.
4. 기존 발급 기록을 재사용해 앱 재실행·중복 클릭으로 중복 접수하지 않음.
5. UI: 단건과 선택 주문 모두 같은 자동 발급·등록 버튼, 수행 중 중복 조작 방지, 결과별 다음 행동 안내. 수동 도구는 보조로 유지.

## 검증 경계
Main 공개 명령과 기존 서버 API 계약, UI 클릭→명령→결과 표시, 설치 패키지. 모든 발급·등록은 가상 서버로만 시험한다. 운영 주문 출고/전송/인쇄를 시험 목적으로 실행하지 않는다.

## 작업 상태 — 0.23.0 설치 완료
- backend: 기존 웹 PREPARE → 우체국 발급 → 플랫폼 등록 계약을 앱 명령 하나로 연결했다. 최신 주문·취소·수취 정보 재확인, 기존 송장 재사용, 전송 전 영속 기록, 통신 유실 후 중복 전송 차단을 포함한다.
- 검토에서 발견한 Cafe24 저장 상태 지연, 같은 화면에서 대기 작업 재개, 수동/자동 등록 간 공통 전송 기록 문제를 수정하고 독립 재검토를 통과했다.
- UI: 단건/최대 20건 선택 `자동 발급·등록`, 주문별 단계와 결과, `진행 다시 확인`, `등록된 주문 보기`를 연결했다. 재확인 취소는 이미 접수한 작업을 취소하지 않으며 이전 결과를 유지한다. 기존 수동 도구도 보존했다.
- 패키지 재생성 후 설치 프로그램 종료 코드 0. 설치 EXE 버전 0.23.0을 확인했다.

## 검증 결과
- 단위시험 152/152 통과, 실패 0.
- 패키지 코드 + 개발 Electron의 격리 프로필: 자동 발급·등록 UI, 기존 다중 송장 등록, 패널 애니메이션/열 정렬, 1040/1440 너비 및 라이트/다크 화면 통과.
- 실제 설치 EXE + 기존 로그인 프로필: 2회 재실행 모두 추가 인증 없이 업무 화면 진입. 진입 확인 약 3.32초/2.58초(환경별로 달라질 수 있음).
- 운영 읽기: ACTIVE 1건, REGISTER 0건, IN_TRANSIT 2건, COMPLETED 87건 조회 및 다음/이전 페이지 통과. 조회당 약 2.0초. 이 수치는 검증 시점 스냅샷이다.
- 실제 설치 UI: 채널/상태 제목과 값의 중심 오차 0px, 패널 닫기 중 22개 목록 폭 관측, 닫힌 패널 비활성/화면 밖 이동, 스크롤바 숨김 통과.
- 운영 주문에 대한 발급·플랫폼 전송·인쇄는 실행하지 않았다. 외부 쓰기 종단간 운영 인수는 미완료이며 위 자동화 시험은 가상 응답 기반이다.

## 사용 방법
Cafe24 또는 쿠팡 판매자배송의 처리 가능한 주문을 선택하고 `자동 발급·등록`을 누른다. 확인 창에서 승인하면 필요한 준비 처리, 발급 결과 확인, 플랫폼 등록이 이어진다. 이미 발급된 송장은 재사용한다. 결과가 대기/확인 필요이면 다시 발급하지 말고 `진행 다시 확인`으로 상태를 조회한다.

## 다음 개발 — 주문 페이지 안에서 계속
1. 웹의 주문 수집·발급 작업 추적·부분 실패 복구 기능을 앱과 다시 대조하고 누락을 연결한다.
2. 송장 라벨/작업표 인쇄·내보내기와 실제 출고용 PC의 프린터 검증을 마무리한다.
3. 실제 출고 대상이 정해진 운영 인수에서 발급 번호와 각 플랫폼 등록 결과를 확인한다. 검증용 임의 발급은 하지 않는다.
4. 위 항목을 확인한 뒤에만 다음 페이지 이식을 시작한다.

네이버 스마트스토어·쿠팡 로켓그로스와 Cafe24 네이버페이 주문은 구별한다. 기존 서버가 지원하지 않는 출고 경로를 임의로 추가하지 않는다. 주문 전체 이식 완료 판정은 이 기능뿐 아니라 수집·추적·부분 실패 복구·문서 기능까지 대조 후 별도로 한다.
