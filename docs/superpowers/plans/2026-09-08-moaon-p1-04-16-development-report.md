# 모아온 P1-04-16 인증 전환 준비 점검

이번 작업은 P1-04-15에서 남긴 테스트 보강과 실제 연결 상태 점검이다. 사용자 화면·런타임 기능을 추가하지 않으므로 앱 버전은 1.58.0을 유지하고 커밋으로 구분한다.

## 재확인한 연결 상태

- app/api/dashboard/login/route.js는 기존 authenticateAccount에 owner·비밀번호·요청 정보를 전달한다. 신규 requestLimit·accountLimit·sessionFence를 전달하지 않는다.
- lib/dashboard-auth.js는 requestLimit을 명시적으로 전달받았을 때만 새 제한 로직을 호출한다. 새 IP 모듈 배포가 곧 운영 로그인 제한 활성화는 아니다.
- app/api/dashboard/logout/route.js는 기존 revokeSession 경로를 쓴다. 신규 로그아웃 요청 어댑터는 공개 경로에 연결되지 않았다.
- app/lib/scripts 검색에서 Vercel admission·새 로그아웃 요청·MFA provider 팩토리는 정의/내보내기 외 실제 앱 연결이 발견되지 않았다.

2026-09-08 운영 비로그인 검사: /login 200, /orders 307, /api/orders/page 401, /api/navigation/operation-snapshot 401. 버전 모두 1.58.0. 기존 접근 제어 응답 확인이며 실계정 인증 성공 증거가 아니다.

## 남은 실제 검증 조건

| 항목 | 현재 판단 | 필요한 다음 작업 |
| --- | --- | --- |
| Vercel 전달 헤더 | 외부 응답만으로 서버가 실제 받은 값을 증명할 수 없음 | 접근 제한된 시험 경로에서 위조 헤더 교체·직접 접속 여부 확인. 원본 IP 응답/로그 금지 |
| 실제 인증 공급자 | 이번 실계정 로그인·메일·MFA 실행 없음 | 검증 계정과 환경 지정 후 본인이 로그인/MFA 수행 |
| 키·DB 권한 | 이번 비밀값/catalog 조회 없음. 현재 준비 여부 미확인 | 지정 환경의 최소 권한·키 제공·후보 SQL 적용/복구 검수 |
| 사업장별 업무 격리 | 인증 부품만으로 증명 불가 | P2 주문·정산·파일·캐시의 교차 사업장 거부 검증 |

새 공개 로그인이나 IP 조회 주소를 임의로 열지 않았다. 내부 모듈 추가만으로 위 실검증 조건이 해소되지는 않는다. 다음 연결 작업은 검증 환경과 접근 제한된 시험 경계를 확정한 뒤 진행한다. 기존 하린식품 로그인은 유지한다.

## 검증 기록

시작 기준 2,521/2,521 통과(60.16초). 추가 후 집중 70/70, 전체 2,523/2,523(64.29초) 통과, 실패·취소·건너뜀 없음. 문법·diff 검사 통과. 작업 독립 검토는 지적 없이 승인됐다. 최종 검토와 배포 결과는 완료 후 기록한다. 기존 동작의 테스트 추가이므로 초기 GREEN을 그대로 기록하며 새 결함 수정의 RED/GREEN으로 표현하지 않는다. 런타임 코드가 같아 로컬 빌드를 다시 실행하지 않았고 기존 1.58.0 빌드 산출물을 이용해 청크 검사를 실행했다.

테스트 추가 커밋 0e193db. 정상 Vercel 환경에서 무시 대상 헤더 6종의 개별/통합 시나리오를 검증하며 필수 헤더가 없으면 매번 새 안전 오류와 RPC 0회를 확인한다. 필수 IP가 정상이면 모순된 대체 헤더가 있어도 기존 canonical IP 해시와 호출 순서를 유지하는지 검사한다. 실제 네트워크·DB는 사용하지 않는다.

최종 독립 검토(4300cb4..9da5d49)도 지적 없이 병합 승인됐다. 작업·최종 검토 모두 Critical/Important/Minor 0건이다. 이전 단계의 테스트 보강 항목을 이번 변경으로 해소했다.
