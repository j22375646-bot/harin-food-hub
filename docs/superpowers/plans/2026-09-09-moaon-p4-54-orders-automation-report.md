# P4-54 / 0.38.6 주문 자동 조회·배송 분류·UI 수정

## 사용자가 보는 변화

- 로그인 후 송장 등록 이력과 미완료 출고 기록을 자동 조회한다. 성공하면 수동 조회 버튼은 숨기고, 실패했을 때만 재시도 도구를 남긴다. 자동으로 불러온 이력은 접힌 요약이며 사용자가 직접 재조회하면 펼친다.
- 주문 목록과 상세 상품 이미지를 정사각형으로 맞췄다. 원본 비율은 보존한다.
- 결제금액은 셀뿐 아니라 실제 글자의 중앙선까지 제목과 맞췄다.
- Cafe24 공식몰 상품 이미지 경로를 제한적으로 허용했다. DB에 있던 상품 이미지가 앱 보안 허용 목록에서 차단된 것이 원인이었다.
- 상단 ‘확인’ 뱃지는 가로로 유지하고 긴 상태 문구는 잘라내지 않고 줄바꿈한다.

## 배송중 목록 조사와 수정

송장이 존재하지만 우체국 배송 추적 응답이 없는 주문에서 플랫폼이 배송중으로 알려준 상태를 집하 대기로 덮어쓰는 오류를 합성 주문으로 재현하고 수정했다. Cafe24 N30과 Coupang DELIVERING을 배송중으로 보존한다. Cafe24 N22는 배송보류이므로 배송중으로 분류하지 않는다.

운영 DB 읽기 전용 조사 시 Cafe24 N30, Coupang DELIVERING, Naver DELIVERING은 없었다. 따라서 수정 후 반드시 배송중 주문이 생긴다고 보장하지 않는다. 이는 저장 데이터의 관찰이며 각 플랫폼 원격 원장의 모든 주문을 직접 대조했다는 뜻이 아니다. 워커 ONLINE과 최근 수집 성공 기록은 확인했다.

## 남은 일과 다음 순서

1. 실제 설치본 로그인 진입 지연을 해결하고 운영 주문 조회를 재검증한다.
2. 기존 우체국 testYn=Y 시험 접수 성공 증거에 이어 플랫폼별 등록 결과·실패 복구를 확인한다. 임의 고객 주문에 가짜 송장을 보내지 않는다. 프린터는 이 API 검증의 선행 조건이 아니다.
3. 주문 페이지 인수 결과를 마감하고 오늘 → 캘린더 → 운영(정산) → 분석 → 설정의 앱 전용 기능 이식을 진행한다. 웹 화면 자체를 삽입하지 않는다.

이번 작업에서 실제 고객 송장 발급·등록, 유료 인프라 추가, DB 스키마 변경, 기존 설치 파일 삭제는 하지 않았다. 로그인 프로필은 유지했다. 주문 페이지 전체와 플랫폼 실등록이 끝났다고 주장하지 않는다.
