# MOAON P1-04-1: 비밀번호 복구의 세션 안전장치

## 범위

P1-04 전체 중 DB 세션 차단 장치를 먼저 구현한다. 기존 로그인/UI/운영 DB는 전환하지 않는다. 실제 이메일 확인·재설정 링크·SMTP·인증 공급자 쓰기·HTTP 경로는 후속 P1-04-2 검증 대상으로 남긴다. 이 결과만으로 비밀번호 복구가 운영 적용됐다고 보고하지 않는다.

## 설계

- 로그인 인증 전에 서버가 짧은 수명의 일회용 접수표를 발급한다.
- 비밀번호 변경 시작 시 계정 세대 번호를 증가시키고, 새 로그인 발급을 잠그고, 기존 허브 세션을 한 트랜잭션에서 폐기한다.
- 인증이 뒤늦게 완료되어도 이전 세대 접수표로 세션을 만들 수 없다.
- 인증 공급자의 비밀번호 변경과 공급자 세션 폐기가 모두 확인된 경우에만 같은 작업 ID로 잠금을 해제한다. 실패·불명확한 결과는 잠금 유지이며 자동 재시도하지 않는다.
- SQL 함수는 service_role 전용이며 클라이언트의 user ID/접수표를 그대로 전달하는 HTTP 경로를 만들지 않는다. 접수표는 인증 증거가 아니다. 실제 공급자 인증과 신원 대조는 후속 서버 조합부의 필수 조건이다.
- 보관 정리는 계정 삭제 FK에 연동한다. 만료/소비 접수표의 주기적 보관 정리와 요청 제한은 운영 개방 전 필요하다.

## 실행·검증

1. PGlite에서 실패 테스트를 먼저 작성: 정상 발급, 재사용·만료·다른 계정, 변경 전 접수표, 잠금·중복 작업·활성 해제·오류 롤백, anonymous/authenticated 접근 거부.
2. 후보 SQL과 서버 전용 명시적 RPC 연결부 구현. 기존 로그인 경로에는 연결하지 않는다.
3. 운영 자료 없는 Supabase 브랜치에 후보 SQL 적용 후 합성 계정으로 같은 흐름·권한 검증. 이는 메일 도착·실제 Supabase Auth 복구 검증을 대체하지 않는다.
4. 전체 회귀 시험·빌드·변경 검토. 결과와 후속 조건 기록.
5. 유료 테스트 브랜치를 삭제하고 목록에서 제거를 확인한다. 운영 main 브랜치는 유지한다.
