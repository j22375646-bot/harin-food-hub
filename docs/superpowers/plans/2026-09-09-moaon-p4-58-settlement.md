# P4-58 운영·정산 이식

## 진행 원칙

P4-57 설치본 재무 실조회는 로그인 필요로 미완료다. 그 검증을 완료 처리하지 않고, 로그인과 무관한 정산 변환 계층 개발은 진행한다. 이 문서는 전체 정산 페이지 완료 보고가 아니다.

## P4-58A: 구현 범위

- 기존 `buildUnifiedSettlementCenter`와 `buildPhase28SettlementModel`을 재사용하는 앱용 `buildWorkspaceSettlementSummary` 구현.
- Cafe24, 네이버, 쿠팡 판매자배송, 로켓그로스 네 채널을 분리한다. 중복/알 수 없는 채널은 거부한다.
- 실제 지급은 READY/PARTIAL/BLOCKED, 예상 지급은 ESTIMATED/BLOCKED로 구분한다. 미확인 금액은 null, 확인된 0원과 음수 차이는 그대로 유지한다.
- 비교 가능한 채널 수와 차이를 함께 반환한다. 일부 채널의 차이를 전체 사업장 확정 차이로 표시해서는 안 된다.
- 요청 기간이 없으면 다른 기간으로 바꾸지 않고 거부한다. 누락 채널은 NO_DATA로 명시한다.
- 원본 정산 증거 객체·계좌정보·웹 이동 주소는 전달하지 않는다. 날짜·금액·설명 등 허용 필드만 반환한다.

## 기존 웹 기능과 이식 순서

| 기존 기능 | 앱 이식 범위/상태 |
|---|---|
| 채널별 매출·환불·수수료·물류·광고·예상/실제 지급 | A: 변환 코드 구현. B: 권한 API, C: 앱 표시 연결 예정 |
| 일부 지급·정산 연결 부족·배송유형 원장 부족 | A: 기존 상태 유지. C: 카드/상세 안내 예정 |
| 지급 일정 | A: 날짜·금액·유형·상태 전달 규격 구현. C: 목록 예정 |
| 기간별 비교 | A: 기간 누락 거부. B: 기존 로더의 실제 지원 기간 대조 후 연결 |
| 수집·재연결·비용 입력 | 이번 코드에 쓰기 기능 없음. 별도 권한과 실제 지원 기능을 대조한 뒤 추가 |
| 원본 근거 상세 | 원본 전체 전달 금지. 필요한 항목을 별도 허용 목록으로 설계 예정 |

## 검증

새 변환 시험 6개와 기존 웹 정산 시험을 합쳐 **43/43 통과**. 실제 웹 계산기를 빈 자료로 실행해 앱에서 미확인 지급이 0으로 바뀌지 않는 통합 시험도 포함했다. 테스트 우선 방식으로 누락 기능의 실패를 확인한 뒤 구현했다.

최종 `npm test` 전체 **2,639/2,639 통과**, UI 디자인 검사와 diff 공백 검사도 통과했다.

운영 DB 조회·정산 API·설치 앱 표시 검증은 아직 하지 않았다. 이 단계는 새 API 경로를 공개하지 않으며 앱 설치 버전도 0.41.1을 유지한다. 운영 서버 배포/추가 과금/송장 쓰기는 없다.
