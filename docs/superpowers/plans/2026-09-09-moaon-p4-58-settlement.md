# P4-58 운영·정산 이식

## P4-58D: 재무 조회 제한 수정·정산 자료 시각 / 0.42.1

- 재무 transport의 30초 설정을 연결 계층의 공통 15초 값이 덮어쓰던 오류를 수정했다. 정산처럼 재무 전용 기본값을 사용하며 주문의 기존 제한은 바꾸지 않는다. 서버 속도 개선이나 실제 재무 조회 성공을 뜻하지 않는다.
- 실제 연결 함수를 가상 시계로 시험했다. 25초 시점까지 대기하고 30초에 TIMEOUT을 반환하는 회귀가 수정 전 실패, 수정 후 통과했다.
- 정산 조회 시각(generatedAt)과 채널별 자료 시각(asOf)을 구분하여 표시한다. 누락 시각은 확인 필요로 표시하며 현재 시각으로 대체하지 않는다. 실패/로그아웃 시 지난 금액과 시각을 제거한다.
- 기존 프리텐다드·색상·슬림 메뉴를 유지하고 자료 시각을 보조 정보로 배치했다. 새 장식선이나 상시 스크롤바는 추가하지 않았다.
- 검증: 앱 단위 테스트 **257/257 통과**. 패키지 app.asar를 격리 프로필의 개발 Electron으로 실행하여 정산·재무·주문 레이아웃 3종 통과. 정산의 시각 누락/실제 제공 시각/실패 초기화, 1040/1440 및 밝은/어두운 테마를 확인했다. 화면 데이터는 합성 시험 자료다.
- Windows 0.42.1 설치 패키지 빌드 성공. 운영 DB·서버·송장 발급 및 플랫폼 등록은 변경하지 않았다. 인증된 실제 재무/정산 조회는 이번 검증 범위에 포함하지 않았으며 완료로 표시하지 않는다.
- 이 PC 설치 종료 코드0, 설치 app.asar와 빌드 app.asar의 SHA256 일치 확인. 기존 앱 정상 종료 후 교체했으며 로그인 프로필은 삭제하지 않았다.

### 다음 개발 묶음

정산 전용 조회를 경량화하고 7/30/90일 기간 선택을 서버·앱에 함께 연결한다. 이후 근거 상세를 이식한다. 실제 인증 조회와 운영 자료 대조는 별도 인수 항목으로 유지한다.

## P4-58C: 앱 화면 연결 / 0.42.0

- 앱 전용 **운영·정산** 메뉴 추가. 최근30일 예상 지급/확인된 지급/대조 차이, 네 채널별 매출·수수료·물류비·광고비·지급 내역, 지급 일정 표시.
- 프리텐다드와 84px 슬림 메뉴, 기존 색상 토큰 사용. 1040/1440 창 크기와 밝은/어두운 테마에 대응. 채널 등장 동작은 짧게 적용하고 움직임 줄이기 설정에서는 끈다. 새 영역의 스크롤 기능은 유지하되 스크롤바는 숨긴다.
- 메인 프로세스의 고정 정산 GET을 IPC에 연결. 렌더러가 URL·사업장을 보내지 못하며, 요청 중에만 정확한 URL의 메인 GET을 허용한다.
- 응답 크기262,144바이트·30초 제한. 금액 문자열/비정상 날짜/중복 채널/알 수 없는 상태를 거부하고 원본 추가 필드는 버린다.
- 첫 메뉴 진입 자동 조회, 5분 내 재진입 조회 억제, 수동 새로 조회 지원. 조회 실패 시 이전 금액을 지우고, 로그아웃은 대기 요청을 중단한다. 주문 탐색으로 무효화된 응답이 주문 화면을 초기화하지 않도록 분리했다.
- 신규 JS/CSS를 앱 로컬 파일 허용 목록에 명시했다. 초기 UI 시험에서 파일이 차단되는 문제를 발견해 수정 후 재검증했다.

### 검증·설치

- 앱 전체 **256/256 통과**. 독립 검토에서 차단 문제 없음. 전송·연결 집중101개 통과.
- 최종 패키지: 정산 UI(부분/0/미확인/일정/실패/로그아웃/조회 억제), 기존 재무 UI, 기존 주문 레이아웃 시험 통과.
- 창 크기 변경 완료를 기다리고 카드 우측 경계도 검사해 화면 잘림을 확인했다. 시험 화면 이미지는 `desktop/dist/p458c-settlement.png`이며 **가상 데이터**다.
- 0.42.0 설치 종료0, 설치 app.asar와 빌드 app.asar SHA256 일치.
- 설치본 실제 정산 검사는 **LOGIN_REQUIRED**. 인증된 운영 금액 조회 성공으로 표시하지 않는다. 이번에는 서버 코드/DB/송장 발급/플랫폼 등록 변경 없음.

### 다음 작업

실제 인증 조회 검증은 별도 유지하면서, 기간7/90일과 정산 전용 조회 경량화, 조회 시각·채널 자료 시각 표시, 근거 상세를 이어간다. 실제 자료를 확인하지 않은 상태에서 전체 정산 기능 이식 완료로 표시하지 않는다.

추가 확인 사항: 기존 `readFinance()`는 transport 기본30초와 별개로 hub-connection의 기본15초 `timeoutMs`를 넘긴다. 이전 P4-57의 앱30초 변경이 실제 연결에 적용됐는지 다음 회귀에서 바로잡아야 한다. 이번 정산 경로는 해당15초 값을 전달하지 않고 전용30초 기본값을 사용한다.

## P4-58B: 30일 정산 권한 API

- 추가 경로: `GET /api/moaon/businesses/{tenantId}/settlement`. 현 단계는 최근 30일만 지원하며 쿼리 매개변수/다른 기간 요청은 거부한다.
- 기존 서명 로그인 세션과 하린식품 고정 사업장 OWNER를 조회 전후로 확인한다. 조회 중 소속·역할·세션·버전이 바뀌면 금액을 폐기한다.
- P4-57의 읽기 전용 권한 연결을 재사용한다. 서버 요청은 25초 제한, 내부 오류는 원문 SQL/비밀정보 없이 정해진 오류 코드만 반환한다.
- P4-58A 변환 계층을 실제 HTTP 응답에 연결했다. 개인 응답은 `private, no-store`로 공유 캐시를 금지한다.
- **범위 변경:** 전용 경량 로더 대신 검증된 기존 메인 로더를 우선 재사용했다. 7/90일과 불필요 조회 제거는 미완료이며 성능 개선 완료라고 표시하지 않는다.
- 검증: 신규 권한/기간/권한 변경/시간 초과/원문 비노출 시험 포함 집중13개 통과. 전체 `npm test` **2,644/2,644 통과**, Next 빌드 성공. 실제 라우트 모듈 비로그인 호출 **401 AUTH_REQUIRED** 확인.
- 앱 UI/새 EXE는 이번 범위가 아니다. 다음은 **P4-58C 앱 정산 메뉴와 30일 요약·채널·지급 일정 화면 연결**이다. 실제 인증 조회·7/90일·근거 상세와 경량화는 별도 남은 항목이다.

P4-57 설치본 재무 실조회는 로그인 필요로 미완료다. 그 검증을 완료 처리하지 않고, 로그인과 무관한 정산 변환 계층 개발은 진행한다. 이 문서는 전체 정산 페이지 완료 보고가 아니다.

## P4-58A: 구현 범위

- 기존 `buildUnifiedSettlementCenter`와 `buildPhase28SettlementModel`을 재사용하는 앱용 `buildWorkspaceSettlementSummary` 구현.
- Cafe24, 네이버, 쿠팡 판매자배송, 로켓그로스 네 채널을 분리한다. 중복/알 수 없는 채널은 거부한다.
- 실제 지급은 READY/PARTIAL/BLOCKED, 예상 지급은 ESTIMATED/BLOCKED로 구분한다. 미확인 금액은 null, 확인된 0원과 음수 차이는 그대로 유지한다.
- 비교 가능한 채널 수와 차이를 함께 반환한다. 일부 채널의 차이를 전체 사업장 확정 차이로 표시해서는 안 된다.
- 요청 기간이 없으면 다른 기간으로 바꾸지 않고 거부한다. 누락 채널은 NO_DATA로 명시한다.
- 원본 정산 증거 객체·계좌정보·웹 이동 주소는 전달하지 않는다. 날짜·금액·설명 등 허용 필드만 반환한다.
