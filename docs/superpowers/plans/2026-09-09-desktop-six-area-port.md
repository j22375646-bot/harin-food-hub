# 모아온 웹 기능 앱 이식 — 6개 업무 영역

사용자 승인 범위: 오늘, 주문, 운영(정산), 분석(인사이트), 캘린더, 설정.
기존 웹 기능과 API·계산을 재사용하고 앱 전용 UI를 유지한다. 웹 페이지 임베딩을 이식 완료로 간주하지 않는다.

## 공통 제약
- 채널과 사업장 격리, 원천 최신성, 미확인 금액 표시를 보존한다.
- 키·쿠키는 렌더러에 전달하지 않는다. Main의 고정 경로와 검증된 IPC만 허용한다.
- 발급·송장 전송·일정 삭제 등 실제 업무 쓰기는 최종 확인·중복 방지·결과 확인을 유지한다. 시험은 격리된 가상자료로 수행한다.
- 앱 공통 스크롤바 숨김, 휠 유지, Pretendard, 기존 앱 디자인을 유지한다.
- 구현, 시험, 설치, 운영 검증을 구분한다. 전 영역 완전 이식 전까지 전체 완료로 표시하지 않는다.

## Task 1: 주문 이식의 미연결 UI 완성
desktop/ui/app.js, 주문 UI 관련 격리 테스트만 수정한다. 기존 채널 조회와 송장등록 Main 구현을 호출하는 누락된 changeOrderChannel/registerSelectedInvoices를 완성한다. viewChannel enum ALL/CAFE24/NAVER/COUPANG; 새 조회는 이전 선택을 초기화하고 늦은 결과를 폐기한다. registerInvoices는 현재 페이지 최대20건 선택, 중복클릭 잠금, 결과REGISTERED/PENDING/FAILED/CHECK_REQUIRED를 구별한다. registrationEligible 투영 보존. 선택한 행의 내용 확인과 단건 송장 등록 진입을 제공하되 발급과 등록을 구분한다. 로그아웃/페이지 변경 시 결과를 다른 목록에 표시하지 않는다. 무조건 성공 처리나 POST 재시도 금지. 기존 order-tools smoke의 채널 fixture를 서버 필터 의미에 맞춰 갱신하되 검증을 제거하지 않는다. 실제 운영 주문 발급/등록 금지.

## Task 2: 6개 영역 기능 목록 및 API 대조
웹 버튼·조회·변경·공통 기능과 앱 지원 여부를 코드 경로로 기록한다. 최소 단위로 미이식 기능을 추적한다. 메뉴 추가만으로 완료 표시 금지.

## Task 3: 오늘·운영·분석·캘린더·설정 순차 이식
Task2 대조표에 따라 읽기 계약을 먼저 만들고, 같은 영역의 변경·실패·재조회까지 연결한 뒤 다음 영역으로 이동한다. 오늘의 업무 집계, 정산의 채널별 원장/비용/대조, 인사이트의 근거·기간·보고서, 캘린더 조회/등록/수정/삭제/사은품, 설정의 계정·연결·기기·프린터를 포함한다. 지원하지 않는 다사업장 경로를 하린 고정 데이터로 대신하지 않는다.

## 검증 및 인도
단위/격리 Electron 시험 → 기능·보안 리뷰 → 패키지 → 설치본 스모크 → 가능한 읽기 운영 검증. 라이브 쓰기는 시험의 일부로 실행하지 않는다.

현재 상태: Task1 구현/리뷰/시험 및0.22.0 설치 완료, Task2 대조 완료. Task3 미착수. 실제 등록 전송은 가상자료로 검증했으며 운영 시험 송장 발급/전송은 하지 않았다. 주문 전체 흐름과6영역 전체 완료는 아니다.
