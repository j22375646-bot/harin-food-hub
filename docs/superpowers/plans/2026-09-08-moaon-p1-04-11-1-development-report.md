# 모아온 P1-04-11-1 개발 보고서

## 이번 단계: 추가 인증 공급자 검증

여러 사업자가 모아온에 각자 로그인해 사용하는 구조를 위해, 중요한 계정 복구 작업 전에 본인을 한 번 더 확인하는 서버 모듈을 만든다. P1-04-10이 인증 증거를 검사하는 문지기였다면, 이번 단계는 인증 서비스에 실제 SDK로 인증번호를 확인하고 결과를 검증하는 연결부다.

구현·집중 검사·빌드·독립 검토 및 수정분 재검토를 완료했다. 운영 배포는 아래 증거가 기록되기 전까지 미확인이다. 실제 운영 계정 인증이나 기능 활성화 완료를 뜻하지 않는다.

## 변경 범위

- 인증 앱의 6자리 TOTP 번호와 이미 등록·확인된 인증 수단을 사용한다.
- 인증 서비스의 서명, 사용자, 세션, 인증 수단, 발급·만료 시각을 검사한다.
- 인증이 성공하면서 바뀐 자격 증명은 후속 서버 저장 계층에만 전달하는 구조로 만든다. 화면이나 로그에 노출하지 않는다.
- 시간이 초과되거나 결과가 불확실하면 후속 작업을 허용하지 않는다. 이미 발송된 인증 요청이 원격에서 완료됐을 가능성을 숨기지 않는다.
- 기존 로그인·비밀번호·UI·주문·정산 API·운영 DB와 환경 설정은 변경하지 않는다.

## 이번에 결정한 사항과 한계

1. 공급자 인증 검증과 허브 세션의 영속 저장/폐기를 분리했다. 두 세션은 서로 다른 신원이므로 같은 ID로 간주하면 안 된다. 그만큼 실제 활성화는 다음 단계까지 기다려야 한다.
2. 이미 확인된 TOTP 인증 수단만 지원한다. SMS 비용과 계정 등록 변경을 피하지만, 인증 수단 등록 화면은 후속 개발이 필요하다.
3. 결과가 불확실한 인증 요청은 자동 재시도하거나 자동 로그아웃하지 않는다. 원격 인증은 이미 성공했을 수 있어 후속 세션 정리 절차가 필요할 수 있다.
4. 시계 함수는 생략하면 Date.now를 사용하고, 명시하면 함수만 받는다. 명세의 기본값과 필수 함수 표현이 겹친 부분을 이 기준으로 정리했다.
