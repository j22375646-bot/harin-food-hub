# P4-45 — 주문 등록 결과 보존과 인수 점검

2026-09-09 / 모아온 Windows 0.30.1 — 이 PC 설치·검증 완료

## 목표와 범위

기존 웹 기능을 앱 전용 화면에서 안전하게 사용한다. DB·API·서버·고정 IP는 기존 것을 재사용하며 웹 화면 자체를 넣지 않는다. 실제 출고/송장 전송/물리 인쇄를 시험 목적으로 실행하지 않는다.

## 이번 코드 대조에서 확인한 기능 경계

| 기능 | 앱 코드 상태 | 인수 경계 |
|---|---|---|
| 채널별 주문/단계/페이지 조회 | 기존 사업장 API 연결 | Cafe24·네이버·쿠팡 선택 제공. 조회와 새 수집은 다름 |
| 준비 → 우체국 발급 → 플랫폼 등록 | issueAndRegister 연결 | 실제 고객 주문 종단간 인수 미완료. 네이버/로켓그로스 자동 발급 대상 제외 유지 |
| 이미 발급된 송장 등록 | registerInvoices 연결 | 이번에는 대기/실패/확인 필요 결과의 화면 이동 후 보존 보완 |
| 서버 등록 이력 | 기존 GET /api/shipping/actions | 우체국 전체 발급 이력이 아니며 서버 최신 작업 범위만 조회 |
| 배송정보/상품 이미지/사은품 | 서버 DTO 및 보충 조회 연결 | 서버 근거 없는 사은품이나 주소를 앱에서 추정하지 않음 |
| 라벨 | 로컬 단건 100×150mm 미리보기·인쇄 설정 | 출고 PC의 실제 프린터/용지 인수 필요. 일괄 출력/출고목록/내보내기 미이식 |
| 등록 후 배송추적 갱신 | 미이식 | 웹 orders-page.js issueAndTransfer는 queueAndPollTracking을 호출하지만 앱에는 해당 연결 없음 |
| 지금 수집 | 미이식 | 웹 POST /api/orders/live-refresh는 앱의 저장 주문 새로고침과 다름 |

이 대조는 소스 확인이며 실제 외부 API 성공을 뜻하지 않는다. 전체 주문 페이지 완료로 표시하지 않는다.

## 구현 내역

1. 수동 송장 등록의 혼합 결과를 출고 확인 목록에 유지한다. 완료 항목은 제거하고 취소/BUSY는 새 확인 항목을 만들지 않는다.
2. 결과에서 서버 이력 조회로 연결하고 읽기 전용임을 명확히 한다. 재전송/재발급 버튼으로 오인하지 않도록 한다.
3. 결과 행의 주문 ID와 상태를 정렬하고 좁은 폭에서는 줄을 나눈다. 이력 버튼의 기본 사각 테두리를 앱 테마 기반 8px 둥근 버튼으로 교체했다. 키보드 포커스도 유지한다.
4. 서버 이력은 조회 후 자동으로 펼친다. 재확인 버튼 중복/잔존을 제거하고 이전 화면에서 만든 버튼의 실행을 차단한다.
5. 실제 Electron UI 시험, 전체 단위 시험, 설치본 로그인/표 정렬/패널 전환을 검증했다.

## 검증 결과

- 기존 우체국 발급·배송추적·채널 전송 관련 로컬 시험 40/40 통과. 실제 외부 접수/전송 호출 시험이 아니다. 기존 Next route의 Node 모듈 유형 경고 1건은 남아 있으며 이번 앱 변경 범위에서 루트 package type은 바꾸지 않았다.
- 앱 단위 시험 169/169 통과.
- 혼합 결과 보존 시험에서 수정 전 0건/기대 3건 실패를 재현하고 수정 후 통과했다. 성공 항목 제거와 화면 이동 뒤 늦은 응답의 목록 불변도 검사했다.
- 수동 등록/자동 출고 패키지 app.asar UI 시험 통과(개발 Electron, 격리 프로필 및 시험 응답). 자동 펼침으로 기존 테스트가 패널을 다시 닫던 실패를 수정 후 재통과했다.
- NSIS 빌드 성공, 설치 종료 코드 0. 설치본 버전 0.30.1 확인.
- 실제 설치 EXE 재실행 두 번 로그인 유지: 3.831초/2.403초. 네 주문 구간과 다음/이전 페이지 실제 조회 통과. 측정 시점 값이며 속도 보장은 아니다.
- 설치본 정렬 오차 0px, 패널 전환 22프레임, 접힘 중 내용 유지/비활성/화면 밖 위치, 스크롤바 숨김 통과.
- 별도 읽기 전용 코드 검토에서 범위 내 스펙/품질 PASS. 지적된 테스트 공백 두 건을 추가 보완했다.

## 다음 개발 P4-46

등록 후 배송추적 조회/갱신 계약과 안전한 앱 연결을 구현한다. 신규 수집, 일괄 문서/내보내기, 실제 출고 인수는 이후 순차 진행한다. 낮은 창 높이에서 여러 이력을 함께 펼치면 주문 목록 공간이 줄어드는 점은 결과 영역 통합/접힘 동선의 추가 UI 점검 대상으로 남긴다.

이번 시험에서는 실제 우체국 접수·쇼핑몰 송장 전송·물리 인쇄를 하지 않았다. 다른 출고 PC의 장비 인수와 실제 고객 주문 종단간 완료는 아직 별도다.
