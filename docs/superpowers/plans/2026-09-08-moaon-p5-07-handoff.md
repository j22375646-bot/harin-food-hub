# P5-07 — 모아온 0.7.0 출고 사전 확인

## 개발 내용

오른쪽 주문 상세 맨 위에 저장 자료 기반 출고 사전 확인을 추가했다. 기존 목록 API 응답으로 계산하므로 추가 API 호출, 새 IPC 권한, 송장 발급 요청은 없다.

- 취소/취소 요청, 배송 진행/완료, 기존 송장 증거는 출고 대상 제외로 안내한다. 잘못된 형식의 송장 기록도 없는 것으로 무시하지 않는다.
- 네이버 주문과 로켓그로스는 별도 처리 경로로 안내한다. Cafe24와 쿠팡 판매자배송만 허브 확인 경로로 분류한다. Cafe24 네이버페이 결제 주문을 스마트스토어 주문으로 바꾸지 않는다.
- 주문 식별번호, 단계, 수량, 서버 출고/선택 플래그, 취소/송장 필드 누락, 일부 채널 누락을 확인한다.
- 수취인 이름/주소 존재, 우편번호 5자리, 연락처 숫자 형식을 Main에서 확인하지만 실제 개인정보는 렌더러에 전달하지 않는다. 저장 주소의 유효성·배달 가능성을 증명하는 검사는 아니다.
- 조건 충족은 '웹 허브 최종 확인 후보'이다. 발급 승인, 실시간 최신 주문 검증, 중복 발급 방지 트랜잭션을 뜻하지 않는다. 실행 버튼은 여전히 제공하지 않는다.

- 데스크톱 단위 41/41 PASS, 기존 허브 전체 2,541/2,541 PASS.

## 남아 있는 로그인 검증 문제

설치 EXE 로그인 제출 검사에서 1회 실패했다. 비밀번호 없는 시험 폼을 제출할 때 문서 상태complete/폼연결true였지만 네트워크 정책 cancel=true와 창닫힘을 관측했다. 원인은 아직 확정하지 못했다. 로드 오류 코드와 요청 창 식별자만 추가 기록하도록 시험 도구를 보완한 뒤 8회 연속 PASS였다. 이 결과를 원인 해결 또는 실제 사용자 인증 성공으로 보고하지 않는다. 실제 비밀번호/입력값/페이지 본문을 수집하지 않고 시험 POST는 항상 전송 전에 취소한다.

## 설치와 다음 개발

개인용 미서명0.7.0 설치본으로 교체했으며 공개 배포·유료 자원·클라우드 브랜치 생성 없음. 앱 종료로 세션이 지워졌으므로 다시 로그인해야 한다. 기존 운영 웹/DB/인증 코드에는 변경이 없다.

다음 단계에서는 간헐 로그인 창 종료의 원인 분리를 먼저 진행한다. 이후 실제 출고 확인·요청·결과 흐름을 기존 서버 안전장치와 연결한다. 읽기 전용 사전 확인 결과를 그대로 쓰기 권한으로 사용하지 않고 발급 직전 최신 주문/이력 재검증과 중복 실행 방지를 적용해야 한다. 이번 인도에서 실제 송장은 발급하지 않았다.
