# 주문 작업실 개선 계획

현재 설치본 점검에서 확인한 배송정보 안내, 탭 표시, 시작 속도 문제를 순서대로 다룬다.

- [x] 배송정보 조회의 대기·지연·정보 부족·조회 실패를 구분한다. 확인이 필요한 주문의 상품명과 채널을 기존 상태줄에서 확인하고 그 주문만 재조회할 수 있게 한다. 쿠팡은 진행 중인 작업을 이어서 조회하고 실패가 확정된 작업은 다음 재조회에서 다시 요청한다.
- [x] 탭의 저장 건수와 조회 상태 문구를 일치시킨다. 주문 목록의 접근성 이름은 실제 연결 여부에 맞춘다. 캐시에서 복원한 집계가 이미 확인된 최신 집계를 덮지 않게 한다.
- [x] 응답 분류, 주문별 재조회, 목록 유지, 연결·조회·수집 회귀를 검증한다. 앱 패키지를 만들고 이 PC의 설치본 및 바로가기에 적용한다.

재조회는 기존 배송정보 조회 경로를 사용한다. 실제 송장 발급·출고는 시험에 사용하지 않는다. 속도는 앱 초기화, 화면 처리, 운영 서버 조회를 별도로 측정한다.

## 검증 및 설치 결과

- 코드 시험 574개 통과. 쿠팡 시간 초과 후 같은 작업 조회와 확정 실패 후 새 작업 시작을 각각 확인했다.
- 0.224.0 패키지 파일 166개를 소스와 대조했다. 격리 Electron에서 배송정보 안내 다섯 종류, 한 주문만 재조회, 기존 주문 유지, 집계와 접근성 이름, 1440·1040·900px와 두 테마를 확인했다.
- 격리 자동화에서 초기 앱 준비 약 141초, 합성 단건 재조회 약 3.6초가 관측됐다. 운영 요청과 사용자 시작 시간은 미측정이다.
- Windows 설치 파일과 Ed25519 업데이트 서명을 생성했다. D 드라이브의 관리 설치본과 바로가기 4개는 0.224.0이다. 공개 업데이트 채널은 배포하지 않았다.
- 기존 0.223.0 세션은 열려 있다. 종료 후 다시 시작한 실제 0.224.0 세션에서의 로그인과 운영 조회 확인이 남았다.

## 다음 개발

1. 앱 실행부터 창 표시와 첫 주문 목록 표시까지 걸리는 시간을 각각 기록한다. 첫 진입과 탭 재방문은 별도로 측정한다. 기록은 구간명, 시간, 성공 여부만 보관한다.
2. 실제 계정으로 조회가 가능한 상태에서 탭 재방문, 전체 검색, 배송정보 상세 조회를 반복 측정한다. 네트워크 대기와 화면 처리를 나눠 어느 구간을 줄여야 하는지 정한다.
3. D 드라이브 I/O 기록과 앱 시작 시간을 대조한다. 지연된 조회에서도 저장 목록과 선택을 유지하고 상태 표시가 낡지 않는지 회귀 시험을 확장한다.
