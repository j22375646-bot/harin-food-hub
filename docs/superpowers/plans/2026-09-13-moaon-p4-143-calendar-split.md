# P4-143 · 업무·이벤트 캘린더 분리

## 사용자 요청과 구성

모아온 0.130.0 / 서버 1.59.0. 업무 관리와 이벤트 기획을 별도 메뉴로 나누고 기존 이벤트·사은품의 주문 적용을 유지한다.

- 업무 캘린더: 기존 담당자/체크리스트 업무 보드, 날짜별 업무, 일정과 메모. 선택한 날짜를 기한으로 업무·체크리스트를 바로 등록할 수 있다.
- 이벤트 캘린더: 기간별 띠지와 겹침별 줄 배치, N(네이버)·C(쿠팡)·24(카페24) 배지. 주를 넘어가는 기간은 다음 주에 이어 표시한다. 일요일·토요일·공휴일을 구분하고 공휴일 조회 불확실성은 유지한다.
- 기획 핵심 항목: 목표, 대상 고객, 혜택/메시지, 준비사항, 결과/회고. 새 이벤트는 기획 중이며 진행 확정으로 저장한 경우에만 사은품 자동 적용 대상이 된다. 사은품 조건은 선택 사항으로 접어 둔다.
- 진행 플랫폼은 복수 선택 가능하며 하나 이상 필요하다. 플랫폼이 없는 기존 이벤트는 기존처럼 전체 플랫폼으로 해석한다. 기존 이벤트를 복사하거나 별도 DB로 이관하지 않고 같은 ID와 저장 데이터를 이벤트 화면에서 보여준다.
- 메뉴 우선순위: 오늘 → 주문·배송 → 고객·CS → 업무 캘린더 → 이벤트 캘린더 → 재고 → 상품 → 키워드 → 분석 → 운영·정산 → 앱 설정.

## 서버·주문 연결

- 기존 이벤트 본문 JSON에 플랫폼·기획 필드를 추가하며 4,000자 저장 한도를 유지한다. DB 스키마 변경 없음.
- 기존 웹/앱 클라이언트가 새 필드를 보내지 않고 수정해도 이전 플랫폼·기획 내용을 보존한다.
- 주문 어댑터가 플랫폼, 한국 날짜의 이벤트 기간, 실결제 금액으로 가장 높은 충족 사은품 구간을 판정한다. 기획 중/잘못된 설정/다른 플랫폼은 적용하지 않는다.
- 이벤트 저장/수정/삭제 후 월간 조회와 주문 재조회를 실행한다. 출고 도중에는 재조회 안내를 남긴다. 앱이 플랫폼·기획 저장 응답을 대조해 이전 서버의 무시 응답을 성공으로 표시하지 않는다.
- 실제 고객 업무·이벤트·주문을 시험으로 생성하거나 출고하지 않았다.
