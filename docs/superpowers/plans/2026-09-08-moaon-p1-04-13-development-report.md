# 모아온 P1-04-13 개발 보고서

## 목적과 현재 상태

계정별 로그인과 저장된 추가 인증이 로그아웃 때 함께 종료되도록 내부 연결을 구현한다. 화면을 바꾸거나 새로운 계정을 실제 운영에 개방하는 단계는 아니다. 시작 소스2d66476, 전체 기준 검사2,448/2,448 통과(57.32초, 실패·취소·건너뜀0). 구현988c02a에서 새 검사13/13, 집중 회귀70/70, 전체2,461/2,461(75.12초, 실패·취소·건너뜀0)과 빌드가 통과했다. 독립 검토·배포 검증 진행 중.

## 사용자 관점 동작

1. 현재 로그인 표의 진위를 확인한다. 사용자가 다른 계정 ID를 입력해서 로그아웃 대상을 바꿀 수 없게 한다.
2. 허브 로그인 세션을 먼저 폐기한다.
3. 해당 세션에 저장된 추가 인증과 암호화 자격 증명을 정리한다.
4. 뒤의 정리가 실패해도 앞에서 폐기한 로그인은 되살리지 않는다. 오류는 비밀값 없이 구분하며 자동 재시도로 중복 작업하지 않는다.

## 정한 조건과 한계

### 독립 검토에서 수정한 내용

시스템 시간이 뒤로 보정되면 두 번째 작업의 대기 한도가 늘어나는 문제가 발견됐다. 실패 테스트에서 제한 시간 내 거부되지 않음을 확인하고, `3875475`에서 경과시간 기준 `performance.now()`로 바꿨다. 로그인 표의 만료일을 검사하는 기존 인증 코드는 그대로다. 수정 후 단위·통합14개, 전체2,462/2,462(70.09초, 실패·취소·건너뜀0), 최종 빌드가 통과했다. 수정분 독립 재검토에서도 문제 해결을 확인했다. 전체 최종 검토와 운영 배포는 진행 중이다.

- 신규 처리기는 공개 경로에 연결하지 않는다. 실제 인증·키·운영 SQL 검수가 미완료이므로 새 동작을 사용자가 지금 이용할 수는 없다.
- 세션 폐기 후 증거를 정리한다. 정리가 실패하면 접근할 수 없는 암호화 자료가 남을 수 있어 후속 정리 확인이 필요하다.
- 전체 시간 제한을 넘으면 성공으로 표시하지 않고 자동 재시도·되돌리기를 하지 않는다. 이미 보낸 서버 작업은 늦게 완료될 수 있으므로 원자적 취소를 보장하지 않는다.

## 현재 운영 경로와 남은 전환 조건

소스 점검 기준 기존 `/api/dashboard/login`은 owner 로그인과 기존 비밀번호 처리를 유지한다. 새 세션 fence와 요청 제한 부품은 아직 공개 호출에 주입하지 않는다. 기존 `/api/dashboard/logout`은 세션 폐기 후 쿠키를 지우며 이번 내부 처리기를 호출하지 않는다.

공개 연결 전에는 신뢰된 프록시/IP·요청 제한, 실제 Auth 계정/MFA·키 관리, 운영 SQL 권한, 로그아웃 오류의 안전한 기록과 실패 안내, 기존 로그인 회귀를 함께 검수해야 한다. 쿠키 삭제만으로 서버 폐기 성공을 확정하지 않는다. 이번 작업은 공급자 전체 기기 로그아웃이나 Supabase Auth 세션 삭제를 수행하지 않는다.

## 검증 범위

실제 로컬 PGlite와 후보 SQL, authenticateAccount/createAuthSessionStore의 로그인, validateSession/revokeSession, createStepUpStorage의 암호화 저장·조회·폐기를 연결했다. 비밀번호 인증과 MFA 공급자 응답은 가명 대역이며, 실제 사용자 로그인·이메일·운영 데이터·native DB 다중 연결 시험과 다르다. A/B 두 계정 격리, 반복 로그아웃, 재로그인 시 옛 인증 재사용 거부, 정리 실패 후 세션 비활성을 확인했다.

기존 production 파일 변경 없이 새 내부 처리기1개, 테스트2개, 테스트 DB 연결 도우미1개를 추가했다. 비밀값·임의 신원·위조 토큰·설정 getter·시간 초과·늦은 결과·오류를 다룬다. 신규 유료 자원·운영 데이터 복사·DB 테스트 브랜치는 만들지 않았다.
