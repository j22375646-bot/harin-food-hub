# P4-54 주문 UI 밀도 보완 — 0.38.2

## 결과

0.38.1에서 실패했던 주문 화면 밀도 검사를 수정하고, 0.38.2 설치본까지 확인했다. P4-54의 실제 출고 장비·실주문 인수는 여전히 별도다.

## 바뀐 화면

- 전체 채널 수집 도구를 주문 목록 위에서 페이지 제목 오른쪽으로 이동했다. 주문 상태 탭과 목록이 위로 올라온다.
- 전체 검색·기간, 현재 페이지 검색, 변경 확인의 불필요한 패딩과 여백을 줄였다. 프리텐다드와 기존 라벤더·다크 테마를 유지했다.
- 수집 진행·실패·채널별 결과와 목록 변경 알림은 계속 표시한다. 수집과 채널 필터의 적용 범위도 안내한다.
- 작은 창에서 여러 결과를 펼쳐도 목록 최소 높이 150px와 하단 이력 버튼 접근을 유지한다. 보이는 스크롤바는 없지만 휠·키보드 스크롤은 유지한다.
- 검색·채널·선택·발급·등록·출력·이력 버튼이나 API 로직은 삭제하지 않았다.

## 같은 조건 비교

시험 주문 8건, 상세 패널 열린 상태, 1440 × 900 창 기준이다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 첫 주문 상단 위치 | 466.89px | 317.80px |
| 주문 목록 높이 | 218px | 367px |
| 왼쪽 메뉴 너비 | 84px | 84px |
| 가로 화면 넘침 | 없음 | 없음 |

1040 × 900에서도 첫 행 313.80px, 목록 높이 373px. 라이트·다크 모두 동일 조건 통과. 스크린샷의 주문과 누락 이미지는 시험 자료이며 실제 상품 이미지 수집 결과가 아니다.

## 검증 기록

- 수정 전 기존 화면 밀도 검사 실패 재현, 수정 후 기준을 낮추지 않고 통과.
- 앱 단위 테스트 **230/230 통과**.
- 패키지 코드 UI **8종 통과**: 화면 배치, 수집, 전체 검색·기간, 서버 필터, 변경 감지, 자동 발급·등록, 송장 등록, 선택 주문 문서.
- 1040 × 720 최소 창에서 수집 결과·출고 결과를 펼쳐도 수집/상태확인/재조회/선택해제/서버이력/이전이력 버튼 접근 가능.
- 수집 요청 중 중복 잠금·선택 유지·명시적 재조회·로그아웃 응답 폐기 검사 유지.
- 실제 설치 EXE 0.38.2 읽기 전용 검사: 로그인 재입력 없이 주문 진입, 열 정렬 오차 0px, 패널 확장 22프레임, 닫힘 후 inert·화면 밖 이동·스크롤바 숨김 통과.
- Windows 설치 파일 빌드 및 이 PC 설치 성공. 설치본/빌드 app.asar SHA256: `CBAC5236D59ABDFFBB7E890C2DBCA785FB504F3B3B2482EBC7FB5393FF484A2F`.

패키지 UI 시험은 격리 프로필에서 시험 응답을 사용했다. 실제 설치본 검사는 읽기 전용이다. 실제 우체국 발급·플랫폼 전송·인쇄는 실행하지 않았다. 서버·DB·API 계약 변경 및 유료 인프라 추가도 없다. 설치 파일은 비공개 Preview이며 코드 서명은 없다.

## 다음 단계

주문 화면의 기존 밀도 실패 항목은 해결했다. 다음은 출고용 PC에 0.38.2를 설치하고 실제 프린터/용지/바코드 및 지정한 소량 실주문의 우체국 발급 → 플랫폼 등록 → 출력 결과를 인수하는 것이다. 현재 개발 PC의 가상 출력 장치만으로 완료 처리하지 않는다. 주문 페이지 마감 후 다음 페이지 이식을 진행한다.
