# P4-43 — 출고 확인 목록의 주문 찾기

2026-09-09 / 모아온 Windows 0.29.0

## 구현

기존 사업장 주문 API는 단건 검색을 지원하지 않아 앱에서 제한된 페이지 조회를 사용한다. 주문 ID의 채널을 선택한 뒤 ACTIVE → REGISTER → IN_TRANSIT → COMPLETED 순으로 총 최대 8페이지(페이지당 최대 20건)를 조회한다. 서버와 DB, 고정 IP 설정은 바꾸지 않았다.

- 찾은 경우 해당 페이지의 서버 DTO와 커서를 적용하고 선택 주문 상세를 연다.
- 제한 도달은 SEARCH_LIMIT, 모든 구간을 확인했지만 없으면 NOT_FOUND로 구분한다. 일부 응답이 PARTIAL이었다면 미발견을 확정하지 않는다.
- 현재 페이지의 주문은 ‘주문 확인’, 페이지 밖이면 ‘주문 찾기’를 표시한다.
- 찾는 동안 연결 상태 안내에 최대 8페이지 범위를 표시한다.
- 못 찾거나 제한에 도달해도 과거 출고 확인 항목을 삭제하지 않는다.
- 검색은 GET만 사용한다. 발급·등록·취소는 실행하지 않는다.
- 동시 찾기/출고 처리 중 요청을 거부하고, 로그아웃·채널 전환 뒤 도착한 응답은 폐기한다.

## 검증

- findOrder 미구현 실패를 재현 후 다음 페이지 주문 발견 시험 통과.
- 8회 조회 한도, 잘못된 ID 거부, 로그아웃 후 응답 폐기 검사 통과.
- 전체 단위 시험 167/167 통과. 마지막 부분조회 판정 보완 후 연결 단위 시험 61/61 재통과.
- 출고 확인 UI의 다른 구간 이동 → 주문 찾기 → 페이지/상세 복귀 검사 통과.
- 같은 UI를 패키지 app.asar로 검사해 통과(개발 Electron 실행).
- NSIS 빌드 성공.
- 설치 종료 코드 0. 설치 EXE에서 실제 Cafe24 완료 주문을 조회해 선택한 주문과 일치하는 FOUND 응답 확인(COMPLETED, offset 0, 7.872초). 측정 시점 값이며 검색 속도 보장은 아니다. 실제 주문 ID/수취정보는 보고서에 기록하지 않았다.
- 실제 EXE 재실행 2회 로그인 유지, 네 주문 구간 및 다음/이전 페이지 조회 통과. 진입 2.586초/2.497초.
- 설치 앱의 표 정렬 오차 0px, 패널 접힘/확장·내용 유지·스크롤바 숨김 검사 통과.

## 한계 및 다음 개발

API가 페이지별로 전체 주문 자료를 읽는 구조이므로 무제한 검색하지 않는다. 8페이지를 넘으면 현재 도달한 페이지에서 수동 조회가 필요하다. 더 큰 주문량을 위해서는 서버의 정확한 주문 ID 조회 API를 별도 설계·검증해야 한다.

이 기능은 기존 서버에 저장된 주문을 찾으며 플랫폼에서 주문을 새로 수집하는 기능이 아니다. 실제 우체국 발급·플랫폼 송장 등록·물리 출력은 이번 테스트에서 실행하지 않았다.

다음은 다른 출고 PC에서도 확인할 수 있는 서버 작업 이력 조회 범위를 조사하고, 주문 페이지의 실운영 인수 항목을 점검한다.
