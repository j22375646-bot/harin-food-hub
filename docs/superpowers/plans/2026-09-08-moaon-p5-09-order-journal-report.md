# 모아온 P5-09 — 주문별 작업 기록·중복 실행 차단

개발일: 2026-09-08

[전체 개발계획·단계별 현황](./2026-09-07-multi-business-desktop-master-plan.md) · [직전 0.11.0 인도 기록](./2026-09-08-moaon-p5-09-confirmation-report.md)

## 이번에 해결한 문제

기존 내부 발급 코어는 사업장당 기록 한 건을 사용했다. 그 작업이 끝나도 초기화하지 않는 안전 정책 때문에, 실제 앱에 그대로 연결하면 다른 주문까지 새로 처리할 수 없는 구조였다. 기록을 지워 다음 주문을 처리하면 중복 발급 방지 근거가 사라지므로, 주문마다 기록을 따로 보존하도록 보완했다.

## 개발 내역

1. **주문별 기록:** 사업장과 주문을 함께 구분한다. A 주문의 완료/결과 불명 상태가 B 주문을 차지하지 않는다. 파일명에는 사업장·주문 원문 대신 해시를 사용한다. 내용은 기존 최소 상태만 저장하며 수취인 개인정보나 비밀번호는 저장하지 않는다. 해시는 암호화라는 뜻이 아니다.
2. **같은 주문은 한 작업:** 동시에 여러 번 호출되어도 디스크를 읽는 시점부터 같은 작업을 공유한다. 다른 주문은 각각 별도로 관리한다.
3. **이전 기록 보존:** 기존 사업장 단위 파일은 삭제하지 않는다. 같은 주문이면 복구에 사용하고 다른 주문이면 별도 기록을 만든다. 손상된 기록을 빈 기록으로 바꾸지 않고 차단한다.
4. **연결 해제:** 초기화 중인 작업과 진행 중인 통신을 차단한다. 진행 작업이 정리될 때까지 기다리는 종료 함수를 제공한다. 다음 연결이 이전 작업과 겹치지 않도록 호스트에서 반드시 이 함수를 기다려야 한다.
5. **재시작:** 접수 결과를 모르는 주문은 `UNKNOWN`으로 유지한다. 자동 재전송/초기화 기능을 추가하지 않았다.

## 검증 범위

- 실제 임시 디렉터리에 기록을 저장·복구하는 시험과 합성 API 응답 시험을 사용했다. 고객 주문 발급은 실행하지 않았다.
- 서로 다른 주문/사업장 분리, 동일 주문 동시 클릭, 완료 후 다른 주문 처리, 재시작 중복 방지, 이전 기록 유지, 손상 기록 차단, 연결 해제 중 초기화/통신 경합을 확인했다.
- 데스크톱 전체 테스트: **89/89 통과**, 실패 0.
- 기존 허브 전체 회귀 테스트: **2,548/2,548 통과**, 실패 0.
- 독립 읽기 전용 검토: 병합을 막을 결함 없음. 검토자가 발급 관련 집중 테스트 **35/35**를 별도로 실행했다.
- `git diff --check` 통과. 이번에는 UI/패키징 변경이 없어 새 EXE 빌드·설치·실제 Windows 화면 시험은 수행하지 않았다.

검토 시 확인한 통합 조건: Main은 같은 인증 세션에 관리자를 하나만 만들어야 한다. 이 factory 자체가 여러 인스턴스 생성을 금지하지는 않는다. 또한 요청 중단은 서버에서 이미 시작한 발급의 취소를 의미하지 않으므로, 다음 실행에서 결과 불명 상태를 자동 재발급하지 않는다.

## 적용 상태와 남은 작업

이번 변경은 **Main 내부 모듈**이다. 기존 0.11.0 설치 앱의 UI나 웹 허브를 바꾸지 않았고 새 설치파일/운영 배포를 만들지 않았다. 실제 발급·출력 완료 또는 다사업장 운영 개방으로 해석하면 안 된다.

다음 구현 단위는 인증 연결부가 이 관리자를 소유하도록 연결하고, 명시적 발급 확인 후에만 고정 API를 호출하며 진행 상태를 표시하는 것이다. 로그인 만료·연결 해제·앱 재시작까지 함께 검증한 뒤 새 EXE를 인도한다. 실제 고객 주문/프린터 시험은 별도 확인을 거친다.

운영 DB 복사, 유료 테스트 브랜치, 새 서버 또는 유료 서비스 신청은 없었다.
