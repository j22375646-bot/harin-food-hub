# P5-14 / 0.15.0 로그인 우선 진입·앱 전용 디자인

## 변경 결과

앱을 시작하면 업무 화면보다 **로그인 진입 화면**을 먼저 표시한다. 기존처럼 샘플 주문 메인이 먼저 나오지 않는다.

1. 시작 시 기존 `viewActive` 읽기 경로로 저장된 세션을 확인한다. 인증 확인만을 위한 별도 API를 추가한 것은 아니며 기존 주문 조회가 함께 수행된다.
2. 유효한 세션의 READY/PARTIAL 응답이면 업무 화면으로 들어간다. 서버가 세션을 유효하다고 인정해야 하므로 임의로 로그인 유지 기간을 늘리지 않는다.
3. 로그인이 필요하면 로그인 화면에 머문다. **로그인하고 시작하기**를 누르면 기존 보안 로그인 창에서 비밀번호를 입력한다. 앱 자체가 비밀번호를 받아 저장하거나 인증 API를 새로 구현하지 않는다.
4. 로그인 취소·세션 만료·로그아웃 시 업무 화면을 숨기고 키보드 접근도 차단한다.
5. 403 접근 거부나 세션 초기화 실패는 원래 안내를 보존한다. **저장된 로그인 해제**로 복구를 시도할 수 있다. 프린터 점검은 로그인 전에도 가능하다.

## 디자인

- 모아온 블루, 네이비, 밝은 캔버스와 기존 다크 테마를 사용하는 중앙 카드형 구성.
- 기울어진 모아온 심벌을 한 가지 포인트로 사용하고 긴 홍보 문구를 줄였다.
- 카드 진입 450ms, 보안 로그인 창 350ms 전환과 버튼 hover를 적용했다.
- OS의 동작 줄이기 설정에서는 해당 애니메이션을 비활성화한다.
- 보안 로그인 창은 기존 서버 폼을 그대로 두고 여백·둥근 모서리·버튼·테마 스타일만 앱 안에서 조정한다. 웹사이트 원본 로그인 페이지나 비밀번호는 변경하지 않았다.

## 검증

- 데스크톱 자동 테스트 **110/110 통과**.
- 개발 코드 및 패키징된 app.asar의 실제 Electron 화면 시험: 초기 로그인 화면, 로그인 취소 시 잠금 유지, 유효 세션 진입, 만료 시 복귀, 403 이후 로그인 해제 통과.
- 패키징 코드의 기존 송장 미리보기/연결 해제, 로그인 전 실제 OS 프린터 열거 시험 통과.
- 로그인 테스트는 합성 응답을 사용했고 실제 비밀번호는 입력하지 않았다. 보안 창 시각 시험 역시 합성 폼으로 동작을 확인한 것이므로 운영 인증 성공 인수를 대체하지 않는다.
- 독립 검토에서 403 복구 경로 누락을 지적받아 해제 버튼과 원래 오류 메시지 보존을 추가했다. 수정 재검토에서 추가 중요 문제 없음.
- 라이트·다크 스크린샷 확인 및 Windows x64 NSIS 빌드 완료.
