# 모아온 P1-04-4 개발 보고서

## 이번 작업의 의미

직전 단계는 비밀번호 복구 전의 지연 로그인과 계정 정보 변경 경합을 막는 연결을 준비했다. 검토에서 남은 문제는 앱 서버와 DB 서버의 시계가 다를 때 정상 로그인도 거부될 수 있다는 점이었다.

예를 들어 앱 시계가 5분 빠르면 앱이 정한 “12시간 뒤”는 DB에게 “12시간 5분 뒤”가 된다. DB는 보안 상한 초과로 발급을 거부한다. 이번에는 허용 시간을 늘리지 않고 DB가 정한 같은 발급·만료시각을 토큰과 저장 요청에 사용하도록 한다.

## 범위

- 릴리스 대상: 1.46.0 / P1-04-4.
- 읽기 전용 `moaon_get_session_window` 후보 RPC와 서버 저장 연결부, 명시적 fenced 로그인 소비 경로.
- 조회는 사용자와 유효한 로그인 접수표에 묶이며 세션 생성·접수표 소비·복구 해제를 하지 않는다. 실제 저장은 기존 프로필·차단·세대·접수표 검사로 결정한다.
- 오류·불완전 응답·시간 초과 때 앱 시각으로 대체하거나 직접 저장으로 우회하지 않는다.
- 기존 기본 로그인·UI·비밀번호·업무 API는 유지한다. 운영 SQL 적용이나 새 인증 경로 활성화는 하지 않는다.
- 추가 유료 DB·서버·패키지 설치 없이 PC 내부의 합성 계정과 PGlite로 검증한다.

## 검증 기록

시작 기준22f2a0d에서 인증 관련 7개 파일 100/100 통과, 실패·건너뜀 0. 실제 운영 기본 응답은 로그인200, 주문307 로그인 이동이며 버전1.45.0이다.

구현 커밋529f7d1. 구현 담당과 주 작업자 모두 수정 전 전체2,165/2,165 통과(실패·건너뜀0)를 확인했다. 독립 검토에서 프로필 조회가 지연되는 동안 로그인 접수표가 만료되어도 오래된 시각을 반환할 수 있는 문제를 추가로 발견했다. 커밋2226425에서 모든 자격 조회 이후의 DB 시각으로 만료를 판단하도록 보완했다. 지연 회귀 검사는 변경 전 실패, 변경 후 통과했으며 SQL 검사19/19를 통과했다.

수정본의 별도 재검토와 최종 빌드·전체 검사는 진행 중이며, 완료 후 이 절에 기록한다. 배포 SHA·READY·실제 주소 응답은 릴리스 실행 결과로 별도 보고한다.

앱과 PGlite의 전역 시계를 함께 변경하면 두 시계가 같이 움직여 실제 오차 시험이 되지 않았다. 따라서 앱 모듈만 별도 실행 공간(VM)에 넣어 ±5분 변경하고 DB는 실제 시계로 유지했다. 변경 전 +5분에서 발급 실패를 재현했으며, 변경 후에는 DB 기준 만료 저장·토큰 발급과 정상 시각에서의 토큰 유효성을 확인했다.

전체 검사에는 기존 모듈 형식 경고와 의도적으로 만료시킨 모의 복구 세션의 고정 진단 메시지가 있다. 실제 인증·메일 요청이나 개인정보 출력으로 해석하지 않으며, 이 경고를 없애기 위해 운영 인증 설정을 바꾸지는 않았다.

## 검증 범위의 한계

앱 시계 ±5분에 대한 시험은 **새 로그인 발급 만료값 산정**에 관한 것이다. 기존 요청 시점의 쿠키 만료 검사와 인증 공급자 확인 시각 정책 전체를 DB 시각으로 바꾼 것은 아니다. DB 자체의 시계가 갑자기 바뀌는 상황도 별도로 운영 점검해야 한다.

PGlite는 로컬 단일 연결 검증이다. 지연 회귀 검사도 합성 RLS 정책으로 조회 지연을 만드는 시험으로, 실제 다중 연결의 잠금 경합 시험과는 다르다. 실제 hosted PostgREST 응답·다중 연결 DB·메일 발송·모든 발급 경로 전환을 입증하지 않는다. 공개 가입·다사업장 실사용·Windows EXE 완료를 뜻하지 않는다.
