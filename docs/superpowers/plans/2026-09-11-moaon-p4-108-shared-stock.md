# P4-108 · 상품/공유 재고 분리와 주문 목록 정리 (0.94.0)

## 변경

- 기존 재고·상품 메뉴를 상품으로 변경하고 재고 메뉴를 분리했다.
- 재고는 PC 로컬 저장소가 아닌 Supabase 사업장 공용 DB를 사용한다. 상품명, 제조번호, 제조일자, 유통기한, 보관방법, 단위, 수량, 메모를 등록·수정한다. 검색과 기한 경과/30일 이내 필터를 제공한다.
- 인증된 사업장 문맥으로 조회/수정을 제한한다. OWNER/OPERATOR만 수정 가능하고 VIEWER는 읽기만 허용한다. 수정 직전 권한 재확인, revision 충돌 검사, 신규 등록 재시도 UUID 유지, 변경 이력을 적용했다. 연결 해제 이후 도착한 UI 응답을 버린다.
- 20260910184833_moaon_shared_stock_lots.sql을 운영 Supabase에 적용했다. 공개/브라우저 역할의 직접 테이블 접근과 RPC 실행을 차단한다. RLS no-policy advisory는 서버 전용 접근을 위한 의도적인 deny-by-default 상태다.
- 주문 목록의 중첩 외곽 테두리를 정리하고 체크박스 머리글을 정렬했다. 옵션 없는 상품은 수량만 표시한다. 주문시각은 채널 옆 별도 열에 월·일·시·분만 표시한다.
- 상품 API의 503/404/시간 초과 원인을 구별하여 표시한다.

## 검증 및 제한

- 서버 코드 2,782개 PASS. 신규 재고 및 상품 집중 시험 8개 PASS.
- 실제 Supabase에서 격리 UUID를 이용한 트랜잭션 시험 후 ROLLBACK: 신규 등록, 동일 요청 재시도, revision 갱신/충돌, 변경 이력, 타 사업장 분리, 공개 역할 접근 차단. 테스트 재고는 남기지 않았다.
- Next.js 기본 Turbopack 빌드는 외부 node_modules junction 때문에 실패했다. next build --webpack은 성공했다.
- 인증된 운영 상품 API는 503 WORKSPACE_UNAVAILABLE이었다. 운영 서버는 오래된 56094df 기준이다. 최신 상품 조회 코드가 운영에서 해결되었다고 주장하지 않는다.
- Vercel CLI 운영 배포는 Not authorized로 실패했다. 따라서 새 stock API 운영 배포와 실제 두 PC 간 사용 검증은 미완료다. DB 스키마 적용과 앱/서버 후보 구현을 운영 API 완료와 구분한다.
- 실주문 송장 발급/출고, 물리 출력, 고객 정보 수정은 실행하지 않았다.
