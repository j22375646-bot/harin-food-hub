# P4-39 — 쿠팡 배송정보 조회와 재확인 UI

2026-09-09 / 모아온 Windows 0.26.0

## 원인 및 구현

앱의 누락 배송정보 조회는 Cafe24만 지원했다. 웹의 `coupangDetail`과 `loadDeliveryDetail`, 서버 ORDER_DETAIL 워커, publicOrderDetail 응답을 대조했다.

앱 Main에서 서버가 내려준 쿠팡 판매자배송 shipmentId를 비공개로 보관한다. 선택된 주문의 배송번호로 `/api/coupang/orders/detail`을 요청하고, 반환된 UUID에 한해 `/api/coupang/operations/{id}`를 조회한다. API 키는 앱에 넣지 않으며 기존 서버·DB·고정 IP 구조를 유지한다. 주문 변경/송장 등록 API는 이 조회에 사용하지 않는다. 상세 조회 GET은 서버의 읽기 작업 큐 항목을 생성할 수 있다.

- 쿠팡 `safeNumber`를 화면의 연락처 필드로 변환.
- 주소·상세주소·우편번호·수취인·연락처·메모만 제한된 길이로 반환. 원본 응답/비밀 필드는 노출하지 않음.
- 응답 shipmentBoxId가 선택한 주문과 다르면 표시하지 않음.
- Main의 현재 허용 URL만 요청 가능. 렌더러의 직접 호출은 거부.
- 동일 주문 동시 조회는 하나로 합침. 같은 로드된 주문의 재확인은 기존 조회 UUID 재사용.
- 최대 10회 결과 조회, 기본 전체 15초 제한. 대기/실패를 완료로 꾸미지 않음.
- 로그아웃/목록 변경 후 늦게 도착한 수취인 정보는 폐기.

## UI

- Cafe24와 쿠팡 주문에서 이름/주소가 없으면 추가 조회.
- 읽는 동안 ‘배송정보 불러오는 중…’, 대기는 대기 안내 표시.
- 주문을 닫았다 다시 열 필요 없이 ‘배송정보 다시 확인’ 버튼 사용.
- 조회 중 중복 클릭 차단, 상태 안내 role=status 및 aria-busy 적용.
- 완료 후 재확인 버튼 숨김, 주소는 텍스트로 표시. 다른 주문 선택 후 이전 결과를 덮어쓰지 않음.
- 기존 앱 디자인·패널 구조를 유지한 동작 디테일 보완이며 새 시안 작업은 아님.

## 검증 근거

- 수정 전 쿠팡 readDelivery가 CHECK_REQUIRED를 반환하는 실패를 재현한 후 READY 전환 검증.
- UI에서 재확인 버튼이 나타나지 않는 실패 재현 후 대기 → 버튼 → 주소/연락처 표시 통과.
- 전체 단위 시험 160/160 통과.
- 배송정보 UI 격리 시험 및 패키지 app.asar 시험 통과. 패키지 검사는 개발 Electron에서 실행.
- 자동 출고 결과 UI 회귀 시험 통과.
- 잘못된 UUID, 다른 shipmentBoxId, 로켓그로스의 판매자배송 조회 차단 시험 통과.
- 시간 초과 후 기존 작업 재조회 및 로그아웃 후 늦은 응답 폐기 시험 통과.
- NSIS 설치 파일 빌드 성공.
- 설치 프로그램 종료 코드 0. 실제 EXE 0.26.0 두 번 재실행 시 추가 로그인 없이 진입(3.959초/2.485초, 해당 시점 측정).
- 실제 서버 주문 네 구간 조회 및 완료 목록 다음/이전 페이지 통과. 발급 전 1건, 등록 후 0건, 배송중 2건, 완료 87건 응답. 이는 새 쿠팡 상세조회 성공을 뜻하지 않음.
- 설치된 앱의 표 정렬 오차 0px, 패널 접힘/확장 22프레임 변화, 내용 유지·inert·스크롤바 숨김 검사 통과.

## 완료라고 하지 않는 범위

운영 쿠팡 주문을 대상으로 새 상세조회 큐가 성공하는 과정은 아직 별도 인수 대상이다. 단위/격리 UI 시험에서는 시험 응답을 사용했다. 실제 우체국 발급·플랫폼 송장 등록·물리 출력은 수행하지 않았다.

추가로 받아온 배송정보는 화면 표시용이며 송장 발급 자격을 임의로 허용하지 않는다. 발급 전 서버 주문 재검증과 기존 중복 방지 장치는 유지한다. 앱 재시작/목록 새로고침 후 조회 UUID 지속 복원은 이번 범위 밖이다.
