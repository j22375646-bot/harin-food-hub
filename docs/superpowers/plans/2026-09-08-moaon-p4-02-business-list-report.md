# P4-02 사업장 선택용 목록 조회

## 결과와 계획 보정

사업장 선택 화면 연결에 앞서 확인한 결과, 기존 제어 저장소에는 특정 사업장 회원 권한 조회만 있었고 본인의 사업장 목록 조회는 없었다. 운영 인증과 제한 DB adapter의 실제 연결도 미개방 상태다. 따라서 화면 연결 전체를 완료로 표시하지 않고 필요한 서버 내부 목록 조회를 먼저 추가했다.

`createTenantControlStore().listBusinesses({sessionCredential})`는 기존 서버 인증 adapter로 본인을 확인하고, DB에서 그 사용자의 ACTIVE 회원·ACTIVE 사업장만 조회한다. 요청에 별도 userId를 넣어도 그것으로 조회하지 않는다. 반환 필드는 tenantId, displayName, role, membershipVersion뿐이다. API 키·회원 이메일·원시 DB 행은 반환하지 않는다.

목록은 권한 증명서가 아니다. 선택 이후 각 업무 요청에서 서버가 현재 membership을 다시 검증해야 한다. 조회 결과는 캐시하지 않아 다음 호출에 변경된 역할·버전·정지 상태가 반영된다. 200개 초과 시 조용히 목록을 누락하지 않고 BUSINESS_LIST_LIMIT 오류를 반환한다. 목록 조회 실패·인증 만료를 정상 0개로 바꾸지 않는다.

## 검증

기존 제어 저장소 16개 baseline 통과 → 신규 함수 미구현 상태의 실패 확인 → 구현 후 관련 80개 시험 통과(신규 목록 6개 포함). 로컬 PGlite에서 실제 SQL을 실행했고 인증·시간·장애 일부는 제어된 시험 adapter를 사용했다. 운영 DB, 실제 두 사용자 인증 및 여러 DB 연결 경합 검증 결과는 아니다.

- 본인 사업장과 최소 반환 필드, 외부 userId 무시.
- 정지 사업장·정지/탈퇴 회원 제외, 정상 가입 사업장 없음은 빈 배열.
- 잘못된 인증·만료·조회 중 만료·DB 실패를 오류로 보존.
- 역할 변경 뒤 새 조회에 최신 역할·버전 반영.
- 200개 허용·201개 초과 명시 오류.
- 기존 인증 adapter·전환 상태 검사 회귀 포함 80/80 통과.

## 적용 상태

서버 내부 모듈과 시험만 변경했다. 새 공개 API endpoint, 로그인 교체, 운영 DB migration, 앱 UI 활성화, 새 설치파일 생성은 하지 않았다. 현재 앱은 0.15.1 유지. 화면에서 사업장을 선택할 수 있게 된 단계가 아니다. 테스트 주도 개발 기준에 따라 실패 사례를 먼저 추가했고 기존 격리 작업공간에서 검증했다.
