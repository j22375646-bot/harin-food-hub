# 모아온 P1-04-5 요청 제한·복구 검토 계약

승인된 P1 인증 연결 후속 작업이다. 기존 운영 로그인·화면·비밀번호는 그대로 두고, 명시적으로 조합하는 새 인증 경로의 요청 제한과 복구 검토 저장 기반을 완성한다. 운영 SQL/인증 전환은 별도 게이트다.

- 요청 제한은 서버 인스턴스 메모리가 아니라 DB에 저장한다. 같은 종류·대상에 대한 요청을 원자적으로 소비하며 DB 잠금 획득 후 시간을 판단한다. 거절 시에도 횟수 상태를 되돌리지 않는다.
- 고정 창 정책: LOGIN 15분 10회, RECOVERY_MAIL 1시간 3회, RECOVERY_COMPLETE 15분 5회, EMAIL_CONFIRM 15분 5회. 성공·실패에 관계없이 공급자 요청 전 횟수를 소비한다. 기존 비밀번호 실패 5회 차단을 대체하지 않는다.
- 서버 전용 HMAC 키로 종류와 대상을 묶어 식별한다. 이메일·계정·토큰 원문을 제한 테이블이나 오류/진단에 저장하지 않는다. 클라이언트가 제한값·시각·해시·키를 결정하지 못한다.
- DB 장애·잘못된 응답·시간 초과는 실패 시 차단한다. 로컬 카운터나 기존 경로로 우회하거나 자동 재시도하지 않는다. 늦은 응답은 quota를 소비했을 수 있으나 후속 인증/메일/세션을 실행하지 않는다.
- 복구는 위험 작업 시작 전에 PENDING 검토 행을 내구성 있게 저장한다. 프로세스가 중단되면 그 행을 조회할 수 있어야 한다. 불명확한 결과는 REVIEW_REQUIRED, 명백한 시작 거부는 REJECTED, DB의 복구 완료가 확인된 경우만 COMPLETED다.
- 검토 이력에는 서버 검증 UUID·고정 상태/단계·DB 시각만 저장한다. 비밀번호·메일·토큰·공급자 오류 원문은 저장하지 않는다. 검토 목록은 신뢰한 서버용이며 고객 OWNER에게 전역 계정 목록을 노출하는 HTTP 경로는 만들지 않는다.
- 검토 저장 실패 시 위험 작업을 시작하지 않는다. 위험 작업 이후 기록 실패는 기존 PENDING 행을 남기고 REVIEW_REQUIRED를 반환한다. 이력 저장/목록 조회는 계정 잠금을 해제하거나 공급자 작업을 재시도할 권한이 아니다.
- 운영 기본 로그인은 새 의존성을 전달하지 않으므로 기존 동작 유지. 기존 세션 쿠키·API·공급자 경계·SQL 발급 상한과 복구 차단 순서를 유지한다. 새 복구 조합에서 reviewStore를 생략하면 이전 서버 계약은 유지되지만, 운영 개방에는 새 limiter/reviewStore가 모두 필수다.
- 단위·PGlite 실제 SQL/재개방 검증과 독립 연결의 로컬 PostgreSQL 경합 검증을 구분한다. 기존 PC의 PostgreSQL만 재사용하고 외부 유료 자원·실제 계정·메일·운영 자료 복사는 금지한다.
- IP/전체 서비스 제한, 계정 별칭 통합, 보관기간 정리 작업, 지원 관리자 검토 화면·수동 해결 절차, 실제 Auth/SMTP/HTTP 전환은 다음 개방 전 조건이다. 이번 제한만으로 분산 공격 전체를 막았다고 주장하지 않는다.
