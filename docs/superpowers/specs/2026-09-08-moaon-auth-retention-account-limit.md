# P1-04-7 인증 제한 기록 수명과 계정 합산

기존 P1-04-6의 미활성 인증 기반을 이어간다. 운영 로그인·UI·비밀번호·업무 API·환경 설정을 유지하며 운영 SQL, 유료 자원, 실제 메일, 운영 자료 복사를 실행하지 않는다. 새 가입·EXE 완성을 주장하지 않는다.

## 정리 규칙

제한 테이블은 감사 원장이 아니라 짧은 요청 창의 카운터다. DB 시각 기준 창 시작 후 24시간보다 오래된 대상별 및 IP 행만 한 번에 각 500개까지 정리한다. 현재 최대 제한 창 1시간보다 충분히 늦게 정리하며, GLOBAL 행·미래 시각·사용 중 잠긴 행·계정·세션·복구 검토 기록은 삭제하지 않는다. 스케줄러/운영 활성화는 이후 단계다.

정리와 요청이 동시에 실행돼도 살아 있는 제한을 지우거나 존재하던 행이 중간에 사라져 요청이 실패해서는 안 된다. 소비자는 충돌 시에도 행 잠금을 획득한 채 현재 값을 반환하는 UPSERT를 사용한다. 정리는 FOR UPDATE SKIP LOCKED로 사용 중 행을 건너뛰고, 여러 정리 실행도 작은 묶음만 처리한다. 시간·보관 기간·삭제 대상을 클라이언트가 지정할 수 없다. 응답은 삭제 건수만 제공하며 식별값은 반환하지 않는다.

정리 경합 검증에 따른 시각 규칙 보완: 사용 횟수가 0이고 시작 시각이 현재보다 미래가 아닌 행의 첫 요청은 잠금 획득 후 DB 시각에서 제한 창을 시작한다. INSERT 기본값이 잠금 대기 전에 계산되는 문제를 막는다. 미래 시각의 0회 행과 기존 1회 이상 행은 기존 규칙을 유지하며 PostgreSQL 시스템 튜플 필드에 의존하지 않는다.

## 계정 합산 규칙

입력 문자열별 사전 제한과 IP/전체 제한을 유지한 뒤, 서버가 조회한 활성 프로필의 검증된 user_id에 추가 로그인 한도를 적용한다. 아이디·이메일이 같은 프로필로 연결되면 합산하며 이름 변경 후에도 user_id가 같으면 같은 제한이다. 서로 다른 계정을 이메일의 점·플러스 주소 같은 추정 규칙으로 병합하지 않는다. 이번 범위는 로그인 별칭의 카운터 통합이지 가입 중복 계정 병합이나 Auth 이메일 변경 처리의 완성이 아니다.

후보 accountLimit 의존성은 명시적으로 주입할 때만 작동한다. 활성화하려면 기존 requestLimit도 필요하다. 프로필이 잘못됐거나 제한 응답이 모호하면 외부 인증/접수표/세션 발급 전에 실패한다. 알려지지 않은 계정과 비활성 계정은 기존 인증 실패 경로를 유지한다. 원문 계정 ID도 SQL 인수로 보내지 않고 기존 HMAC 제한 어댑터를 재사용한다.

## 인수 기준

실제 SQL 보관 경계·한 번의 처리 상한·권한·롤백, 실제 PostgreSQL 잠금/정리 경합, 실제 로그인 소비자에서 아이디/이메일 교대 10회 허용 및 11회 거절, 시간 초과 후 인증 미진행, 기존 미주입 경로의 회귀 검사를 요구한다. 작업별 독립 검토와 최종 전체 검토/빌드/전체 테스트 후 코드만 배포한다.
