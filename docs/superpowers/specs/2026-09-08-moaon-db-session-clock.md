# MOAON P1-04-4 DB 기준 로그인 만료 계약

직전 P1-04-3 최종 검토에서 앱이 DB보다 앞서면 앱 기준 +12시간 만료가 DB의 +12시간 상한을 넘는 문제가 남았다. 이번 범위는 그 발급 경로의 시계 의존성을 제거하는 서버 코드와 미적용 후보 SQL이다.

- 새 fenced 로그인은 DB가 계산한 발급 기준시각과 12시간 뒤 만료시각을 사용한다. SQL의 최대 12시간 상한을 늘리거나 앱 시계 오차만큼 수명을 연장하지 않는다.
- DB 시각 조회는 유효한 사용자·로그인 접수표에 한정된 읽기 전용 RPC다. 발급/접수표 소비/복구 해제 권한이 아니다. 실제 저장은 기존 원자적 프로필·세대·접수표 검사를 그대로 거친다.
- DB 시각 조회 실패·불완전 응답·시간 초과에서 앱 시각으로 대체하지 않는다. 새 조회는 기존 제한시간을 적용하고 늦은 응답에서 후속 세션을 만들지 않는다.
- 기존 기본 로그인·UI·비밀번호·v2 쿠키·업무 API·현재 세션 검증 정책은 유지한다. 새 서버 의존성은 필수인 명시적 fenced 경로에만 추가한다. 운영 route/환경 설정은 변경하지 않는다.
- 후보 SQL은 운영에 적용하지 않는다. 공개 가입·복구 화면, 실제 SMTP/계정 변경, 유료 테스트 자원, 추가 패키지 설치는 범위 밖이다.
- 앱 시계 ±5분과 DB 시계를 분리한 로컬 시험에서 실제 SQL·저장 모듈·로그인 함수를 조합해 양방향 발급 성공과 DB 기준 만료를 확인한다. DB 자체의 시계 점프, 요청 시점의 parseSession/validateSession 시각 정책, 인증 공급자 확인 시각 정책은 이 시험만으로 해결됐다고 주장하지 않는다.
- 실제 hosted PostgREST·다중 연결 PostgreSQL·SMTP·모든 발급 경로 전환·사업장 데이터 격리는 별도 운영 개방 조건이다.
