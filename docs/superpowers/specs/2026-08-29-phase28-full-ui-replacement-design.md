## 1. 결정과 목적

V106 시안은 운영 허브 위에 얹는 장식이나 부분 리모델링이 아니다. **V106의 화면 구조와 디자인을 운영 허브의 새 프론트엔드로 전면 채택한다.** 기존 허브의 화면 마크업과 페이지 컴포넌트는 새 UI의 자식으로 넣지 않는다.

운영 허브에서 보존할 대상은 다음뿐이다.

- 로그인, 세션, 권한 확인
- 서버 데이터 로더와 데이터베이스 접근
- 외부 채널 API와 수집 작업
- 계산식, 신뢰도 판정, 오래된 자료 판정
- 쓰기 작업, 확인 절차, 멱등성, 감사기록, 재조회, 롤백
- 네이버·쿠팡·Cafe24 등 채널별 데이터 및 실행 경계

즉, **시안이 화면을 소유하고 기존 허브가 기능을 공급한다.**

이 문서는 기존 `2026-08-29-phase28-overlay-readiness-design.md`의 페이지별 오버레이·혼합 전환 방식을 대체한다. 기존 명세에서 유효한 API 안전성과 ViewModel 원칙은 유지하지만, 레거시 UI를 Phase 28 안에 삽입하거나 페이지별로 두 UI를 섞는 구조는 폐기한다.

## 2. 완료 상태의 정의

전면 교체가 완료되면 사용자는 현재 운영 주소에서 V106 시안과 같은 화면을 본다. 다음 항목이 시안과 일치해야 한다.

- 공통 셸, 좌측 내비게이션, 상단바, 모바일 내비게이션
- 본문 시작점·끝점, 최대 폭, 여백, 반응형 전환점
- 제목 위계, 한국어 상태 문구, 강조 밑줄 애니메이션
- 색상, 표면, 모서리, 테두리, 그림자, 채널 로고
- 목록과 카드의 글자 크기, 행 높이, 조작부 높이
- 오른쪽 작업석의 열린 상태, 접힘 모션, 모바일 배치
- 페이지별 차트, 흐름선, 탭, 필터, 선택, 펼침 상태
- 라이트·다크 모드와 모션 감소 환경

여기서 “같다”는 시안의 분위기를 참고한다는 뜻이 아니다. **V106의 실제 DOM 구조, CSS 수치, 상태 전환과 반응형 동작을 이식 기준으로 삼는다.** 단, 시안의 샘플 숫자와 가짜 성공 상태는 운영 데이터로 복사하지 않는다.

## 5. 목표 코드 구조

### 5.1 새 앱 셸

`Phase28AppShell`이 V106의 좌측 내비게이션, 상단바, 본문 캔버스, 모바일 메뉴, 명령 팔레트, 자료 근거 서랍을 소유한다. 전면 교체 모드에서 기존 `HarinDashboardShell`의 시각 구조는 렌더링하지 않는다.

### 5.2 라우트 렌더러

`Phase28RouteRenderer`가 `phase28-route-registry.js`의 17개 안정 주소를 새 페이지 컴포넌트에 연결한다. URL, 브라우저 뒤로 가기, 새로고침, 직접 주소 진입이 모두 동일한 페이지 상태를 복원해야 한다.

### 5.3 페이지 컴포넌트

각 페이지는 V106 DOM을 React 컴포넌트로 직접 이식한다. 예를 들어 주문·배송 페이지는 `UnifiedOrdersCenter`를 통째로 자식에 삽입하지 않고, V106 주문 목록·출고 작업석·오른쪽 레일이 운영 주문 ViewModel과 액션을 직접 소비한다.

같은 원칙을 CS, 재고, 상품, 키워드 등 모든 페이지에 적용한다. 레거시 페이지 컴포넌트는 데이터 공급원이 아니다. 데이터는 서버 서비스와 어댑터에서 받는다.

### 5.4 서버 ViewModel

페이지별 서버 어댑터가 기존 서비스 결과를 V106에 필요한 형태로 변환한다. 공통 증거 필드는 다음을 유지한다.

```text
value
unit
source
metricKind: actual | calculated | relative | estimate
status: READY | PARTIAL | BLOCKED | SETUP_REQUIRED | ERROR
period
asOf
sampleSize
formulaVersion
reasons
```

어댑터는 새로운 운영 계산을 임의로 만들지 않는다. 기존 계산 결과를 표현에 맞게 정규화하고, 누락·오래됨·근거 부족 상태를 보존한다.

### 5.5 액션 어댑터

버튼과 폼은 기존 인증 API와 실행 함수를 호출한다. V106의 인터랙션 모양만 사용하고 실제 작업은 다음 순서를 지킨다.

1. 사장님 확인창
2. 서버 권한·최신성·쓰기 잠금 검증
3. 멱등키를 포함한 실행
4. 실제 저장값 재조회
5. 감사기록과 성공·실패 상태 표시

시안의 `onclick`, `innerHTML`, 브라우저 `localStorage`는 운영 기능 구현으로 사용하지 않는다.

### 5.6 전면 교체 플래그

- `HARIN_PHASE28_ENABLED=false`: 현재 레거시 앱 셸을 렌더링한다.
- `HARIN_PHASE28_ENABLED=true`: 준비 검증을 통과한 경우에만 V106 앱 셸 전체를 렌더링한다.
- 기존 `HARIN_PHASE28_PAGES`는 개발 중 어댑터 준비 상태와 숨겨진 검증 범위를 표시하는 용도로만 사용한다. 운영에서 같은 셸 안에 신·구 페이지를 섞는 라우팅 스위치로 사용하지 않는다.
- 17개 라우트, 필수 어댑터, 공통 자산 중 하나라도 준비되지 않으면 전면 교체 플래그는 활성화되지 않고 차단 이유를 서버 로그와 준비 보고서에 남긴다.

오늘·주문·배송·고객·CS 세 화면이 공통 셸과 가독성의 비교 원본이다. 다른 페이지는 업무 정보 구조만 달라지고 공통 수치를 재정의하지 않는다.

## 7. 데이터 신뢰와 채널 경계

- 시안의 샘플 숫자는 운영에서 사용하지 않는다.
- 실제 0과 미수집·실패·오래된 자료를 구분한다.
- 근거가 없으면 `확인 필요`, `판단 보류`, `BLOCKED`, `SETUP_REQUIRED`, `표본 대기`를 표시한다.
- 이전 성공 자료를 사용할 때는 기준시각과 오래됨을 함께 표시한다.
- 네이버, 쿠팡, Cafe24의 데이터와 쓰기 경로를 합치지 않는다.
- 고객 개인정보, 비밀번호, 토큰, API 키 원문은 클라이언트로 보내지 않는다.
- 상품분석과 인사이트의 저장 목록은 메타데이터를 먼저 읽고, 상세는 펼칠 때 한 건씩 불러온다.
- 긴 로딩은 페이지 전체를 막지 않고 섹션별 로딩·부분 오류로 격리한다.

## 8. 이행 방식

### 8.1 개발 중

운영 화면은 현재 레거시 UI로 유지한다. 새 V106 앱은 숨겨진 전면 교체 플래그 아래에서 17개 페이지 전체를 만든다. 페이지별 개발은 가능하지만, 운영에서 레거시 셸과 새 셸을 섞어 노출하지 않는다.

### 8.2 최종 전환

공통 셸과 17개 페이지가 모두 검증된 뒤, 하나의 전면 교체 플래그로 운영 UI 전체를 V106으로 전환한다. 주소와 인증은 그대로 유지한다.

### 8.3 정리

운영 전환과 안정화가 끝나면 다음을 별도 정리 커밋에서 제거한다.

- `Phase28OrdersDashboard` 안에 `UnifiedOrdersCenter`를 넣는 현재 오버레이 구조
- `Phase28CsDashboard` 안에 `UnifiedCustomerServiceCenter`를 넣는 현재 오버레이 구조
- 새 UI에서 더 이상 참조하지 않는 레거시 화면 전용 컴포넌트와 CSS

서버 서비스, API, 계산, 저장소, 안전장치는 삭제하지 않는다.

- 확인창, 멱등성, 재조회, 감사기록, 롤백 회귀
- 오른쪽 작업석의 접근성 속성, 키보드, 모션 감소
- `pnpm test`

- 1728px 및 1920px 데스크톱

- 라이트·다크 모드

### 10.3 시각 대조

같은 화면 크기와 같은 상태로 시안과 운영 후보 화면을 캡처하여 비교한다. 다음은 승인 차단 항목이다.

기준 폭에서 공통 셸과 주요 요소의 기하 차이는 2px 이내, 색상 토큰은 동일 값, 텍스트 줄바꿈은 같은 상태를 목표로 한다. 운영 데이터의 길이 차이로 줄바꿈이 달라질 때는 글자를 줄이지 않고 시안의 재배치·말줄임·펼침 규칙으로 처리한다.

- 공통 셸 폭·여백·제목 크기의 불일치
- 시안에 없는 레거시 카드·헤더·탭의 잔존
- 레거시 페이지 전체가 새 페이지 내부에 중첩됨
- 오른쪽 접힘 뒤 빈 세로 레일이 남음
- 모바일에서 텍스트나 기능이 삭제됨
- 샘플 값이 실제 값처럼 표시됨
- 보호된 쓰기가 기존 안전 절차를 우회함

## 11. 롤백

개발·검증 중에는 전면 교체 플래그를 끄면 기존 운영 UI가 그대로 나온다. 최종 안정화와 레거시 프론트엔드 정리 후에는 오래된 UI 코드를 상시 유지하지 않고, 검증된 이전 Vercel 배포 또는 Git 커밋으로 롤백한다.

## 12. 범위 밖 작업

- 기존 API 계약과 데이터베이스의 전면 재설계
- 외부 채널 권한 확대
- 검증된 계산식의 임의 변경
- 시안에 없는 새 디자인 방향 추가
- 사용자의 별도 승인 없는 정보 구조 변경
- 샘플 데이터를 운영 데이터로 이관

## 13. 최종 인수 조건

- 현재 운영 주소 17개가 V106 새 UI를 렌더링한다.
- 기존 허브 UI가 새 UI 안에 보이거나 중첩되지 않는다.
- 시안의 공통 셸·페이지 구조·모션·반응형이 그대로 이식된다.
- 실제 데이터와 기능이 기존 서버 경계를 통해 동작한다.
- 미수집과 오류가 0이나 성공으로 위장되지 않는다.
- 쓰기 작업의 기존 안전장치가 모두 유지된다.
- 전체 테스트·빌드·UI 가드와 브라우저 시각 대조가 통과한다.
- 운영 전환 뒤 동일 주소에서 로그인과 핵심 업무 흐름이 정상 동작한다.
