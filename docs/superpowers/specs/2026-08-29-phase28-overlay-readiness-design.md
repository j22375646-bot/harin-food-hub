# Phase 28 운영 허브 이식 준비 설계

작성일: 2026-08-29
대상 시안: `main-ui-v28-preview` V106
대상 운영 허브: `harin-cafe24-sync` 1.38.99

## 1. 목적

V106 시안을 기존 운영 허브의 기능, 인증, 데이터 계산, 외부 채널 경계와 결합할 수 있는 구조로 바꾼다. 정적 HTML을 운영 화면 위에 복사하지 않는다. 기존 화면을 기본값으로 유지하고, 검증된 페이지만 기능 플래그로 전환한다.

이번 작업은 운영 배포나 실제 화면 전환을 포함하지 않는다. 이식 계약, 공통 컴포넌트 경계, 라우트 매핑, 데이터 어댑터, 저장 경계, 검증 장치를 먼저 만든다.

## 2. 고정 원칙

- 오늘, 주문·배송, 고객·CS를 공통 UI 기준으로 사용한다.
- 기존 API, 계산식, 인증, 감사기록, 멱등성, 롤백을 유지한다.
- 네이버, 쿠팡, Cafe24의 데이터와 쓰기 경로를 합치지 않는다.
- 오래되거나 누락된 값은 `0`으로 바꾸지 않는다. `확인 필요`, `판단 보류`, `BLOCKED`, `SETUP_REQUIRED`를 유지한다.
- 오른쪽 보조 패널, 제목선, 텍스트 크기, 선택 상태, 반응형 동작은 V106 공통 규칙을 사용한다.
- 운영 모드에서는 시안 샘플과 브라우저 `localStorage`를 운영 근거로 사용하지 않는다.
- 실제 채널 변경은 기존 사장님 확인창과 서버 검증을 통과한 뒤에만 실행한다.

## 3. 선택한 접근

페이지별 어댑터와 기능 플래그를 사용한다. 기존 운영 페이지는 계속 서비스한다. Phase 28 컴포넌트는 같은 서버 데이터에서 별도 ViewModel을 받아 렌더링한다. 한 페이지의 통합 테스트가 끝나면 그 페이지만 전환한다.

정적 HTML 전체 복사 방식은 사용하지 않는다. 이 방식은 Next.js 라우팅, 인증, 서버 계산, API 오류 처리와 분리되어 운영 기능을 잃는다. 전체 프론트엔드 재작성도 하지 않는다. 이미 검증된 서비스와 API를 재사용한다.

## 5. 코드 경계

### 5.1 라우트 레지스트리

`lib/ui/phase28-route-registry.js`가 다음 정보를 소유한다.

- V106 화면 ID
- 운영 주소와 기존 view
- 기능 플래그 키
- 데이터 어댑터 ID
- 쓰기 정책
- 기존 workspace 보존 여부

레지스트리는 중복 주소, 미등록 화면, 잘못된 쓰기 정책을 거부한다. 사이드바와 링크는 이 레지스트리에서 주소를 읽는다.

### 5.2 기능 플래그

`lib/ui/feature-flags.js`에 Phase 28 설정을 추가한다.

- `HARIN_PHASE28_ENABLED`: 전체 준비 스위치, 기본 `false`
- `HARIN_PHASE28_PAGES`: 전환할 화면 ID 목록, 기본 빈 목록

전체 스위치와 페이지 목록을 모두 만족해야 새 화면을 렌더링한다. 알 수 없는 화면 ID는 무시하지 않고 설정 오류로 보고한다. 기존 `HARIN_V8_ENABLED` 롤백 경계는 유지한다.

### 5.3 ViewModel 계약

`lib/ui/phase28-view-model.js`는 UI가 사용할 공통 증거 계약을 정의한다.

```text
value
unit
source
metricKind: actual | calculated | relative | sample | estimate
status: READY | PARTIAL | BLOCKED | SETUP_REQUIRED | ERROR
period
asOf
sampleSize
formulaVersion
reasons
```

화면은 원본 DB 행을 직접 받지 않는다. 각 페이지 어댑터가 기존 서비스 결과를 위 계약으로 변환한다. 값이 없거나 오래되면 숫자를 제거하고 상태와 이유를 표시한다.

### 5.4 페이지 어댑터

어댑터는 `lib/ui/phase28-adapters/`에 페이지별로 둔다. 어댑터는 계산하지 않고 기존 서버 서비스의 결과를 정규화한다.

- 운영 어댑터: 실제 서버 데이터만 사용한다.
- 시안 어댑터: 명시적인 design-sample 모드에서만 샘플을 반환한다.
- 오류 어댑터: 실패한 채널만 격리하고 이전 성공 자료의 상태를 보존한다.

상품분석 저장 이력은 브라우저 저장소가 아니라 서버 저장소를 사용한다. 분석 목록은 메타데이터만 먼저 읽고, 상세는 펼칠 때 한 건씩 불러온다.

### 5.5 UI 컴포넌트

V106의 33개 CSS와 20개 스크립트를 그대로 복사하지 않는다. 다음 단위로 옮긴다.

- `Phase28PageFrame`: 제목, 요약, 페이지 여백
- `Phase28EvidenceState`: 자료 상태와 기준시각
- `Phase28RightRail`: 공통 접기·펼치기와 모바일 배치
- `Phase28Selection`: 균형 잡힌 1px 전체 테두리 선택 상태
- `Phase28ChannelLogo`: 네이버, Cafe24, 쿠팡 고정 로고
- `Phase28Metric`, `Phase28Chart`, `Phase28EmptyState`

페이지 CSS는 공통 토큰을 소비한다. 버전별 덮어쓰기 파일을 새 운영 코드에 누적하지 않는다.

## 6. 데이터 흐름

1. Next.js 라우트가 기존 인증을 확인한다.
2. 기존 `app/page.js` 로더와 서비스가 필요한 데이터를 읽는다.
3. 페이지 어댑터가 원본 결과를 Phase 28 ViewModel로 변환한다.
4. 서버가 기능 플래그를 확인한다.
5. 플래그가 꺼져 있으면 기존 V8 화면을 렌더링한다.
6. 플래그가 켜진 페이지는 Phase 28 컴포넌트를 렌더링한다.
7. 쓰기 작업은 기존 API와 확인창을 사용한다.
8. 실행 뒤 서버가 실제 저장값을 재조회하고 감사기록을 남긴다.

클라이언트는 API 키, 비밀번호, 원본 고객정보를 받지 않는다.

## 7. 오류 처리

- 인증 실패: 기존 로그인 이동과 `401` 응답 유지
- 한 채널 실패: 다른 채널과 격리하고 이전 성공 자료를 `PARTIAL`로 표시
- 데이터 없음: 정상적인 0건과 미수집을 구분
- 계산 근거 부족: 금액과 비율을 숨기고 `BLOCKED` 표시
- 쓰기 실패: 기존 멱등키와 재조회 결과를 유지
- 어댑터 오류: 해당 페이지의 Phase 28 렌더링을 중지하고 기존 V8 화면으로 복귀
- 잘못된 플래그: 서버 로그와 검증 보고서에 오류를 남기고 새 화면을 활성화하지 않음

## 8. 테스트 전략

모든 기능은 실패하는 테스트를 먼저 추가한다.

1. 라우트 레지스트리: 17개 화면, 고유 주소, 기존 workspace 보존
2. 기능 플래그: 기본 비활성, 허용 목록, 잘못된 ID 차단
3. ViewModel: 누락값·오래된 값·0의 구분
4. 페이지 어댑터: 채널 격리와 계산식 보존
5. 컴포넌트: 제목선, 선택 상태, 44px 조작부, 오른쪽 패널
6. 통합 라우트: 인증, 새/기존 화면 선택, 직접 주소 복원
7. 쓰기 회귀: 확인창, 멱등성, 실제값 재조회, 롤백
8. 브라우저: 데스크톱, 390px, 430px, 다크 모드, 동작 감소
9. 전체 회귀: `pnpm test`와 `pnpm build`

## 9. 전환 순서

1. 공통 레지스트리, 플래그, ViewModel
2. 공통 셸과 고정 UI 컴포넌트
3. 오늘
4. 주문·배송
5. 고객·CS
6. 재고·상품
7. 정산·비용과 키워드
8. 상품분석과 인사이트
9. 상품개발과 시스템
10. 알림, 진단, 변경, 검증, A/B, AI 기준자료

각 단계는 기존 화면과 새 화면의 데이터 스냅샷을 대조한다. 한 단계가 실패하면 해당 페이지만 플래그에서 제거한다.

## 10. 완료 기준

- 운영 코드가 V106 화면 17개를 고유 운영 주소에 매핑한다.
- 기본 설정에서 운영 화면은 바뀌지 않는다.
- 활성화한 페이지는 기존 서버 데이터와 액션을 사용한다.
- 시안 샘플, `localStorage`, 인라인 `onclick`, 전역 `innerHTML`이 운영 경로에 없다.
- 기존 1,105개 테스트와 새 Phase 28 테스트가 통과한다.
- 프로덕션 빌드와 인증 경계가 통과한다.
- 페이지별 롤백이 환경변수 변경만으로 가능하다.

## 11. 범위 밖 작업

- 이번 준비 단계에서 운영 배포를 실행하지 않는다.
- 데이터베이스를 삭제하거나 기존 테이블을 교체하지 않는다.
- 외부 채널 쓰기 권한을 새로 열지 않는다.
- 시안의 샘플 숫자를 운영 데이터로 이관하지 않는다.
- 기존 운영 페이지를 한 번에 제거하지 않는다.
