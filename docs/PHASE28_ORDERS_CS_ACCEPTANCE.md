# Phase 28 주문·배송 / 고객·CS 수용 기준

## 같은 주소와 기존 기능 유지

Phase 28 주문·배송과 고객·CS는 별도 서비스나 미리보기 주소를 만들지 않는다. 현재 허브의 `/orders`, `/cs` 주소, 로그인 인증, 서버 데이터 로더, 채널별 데이터 경계와 쓰기 API를 그대로 사용한다.

새 화면은 기존 작업센터를 기능 단위로 다시 만들지 않는다. Phase 28 제목·요약·출고 레일·응답 우선순위·우측 보조석 안에 기존 `UnifiedOrdersCenter`와 `UnifiedCustomerServiceCenter`를 임베드한다. 따라서 다음 기능은 기존 구현이 계속 소유한다.

- 주문: 판매자배송 분리, 로켓그로스 조회 전용 경계, ePost 송장 발급, 쇼핑몰 송장 등록, 배송추적, 취소 요청 격리, 일괄 선택, 수동·자동 수집, 최근 30일 완료 이력
- CS: 채널별 문의 수집, 답변 초안과 확인, 쿠팡 문의·클레임 실행, 주문 연결, 처리 이력, 빠른 답변 양식
- 공통: 페이지별 AI 패널, 채널별 실패 격리, 기존 감사·멱등성·재조회 경계

## 기본 비활성 및 페이지 단위 검증

코드가 병합돼도 기본 설정에서는 기존 V8 화면이 계속 표시된다. 승인된 검증 환경에서 다음처럼 대상 페이지를 명시한 경우에만 새 화면을 사용한다.

```dotenv
HARIN_PHASE28_ENABLED=true
HARIN_PHASE28_PAGES=home,orders,cs
```

서버 런타임 플래그, 요청 주소, 페이지 어댑터 성공 상태가 모두 일치해야 Phase 28 화면이 렌더링된다. 주문 또는 CS 어댑터가 실패하면 해당 요청은 같은 주소에서 기존 V8 작업센터로 돌아간다.

## 표시 원칙

- 서버 초기 자료만으로 확정할 수 없는 주문 재시도 건수는 `0건`으로 만들지 않고 `확인 필요`로 표시한다.
- 채널의 `SETUP_REQUIRED`, `FAILED`, `PARTIAL` 상태를 정상 또는 0건으로 바꾸지 않는다.
- 주문의 취소·로켓그로스·판매자배송 경계를 합치지 않는다.
- 네이버, Cafe24, 쿠팡 로고와 상태를 개별 행으로 표시한다.
- 제목 밑줄은 왼쪽에서 한 번만 그려지고, 선택 상태는 한쪽 선 없이 균형 잡힌 전체 테두리와 배경을 사용한다.
- 오른쪽 보조석은 48x48 버튼으로 접히며 440ms 전환, `aria-expanded`, `aria-hidden`, `inert`, reduced-motion을 지원한다.
- Phase 28 우측 보조석이 표시될 때 기존 전역 사장님 작업석을 중복 표시하지 않는다.

## 검증

```powershell
pnpm verify:phase28-orders-cs
pnpm test
pnpm build
pnpm ui:guard
git diff --check
```

- 집중 검증은 Phase 28 기반·메인·주문·CS 테스트와 기존 주문 기능 회귀 테스트를 함께 실행한다.
- 전체 테스트는 기존 허브의 API, 계산, 인증, 채널 분리 회귀를 확인한다.
- 프로덕션 빌드는 `/orders`, `/cs`가 인증된 동적 라우트로 유지되는지 확인한다.
- UI 가드는 새 CSS가 그라데이션, 한쪽 선택선, 과한 그림자 같은 금지 패턴을 추가하지 않았는지 확인한다.

## 롤백

문제가 확인되면 다음 설정으로 즉시 기존 화면만 표시한다.

```dotenv
HARIN_PHASE28_ENABLED=false
```

한 페이지만 문제가 있으면 `HARIN_PHASE28_PAGES`에서 `orders` 또는 `cs`만 제거한다. 롤백은 주소, 인증, 주문·문의 원본, 송장번호, 처리 이력, 감사기록을 삭제하거나 변경하지 않는다.
