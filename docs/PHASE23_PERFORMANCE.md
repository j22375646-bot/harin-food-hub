## 검증 결과

### 반응형·접근성

로컬 프로덕션 빌드의 로그인 셸을 실제 브라우저로 확인했다.

| 화면 | 브라우저 뷰포트 | 문서 너비 | 가로 넘침 | 기본 버튼 높이 | 계측 마커 |
| --- | ---: | ---: | --- | ---: | --- |
| 소형 모바일 | 390×844 | 375px | 없음 | 54px | 23-8 |
| 대형 모바일 | 430×932 | 415px | 없음 | 54px | 23-8 |
| 데스크톱 | 1440×900 | 1440px | 없음 | 54px | 23-8 |

- 모바일 운영 화면은 하단 5칸 고정 메뉴와 112px 본문 여백을 유지한다.
- 공통 터치 기준은 48px이며, `prefers-reduced-motion` 사용자는 전환 효과를 줄인다.
- 브라우저 콘솔 오류는 0건이었다.
- 기존 운영 빌드에서 발견한 React hydration 불일치는 서버의 수집 시각을 최초 시계 값으로 사용한 뒤 브라우저 시각으로 전환하도록 수정했다.

인증이 만료된 상태에서는 비밀번호를 자동 입력하지 않았다. 따라서 보호 화면의 실제 전환 시간은 운영 로그인 후 브라우저의 `window.__HARIN_CLIENT_HEALTH__.snapshot()`으로 확인한다. 계측은 최근 30개만 메모리에 보관하며 서버 전송·영구 저장·화면 내용 수집을 하지 않는다.

### 대량 자료

- 키워드 10,000행은 한 번에 36행만 화면 작업대로 전달한다.
- 상품 원가 10,000행은 한 번에 8행만 전달한다.
- API 공급자 목록은 허용된 페이지 크기로 제한한다.
- 기본 화면에서 대량 입력칸을 동시에 생성하지 않는 23-4 규칙을 회귀 테스트로 고정했다.

### 부분 장애

네이버 광고 수집기에 강제 오류를 주입한 상태에서 다음을 확인했다.

- 전체 동기화 결과는 `PARTIAL`로 표시된다.
- Cafe24 11행 수집 결과는 `SUCCESS`와 `READY`로 보존된다.
- 쿠팡과 네이버 커머스 고정 IP 작업 큐는 계속 `RUNNING` 상태를 유지한다.
- 실패한 네이버 광고만 `FAILED`가 되며 다른 채널을 실패로 바꾸지 않는다.
