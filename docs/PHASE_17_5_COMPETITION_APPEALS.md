# 17-5 경쟁상품·경쟁 리뷰·소구점 분석

## 목적

선택한 상품 프로젝트 안에서 실제 경쟁상품, 개인정보 없는 경쟁 리뷰 집계, 우리 상품의 소구점을 연결한다. 작수차는 첫 검수 상품일 뿐이며 화면과 데이터 구조는 다른 판매 중 상품에도 그대로 재사용한다.

## 확인 규칙

- 경쟁상품은 같은 프로젝트의 검증 Evidence와 사장님 확인이 모두 있어야 `VERIFIED`가 된다.
- 경쟁 리뷰는 원문, 고객명, 주문번호, 연락처를 저장하지 않는다. 기간, 표본 수와 반복 불편·만족·구매·이탈 이유만 집계한다.
- 경쟁 리뷰 집계는 검증된 경쟁상품, 표본 10건 이상, 검증 Evidence와 사장님 확인이 모두 있어야 `VERIFIED`가 된다.
- 소구점은 검증 경쟁 리뷰, 경쟁 불편 Evidence, 우리 해결 Evidence가 모두 같은 상품 프로젝트에 있어야 `VERIFIED`가 된다.
- 치료·완치·최고·무조건 같은 표현은 `BLOCKED`, 건강·효과 관련 표현은 `VERIFY`로 남긴다.
- 가격이나 표본이 없으면 0으로 만들지 않고 `확인 필요` 또는 `판단 보류`로 표시한다.

## 데이터와 접근

- `market_competitors`: 플랫폼별 실제 경쟁상품과 가격·구성 스냅샷을 보관한다.
- `market_competitor_review_insights`: 개인정보 없는 경쟁 리뷰 묶음 집계만 보관한다.
- `market_appeal_points`: 경쟁 불편과 우리 해결 근거를 양쪽 Evidence ID로 보관한다.
- 모든 테이블은 RLS를 켜고 `anon`, `authenticated` 접근을 회수하며 서버의 `service_role`만 사용한다.
- 프로젝트-상품 불일치, 다른 프로젝트 Evidence·리뷰 연결은 DB 트리거에서 거절한다.
- 모든 저장 작업은 프로젝트 버전 이력에 이유와 안전한 스냅샷을 남긴다.

## 화면

- 경쟁상품: 플랫폼, 가격, 구성과 검증 상태를 카드로 비교한다.
- 경쟁 리뷰 신호: 표본 수와 반복 불편을 집계 단위로 비교한다.
- 소구점 연결: `경쟁 불편 → 우리 해결 → 확인 근거`를 한 화면에서 비교한다.
- 입력은 기본 접힘이며 검증 Evidence 선택과 사장님 확인을 분리한다.
- 페이지별 AI는 기존 별도 접이식 영역을 유지하며 현재 OpenAI 호출 비용은 0원이다.

## 완료 기준

1. 다른 상품 프로젝트의 경쟁상품·리뷰·Evidence를 연결할 수 없다.
2. 경쟁 불편과 우리 해결 중 한쪽 근거라도 없으면 소구점이 확인 완료되지 않는다.
3. 리뷰 원문과 개인정보가 서버·브라우저·버전 스냅샷에 저장되지 않는다.
4. 위험한 건강·치료 표현이 사용 가능한 소구점으로 표시되지 않는다.
5. 데스크톱과 모바일에서 16px 이상 본문, 48px 이상 조작 영역과 파스텔 V8 구조를 유지한다.
