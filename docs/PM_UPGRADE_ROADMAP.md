# 하린식품 허브 PM 업그레이드 실행 기준

기준 문서: `하린식품 광고·매출 진단 허브 PM·UX·개발 업그레이드 기획서`

## 제품 원칙

- 운영자는 10분 안에 실제 이익, 데이터 신뢰도, 오늘 할 일과 실행 결과를 판단할 수 있어야 한다.
- 알 수 없는 값은 0으로 바꾸지 않는다. `NO_DATA`, `PARSE_ERROR`, `BLOCKED`, `PARTIAL`처럼 원인을 보존한다.
- 화면 숫자보다 계산 출처·공식 버전·차단 사유를 먼저 신뢰할 수 있어야 한다.
- 금액을 바꾸는 조치는 표본·원가·귀속·작업자 상태가 모두 충족될 때만 허용한다.

## 현재 P0 재점검

| ID | 과제 | 현재 상태 | 완료 기준 |
|---|---|---|---|
| P0-001 | 데이터 소스 거버넌스 | 1차 구현 | 핵심 4개 지표에 source/status/as-of/formula-version 제공, 전 지표 확장 필요 |
| P0-002 | 배포 파이프라인 | 운영 중 | 테스트한 `main` 아티팩트 검증 후 고정 운영 주소 승격 |
| P0-003 | 인증·RBAC | 진행 필요 | 공용 PIN 제거, 사용자·역할별 권한 분리 |
| P0-004 | HTTP/API 안전 | 1차 구현 | GET 부작용 제거, 공통 no-store·보안 헤더, JSON·XLSX 검증 완료; 전 API 계약 확장 필요 |
| P0-005 | 재무 신뢰 게이트 | 구현 | 원가 95% 미만 또는 미귀속 광고비 존재 시 관련 지표 미산정 |

| P0-007 | 고정 IP 작업자 | 운영 | 서울 Lightsail 고정 IP 워커·상태·재시도·실패 알림·변경 차단 |

| P0-009 | KST 크론·멱등성 | 진행 필요 | 중복 실행 방지와 재처리 가능한 실행 이력 |
| P0-010 | 긴급 데이터 배너 | 구현 | 차단 사유·영향 지표·복구 동선을 전 화면에 표시 |

## 재무 신뢰 게이트 규칙

- 판매매출 기준 원가 반영률이 95% 미만이거나 확인 불가이면 공헌이익, 공헌마진, 손익분기 ROAS, 목표 CPC를 노출하지 않는다.
- 상품 미귀속 광고비가 0원이 아니거나 확인 불가이면 상품 ROAS, 상품 공헌이익, 입찰 증액 판단을 노출하지 않는다.
- 차단 화면에는 원가 반영률, 원가 미입력 상품 수·매출, 미귀속 광고비, 상품 허브 복구 동선을 표시한다.
- 클릭 30회와 전환 3건은 OR가 아니라 AND 조건이다. 하나라도 부족하면 `HOLD_FOR_DATA`다.

## 다음 개발 순서

1. P0-001: 공통 MetricSnapshot과 provenance 계약을 정의한다.
2. P0-004: 인증·동기화·파일 업로드 API의 메서드, 캐시, 헤더, 입력 검증을 감사한다.
3. P0-008: 완료 — 원가·채널비용·배송규칙·목표/예산을 preview → approve → execute → verify 상태 머신으로 통일했다.
4. P0-009: 모든 자동 실행에 KST 기준 실행키와 멱등키를 부여한다.
5. P1: 오늘의 우선순위와 Action Center를 동일한 신뢰 게이트 위에 연결한다.

이 문서는 코드와 운영 검증 결과에 맞춰 갱신한다. 원본 기획서의 범위를 축약한 실행 인덱스이며, 상세 UX·데이터 계약·테스트 기준은 원본을 따른다.
