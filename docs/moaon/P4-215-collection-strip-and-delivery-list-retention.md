# P4-215 주문 유지 및 통합 수집 상태 줄

작업일: 2026-10-27. 대상: 모아온 Windows 앱 0.215.0.

## 원인

1. 배송정보 자동 준비 후 `recheckShippingSelection()`이 현재 페이지를 재검증한다. 기존에는 재조회 UNAVAILABLE/SNAPSHOT_CHANGED를 일반 연결 실패처럼 `applyHubResult()`에 전달해 기존 목록과 선택을 비웠다. 배송정보 갱신 등으로 조회 기준이 바뀌는 409 뒤의 경로도 복구하지 않았다.
2. 수동 수집과 백그라운드 수집은 서로 다른 요청·상태 객체를 사용했다. 자동 수집 중에도 수동 화면에는 상태 기록 없음/BUSY가 보일 수 있었다.
3. 첫 수집 응답 이후에는 사용자가 직접 결과 확인을 눌러야 플랫폼별 상태가 갱신됐다. 완료/진행/확인 필요와 최신 저장 목록 조회가 서로 떨어져 있었다.

사진 속 개별 주문의 서버 원문을 특정할 정보는 없어 해당 실주문의 최종 이동 사유까지 단정하지 않았다. 위 실패 경로를 코드에서 확인하고 격리 Electron 시험으로 재현했다.

## 변경

- 일시적인 재조회 실패 시 현재 주문, 선택, 상세, 검색, 스크롤을 유지한다. 최신 확인 전 발급·등록·문서 작업은 잠가 오래된 상태로 처리하지 못하게 한다.
- 배송정보 준비 후 조회 기준 변경 시 최신 목록을 한 차례 다시 읽는다. 이 요청까지 실패해도 기존 목록을 비우지 않고 `다시 조회`를 제공한다.
- 확정된 로그인 만료·권한 상실·로그아웃에서는 기존과 같이 개인정보를 비운다. 성공 응답으로 확인된 실제 주문 상태 이동은 반영한다.
- 수동/자동 수집의 Main 요청 객체를 통합했다. 플랫폼 요청번호와 고객 원문은 Main에만 남기며 Renderer에는 허용된 상태·시각·오류 분류만 전달한다.
- 검색 아래 한 영역에 지금 수집/진행 확인/목록 반영, 플랫폼 칩, 최신 저장 목록 확인, 배송정보 준비 요약을 모았다. 헤더의 별도 수집 패널은 제거했다.
- 연결 확인 → 요청 → 플랫폼 대기/수집 → 완료/확인 필요를 서버가 확인한 범위에서 표시한다. Cafe24 처리 중간 세부 단계처럼 서버가 제공하지 않는 진척은 만들어 표시하지 않는다.
- 연결은 파랑, 수집은 보라, 성공은 초록, 확인 필요는 주황으로 구분한다. 진행 중만 회전/점 애니메이션을 적용하고 모션 감소 설정을 존중한다.
- 사용자 추가 요청에 따라 플랫폼 칩은 동일 너비의 3열·최소 높이 32px로, 수집 버튼은 120×32px로 통일했다. 준비 요약도 최소 높이 32px와 같은 8px 곡률을 사용하며, 좁은 화면의 버튼은 줄바꿈을 허용한다.
- 보이는 주문 화면에서 로컬 상태를 3초마다 읽고, 대기 중인 원래 요청은 최소 10초 간격으로 진행 조회한다. 새 POST 반복으로 진척을 확인하지 않는다. 다른 페이지·백그라운드 탭에서는 Renderer 상태 조회를 멈춘다.
- 시간 초과 시 확인된 플랫폼 상태는 유지한다. 원래 요청의 결과가 불명확하면 재수집을 잠그고 기존 요청 확인 또는 웹 허브 확인을 제공한다.

## 검증

- 연결/IPC/수집 코드 시험: 131개 PASS. 수동 요청을 자동 수집이 이어서 조회하며 POST를 중복하지 않는 사례, 인증 실패와 로그아웃의 늦은 결과 폐기 포함.
- 위 131개에 포함된 수집 상태 시험 3개를 별도 재실행해 PASS. 진행 상태의 요청번호 비노출, 조회 실패 시 이전 플랫폼 성공 보존, 실패 종료 후 명시적 재수집 가능 여부 확인.
- 오른쪽 보조 모니터의 격리 Electron UI PASS: 배송정보 후 실패 및 기준 변경+최신 조회 실패에서도 주문·선택 보존, 발급 잠금, 단계별 색상/움직임, 라이트/다크, 가로 넘침, 로그아웃 초기화. 실제 주문 발급·등록 쓰기 0회.
- 화면 캡처에서 기존 헤더용 CSS가 단계 문구를 숨기고 정렬하는 충돌을 발견해 수정했다. 설치 패키지 시험에서 문구 표시·좌측 정렬까지 재확인한다.
- 운영 저장 주문 읽기 전용 확인: 169건 PASS, 약 4.5초. 이 확인은 채널 신규 수집이나 실주문 발급 시험이 아니다.
- 검증 PC의 가용 메모리 약 0.45GB 상태에서 자동화 시작 지연·network service 종료 발생. 자체 도구 프로세스의 작업 메모리를 정리했으며 다른 사용자 앱은 종료하지 않았다. 여유 메모리 회복 후 UI 시험 통과.

## 단계

이번 작업은 1) 원인 재현, 2) 목록 유지·통합 상태 UI, 3) 설치본 검증·배포의 3단계다. 최종 패키지·설치본·공개 피드 결과는 아래 후속 기록에 남긴다. 기존 앱 성능 개선 6단계 중 3단계 완료 기준은 별도로 유지한다.

로그와 화면: `D:\GPT\Temp\moaon-collection-strip-215`, `D:\GPT\Temp\collection-connection-retest.log`.

패키지 일치 검사에서 1차 빌드의 CSS 이후 파일 오프셋 불일치를 발견해 배포·설치를 중단했다. 빌드 도중 임시 소스를 갱신한 작업을 원인 후보로 보며, 최종 소스를 고정한 새 폴더에서 재빌드한다. 이 파일은 공개하지 않았다. 이후 사용자 박스 크기 통일 요청으로 진행 중이던 빌드도 중단하고 보완본을 새 폴더에서 빌드한다.
