# P4-217 수집 결과 자동 반영 및 검색 영역 정리

2026-10-27 · 모아온 Windows 0.217.0

## 확인한 기존 동작

자동 수집과 별도로 약 30초마다 저장 주문 변경을 확인했다. 첫 페이지에서 선택·상세·검색이 없고 화면 위쪽에 있을 때만 자동 반영했다. 플랫폼 수집 완료가 변경 확인을 즉시 깨우는 연결은 없었다.

검색 입력란은 1px 테두리 외에 바깥 focus outline이 추가되고 form overflow로 잘렸다. 선택 요소에는 :focus와 :focus-visible 공통 규칙이 섞여 있었다. 확인 시각과 송장 확인 시각은 서로 다른 폰트/행간을 사용했다.

## 변경

- 수집 결과의 플랫폼별 SUCCESS/PARTIAL 기록이 새로 확인되면 Main에서 개인정보 없는 changeVersion을 갱신한다. 기존 변경 확인의 30초 대기와 오래된 pending delta를 무효화한다. 같은 기록을 재조회해도 중복 버전을 만들지 않는다.
- UI는 기존 3초 로컬 상태 조회에서 새 버전을 감지해 변경 확인 → 목록 반영을 자동으로 연결한다. 플랫폼 요청번호와 고객 원문은 Main에 유지한다.
- 첫 페이지에서 선택·상세·발급·입력 작업이 없으면 현재 조건을 유지해 자동 반영한다. 목록 조회 중에도 기존 주문을 표시한다. 실제 변화가 있으면 새 주문/변경 반영 결과를 안내한다.
- 선택, 상세, 발급, 입력 중에는 반영을 보류하고 조건이 풀리면 자동으로 이어간다. 다른 페이지를 읽는 중에는 강제로 첫 페이지로 이동하지 않으며, 첫 페이지 복귀 후 이어간다. 화면 비표시 중 Renderer의 조회는 기존처럼 억제한다.
- BUSY/SKIPPED를 이전 CURRENT 표시만 보고 반영 성공으로 취급하지 않는다. 오류는 기존 목록을 유지하고 최신 확인 전 발급을 잠그며 재시도한다. 로그아웃·권한 상실에는 대기 버전을 초기화한다.
- 반영 후 검색·선택·상세 보존 정책과 스크롤 기준 주문을 유지한다. 실제 목록 갱신은 현재 상태·채널·기간 조건 안에서 이루어지며 필터를 임의로 ALL로 바꾸지 않는다.
- 전체 검색/날짜/선택 입력의 포커스를 안쪽 1px 테두리로 통일했다. form 너비·padding·반응형 열을 정리해 왼쪽 잘림과 가로 넘침을 방지했다. 자동 조회 종료 후 검색 입력이 잠긴 채 남지 않게 제어 상태를 갱신한다.
- 플랫폼별 작은 박스 3개는 유지하고 상태 아이콘과 옅은 배경으로만 보완했다. 큰 바깥 박스의 테두리·배경·그림자는 제거했다.
- 주문 확인/송장 서버 확인 시각은 동일 11px, 20px 행간, 일정한 간격과 우측 묶음 정렬을 사용한다.
